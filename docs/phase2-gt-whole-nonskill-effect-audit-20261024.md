## A：変換と出典保持の実装

1. `flattenRoutes`（従来と同じGameTora分岐展開器）で、元イベント・選択肢・結果の**数値位置**を保持。文章・選択肢セリフを出力しない。
2. 単一符号付き整数は型を変換せず保持。絆の受け手`char_id`は`recipientCharId`として数値を保持し、異なるキャラクターを集計時に混同しない。*同じ*受け手・同じ効果種が重複すれば保留。
3. 型が不明、分岐条件が未表現、停止マーカーがある場合はその経路を保留し、元イベントの一部でも保留があれば**イベント全体を孤立プレビューへ昇格させない**。
4. 結果未選択の成功・失敗を合算しない。匿名の`result-N`で排他的に保持し、プレーヤー選択肢があるときは未選択状態で効果を得たものと扱わない。
5. 安全な結果形状だけ`event_schema.validateCatalog`へ通し、`core.directEffectRoutes`で数値経路を再生。ただし**元のイベント到達・前後のチェーン接続・未照合スキル・発生抽選は含まない「孤立した非スキル効果プレビュー」**。本番側の`directRoutes/aggregate`やスキル保有枚数は変更しない。
6. 入力母集団・全効果・結果位置・スカラー効果数の保存則を検査し、データ変化によって黙って計測対象を減らさない。

## A/B/Cと限界

**A**：`node --test poc/tests/phase2_gt_whole_nonskill_effect_inventory.test.cjs`。数値の負号・対象受け手ID・成功失敗・ランダム結果・選択未設定・不明型や条件の退避・固定母数違いを検出。

**B**：ピン留めした実ソースで559/563、2,488、4,129、4,376を検証した上で出典数値と保留位置を全件測定。GameWithへの一律全面取得はしない。疑義の出た箇所だけ基準出典・例外資料で個別裁定する。

**C**：GitHub Pagesへの非公開候補追加も非スキル結果表示も行わない。ブラウザ回帰テストは現行UIの保全確認であって、ゲーム結果を実機で証明するものではない。

**次の最優先**：未対応コードのうち多い`condition`／`all_stats`／`heal_status`の意味を既知コードとの整合性と元の値・対象から詳しく分類し、継続停止フラグや条件付き`segments`の欠落なしに実行カタログへ組み込める変換規則を段階的に増やす。その際、元資料に明示される個別事実を別サイトや実機の不足を理由に保留しない。
