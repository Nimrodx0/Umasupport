# Phase 3 F-01：名前付きデッキ管理の実装・受け入れ

2026-10-17、PR #50。[要件F-01](requirements.md#f-01-デッキ管理)に対して本育成・継承育成それぞれの**名前付きデッキを複数保持できる**ようにした。比較対象は各側で選択中の1デッキのみ。各デッキは6枚スロット・0～4凸・カードごとのイベント選択を完全に別保存する。目標スキルセットはデッキとは独立。

## UIと保存形式

- 「本育成」と「継承育成」の各パネルに、それぞれ保存デッキ選択リストと「管理」を設置。
- 管理画面で空のデッキ作成、現在のデッキの複製、改名、削除。最後の1件は削除不可。上限は本育成／継承育成それぞれ50件。
- 複製はステージ・イベント選択を含むdeep copy。複製後の変更は元の編成へ波及しない。
- 変更は従来どおりブラウザlocalStorageへ自動保存。JSONエクスポート／インポートにも両デッキライブラリと選択中IDを含める。
- スキーマv2：decks.main/decks.inheritが配列、activeDecks.main/activeDecks.inheritがそれぞれ選択ID、nextDeckIdが生成番号。旧v1の2つの単一デッキはカード構成・凸段階・イベント選択・目標を失わずにパース時のみ変換し、**ユーザーの明示操作前に元のlocalStorageを上書きしない**。
- 破損JSON、未知サポカ、非表示の保存デッキを含む不整合ID、重複デッキID、選択対象欠損を拒否。エラー時に確認なく初期化しない。

## 手動受け入れ（将来まとめて依頼）

1. 本育成デッキにカードを数枚置き、「管理」→「現在のデッキを複製」。元デッキと複製を選択欄で切り替える。
2. 複製のカード・凸設定を変えて元へ戻す。元の内容が変わらず、継承育成も変わらないことを確認する。
3. 空のデッキ作成→改名→再読込→選択を確認。不要なデッキを削除し、最後の1件は削除できないことを確認する。
4. JSON保存・読込で複数デッキ名と選択が復元されるか確認する。
