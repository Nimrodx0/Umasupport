# GameWithイベント記事のオフライン解析パイプライン（2026-10-19）

## 実施範囲と利用条件

対象は、GameWithの個別サポカ記事から**元文章を転載せず**、スキル・ヒントLv・選択枝順などのゲーム上の事実を独自JSONの**草稿候補**として抽出する処理。現時点でコードにWebアクセス機能はない。自動スクレイピング・一斉ページ取得・GameWithのHTML保存公開・生成した草稿の無審査公開は**実施しない**。

確認したもの：
- [GameWith日本語版利用規約](https://gamewith.jp/terms)（2024-05-16改訂版、第9条14号の過剰なサーバー負荷、第9条17号の提供機能の複製・解析、第10条の知財権帰属）。
- [GameWith robots.txt](https://gamewith.jp/robots.txt) はsitemapを表示。robotsで禁止されていないことはアクセス許可・再配布許可を意味しない。
- [GameWith英語版創作ガイドライン](https://gamewith.net/guidelines) は明示的に**gamewith.jpを適用対象外**としている。このガイドを日本語記事収録の権利根拠に使わない。

大規模・反復収集に先立ち、GameWith側に自動取得の方法、頻度、加工データの公開範囲について照会し、適切な許諾条件または別の適法な取得方法を確定すること。**全件取得に懸案がない状況ではないため、563枚を一括HTTP取得していない。** 解析器は、条件が満たされて合法的に準備された**ローカルの本文テキスト／HTMLファイル**を受け取る。

## 新規実装

- `poc/tools/import_gamewith_article.py`：1記事のローカルMarkdown／可読テキスト／一部HTMLを読み、UmaSimカードID・レアリティと記事見出しを突き合わせる。出典URLを索引から照合し、通常イベントの選択枝と『スキル』ヒントLvを辞書IDに照合して元文章を含まないJSON**提案**を保存する。未知IDはスキル名・Lvを未照合として保持。
- `poc/tools/batch_gamewith_import.py`：全UmaSimカードを並べ、既存索引URL・ローカル資料・提案済み・解析拒否を区別する。将来、権利面と資料準備が解決すれば、適法に保有するカード記事群の入力を1回のコマンドで処理できる。**自動リンク推定はしない**。
- `poc/tests/test_gamewith_article_import.py` と `test_gamewith_batch_import.py`：すべて架空の記事を使用。カード混同、別レアリティ、記事抜け、未知スキル、成功・失敗、連続イベント、HTMLテーブル、差分などを検査。

**安全な一段階目**：単純な通常イベントのみ提案。連続イベント・成功／失敗／大成功・継続／打ち切り・ヒント表記をパースできない分岐は**手動確認リスト**へ。これらを自動的な `type:auto` の確定報酬にしない。出典記事と草稿JSONの原本内容が一致すること、記事が全イベントを列挙していることを機械だけでは証明できない。

## ローカル実行

外部記事本文をリポジトリに入れない。 `poc/inputs/`, `local-data/` は `.gitignore` で無視する。実際のファイル名例：

```text
poc/inputs/gamewith/
  10003.md
  10004.html
```

外部由来の実記事は**権利のある保存方法で用意した場合に限り**配置。誤登録の予防として `--source-index` に登録されていないカードIDを解析しない。取得可能な元記事URLが確定しない残り543枚は、まず出典URLを台帳へ追加する必要がある。

```bash
python3 poc/tools/import_gamewith_article.py \
  --card-id 10003 \
  --article-file poc/inputs/gamewith/10003.md \
  --support-card local-data/umasim-support-card.txt \
  --skill-data local-data/umasim-skill-data.txt \
  --existing-draft poc/data/curation/drafts/10003.v1.json \
  --output local-data/gamewith-proposals/10003.proposal.json

python3 poc/tools/batch_gamewith_import.py \
  --support-card local-data/umasim-support-card.txt \
  --skill-data local-data/umasim-skill-data.txt \
  --input-dir poc/inputs/gamewith \
  --out-dir local-data/gamewith-proposals
```

必要なUmaSimファイルは既存の固定取得元にあるものを利用する。プログラム自体はこれらのファイルやGameWithページをネットワークから取得**しない**。出力ディレクトリと入力ディレクトリは同一にせず、ユーザーが確認できる提案JSONと `batch-report.json` を作成するだけ。本番DBへの反映はしない。

## 収録時の必須確認

1. 出典URLが特定カードを示し、カードの二つ名・レアリティが一致しているか。別カード、特に同キャラ別レアリティなら拒否。
2. `observedEventHeadings` と `proposedEvents` の差がどこで生じたか。連続イベント、未確認の結果依存、読み損ねのイベントが残っている状態で「全件完成」としない。
3. `comparison.status` が `identical` 以外なら手動で元記事と既存草稿の分岐・報酬を再照合。記事更新時の差分で自動上書きは禁止。
4. `unresolvedRewards` のIDを原本辞書＋草稿専用補完台帳で確定する。補完に根拠が不足した場合は未解決として保持し、虚偽の数値IDを作らない。
5. 元記事のテーブル構造の変更、複雑な選択肢や発生条件、ページにない記事IDは**解析不能**として記録。正常終了やJSONファイル数を100%信頼性と解釈しない。
6. 既存の `curated_event_inventory.cjs` と公開承認ゲートによる確認を継続。編集用提案は承認済みDBにも通常アプリにも直接読み込ませない。

## 現在の状態

固定UmaSimのサポカ母数は563枚。GameWithの個別記事URLの索引があるのは20枚、独自草稿も20枚・47イベント。残り543枚は記事紐付けから未収録。今段階の自動解析結果は**架空のユニットテストのみ**であり、GameWith現行HTMLを取得・バッチ変換できると実証したものではない。

次の実装の入口：許諾等が整えば、R/SR/SSR各1ページを安全な方法で取り込み、本番HTMLのDOM表現を使った構造テストを追加し、複雑な分岐も解析する。成功率・差分率・未解決スキル率を確認してから、対象を20、100、563へ段階的に広げる。**数が多いだけの誤データを採用しない。**

## 2026-10-19：連続イベント・成功／大成功を情報を失わず収録する改良（PR #87）

GameWithの実際の表示構造について、[SRスイープトウショウ](https://gamewith.jp/uma-musume/article/show/259506)は「連続2件＋通常2件」、[SSRエフフォーリア](https://gamewith.jp/uma-musume/article/show/573288)は最終連続イベントの選択肢ごとに成功と大成功の報酬が分離していることを確認。

解析器を改良し、**自動発生条件が不明な連続イベントも丸ごと捨てない**。観測したイベント順序、連続／通常のカテゴリ内順序、選択肢の位置、各報酬の数値スキルIDとLvを `manualCandidates` に保存し、`reviewRequired` と結び付ける。成功／大成功については `outcomes: [{id:"success"...},{id:"great"...}]` に個別の報酬集合を格納し、絶対に無条件報酬へ合算しない。

`manualCandidates` は**公開スキーマと別の非公開提案情報**であり、アプリのイベント獲得経路に接続しない。継続・終了条件、正確なゲーム内event ID、ヒント報酬以外の効果の取り扱いは別途編集者が確かめる必要がある。結果の片方しか掲載されていない、認識不能な報酬や不明な続行条件は失敗せず `reviewRequired` で隔離し、選択肢やIDを捏造しない。

**重要な不具合修正：** 最初の通常イベントが複雑で保留された場合、2件目に本来の「通常02」ではなく「通常01」という仮IDを付与していた。今後は**提案が通ったイベント件数ではなく、記事で見た見出し順**をイベントの仮IDへ使用する。既存草稿との差分検査も報酬配列だけでなく**イベントID・分岐結果まで比較**し、同じスキルの別イベントを誤って同一視しない。

この改良の回帰は**人工作成したR/SR/SSR風サンプル**を使用している。GameWith実サイトのHTMLファイルをシステムへ取り込んだ試験ではない。利用条件・記事権利を確認するまで、大規模なライブ取得を行わない。正式な独自草稿は20枚47件、公開承認イベント0件のまま。

## 2026-10-19：選択肢なし＋成功／失敗のイベントを編集用候補に保持（PR #89）

実記事の[SSRトウカイテイオー30003](https://gamewith.jp/uma-musume/article/show/257458)にある「選択肢なしの連続3段」および[SRスペシャルウィーク20043](https://gamewith.jp/uma-musume/article/show/320057)にある「選択肢なし／成功・失敗」の連続2段を参考に、オフライン解析器が1行の `選択肢なし | 報酬` を見た場合、報酬がないものを含めて編集専用の `manualCandidates` に `eventKind:"auto"` と数値報酬の `facts` を保持できるようにした。成功＋失敗、成功＋大成功、成功＋大成功＋失敗の明示的な複数結果を区別して保存する。

**依然として自動公開しない。** 1行に「選択肢なし」と見えても、カード編成での確定獲得、イベント続行、成功率、イベント内部IDが証明できるわけではない。複数結果を含めても `proposal.cards[*].events` には入らない。結果が成功しか書かれていない、別の選択肢を認識できない、パーサーが理解できないヒント形式は `reviewRequired` にし、無条件スキルとして扱わない。

入力用の生サイトHTMLは引き続き未検証。元記事や実HTMLの同梱なしで、記事の**構造だけを模した人工テスト**で本処理を検査した。独自草稿22枚・56イベントは変更せず、通常本番公開0件も維持。

## 2026-10-19：オフラインHTML改行と未解析ヒントのフェイルクローズ

GameWithの記事を**適法にローカルへ用意した場合だけ**解析するという取得範囲は変更しない。収録器のHTML表セル中の `<br>`、`<div>`、`<p>`、`<li>` による改行を保持し、成功／失敗／大成功を一つの文字列に連結してスキル報酬を誤配賦しないようにした。複数スキル記述のうち一つでも「ヒント」の構文が未解析なら、部分的な候補公開を行わず手動確認へ送る。結果ラベルより前にヒントが現れる場合も所属する結果が不明なので自動判定しない。

人工HTMLによる回帰テストでは「選択肢なし＋成功／失敗」「同一セル内の複数の正常なヒント」「正常／不明ヒント混在」「成功結果より前のヒント」を独立に検証する。これらは**記事形式の一部への耐性**であって、実GameWith DOM網羅・権利・条件・サポカイベントの全件正確性を保証しない。収録草稿は22枚56イベント／通常公開0件のまま。

## 2026-10-19：バッチ候補の出力先防護

`batch_gamewith_import.py` は出力先を作る前に、記事入力ディレクトリとその配下・上位ディレクトリ、またはリポジトリ内の `poc/data` とその配下・上位ディレクトリに重なるパスを解決後の実体パスで拒否する。直接呼ばれる `plan_and_import()` でも同じ検査を適用し、入力が0件または全件拒否される場合にも例外を出す。編集候補をGit追跡データ領域に誤出力しないための防護であり、編集候補の正式公開権限を意味しない。既定の安全な出力例は `local-data/gamewith-proposals/`。

## 2026-10-19：実記事のカード識別情報を使う照合

[SSRトウカイテイオー30003](https://gamewith.jp/uma-musume/article/show/257458)のように記事見出しが「SSRスピード」、[SRスペシャルウィーク20043](https://gamewith.jp/uma-musume/article/show/320057)のように見出しが「イベント配布報酬」でも、記事の「キャラクター名(SR/SSR)の性能」と性能表の「レア」「二つ名」で特定カードを区別できる。従来の `(SSRサポート)` という記事タイトル仮定を必須とせず、**カード名＋レアリティの性能見出し＋レア欄＋SR/SSR二つ名**を記事冒頭で独立に照合する方式を追加した。

実形式をモデル化した人工HTMLと不一致・欠損ケースの回帰テストを導入。従来の簡略化された `(Rサポート)` Markdown入力も引き続き受理するが、レア欄が存在して矛盾する場合は拒否する。SSR/SRは二つ名一致を必須とする。これはGameWithの**公開ページで見える表記の限定的な確認**であり、現行の生HTML DOM全体を保存・一括取り込みした実証、全件正確性、転載権限の承認ではない。複雑な連続イベントは依然として手動候補のまま。本番0件、草稿22枚56イベントは不変。
