# Phase 2：GameTora由来の全イベントを数値中間DBへ変換（2026-10-21）

## 目的と今回の成果

[GameToraを基礎、GameWithを疑義裁定に使う開発方針](gametora-baseline-event-policy-20261021.md)を実現するため、GameTora由来固定ソースに存在するイベントを一件も省略せず、カード→イベント→選択肢→結果経路→効果→数値スキル情報の形で中間DBに変換した。**GameWith記事から全件を作り直していない。**

実行可能コード：

- `poc/src/gametora_whole_event_normalize.cjs`：カードごとの構造・数値事実・未解決マーカーを正規化
- `poc/tools/generate_gametora_whole_event_candidate.cjs`：固定版の全件を照合して未公開の一時JSONファイルへ出力
- `poc/tests/gametora_whole_event_normalize.test.cjs`：データ欠損、結果別終了、特殊条件、非公開化、直接獲得、件数保存の人工テスト
- `.github/workflows/whole-event-inventory.yml`：元データを一時チェックアウト、既存のChecker×GT暫定索引と突合後に中間DBをActions artifactだけに記録

## データの意味

イベントIDは `gt-<cardId>-event-<sourceOrdinal>` の内部仮IDで、**実ゲームstory_idではない**。元ソースのローカル数値event IDは記録するが、ゲームのstory_idとは同定しない。イベント名・選択肢名は独自の仮表示に置き換え、原名からの一方向ハッシュだけを照合用に保存した。

各イベントは元のセクション、連続イベント内での出現位置、候補次段階、選択肢の順序と結果の順序、効果型コードと数値、スキルの原数値ID・ヒントLv、特例の `chain_end`、前段結果条件マーカーを保存する。各結果経路は `TERMINAL`・`DEFAULT_CONTINUE`・`OBSERVED_CHAIN_TAIL`・`NOT_A_CHAIN` の仮分類を持つ。

**通常継続**はGameToraの編集上のデフォルト挙動として使い、通常の隣接段階を逐一GameWithで確認する必要はない。ただし「出典内に並んだ2つのイベント」をゲーム内で必ず連続する同一チェーンと独立立証したわけではないため、後続位置は候補メタデータのままとし `sourceOrderAdjacencyVerified:false` を維持する。

### アプリのスキルIDへの変換は残工程

GameToraデータの`skill_id=200532`などは数値IDである。一方、既存PoCの通常ヒントは `hint:スキル名` という文字列IDを使用する。**根拠なしに数値IDと名前IDを同一視しない**よう、中間DBでは`appSkillIdVerified:false`としている。次の工程で正規化されたスキル辞書との照合を行い、確実に1対1に対応付けられるヒントだけUIの報酬として使う。

`skill_hint_or`・不完全な数値／IDは13件の未解決として別管理する。`obtain_skill` 7件は**ヒントLvではなくスキルの直接獲得**であるため独立した未承認レコードとして保持した。前段成功・条件付きセグメントは、数字が取れていても特定の結果で確実に獲得できると断定しない。非連続イベントで見つかった18の`chain_end`も無視せず、意味を後続レビューで確認する。

### 例外レビューと公開

連続イベントがソース内で隣接しているだけなら、**疑義として毎回GameWith照合キューには入れない**。例外キューには未解析ヒント、直接獲得、前段条件、非連続イベントの明示打ち切りなどを小さな単位で登録する。今後、別ソースとのヒント差異や名寄せ衝突をこの台帳の同一カード・イベント・選択肢・経路位置に紐付け、疑義があるものだけGameWithを裁定者として使う。

出力には原イベント文・選択肢の第三者文章を含めず、第三者のJSONを丸ごとコミットしない。`releaseApproved:false`、`gameVerified:false`、`noEventCanPublishFromThisCandidate:true` を固定。**本番公開DBの承認済みイベントは依然0件**。元記事や日本語名を転載できると判断したわけではない。GitHub Actionsの一時生成結果を本番`poc/data/reviewed_events.v1.json`へ直接書き込む運用は禁止する。

## 次の開発工程

1. **数値ID→アプリスキルID対応**：ゲームスキル数値IDとヒント辞書の名前を一意に照合。レア度・上下関係・ヒントLvの表記を維持。
2. **未対応例外の処理**：13件の未解析ヒント、7件の直接獲得、8件の条件付き結果と非連続18件の打ち切りをそれぞれ分類。GameToraのままで意味が確定すれば自動処理し、解釈が割れる箇所だけGameWithで裁定。
3. **全件の内容を公開可能な独自表現へ投影**：仮名前を実際に表示できる独自表現へ変え、文言・利用条件・数値事実・前段条件・スキルIDを承認してから本番DBへ段階的に昇格。
4. **網羅性の残差**：GameToraにない4カード、Checkerだけで観測されたイベントと元資料の不一致を別キューで補完。現行ゲーム版の完全イベント一覧の証明とは切り分ける。

**検証済み中間DB ≠ 本番公開済みDB**。変換ができたという事実と、現行ゲームのすべてのイベント・報酬が正しいことを区別する。
