# Phase 2：問い合わせを前提にしない公開方式の検証（2026-11-02）

## 決定・目的

利用者の2026-11-02の意向を反映し、**GameTora / GameWithへの個別問い合わせをリリースの必須工程から外す**。ただし「問い合わせ不要」は「許諾不要」や「公開してよい」と同義ではない。該当する明示ライセンス、閲覧・取得の条件、独自の事実記述と創作的なデータベース構成、元ゲームの表現を**別々に**評価する。判断根拠が不足する範囲は保留する。

プロダクト要件は変更しない。イベント名を保持し、選択肢・結果は番号付き仮称。一般利用者はファイル操作不要で起動時に自動読込。既存非公開563サポカ・2,512イベントの再作成はしない。**今回も公開イベント0件**。

## 取得・配信方式の判定

| 候補 | 利点 | 依然として必要な確認 | この時点の判定 |
| --- | --- | --- | --- |
| A. ウマサルタント独自の事実・数値JSONをPagesから配信 | 既存の本番ローダー・キャッシュを使える。利用者操作不要 | 元の取得経路、短いタイトル、元DBの選択・体系的構成の創作性、他者の創作的表現、必要な表示条件、ゲーム事実の正確性 | **主経路として継続調査**。許諾済みと断定しない |
| B. 各利用者のブラウザで第三者GitHub JSONを取得 | ウマサルタント側の元データ再配布を回避できる | 元ファイルごとの許諾・第三者の権利、取得行為、CORS、数百ファイル・通信負荷、既存全件変換器との差、元サイト・GitHubの条件 | **採用保留**。「読むだけ」では条件を解決しない |
| C. 利用者の私的ローカルJSONを選択読込 | サーバーから素材を配信せず、実2,512イベントの技術試用は実証済み | JSONの適法な取得方法、利用者ごとの操作負担 | **開発・検証用**。一般利用の完成条件にしない |
| D. 許諾範囲を明示した別ソース／適法な独立観測から事実を編纂 | 元DB独自の構成に依存する範囲を減らせる | そのソース自体の使用条件、独立性、全件のID・分岐正確性、ゲーム素材の権利 | **将来の有力な補完経路**。現2,512件の元出典を遡及的に無権利化するものではない |

### 問い合わせなしで成立しうる条件

- 第三者由来の創作的な台詞・選択肢本文・画像は出さない。短いイベント名は一律削除しないが、個別の著作物性や利用条件に関する不明点を「短いから許可済み」としない。
- 事実・数値・分岐という内容と、*どの素材を収録し、どの対応関係・並びで選択して編纂したか*という元データベースの構成を区別する。単純なJSON書換・表示ラベル変更だけではデータベース由来の問題を解消しない。
- AGPLを掲げる派生GitHubリポジトリのライセンスは、元GameTora独自編集・Cygames素材まで自動的に許諾する証拠にならない。
- GameWith.jpに対する大量・継続取得を新規に実装しない。編集上の数値事実の採用とアクセス・契約条件は別問題。
- **公開根拠が確定していない実イベントを公開しない**。機械的な分類は権利判断の代用にならない。明示的な再利用条件を確認できなければ、法的専門家への相談や独立に収集した事実へ切り替える余地はあるが、サイトへの問い合わせは必要条件ではない。

### 分岐構造の著作権の具体的当てはめ

[著作権法第12条の2](https://laws.e-gov.go.jp/law/345AC0000000048) の保護対象は、情報の**選択又は体系的な構成に創作性がある**DB。カード→イベント→選択肢／排他結果→数値効果の通常の対応付けや、ゲーム内の既定の前後関係は、ゲーム上の事実を機能的に記述するもので、**それだけで元データベース独自の創作的表現とは評価しにくい**。

[東京地裁2010年12月21日住宅ローン金利比較表事件](https://jucc.sakura.ne.jp/precedent/precedent-2010-12-21c.html) は、全国の商品を網羅的に収集する選択・普通の比較表の配列には創作性を認めず、具体的なデータベース構成について主張立証も不足とした。ウマサルタントが「全サポートカードのゲーム内イベントを機械的に記録する」方針なら、その着眼は類推可能。ただし、**ウマサルタントの固定元は当時の559枚・2,488イベントであり現行ゲーム全件ではない**。GameTora固有の取捨選択を複写していないかは、機械的な網羅性の主張だけでは証明できない。

[知財高裁2016年1月19日旅行業システムDB事件](https://www.ip.courts.go.jp/app/files/hanrei_jp/639/085639_point.pdf) は反対方向の重要な事例。個別の項目が業務上必要でも、具体的なテーブル・フィールド・参照関係の選び方や多数の観光・道路地点の選定に創作性があり、共通する体系的構成の複製・翻案が認められた。したがって、**『個々の分岐が単純なら、元DB全件の体系的構成を複製しても必ず安全』とは言えない**。ただし本件のGameTora→ウマサルタントは、旅行業者向け多数の独自検索テーブル・フィールドの採用と同一の事実関係ではない。実際の共通部分とその創作性を個別に見る。

具体的な元 [support_30080.json](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/data/events/gametora/support_30080.json) では、`kind/id/events/events_ja` と、各イベントの `section`・`event_type`・`choices`・`effects/outcomes` を確認できる。既存のウマサルタント用投影は**元サイトのHTML、ページ構成、解説文、`section`や`event_type`をそのまま転載していない**。ただし **GT由来イベントIDが元出典の掲載位置に由来し、収録範囲と結果順・イベント内の前後関係も元資料を参照している**ため、「他社DBを一切使っていない」とは言えない。*単純な関連付けの通常性* と、*編集物の創作的な部分の複製* を別の問題として扱う。

### この監査の判断と保留

- **著作権上の主見通し**：短いイベント識別名と客観的なID・分岐・スキル／能力数値・通常の階層関係を、ウマサルタントの既存独自JSONで使う方法は合理的。単純な分岐の記述を「データベース著作権があるから不可」と一律判定する根拠は乏しい。
- **残る具体的な論点**：(a)GameToraが独自に行った収録対象の選定の創作性の有無、(b)23文字以内のイベント名の出所・個別の表現性、(c)GitHubに掲載された保護対象部分がある場合の権利範囲、(d)GameWith由来25件のサイト利用方法・規約との関係、(e)元位置に依存するIDと後続のモデルの正確性。
- **既存ゲートへの反映**：`poc/src/event_release_cohorts.cjs` の v2 人手審査には、個別権利者の許可を必須としない `publicationBasis.kind="original-factual-description"` が**すでに存在する**。許可のないデータを「許可済み」と偽装する必要はない。一方で、実際の対象・情報の根拠・取得方法についてレビューして記録する工程を省略してはならない。
- **結論の範囲**：ここでの判断は、法務担当者や裁判所による個別ケースの適法性保証ではない。現時点の正式公開イベントは0件。今回の監査は外部へ新規大量アクセスせず、CIの既存固定出典を検査した。

**続く実装・運用の焦点は、ソースごとの客観的事実利用と公開根拠を、人手が再現可能な記録にすること。2,512件を手作業で再収集する必要はない。**
