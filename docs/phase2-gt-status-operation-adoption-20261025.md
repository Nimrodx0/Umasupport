# Phase 2：固定GameToraの状態付与・状態回復を結果別の非公開候補に変換（2026-10-25）

## 目的と出典による確定範囲

前段の[スキル2,512件と非スキル2,220件の結合](phase2-private-2512-skill-nonskill-join-20261025.md)では、GameTora効果コードのうち`condition`（93記載）と`heal_status`（28記載）を未対応としていた。これらは数値の加減算ではない。

固定GameTora由来リビジョン`systemless10/UmamusumePS@6e38b54af4fad397ff4491e63007a90705a4fe67`に含まれる`server/app/event_engine.py`の[状態付与・状態回復の処理](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/event_engine.py#L1476-L1517)を根拠として採用した。

- `condition`：`condition_id`で指定した状態の**付与を試みる**。実行処理側に状態による適用ガードや個別確率条件があり、単にデータ行が存在するだけで確定付与とは言えない。
- `heal_status`：その時点で保有する悪い状態があれば、**ランダムに1つだけ治す操作**。複数の悪い状態をすべて治すことも、固定された状態IDを治すことも意味しない。`chance`が明示される場合はその値による判定もある。
- `chance`は固定元データに書かれている場合のみ0超1以下の有限数として伝搬。値がない場合はアプリで創作しない。**コードに埋め込まれた確率・状態ガードを本実装が完全にシミュレートしたという意味ではない。**
- GameTora個別カードから疑義が見つかった場合にのみ採用優先順位契約に沿ってGameWithを調べる。今回の固定出典コードに明示された仕組み自体の説明のために新しい第三サイトの採用を要求しない。

## 実装

`poc/src/event_schema.js`の既存`effects[]`は**符号付き数値の種類と値**専用のままにする。新しい`statusEffects[]`はイベント・選択肢・排他的な結果`outcomes[]`の**末端**に置く。

| 属性 | 内容 |
| --- | --- |
| `kind:'add-condition'` | 正の整数`conditionId`を伴う状態付与操作候補 |
| `kind:'cure-one-bad'` | 対象IDを指定せず、保有する悪い状態からランダムに1つ回復する候補 |
| `possible:true` | **両種とも必須**。実行可能性と確定適用を混同しないためのフラグ |
| `chance` | 元効果に明示された0超1以下の値のみ任意で含める |
| 重複・出典形状 | 同一操作と同じ状態IDが重複、条件IDが不正、未知フィールド、確率の表記が不正ならその結果経路・イベントを保留 |

`poc/src/core.js`の`UmaCore.directStatusRoutes`は、既存の`reachability`／選択肢・結果の依存解決を再利用するが、**必ず`conditional:true`かつ`possible:true`**で状態操作候補を返す。これを既習得状態・確定回復や数値能力値・スキルヒントとして合算しない。

`poc/src/phase2_gt_whole_nonskill_effect_inventory.cjs`は固定GTの全2,488イベント・4,376結果経路で121記載の状態コードを単独分類し、スキル・数値・制御コード・未対応コードとの排他的な保存則を維持。数値と状態の両方を同じ結果位置へ保持する。既存`phase2_2512_private_effect_join.cjs`は元カード・イベント順位・選択肢・結果祖先番号を一致させて**状態操作候補も同じ排他的結果へ結合**し、`statusEffects`を取り去った構造は全スキル候補の元SHAと完全一致する必要がある。

## A/B/C・限界

A：合成テストで正・負の能力値と状態操作の別管理、正の状態ID・確率のバリデーション、出典の未知フィールド・重複状態の拒否、結果未選択の非保証、元の排他的なスキル候補への効果引継ぎを確認。

B：固定GT全件の分類母数・出典コード値・状態の保留理由、本番ローダーでの再現、元スキル経路のSHA不変を検証する。これは固定元コードの意味を採用した技術評価であり、現行ゲーム内での全状態変化の独立直接確認ではない。

C：通常のGitHub Pages・正式公開カタログ・ユーザーの保存設定は変更しない。現行Chromium回帰は既存UI保護のテストであって、状態操作の公開UI・実ゲームの物理端末検証ではない。

**未完了**：元GTの残り200イベントには、未対応コード（例：ランダム能力増減、シナリオ固有要素）、打ち切りや条件付き分岐、非整数効果・重複が含まれる。その他、GTにない追加イベントの非スキル報酬・公開用独自表現・出典・利用承認は別工程。正式公開イベントは0件のまま。
