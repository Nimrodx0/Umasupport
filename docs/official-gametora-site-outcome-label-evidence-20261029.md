# GameTora元サイトの「表示グループ」と「結果ラベル」を分離する限定監査（2026-10-29）

> **履歴・現行の開発工程では採用しない（2026-10-29利用者再確認）**：本書の個別サイト比較・結果名の分類は、現在の「GameTora本体だけからウマサルタント独自形式へ汎用変換する」工程から外した。現行の変換器・CI・元サイトChrome確認は、この文書のGameWith裁定や成功／失敗という名称を必要としない。歴史的な出典比較の記録としてだけ残す。最新の方針は [requirements.md](requirements.md)・[roadmap.md](roadmap.md) を参照。


## この段階で分類するもの

元GameToraサイトのイベント詳細を開いたとき、外側に並ぶ**表示グループ**と、その中のOR区切りで分かれる**結果候補**がある。しかし表示グループがゲーム内でプレイヤーが押す選択肢か、ORが成功／失敗・運試し・他の分岐かは、HTMLの位置と数値効果だけでは決められない。第1イベントの表示結果グループがないことも、ゲーム内で報酬がないことではない。

そこで `poc/src/official_gametora_site_outcome_label_evidence.cjs` を新設。**元サイトの結果DOM内で、子要素のない末端の独立した文字列**が「成功」「失敗」「大成功」「大失敗」（対応する英語ラベルも）に完全一致した場合だけ、*表示ラベルの観測*としてその結果座標に紐付ける。例えば「成功率+10」や「成功するとスキルを獲得」は成功結果のラベルではない。両側の結果が別々に「成功」「失敗」と明示されている場合にのみ、**元サイトに表示された対**として集計できる。ゲーム本体の抽選条件・確率・後続イベントへの到達を検証した意味ではない。

取得元の文章・選択肢テキスト・HTML・画像は出力しない。観測記録の出力は `success`／`failure` 等の分類コード、結果位置、判定不能件数のみ。前工程の四系統厳格統合器 `official_gametora_live_event_assembler.cjs` へ**第五の構造観測**として追加した。同一結果位置で一致しなければ停止する。新しいデータは `appEventSchemaAdoptable:false`、`publicationApproved:false`、`playerChoiceSemanticsVerified:false`、`nextEventReachabilityVerified:false` を維持する。**イベントの `choices[]`・`outcomes[]`・`terminal`・`requires` は生成しない**。

## 元サイト2カードの実Chrome結果

[SSR30322/30323限定2ページ実Chrome Actions](https://github.com/Nimrodx0/Umasupport/actions/runs/40799547219)。既存検証と同じ、SSR30322の6パネル13結果候補、SSR30323の12パネル14結果候補だけを調査。サイト上の結果に局所的に独立した成功・失敗ラベルが現れたかを確認した。

| サイトからの観測 | SSR30322 | SSR30323 |
| --- | ---: | ---: |
| 表示結果の候補 | 13 | 14 |
| ORで結果候補が分離された表示グループ | **3**（第4イベント） | **0** |
| 結果DOM末端で独立表示された成功等のラベル | **0** | **0** |
| 明示的な「成功／失敗」が1グループ内で対になったもの | **0** | **0** |
| 複数ラベルが衝突した結果 | 0 | 0 |

**結論**：SSR30322の第4イベントには3か所の表示上のORがあることが確認できる。しかし、今回のHTML末端ラベルの検索範囲で**成功／失敗という結果名が1つも明示されていない**。このため「表示上に選択肢が6つある」「3か所のORがゲームの成功／失敗だ」と確定することはできない。SSR30323についても「成功・失敗ラベル0」の観測は**ゲームに成功・失敗が存在しない証拠ではない**。

この限定スナップショットを実Chromeの固定期待値とし、将来GameToraの表示が変われば再検証を要求する。元サイトの選択肢文言が確認できない場合、[例外裁定の優先順位](event-adjudication-enforcement.md)に従い、カード・イベントを同定したGameWith記事の具体的事実で不足部分を判断する。追加の独立編集サイトやゲーム実機プレイを、GameWithの明示事実の採用に必須とはしない。**ただし根拠のないプレイヤー選択・結果の分類、連続内部の依存を創作してはならない**。

## 検証段階

- **A：機構**。合成8件と既存統合器の回帰。完全一致ラベル、混ざった説明文や数値の拒否、結果ごとの座標、OR表示を結果の意味と混同しないこと、衝突ラベル、非公開フラグを検証。
- **B：実出典**。2カード18イベントパネル27結果候補に限定した元GameToraサイトのHTML表示の観測。スキル収録範囲・全イベントの意味の裁定ではない。
- **C：実Chrome**。GitHub ActionsのChromeで元サイト2ページを取得・結果位置へ分類。ユーザーの物理Windows／Android端末でのアプリ操作やゲーム内再現は今回の対象外。

今後の重点は、GT本体で曖昧なイベントを**カード・イベント単位でGameWithと結果報酬を照合**し、ゲーム内のプレイヤー選択肢と成功・失敗結果を確定すること。後続到達条件は編集上の独立根拠が必要。正式公開用イベント0件は不変。
