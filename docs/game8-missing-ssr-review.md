## 検証用の独自JSON

[poc/config/missing-ssr-event-facts.v1.json](../poc/config/missing-ssr-event-facts.v1.json) は**公開アプリに読み込ませない研究候補ファイル**。

- 実サポカID、イベントの種別と連続段階番号、選択肢数、ヒントが付与される選択位置、スキル名・ヒントLvという事実情報だけを保持する。
- イベント名、セリフ、選択肢の原文、Game8の解説文章、スタミナ・体力等の報酬本文は複製しない。
- 4枚の確認可能な範囲では、選択肢イベント16件、選択肢なしイベント4件、スキルヒントの選択・発生位置計14行を確認。30240の5イベントは分岐・ヒント不明として保持。
- Game8に5件の見出しがあってもゲーム内の全イベントが確実に網羅されているとは断定しない。成功／失敗、発生確率、打ち切りの存在・不存在、スキルの正式数値IDなども**未検証**。
- バリデータ [missing_ssr_fact_review.cjs](../poc/src/missing_ssr_fact_review.cjs) は元記事の文章・未知のフィールド・不正な選択位置・欠けたカードID・未確認の30240への報酬割当を拒否する。架空の不正ケースを回帰テストしている。

### この段階で公開アプリに接続しない理由

現行の `poc/data/reviewed_events.v1.json` に必要な確定事項は、各カードの正式なイベントIDとイベント名の表示方針、各イベント選択位置・継続/打ち切り、獲得スキルの一意な内部ID、効果の成功・失敗、出典内容の公開利用可否など。今回のデータは**単一攻略サイトによる報酬事実候補**で、これらをすべて満たしていない。特にイベントスキルはUmaSim通常ヒント辞書に存在しないものがあるため、名前からの自動的な `hint:` ID生成は禁止する。

## 連続イベント到達条件の修正

`poc/src/event_schema.js` では従来、先行イベントが選択式なら後続の `requires` に `choiceId` が必須だった。しかし、実際の連続イベントではどちらの選択肢でも連続を継続できるケースがある。

新しい明示条件：

~~~json
{
  "requires": { "all": [{ "eventId": "previous" }] }
}
~~~

この条件を選択式の親に使う場合、**親で実際に選択された選択肢が存在し、その選択肢が `terminal:true` でないこと**を意味する。未選択や打ち切りでは絶対に後続へ進まない。親イベントが自動式の場合は従来通り親の到達を要求。全分岐が打ち切りの親から後続を指定した場合も拒否する。

この修正は集計側の `core.isReachable` に既にあった判定と、スキーマ検証を一致させるもの。自動発生やランダム発生を「必ず発生する」と保証するものではない。

## 次の工程

1. Game8の4枚の全選択肢について、スキル以外のステータス効果、成功／失敗、打ち切りと連続イベントの進行条件を個別レビューする。
2. ゲームマスターに対応付いたスキル辞書を整備し、14件のスキルヒントの内部IDを確定する。金スキルと白スキルを混同しない。
3. ジャングルポケット30240の全イベント効果・選択肢をU-tools以外の出典（Umamusume Wikiのデータ更新、別の攻略サイト、直接ゲーム検証等）で確認する。
4. 各サイトの利用条件を確認し、許諾が必要な表現の転載を避ける。レビュー済みで独自形式に変換できるものから公開DBへ追加する。
5. 既存412枚のイベント単位の網羅性監査も続ける。カード単位でイベントが「ある」ことだけを完全収録と呼ばない。

**今回の検証段階では公開済み実イベント0件。** 本番アプリのイベント収録数は変更しない。
