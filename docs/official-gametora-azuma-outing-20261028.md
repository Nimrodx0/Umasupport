## 限定Chromeと記事の事実照合

旧GitHub派生GameTora固定データには新SSRの対象イベントが欠けるため、**旧固定ファイルの数字で見出しを創作・補完しない**。GameWithの該当カードに掲載された6見出しの原文はGitに保存せず、NFKC正規化＋空白除去＋横線の表示差の統一による**SHA-256と文字数**で元サイトの表示見出しに一意対応するか確認した。次の順序はGameWith記事内の掲載順であり、プレイヤーの選択順や実ゲームでの到達順序を表すものではない。

| GameWithの見出し位置 | GameTora内の開閉パネル位置 | 画面上の選択肢候補 | 照合 |
| ---: | ---: | ---: | --- |
| 1（解放イベント） | **8** | **2** | タイトルと候補数が一致 |
| 2（お出かけ候補） | **2** | 1 | 一致 |
| 3（お出かけ候補） | **3** | 1 | 一致 |

| **合計** | **6/6見出しを一意に同定** | **8グループ** | **6/6の候補数が一致** |

初回は末尾に横線を含む見出し1件が旧表記と一致しなかったが、長音符・横線のUnicode表示差だけを統一して**6/6**に達した。任意の文字類似度を用いた推測対応は行っていない。

**解放の事実**：GameWithは解放イベントの**選択肢1・2の両方**で吾妻のお出かけが可能になると明記する。GameTora本体でも、対応する8番目のパネルには**2つの独立した選択肢候補**があり、それぞれにお出かけ可能化の表示が存在する。したがってこのカード・イベントだけは、`choiceOrdinal:1`と`choiceOrdinal:2`の各経路に「お出かけを解放する」**非公開候補事実**を付けられる。候補グラフの帰属はGameToraの表示上の位置を用い、男性向けの選択肢文章は出典の再配布許可・公開承認が未確認のため保存しない。

**後続の5候補**：GameToraページでそれらの見出しは**画面上2〜6番目の連続したリスト**に並び、GameWithの記事内順序とも一致した。ただしこれはページの並びであって、「前の回が成立した時だけ次の回へ進める」ことや「最後のイベントでお出かけが終了する」ことの独立証明ではない。スキーマの`requires`／`terminal`は今回これだけから生成しない。場面の外的な発生率は従来通り対象外である。

## 3層を別々に扱う

1. **A（機構）**：6件のハッシュ一致・曖昧重複の排除、2択の解放の形式的候補の生成、文章を含まない結果、未確認後続条件のfalse固定を合成テスト。
2. **B（出典）**：GameToraの6見出しと6選択肢数がGameWithの該当欄と一致し、**解放イベントの2選択肢が双方ともお出かけ解放**とGameTora上でも読めた。継続・終了は未確認。
3. **C（実ブラウザ）**：GitHub Actions Ubuntu 24.04のChromeでSSR30323を閲覧。Android等の物理端末やゲーム内でのイベント再生ではない。
4. **D（公開）**：サイトの利用条件、本文の転載権利、全対象母集団とイベントの個別承認は別ゲート。**公開済みイベントは0件**、アプリの本番ソース更新経路も不変。

次は、GameWithに明記された各お出かけ段階の先行条件と終了の扱いを、GameToraの表示から得たタイトル・報酬の一意対応と合わせて、**確実に出典がある部分だけ`requires`や`terminal`へ反映する**。元サイトや記事に見当たらない分岐依存は未設定で残す。
