# Phase 3 F-02：所持サポカ一括登録の実装・受け入れ

更新：2026-10-18。関連：[要件F-02](requirements.md#f-02-サポカ検索所持管理)、[全フェーズロードマップ](roadmap.md)、PR #51。

## スコープとUI

既存のUmaSim採用カード **563枚** を現在のデータ源として表示し、「所持サポカ管理」のモーダルを開く。名前・キャラクター・タイプ・レアリティ・通常ヒントのスキル名で絞り込み、所持／未所持／未登録の状態を1枚ずつ指定。各所持カードの所有凸（0～4）を設定できる。**所持凸と編成中の想定凸は異なる独立した情報**。

一覧は36枚ごとのページングで、絞り込みに一致する**全件**（現在ページ外を含む）の所持／未所持／未登録への一括変更を確認ダイアログ付きで行える。「全件」は採用元563枚の現在のフィルター結果を指し、ゲーム全体の全カード枚数と同義ではない。検索後の一括変更には絞り込み条件と件数を表示し、誤操作を避ける。

編成ピッカーには「所持サポカのみ表示」チェックを設置する。オフであれば未所持・未登録カードも選択でき、すでに編成されているカードが未所持になっても自動的に外さない。

## 保存形式・移行

設定 v3 はこれまでの複数デッキ＋目標セットを保持し、疎な ownedCards 辞書を追加した。

- 未登録：辞書にカードIDなし。**未所持と同義にはしない**。
- 未所持：カードIDに status=unowned のみを記録。
- 所持：カードIDに status=owned と stage=0..4 を記録。段階を変えても各保存済みデッキの想定凸を変えない。
- v1単一デッキ、v2複数デッキのJSONを検証後v3へ変換し、旧デッキ・凸・イベント選択・目標はそのまま引き継ぐ。旧版に所持情報がなかったからといって「未所持」に分類しない。
- 不明カードID、stageの欠落・範囲外・文字列・余計なキー、未所持なのにstage指定、未登録という明示レコードを拒否する。不正なJSONインポートで正常なlocalStorageを上書きしない。
- 一括登録は**全対象IDと状態を事前検査**し、不正な候補があれば途中まで更新しない。すでに所持していたカードの所有凸は一括「所持」にしても維持する。

## 受け入れゲート

| 軸 | 合格基準 | 手段 |
|---|---|---|
| A：ロジック | 3状態、所有凸0..4、編成凸との非干渉、v1/v2移行、JSON不正拒否、全件一括変更の部分適用防止 | settings.test.cjs |
| B：カード母集団 | 採用元563枚から一覧・検索・登録でき、特定の120枚だけに所持記録が限定されない | 人工563件のモデル、ブラウザで36枚/ページと111件の絞り込み一括処理 |
| C：ブラウザ | 3状態変更、所有凸3、一覧フィルター、一括確認の拒否と実行、所持のみピッカー、保存・再読込と独立した編成0凸、390px表示 | NodeのPlaywright/Linux Chromium実ブラウザ回帰 |

今回追加したカード一覧は **第三者の画像を配信せず、既存のキャラクター略字アイコンを使う暫定グリッド**。F-02で要求する画像付きグリッドにはまだ未達。カードの全検索要件のうち、イベント経路・適性条件・高度なスキル経路絞り込みは未実装。特に実イベントDB0件のためイベント報酬に基づく検索は未検証。

**未通過：** Android/Windowsの物理端末UI受け入れ、画像の利用可否、カード・スキル全件照合、将来の元データ追加・削除時に利用者の保存IDをどう扱うか。現行ゲームの実所持を読み取る連携機能ではない。

## 実機で後日確認する操作

「所持サポカ管理」を開き、カードを1枚「所持」→3凸へ変更。名前やタイプで絞り、検索結果への一括変更を確認・キャンセルしてから実行。画面を閉じて編成ピッカーの「所持サポカのみ表示」を切り替え、未所持カードもオフ時には編成可能か確認。再読込とJSON保存・読込で所持情報が保持され、編成の想定凸が変更されていないか確認する。

CI実行記録・最新の合否は[PR #51](https://github.com/Nimrodx0/Umasupport/pull/51)のChecksを参照。正式版のF-02完了や実イベント網羅と扱わない。

## 2026-10-18：検索機能の拡張（PR #52）

[新しい複合検索の詳細](card-route-search-acceptance.md)。旧「カード名・通常ヒント名を含む一つの文字列検索」を分け、カード名・キャラクター名と提供スキル名・IDのAND絞り込み、タイプ・レアリティ・所持状態、提供経路（照合済み通常ヒント／承認済みイベント）を追加。編成ピッカーの先頭120枚表示制限をページ送りで解消。人工563枚規模のブラウザとNodeテストのみで、実ゲーム内イベントの採用・カード画像の利用は未達。
