# Phase 3 F-02：カード・スキル・提供経路の複合検索

更新：2026-10-18。[要件定義F-02](requirements.md)、[所持一覧の受け入れ基準](owned-card-registry-acceptance.md)。

## 追加した操作

- 「所持サポカ管理」と「編成スロットのカード選択」の両方で、カード名・キャラクター・IDと**提供スキル名またはIDを別々に検索**。カードのタイプ、レアリティ、所持状態も他条件とANDで組み合わせる。
- 提供経路は「全経路」「照合済み通常ヒント」「公開承認済みイベント」「両方」から選ぶ。スキル名を入力したときはその検索語に一致する直接提供スキルの経路のみを照合し、履歴資料由来の未承認 \`referenceSkills\` は含めない。
- イベント選択肢、直接報酬、成功・失敗等のアウトカムに実際に**公開承認済み**スキルIDが存在すれば候補に含む。ただしイベント分岐の実際の到達・獲得確率は検索UIでは評価しない。これまでどおり選択式イベントはデッキ集計では未選択の間は加算しない。
- 通常ヒントはカードの検証済み5段階でのIDを重複なく和集合とする。「全段階のいずれかで提供」検索であり、**特定段階で必ず提供される証拠や、全段階で同じヒントを持つとの主張ではない**。旧候補や実カード以外の未照合IDは混ぜない。
- 「承認済みイベント」は、公開DBの実イベント0件なら候補0件。これを「ゲームにイベントがない」証明とは解釈しない。
- 編成ピッカーは1ページ120枚を維持しつつページ送りを追加。先頭120枚を超えるカードを検索語なしで選択可能にした。所持のみ絞り込みは従来どおり表示条件であり、未所持登録自体を禁止しない。

## 未実装・今後

- 要件F-02の**実カード画像付きグリッド**：第三者ゲーム画像の公開配布許可・安定した画像配信経路が未確認のため、現段階では略字アイコン。勝手にスクレイピング・再配布しない。画像が正規に利用可能と確認できた場合に限って追加する。 [Cygames公式ガイドラインを踏まえた画像利用条件の調査記録](card-image-rights-decision.md)を参照。
- イベント経路の網羅：公開DBには承認済みの実イベントが0件であり、イベント名・到達条件・効果・正しいゲームIDの完全性はPhase 2の独立ゲートに従う。
- スキルのタイプ・適性・因子化対象・イベント分岐依存性を跨ぐ高度な条件、表示の初期順と適切な並べ替えは別の受け入れ項目。F-02やPhase 3全体完了の宣言は行わない。

## 手動受け入れケース（後で一括検証）

1. 所持一覧で「右回り○」など通常ヒント名を入力し、カード名検索とのAND・レアリティ・タイプ・所持状態を組み合わせる。
2. 経路を「承認済みイベント」に変えたとき、公開DB0件では検索結果0件で、情報なしの説明があることを確かめる。
3. 編成ピッカーで「前へ／次へ」を使い、2ページ目以降・末尾のカードを選択し、元の編成と想定凸を変えずに絞り込み操作ができることを確認する。
4. PC・Android双方でモーダル横幅・スクロールを確認する。

[CI](../.github/workflows/ci.yml)の実行結果は対応PRのチェック履歴に残す。
