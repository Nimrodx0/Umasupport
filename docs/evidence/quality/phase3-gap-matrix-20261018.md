# Phase 3 残件棚卸しとF-04/F-07集計修正

更新：2026-10-18。要件正本：[F-01〜F-09](requirements.md)。この文書は実装状態の棚卸しであり、正式受け入れ宣言ではない。

## 先に修正した計算上の不一致

### F-04：「異なるサポカの枚数」をカードID単位に修正

旧集計では、同一サポカIDを同じデッキ内の2スロットに設定した場合、提供枚数が2枚と計上されていた。仕様は「直接提供する**異なるサポカの枚数**」であり、異なる物理スロット数ではない。

- 提供枚数：スキルID × サポカIDの組を一意に数える。例：同じカードAを2枠、別カードBを1枠に配置して同じスキルを提供すれば**2枚**。
- 提供経路：各スロットの凸・イベント選択は独立したまま保持し、詳細にはスロット1・2の経路を両方表示。集計値が少なくても提供経路が失われない。
- 重複判定：Aを2枠だけ配置しても「デッキ内重複2枚」にはしない。Aが本育成と継承育成の双方にある場合、「デッキ間共通」の判定は保持。
- 詳細表示：同じIDが複数枠ある場合は「同カード複数枠」と明示し、直接提供枚数と枠ごとの経路件数が異なる理由を伝える。ゲーム内で同じカードを1デッキに複数編成できるという事実を認定したものではない。

### F-07：各スロットの通常ヒント経路に段階別ヒントLv

従来はカード詳細に段階別ヒントLvを表示できていたが、スキル側の提供経路はLv情報を失っていた。`core.directRoutes` は選択枠のstage（0〜4）に対応する`hintPerformanceByStage`が検証可能な場合のみ、既存のカード詳細と同じ`1 + levelBase + levelUnique`を参照する。値が未収録、不正、文字列などならLvを推測せずnullとする。イベント報酬のLvは従来どおり公開承認済み報酬の値のみ使う。

## 検証区分と禁止する読み替え

- **A 機構**：`poc/tests/core.test.js` でカードID重複排除・経路全保持・段階Lvの欠損無補完を検証。`poc/tests/browser_skill_smoke.cjs` で人工563枚、同じカードの本育成2枠と継承1枠、Lv・直接枚数・フィルター・保存を操作して確認。
- **B データ網羅**：今回の変更ではゲームデータは採用も配布もしない。公開承認済みの実イベント0件、画像未収録、563枚母集団の全現行ゲーム網羅未確認を維持。
- **C 実機**：GitHub ActionsのLinux Chromium検査とAndroid/Windows実機での受け入れを混同しない。物理端末検査は一括受け入れの段階まで留保。

**次の重点**：Phase 2の承認可能な実イベント元データ、Phase 1の独立マスター照合、F-02/F-05の画像/適性/因子の根拠、Phase 4実機を横断して優先。新しい小さなUIを無制限に増やす前にこの未解決ゲートを閉じる。
