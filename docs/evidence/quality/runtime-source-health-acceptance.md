# Phase 3 F-08：実行時のデータ収録・取得状況と障害表示

更新：2026-10-18。関連：[要件F-08](requirements.md)、[検証基準](verification-plan.md)。

## 設計と表示

メイン画面に「データの収録状況」入口を設置。起動時に確認したソースごとの処理結果をブラウザ内メタデータに残し、別の通信や「更新ボタン」を増やさず表示する。

- サポートカード・通常ヒント：公開元から取得したか、前回検証済みキャッシュを利用したかを区別。採用ソース内のカード枚数、4凸通常ヒント記録数、0～4凸の5段階構造が揃ったカード数、ヒント性能の5段階数値が揃ったカード数を表示する。受信日時と確認日時は別々に記録。
- 数値スキル辞書：オンライン取得／検証済みキャッシュ／利用不可の区分、受信日時、アプリに存在するスキル候補件数、金白構造リンク候補件数を表示する。アプリ内スキル候補数には通常ヒント由来も含まれるため、**数値辞書の全件数と混同しない**。
- 公開イベントJSON：取得・検証成功（実イベント0件でも成功）、取得または検証失敗（**件数未確定**）、その他不明を区別。障害経路で空の検証済みフォールバックを内部適用した場合にも、公開ソースの検証が成功したことに書き換えない。障害時のイベント報酬を集計しない既存動作を保持。
- 公開元のURL・ブラウザの受信日時は、実ゲームデータの更新日、最新配信バージョン、全カード件数の証明ではない。構造上5段階がすべて揃っていても、それだけで独立ソースとの正しさを証明しない。
- 第三者ソースの新たな取得・中身のコピー・公開は行わない。ユーザー設定・IndexedDBの保持方針は変更しない。

## 独立ゲート

| 軸 | 検証 |
|---|---|
| A：機構 | `poc/src/source_health.js`の人工モデル。全5段階/一部欠落、通常取得とキャッシュ、成功0イベント、失敗イベント（0件と誤表示しない）、数値スキル辞書利用不可、モデル異常の拒否 |
| B：採用元データ | 既存UmaSim由来カード・通常ヒント・ヒント性能・数値スキル辞書だけに由来する計数。2026年現行マスターの収録率やイベント正しさを新たに保証しない。承認済み実イベント0件のまま |
| C：実ブラウザ | Chromiumの人工563枚で、通常取得→キャッシュへのフォールバック→イベントJSON通信失敗の3つの起動経路を切り替え、画面表示と内部ステータスが一致することを確認。Android／Windowsの物理端末は未受け入れ |

## 未完と注意事項

配信アプリ本体の完全オフライン起動、通常元データの更新時差分と正式データ版の自動照合、個別収録カードの情報欠損マップ、実機の視認性・読み上げ試験は未完。F-08は部分実装、Phase 3も未完了。

「公開イベント0件」と表示されるのは、空の公開イベントJSONを正常に取得しスキーマを検証した場合だけ。公開JSONが失敗した場合はイベント0件の公開事実を保証しない。
