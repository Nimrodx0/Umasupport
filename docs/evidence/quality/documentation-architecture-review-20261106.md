## 目的・判定基準

過去のChatGPT会話やAIの記憶を**唯一の開発コンテクストにしない**。新しいエージェント・開発者が、GitHubの現行ブランチから「何を／なぜ／どう／どこまで／次に何を／何が未検証か」を判断できることを受入基準とする。

参考：Diátaxis（学習・手順・参照・説明の目的を混ぜない）、ADR（決定に背景・理由・置換関係を残す）。**本レポジトリに新しいドキュメント体系を機械的に全面適用するものではない**。文書の役割と具体的な更新先は [documentation-policy.md](../../governance/documentation-policy.md) が正本。

原則は次の4点：

1. **現在有効な契約と日時付き観測は別**：要件・設計・検証基準を実装結果や当時の計測と混ぜない。
2. **一情報一正本**：索引・README・AGENTSに同じ現行数値や実装報告を複製せず参照でつなぐ。
3. **再開経路を短くする**：README→AGENTS／索引→roadmap＋status→対象要件・コード・研究根拠。
4. **証拠・履歴は捨てない**：研究の反例と停止判断、固定出典と未検証を保持し、旧「次工程」が現在の作業を上書きしない。

## 再開時に守る判断の境界

- 現在の仕様は`requirements.md`、その判断履歴は`decisions.md`。過去の一節にある「公開0件」「最優先」は現在値ではない。
- `roadmap.md`は未完と依存関係、`status.md`は最新の測定・未検証。Issueは作業単位の保留・次手を持つ。
- 実装の真偽は現行のコード・配信JSON・テストに対して検証し、数値の根拠は監査文書の版・母集団・限界に戻る。研究用モデル成立率を実発動率として扱わない。
- 決定・要件の変更が生じたら会話内で完結させず、その作業内で関係する正本へ反映する。保留・レビュー待ちなら未反映と示す。第三者権利・公開認可は独立。

## 今回残す課題（意図的な非変更）

- `decisions.md`は長大な時系列ログで、旧決定の中には後続決定で置換された記述がある。**過去のユーザー決定を独断で書換・再分類しない**。今後の大きな判断のみ必要に応じて小さなADR形式に分割する案を検討し、既存ログと矛盾させない。
- `data-sources.md`、`requirements.md`、`architecture.md`の詳細には日付付きの技術背景が残る。今回、現行と履歴の誤読に直結する箇所を優先して修正した。全件の論理的真偽と権利評価は別途機能／出典別に監査する。
- 研究・監査ファイルの一括移動／リネームは既存の相互参照と再現性を壊しうるため実施しない。証拠索引で発見性を確保し、個別の追加・置換は必要時に行う。
- 新しいエージェントの実際の引き継ぎを利用者の端末で検証したわけではない。今回の合否は**構成・参照・通常CI**の範囲で判定する。
