# 別系統サポカ資料による通常ヒントID→名称の独立照合

検証日：2026-10-17（JST）　関連：[Phase 1](roadmap.md) / [カード母集団ID監査](card-population-independent-audit.md) / [金白辞書照合](independent-skill-json-audit.md)

## 目的と検証入力

前段で確認した**サポカIDの収録漏れなし**と、カードの**通常ヒントの正確性**は別の検証項目である。今回は別系統の日本版資料に掲載された**選択収録45カード**について、通常ヒントの数値IDリストを照合し、名称集合を比較する。

- UmaSim [`support_card.txt`](https://github.com/mee1080/umasim/blob/cf9366f6a487bd8f197b53d8a11981207beb9f6c/data/support_card.txt)（2026-10-13固定版）。SHA-256 `153213019b5232df6c211427b862978218b60df6baee03c2a5fee75e0966d424`。
- UmaSim [`skill_data.txt`](https://github.com/mee1080/umasim/blob/cf9366f6a487bd8f197b53d8a11981207beb9f6c/data/skill_data.txt)（同版、2,139件）。SHA-256 `b7ba1d6c5dd2af9ed1f4e649f16ec1d319198e2f1ac9db07c54e14d29f0b25ec`。
- [Tsuyuchan-jp `data/supports.json`](https://github.com/Tsuyuchan-jp/umamusume-data/blob/0cacbb1aaf9dca10283d5b9ea20b205b9d204535/data/supports.json)（2026-09-30に別途抽出、**全カードではない選択45枚**）。SHA-256 `7b6e119a007a64bc494ba5b65dada7700c856993f02dba35319bc0d8aa437f5b`。
- [同 `data/skills.json`](https://github.com/Tsuyuchan-jp/umamusume-data/blob/0cacbb1aaf9dca10283d5b9ea20b205b9d204535/data/skills.json)（同版、2,194件）。SHA-256 `11bf7aa86d611047f5052b48059cf77d6aa9b4a7ad8e25ba2f7f901dcd267e62`。

第三者原文・元データをレポジトリに同梱せず、限定的なActionsで必要な4ファイルを各1回だけ取得、メモリ内で比較し、ログには件数・ID・不一致に限る。独立資料の生成元が非公開なので、原マスターの完全な独立性は保証しない。

## 照合手順

1. 両資料のサポカID・日本語の完全名称・レアリティを一致させる。45カードがすべてUmaSimに存在することは前回の監査でも確認済み。
2. 各カードの`hintSkillIds`（数値ID）を、まずUmaSimのスキル辞書で名称に解決する。
3. 解決できないIDは、**別系統のスキル辞書で数値ID→名称を確認**する。この段階でUmaSimのスキル辞書に足りない数値IDを**未解決として保持**し、元データの欠損を推測補完しない。
4. それらの名称集合をカードごとの0凸／4凸通常ヒント名集合と比較。余分・不足・重複・数値IDの異名を区別する。カードIDが合うだけでは成功と数えない。

## 実測結果

[一時取得監査のGitHub Actions #39006029802](https://github.com/Nimrodx0/Umasupport/actions/runs/39006029802)（修正後の初回成功）。数値クロスウォークの欠損を別辞書で補った結果：

| 判定項目 | 実測 |
|---|---:|
| 照合対象の日本版サポカ | **45/45枚** |
| 数値ID指定の通常ヒント | **527件** |
| UmaSimスキル辞書だけで名称確認 | **526件** |
| 別系統スキル辞書のID→名称で補足確認 | **1件** |
| 両方の辞書でもIDが解決不能 | **0件** |
| IDは解決できるが名称が衝突 | **0件** |
| **通常ヒント名称集合が一致したカード（4凸）** | **45/45枚** |
| 0凸・4凸とも名称集合が一致 | **45/45枚** |
| 名前集合に不足・余剰・重複のあるカード | **0枚** |

**唯一の数値辞書ギャップ**：カードID `30296`「[単焦点でつかまえて]アストンマーチャン」の`hintSkillIds`中の **`201012`** が2026-10-13固定版のUmaSim `skill_data.txt`にはない。しかし2026-09-30の別辞書では `201012` = 「**後方釘付**」（groupId `20101`）で、UmaSimのカード通常ヒント名称にも「後方釘付」が入る。すなわち**ヒント名や表示カードの欠落ではなく、UmaSim数値辞書の当該IDが不足している**。2026-10のスキル辞書に追加してよいかはマスターの版・運用ポリシーを別途確認する。第三者辞書から実行時マスターを無断合成・補完しない。

上記は独立資料が選択した45カードの検証であり、**563枚の全ヒント4,015件が独立に正しい**と一般化しない。全カードのヒント集合のゲーム内検証は別ゲート。

## ゲーム標準のスキル表示順について

別系統 `data/skills.json` の**2,194件の最上位フィールド全件**を走査したところ、`disp_order`、`displayOrder`、`sort`、`rank`に相当する明示的なソートキーは存在しなかった。ID順・JSON格納順をゲームの表示順とみなす根拠もない。

[Umamusume Wikiのデータ抽出コード](https://umamusu.wiki/Module:Game/Skills/Data)には、**ゲームの`skill_data.disp_order`を`displayOrder`に変換する仕組み**が見られる。これは有力な調査対象だが、**2026年10月版の同一スキルIDへの数値取得と、ゲーム実UI上の実際の並び順との一致は未検証**。現在のアプリの五十音順／金白階層は変更しない。

## ゲートと残作業

- **A（機構）**：ID解決、部分的な辞書欠損、数値名称衝突、不正入力、前のカードの欠損が後続カードに影響しないことのNode回帰と、一時取得監査が合格。
- **B（データ）**：この45枚・527件の通常ヒント名称照合は**Pass**。UmaSim側の数値辞書1ID不足は例外として記録（補完保留）。563枚全体の独立通常ヒント・ヒント性能、およびゲーム標準の表示順は未通過。
- **C（実機）**：CLI監査のみであり、この監査単独ではスマートフォン・Windows実端末のアプリ動作を検証していない。ユーザーの合意に従い、追加実機テストはまとめて管理。
- 公開ゲームデータをアプリに新規同梱したり、イベントJSONへ転記したりはしない。
