# GameTora本体の結果別スキルID照合で、広い親要素を誤って優先した問題と修正（2026-10-28）

## 事象・根拠

[前段の結果別ヒント候補の監査](official-gametora-site-route-hint-candidates-20261028.md)では、SSR30080の**GameTora本体画面上第6イベント**（旧固定GT派生元では第8イベント）にヒント表示1件があるが、独立UmaSim辞書とのID一意照合は0/1件だった。

[元サイトを実Chromeで読んだ診断Actions #40695973649](https://github.com/Nimrodx0/Umasupport/actions/runs/40695973649)で、同じヒント行のHTML要素から親方向へ並んだ**実際の文脈3段**を匿名の件数だけ調べた。

| 実DOMから採取した文脈位置 | 表示文字数 | 独立UmaSim辞書での判定 |
| --- | ---: | --- |
| ヒント行に最も近い要素 | 16 | **一意のスキルID** |
| その外側の要素 | 72 | **候補名2件／数値ID2件で曖昧** |
| さらに外側の要素 | 74 | **候補名2件／数値ID2件で曖昧** |

原因は、親要素に**隣接報酬の別スキル名が見える**ため、局所行で一意に読めたIDまで「曖昧」として棄却する、変換器の過剰な拒否条件。サイトに必要な情報がないという判断は誤りだった。

## 共通変換器の修正

`poc/src/official_gametora_site_hint_draft.cjs` は既存のDOM抽出による**近い要素→遠い親要素**の順序を用い、次を満たす場合だけヒントのID・Lv候補を確定する。

- 現在のヒントの近傍に、固定UmaSim辞書への**一意照合が成立する狭い文脈**がある。
- その一意照合より**近い要素に曖昧なヒント名がない**。近傍で既に複数名・同名異IDなら未解決。
- 親方向も含めて**別の一意な数値IDが出現しない**。独立ID同士が矛盾すれば未解決。
- 先に確定した局所IDが存在する場合、その外側の親要素に複数の報酬名が見えるだけでは棄却しない。

旧GameTora派生元のスキルID、ヒントLv、報酬をサイト観測へ補完しない。GameToraの文章・選択肢文言・HTML・画像もリポジトリへ同梱しない。**これは結果別のスキルヒント候補の同定**であり、イベントの直接取得スキルや全報酬、内部分岐、文章の再配布を承認するものではない。

## 修正後の実サイト照合

[修正版の実Chrome Actions #40696335977](https://github.com/Nimrodx0/Umasupport/actions/runs/40696335977)で、対象イベントは外側3グループ・表示結果4経路・符号付きスカラー12件を維持し、表示ヒント1件に**数値スキルID `202032`・ヒントLv `1`**を独立辞書で一意に結びつけた。画面上第3グループ・第1結果に限る。他の結果へは複製しない。

以前の**0/1件→今回1/1件**は、この1イベントの元サイト表示での同定成績。全サポカのヒントID照合率を表さない。

## A・B・Cと保留点

- **A＝Pass**：合成9件（従来6件＋今回3件）。狭い行の一意照合を親コンテナが妨げないこと、狭い行自体の曖昧性は親で救済しないこと、同名異IDのままなら未解決であることを検証。異なる一意IDが同じ文脈系列にあれば従来どおり未解決。
- **B＝限定Pass**：固定した独立UmaSim辞書と元サイトの1イベント1ヒント。旧派生GTデータの数値を新しい値へ書き換えることはしない。
- **C＝限定Pass**：GameTora本体の1カード・1イベントをGitHub Actionsの実Chromeで読み取り、結果別候補の一意同定に成功。物理Android／Windows端末やゲーム本体の操作は今回の検証に含まない。

正式なイベント `rewards[]`、スキル報酬の全件収録、連続イベントの後続 `requires` と打ち切り意味、確率、男性トレーナー用選択肢文言、公開権利の審査は未完成。**正式公開イベント0件**を継続する。
