# 元サイトの汎用変換規則検証に使う既存旧カード3種（2026-10-28）

## 目的

[SSR30001の単一イベントJSON照合](official-gametora-30001-combined-app-parity-20261028.md)まで、GameToraの**表示された数値効果**と既存のウマサルタント用変換結果を5イベント・9経路で再現できた。これは**1枚しか実測していない**という問題を残す。実装の適用範囲を裏付けるには、条件や分岐の異なる**既存固定データのカード**で同じ試験を行う必要がある。

この監査では未収録新サポカを選ばず、既存固定資料`systemless10/UmamusumePS@6e38b54af4fad397ff4491e63007a90705a4fe67`の旧3枚を次の検証コホートとして選定した。各元ファイルのGit blob SHAを固定し、出典の本文・選択肢・画像を出力せず、機械的な**構造だけ**を検証する。

## ここで判定したこと、していないこと

- **A＝Pass**：対象3構造の分類・違い・固定母数変更の合成異常系を検出。
- **B＝Pass（旧固定データの形だけ）**：上記3枚の元イベント・選択肢・結果数、範囲値の出典位置、終了コードの記載数を固定Git blobで実測。
- **C＝未実施**：GameTora**元サイトのイベント表示／DOM**をまだこの3枚では抽出・比較していない。したがって**サイト取得による変換の再現性、範囲値がどの結果へ属するか、ゲーム上の選択肢対確率結果、後続進行**は未確認。
- **配信＝未実施**：本番イベントDBの公開件数、権利ゲートは変化なし（0件）。

## 次の実装に必要な具体的試験

1. 元サイトのSSR30030／30041のイベント見出しを**旧固定に結びつけてから**、数値範囲を独立に読み取る。元サイトが1欄に「10/30」と表示するのか、2結果に展開するのか、確率・分岐ラベルをどこまで含むのかを確認。元の固定範囲を画面の数値欄へ逆流補填しない。
2. SSR30080では3択と4結果の区別、打ち切り位置、お出かけの解放条件を別々に確認。ゲーム内発生確率の数値化は要求しないが、**連続内部の進行を捏造しない**。
3. 既存SSR30001専用比較器のハードコード（5イベント／9経路、カードID、DOM見出しの既知要素）を分離し、上記の異なるカードにも同じ汎用取得・変換器を使えるようにする。
