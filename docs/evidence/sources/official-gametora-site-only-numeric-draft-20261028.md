# GameTora本体の直接数値取得を旧固定GTから切り離す非公開中間変換（2026-10-28）

## 目的

[SSR30080の数値差の実測](official-gametora-30080-numeric-drift-20261028.md)で、旧固定GT派生データと元サイトの表示効果は**4経路すべてで非等価**であることが判明した。古い値を元サイトに当てはめて収録してはならないため、出典元サイトの画面を起点に、**過去版を参照しない数値・結果形状の候補生成器**を追加した。

この候補は、ユーザーが求める「GameTora本体→ウマサルタントデータベース」のうち**最初の非公開中間表現**であり、ゲームイベントそのものを完成させるものではない。旧GT比較は別監査として維持するが、候補生成器 `poc/src/official_gametora_site_numeric_draft.cjs` の引数には旧固定のイベント、報酬、ID、ラベルを渡せない。

## 中間候補の契約

入力は、元サイトのカード数値ID、見出し位置、GameTora DOMから独立に取り出した外側グループ、表示されたOR区切りと結果別の符号付き数値断片。各結果に現れた有効なスカラー効果だけを `{kind,delta}` として記録する。受け手ID、元カードに記載のないシナリオ成分、成功失敗の内部条件、発生確率を捏造せず、各グループには表示位置と結果候補の数だけ保持する。

**スキル報酬が未解決なら `rewards:[]` は出さない。** 空の報酬欄を見て「スキルは存在しない」と誤解させないためである。 `skillRewardsStatus:'unresolved'` を明示する。選択肢の日本語ラベル・イベント名・連続内の `requires` は転写しない。画面上の打ち切りの文が単一結果のグループにある場合だけ `terminalEvidence:'displayed-on-single-route'` とするが、ゲーム用 `terminal:true` の採用は行わない。複数結果のどこに付くか分からない場合は未確定。

**一般の `event-schema.v1` には昇格しない。** `appEventSchemaAdoptable:false`／`publicationApproved:false` を常に維持。サイト文言・HTML・画像・全カードイベントJSONを出力せず、テスト実行時のRAM内処理と種類・値・件数を含む限定監査要約だけ扱う。

## 検証

- A（機構）：合成7テスト。旧固定値不在でも実サイト由来の数値が候補に入る、OR内部で結果が混ざらない、非数値スキルヒントを報酬に自動昇格させない、未知数値・構造不整合・長すぎる入力・複数結果の打ち切りの誤配属を防ぐ。
- B（データ）：旧固定GTはPR #255で検出した差異の監査参照だけ。新しい中間候補の真偽は**元サイトから得た12数値・4候補・3グループ**を入力して検査する。4結果の実ゲーム正確性や全カード網羅は未検証。
- C（環境）：元GameToraカードSSR30080の1イベントをChromeで直接読み、同じブラウザ処理内でサイト数値中間候補を生成。旧データから候補を補正しない。Windows・Androidでの本番アプリ実機は別工程。

## 次工程

現DOMで「最大体力」が何という言い回しで表示されるかの独立同定、スキル名／ヒントLvを数値IDに解決する辞書の連携、選択肢文言の非再配布下での対応、報酬の実際の排他性と後続進行の裁定が必要。その後初めて `event-schema.v1` のレビュー候補を作れる。権利と公開承認ゲートは引き続き別扱い。正式公開イベント0件は不変。
