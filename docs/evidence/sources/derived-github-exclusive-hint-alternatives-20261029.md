# 2026-10-29：GameTora派生JSONの「いずれか1つのスキルヒント」を結果別に保持

## 目的

前工程 [派生GitHub JSON→アプリ用非公開イベント草稿](derived-github-app-schema-draft-20261029.md) では、通常ヒント・直接獲得・イベント結果・打ち切りの変換を開始したが、GameTora派生JSONの `skill_hint_or` は保留していた。これは**複数のヒントを同時に得る報酬ではなく、候補のうちいずれか1つ**を表す。ウマサルタントでは同時獲得として過大計上しないことが必須。

## 実装した一般規則（PR #277）

- `poc/src/derived_github_runtime_draft.cjs` で、**1元結果に1つの排他的ヒントグループ**があり、選択候補が**2〜8件**の数値IDとヒントLvを持つ場合、元結果を候補数個の独立した**結果バリエーション**へ展開する。
- 結果番号は元経路IDと候補番号を組み合わせて安定化。元の選択肢と出典結果の位置、通常の確定ヒント、直接付与、明示打ち切りを各候補結果に保持する。**選択の当たりやすさ・成功条件は推測しない**。
- ヒントIDは別に固定したUmaSim数値辞書の `normal`／`rare` に限り採用。候補に同じスキルが複数ある、通常ヒントと選択候補が重複、数値IDがない、ヒントLvが範囲 `+1/+3` として未確定、複数グループがある、未知条件が付く場合は**元イベント単位で保留**。
- 結果バリエーションが発生しても、アプリ側 `core.directRoutes` の結果選択では**選ばれた候補のスキルだけ**を計上する。合成の到達・排他テストをCIへ追加。
- イベントと選択肢には原文を転載せず仮の中立表示を使う。草稿には公開禁止の `sourceKind` を保持し、`verifyRelease` の審査なしに正式DBへ移行できない。

## 実データ確認

[固定派生GitHub JSONの4枚限定CI](https://github.com/Nimrodx0/Umasupport/actions/runs/40825469612)では、GameTora派生 `systemless10/UmamusumePS@62ec54e754f903e347da807d30aad40e53d794d2`、固定UmaSim数値辞書を読み、コピー元イベントのテキストをログに記録せず、元イベント数・非公開アプリ形の件数と保留理由だけを出力した。

| カード | 派生GitHubの元イベント | 非公開アプリ形 | 保留 | 保留理由 |
| --- | ---: | ---: | ---: | --- |
| R10016 | 2 | 2 | 0 | なし |
| SR20075 | 3 | 3 | 0 | なし |
| SSR30010 | 5 | 2 | 3 | 未対応効果種別1、前段階が保留の連続イベント2 |
| SSR30030 | 5 | 4 | 1 | 数値スキルID未照合1 |
| **合計** | **15** | **11** | **4** | |

**今回の実データ検証は、上記4枚で `skill_hint_or` が新たに承認可能になったと示すものではない。** SSR30010には数値範囲を含む候補があり、別の未対応効果や前段階の保留も存在する。今回の明確な進展は、**候補ID/Lvが確定した一群なら、複数ヒントの一括獲得に変えずに、排他的結果として表現できる機構を作ったこと**である。特殊型やスキルヒントの範囲値の正確な結果への対応は未解決。以前のSR20075の元サイト表示5パネルと派生GitHub3イベントの差も、今回解消されたわけではない。
