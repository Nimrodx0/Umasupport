# GameTora本体の結果別4系統を厳密に結合する非公開中間候補（2026-10-29）

## 対象と検証済みの出典

前工程では元サイトの効果を独立に処理する `site_numeric_draft`、`site_hint_draft`、`direct_skill_draft`、`site_flow_draft` を実装した。今回の `poc/src/official_gametora_site_unified_draft.cjs` は、**元GameTora本体の同一イベント・同一結果から得たこれら4つの非公開候補だけ**を受け、アプリ用のイベント構造より手前で結果を統合する。

限定現場試験はGameTora元サイトSSR30080（カードID 30080）のうち、画面上第6イベント（旧固定派生GTの第8イベントとの名称比較で一意に選択）**1イベントのみ**。旧派生GT JSONの値・スキルID・分岐情報は**統合器の入力に一切渡さない**。従来のChrome限定調査はイベント画面を選ぶ際に旧出典のイベント名を使い、旧版と現サイトの数値相違を監査するが、それは新しい結果候補の元データではない。

## 統合のための厳格な条件

- `cardId`・`siteEventOrdinal`・出典種類・版番号・非公開承認フラグが4入力すべてで一致しなければ**拒否**。
- 数値元の外側グループ、内部ORで分かれた全結果、ヒント候補の同位置、直接スキル候補の同位置、進行表示の同位置が、**順序も含めて全件一致**しないと拒否。別カードの情報や余分な結果を近接位置へ流用しない。スキルヒントID・Lvは独立固定UmaSimスキル辞書で元サイト表示から照合されたものだけ。
- 同じ結果の非スキル数値 `numericEffects`、スキルヒント `skillHints`、直接付与候補 `directSkills`、進行表示 `visibleFlowMarkers` を**分離した列**に保持する。ここで効果を合算・繰返し統合・他経路へ複製しない。
- 明示的な進行マーカーでもORの位置が分からない場合、`unlocatedVisibleFlowMarkers` として保留し結果に付与しない。
- `unresolvedReasons` を各結果に残す。**報酬全件の網羅、選択肢と結果の意味、数値効果の受け手、連続イベントの後続依存、選択肢文章、公開・再利用権限**はまだ未確認。正式な `rewards[]`、`terminal`、`requires` は出力しない。

すべての統合候補は `appEventSchemaAdoptable:false`、`publicationApproved:false`。結果候補の構造が作れても、ゲーム中の次段イベントへの到達条件を推測してはいけない。非公開データやCIログに、元GameToraのイベント文章・選択肢文言・HTML・画像を保存しない。

## 元GameToraの1イベントでの実Chrome測定

[元サイトを読んだ実Chrome成功ジョブ](https://github.com/Nimrodx0/Umasupport/actions/runs/40794434904)で次を観測し、同一の元サイトDOM結果範囲から四系統の結果候補を生成・統合した。

| 画面の結果位置（外側グループ／結果） | 数値効果行 | ID確定ヒント | 直接付与の一意候補 | 表示された進行マーカー |
| --- | ---: | ---: | ---: | --- |
| 1／1 | 4 | 0 | 0 | お出かけ解放 |
| 1／2 | 2 | 0 | 0 | お出かけ解放 |
| 2／1 | 3 | 0 | 0 | お出かけ解放 |
| 3／1 | 3 | **1** | 0 | **連続イベント打ち切り** |
| **合計** | **12** | **1** | **0** | **4** |

スキルヒント1件は独立UmaSim辞書の数値ID `202032`・Lv `1`（第3グループ・第1結果）であり、他の結果へ移動しない。「獲得」に関連する短い断片は**2件**あったが、明示的なスキル名が一致する直接獲得とは特定できず、2結果の `direct-skill-facts-unresolved` として残した。**一意候補0件は直接付与スキルが存在しないことを意味しない**。

ここで「3件のお出かけ解放」と「1件の連続打ち切り」は元サイト**表示の分類**であり、ゲーム内でそれぞれの状態遷移が実行されること、後続でどのイベントが起こるか、ゲームに出る選択肢文章を確認したわけではない。

## A・B・Cと残件

- **A（機構）**：合成8試験。4元データの出典/数値ID/結果番号の不一致、ORを移さない、無効な数値スキルIDの拒否、未承認公開の拒否と、効果・ヒント・直接スキル・進行マーカーを別々に保持することを検査。
- **B（実データ）**：元GameTora SSR30080の1イベント、3グループ・4結果・数値12行・ヒント1件・進行表示4件という限定母数で実証。全サポカ、全イベントや直接獲得全件の代表値ではない。
- **C（実ブラウザ）**：Playwright＋ChromeでGameTora本体を直接読み、4結果を一致検査。GitHub Pagesへ配信したイベントとしての物理Windows/Android端末操作や育成ゲーム内再現は未実施。

次段階は、元GameTora画面で正式な選択肢と結果の意味、連続イベントの後続到達を再現できる明示的な根拠を集めること、欠落事実だけ[GameTora→GameWith例外裁定](event-adjudication-enforcement.md)で確認すること、スキル直接付与の陽性例を増やすこと。現時点の成果を**公開用イベントDBへ自動変換しない**。正式公開イベントは**0件**のまま。
