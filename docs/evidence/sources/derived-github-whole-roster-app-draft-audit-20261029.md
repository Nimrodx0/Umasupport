- 独立数値スキル辞書：`mee1080/umasim@910dd79f046710245e0cc88a09c5c92b1044897e/data/skill_data.txt`。
- 実行：[全件非公開変換GitHub Actions（2026-10-29）](https://github.com/Nimrodx0/Umasupport/actions/runs/40830053625)。元資料は実行中のActionsチェックアウト／一時ファイルにのみ保持し、ログには件数・理由コードだけを出す。
- 判定：`poc/src/derived_github_runtime_draft.cjs` のイベントv1投影器を各カードへ実行。`event_schema.validateEvents` を通ったものも**`sourceKind:derived-github-unreviewed` により公開不許可**。全カードの新規取得検出を再現したわけではなく、前名簿0件の**人工監査用差分**で固定版全件のblob照合ゲートを共通利用している。

## A/B/Cの限界と次工程

- **A 機構**：完全なGit treeにある1カード1blobのSHAを各JSONで検査。欠落／二重カード／バイト改ざん／元イベント件数不一致を拒否する。出典の表示文言・効果本文・未承認草稿をCIで再配布せず、純粋な集計値だけをログへ出す。人工試験では `special`／`dates_random` の報酬を実 `core.directRoutes` が条件付きと認識し、`dates` と不明な内部条件は保留する。
- **B データ**：2026-10-29の固定第三者GitHub DB559枚・2,488件を完全検査した。ただし元GameToraサイトの最新データと全件一致するとはいえず、例えば以前のSR20075のサイト表示5パネルと本DBの3件の差も残る。新カード分の収録とゲーム内の完全網羅は独立の課題。
- **C 実環境**：GitHub ActionsのNodeで実Git checkoutを使い、既存のCIブラウザ回帰を実行。物理Windows／Androidの利用者端末で審査済みイベントを読み込む実機受け入れは未実施。
- **公開と品質**：`event_release_gate.verifyRelease` の個別証拠、出典利用・再配布の確認、日本語ラベルの公開判断、`appendApprovedNewCards` の原子的追記は**未実施**。現状は独自公開イベント0件。技術的候補を公開済みに書き換えない。

**次の重点は、82件の未対応効果の意味別分類と80件のスキルID不一致の根拠整理、または111件の `dates` 内部到達を安全にモデル化する共通機構**。例外別の追記ではなく、スキルの集計に影響するパターンを優先する。
