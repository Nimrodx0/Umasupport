# W3新カードのイベント保留と製品側の表示・検索改善（2026-11-11）

## 新カードの現状

[Issue #283](https://github.com/Nimrodx0/Umasupport/issues/283)に保存された未取込カード5ID（`10149`, `20102`, `30322`, `30323`, `30324`）について、2026-11-11に`systemless10/UmamusumePS`の`main`で次のパスの存在確認を行った：`server/data/events/gametora/support_<ID>.json`。5件ともGitHub Contents APIは**HTTP 404**。これはその固定パスが取得できないことを意味し、実ゲームのイベントの不在や他の出典での未掲載まで証明しない。

W3の技術的パイプラインはすでにUmaSim名簿の検出、版固定のJSON取得、ソースの個別検証、未変換事項の台帳、承認前の公開停止を備える。今回は未掲載を推測で埋めず、日次監視を継続する。GameWithの個別裁定や第三者本文の利用許諾は得られたとは扱わない。

## 製品側の改善 [PR #399](https://github.com/Nimrodx0/Umasupport/pull/399)

### サポカのイベント状態

- 公開済み・検証済みイベントJSONに登録があるサポカは「公開イベントN件」と表示。
- **イベント未収録**：検証済みJSONのうち、当該カードIDにイベントレコードが存在しない。実ゲームでイベントがないという意味ではない。
- **イベント情報未検証**：公開JSONの取得や検証に失敗したときは空集合の意味にしない。
- カードの詳細画面にも「イベントは未収録、通常ヒントは別途利用可能」と説明を出し、空のイベント欄が「イベント無し」に見える問題を防ぐ。

### 目標スキル候補順

サポカ選択モーダルに「目標候補が多い順」を追加。使用するのは**現在の目標セットのうち、選択中デッキ（本育成／継承育成）が対象に含まれる**スキルIDだけ。指定範囲が「両方」「どちらか」の目標は両デッキで対象にする。

- 通常ヒントは当該カードの検証済み**4凸**ヒント集合のみ。
- イベントの候補IDは検証済み公開イベントの報酬集合のみ。結果未確定・到達条件ありの候補も含むため、実ゲームでの獲得保証・最適編成の確率ランキングではない。
- 同一スキルが通常ヒントとイベント両方から出ても、**目標1件**として集計。
- マイナススキル付与や、未承認資料／参照のみのスキル、検証に失敗したイベントレコードは含めない。
- 同点カードは元のUmaSimカード順を維持。カードIDから実装日を推測しない。所持状態・既存デッキ・保存済みイベント選択には変更を加えない。
- ユーザーがまだ目標を登録していなければ、目標候補数は表示せず元の順で並べる。

## 試験と限定事項

- [単体テスト](../../../poc/tests/card_search.test.cjs)：目標の対象デッキ、4凸と前段凸の差、同一スキル重複、実際のイベントデータ取得失敗、マイナススキル非採用、安定した並び順。
- [Chromium疑似563カード試験](../../../poc/tests/browser_skill_smoke.cjs)：画面の未収録／検証失敗ラベル、4凸通常ヒント目標、目標候補順、スコープ差、詳細説明。
- [固定UmaSim＋公開イベント結合試験](../../../poc/tests/browser_w1_pinned_public_integration.cjs)：公開承認済みのイベント候補を目標スキルに設定し、画面から候補順でカードを発見する。
- **新カードのイベントデータそのものを追加・承認したわけではない。** GitHub Pages配信コミットやWindows/Androidの物理端末も未検証・保留。固定ソースの正常読込試験は、ゲーム現行版に関する独立した完全性の証明ではない。

W2の公開利用条件、W4の未解決データ差異は個別例外として継続するが、製品の通常ヒント・編成比較の改善を妨げない。
