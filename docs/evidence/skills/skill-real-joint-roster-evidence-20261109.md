## 2. 周辺度数だけでもわかる「取り得る範囲」

相手6頭を40レース記録した場合、ある脚質の総出走数を `E` とする。**その脚質が1頭もいなかったレース数** `Z` は、`R=40` レース、`m=6` 相手／レースとして、以下を満たす。

```text
R - min(R, E) <= Z <= R - ceil(E / m)
```

左側はその脚質がなるべく各レースに分散したとき、右側は1レースに可能な限り集めたときの限界。**これは観測から得られた数学的な範囲であって、統計的な信頼区間ではない**。以下の「逃げ不在」は**相手6頭の中に逃げがいない**意味であり、**自チーム3頭を含む9頭で逃げが0頭**とは別である。

| 観測した大会の相手240頭 | 逃げ合計 E | 相手6頭で逃げ不在の試合数の取り得る範囲 | 40戦中の割合で書いた場合の範囲 |
| --- | ---: | ---: | ---: |
| 2025-10 短距離 A予選 | 39 | **1～33戦** | 2.5～82.5% |
| 2025-12 マイル A予選 | 22 | **18～36戦** | 45.0～90.0% |
| 2026-01 長距離 A予選 | 21 | **19～36戦** | 47.5～90.0% |

つまり2026-01の先行60%／逃げ8.8%という周辺頻度だけから、「逃げ不在は約何割」という**具体的な1点の出現率は決定できない**。逃げの分布が試合ごとに偏るか（マッチングの相関、各トレーナーの3頭同時採用）が必要である。各脚質の平均だけから独立に乱数抽選する仮定は従来の[感度用モデル](skill-position-population-priors-20261105.md)にはあったが、**現実の同時編成を復元したことにはならない**。

### なぜ周辺度数から9頭の組合せを復元できないのか

例示用の**人工的な**9頭×2試合について、次の2つのサンプルを考える。

- 集合A：9逃・0先を1レース、0逃・9先を1レース。
- 集合B：5逃・4先を1レース、4逃・5先を1レース。

両者とも2レース計で逃9頭／先9頭だが、「逃げ不在」はAで1試合、Bで0試合。平均数・脚質別割合が同じでも、同時編成は一意に決まらない。

## 3. 今回実装した出典確認と集計のルール

[研究専用の監査器](../../../poc/tools/skill_joint_roster_source_audit.cjs)、[人工テスト](../../../poc/tests/skill_joint_roster_source_audit.test.cjs)は次を厳格に検査する。

1. **全9頭の実観測**は競技月／ラウンド／9頭人数合計／元ソース・公開日・匿名の観測識別子を必須とする。自チーム3頭が独立にわかる場合だけ相手6頭を派生できる。**大逃げを逃げに統合してよいかは明示的な証拠なしに承認しない**。
2. **相手6頭×R戦の脚質別周辺度数**はR・人数合計・脚質別度数・出典を確認し、各脚質について**「不在試合数の下限～上限」**だけを算出。9頭編成の確率分布へは変換しない。
3. 出典コホートID・競技月・ラウンドと形式の違う標本を**勝手に混ぜない**。同一コホート内の観測キー重複を拒否し、個人識別子・画像・ログ本文を公開しない。出典を持たない外部数値を混ぜない。
4. 全9頭の観測件数が30件未満なら各編成の観測割合を非表示（NULL）とする。この30件は**表示時の誤解防止の実装上のゲート**にすぎず、30件以上を代表的な確率推定と認める統計閾値ではない。30件以上でも「その集計対象内の記述値」であり、母集団頻度やP3の重みとはみなさない。
5. 自チーム3頭と他者6頭の構成、イベントの距離・ラウンド・参加者の強さの偏り、同一チームの繰り返し観測、報告者の自己選択、大逃げの分離有無が不明な場合、**実ゲーム母集団の編成分布は未識別**のままとする。

実行：`node poc/tools/skill_joint_roster_source_audit.cjs poc/data/p2_public_full_race_one_20261109.json poc/data/p2_public_opponent6_marginals_20261109.json /tmp/p2-joint-roster-source-audit.json`

結果は、9頭の公開観測**1レース**、予選の周辺度数**3コホート**。**大きな9頭同時編成サンプルの確認は0件**。直接取得・ログ提供の機構や当日の観測データはまだ存在せず、最頻編成が「均衡」と判定できたわけではない。

## 4. 次のデータ取得を可能にする検証計画

- **収集単位**：同じチャンミ大会・リーグ・ラウンドの1レースについて、逃げ／先行／差し／追込の**9頭全体の人数**、そのうちの自チーム3頭（わかる場合）、可能なら独立の大逃げ・牽引役を区別する。9頭と12頭は分離。
- **プライバシー**：出走者名、トレーナー名、トレーナーID、プロフィール、外部アカウントID、対戦画面全体やリプレイ、画像は研究データに保存しない。必要な事実の集計のみ、取得・公開条件の許可がある場合に取り込む。
- **サンプリング**：記録漏れ／勝敗による選別を防ぐため、事前に決めた一連の対戦を連続記録し、勝敗を見て都合の良いレースだけ選ばない。複数報告者の同じ対戦の重複・同じ編成が繰り返し当たる偏りを識別できる仕組みは、プライバシーを保護しつつ別途検討する。
- **評価単位の分離**：同じイベント・ラウンドの分布を記述してから、異なる大会・距離・時期で変動するかを判断する。相手6頭の同時分布と、自チーム込み9頭の同時分布とを混ぜない。12頭LoHはNPC人数と役割を含め独立に設計・計測する。
- **製品への採用ゲート**：十分な標本の独立性・出典許可・競技条件・ゲーム版を確認し、モデルに適用できる脚質分類（大逃げ等）と照合した後に、**利用者と別途合意**を得る。データが増えただけで標準の均衡編成を変更しない。
