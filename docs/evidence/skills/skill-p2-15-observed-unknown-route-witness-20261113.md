# P2.15：元スキルの未判定経路を実測モデルの判定時刻から診断（2026-11-13）

## 問い

[元スキルの位置由来5条件を追加した固定研究](skill-p2-15-source-position-family-join-20261113.md)では、固定8レース・元`distance_rate`対象253スキルのうち、**21,252スキル×モデル走者×モデルレース**の判定が「1回以上成立778／未判定16,535／観測全不成立3,939」だった。約1,654万の元述語観測事実を増やしても、未判定は多く残る。

今回の問いは、**未判定の各走者×スキル×モデルレースについて、実際に観測された判定時刻のどの元Invoke／条件OR経路に成立可能性が残っており、次に何の観測が必要か**、である。**全時刻・全経路の未判定原因を完全に確定したという主張ではない**。

## 元の論理を維持した候補選定

固定元UmaSim辞書 `mee1080/umasim@f6e4501ee6c6c2d4ac8698e7796e309d31575bde` の全AND/OR・`preConditions`・複数Invokeを既存の[三値tick判定器](../../../poc/src/skill_source_whole_tick_monitor.cjs)で評価する。GlobalSim v77 `80b54cacf174b54ff6f7ca27ee7f88b5856c0bd1` の独立位置観測を使った同一モデル判定時刻だけを対象とし、元UmaSim実レースや実ゲーム技能発動を観測したとは扱わない。

各スキル×モデル走者×モデルレースにおいて、全観測時刻を通じ`true`が一度もなく`unknown`が一度以上ある場合だけ、未判定の観測時刻から**原条件の候補経路**を探す。

1. `overallCondition=unknown`の時刻で、まだ`conditionConjunction=false`になっていないInvokeのみを検討。
2. そのInvokeの条件ORを構成するAND経路について、既知`false`を含む経路を除外し、未観測の元述語を型別に数える。**元のInvoke・OR・predicate identity**を維持する。
3. `preconditionLatched=unknown`の経路には、通常の現在値の不明と分けて`precondition-latch-unknown`という保留条件を1つ記録する。元の`t=0`以前や未観測初期履歴を偽と推定しない。現在`preconditionNow=false`でも、過去に真だった可能性のある履歴は残す。
4. 「**この時刻で、成立可能な1経路を調べるのに足りない異なる条件種類の最少数**」が小さい候補を1つ保持する。別の時刻にさらに少ない候補が見つかったら更新する。最少数が1になった時点では以後の未知時刻を精査しない。

この方式で記録するのは、**観測した時刻の、元スキル1経路に対する「次に観測すべきもの」の代表例**である。たとえば`phase_random`1種類の観測が足りないと出た場合、その1種類を測れば`true`になるという意味ではない。測定結果が`false`なら成立しないし、他のOR経路や別の時刻では異なる未観測条件を要する場合もある。

同一スキルに複数の実現候補経路があっても独立率の積やスキル全体の確率に直さない。1経路の代表候補が見つかっても元スキル実発動の証拠ではない。欠測が多い条件型を示す件数はモデル人工レースの相関した走者サンプルであり、実ゲーム対戦分布や重要度そのものではない。

## 測定結果と次の追加研究

モデル実測の診断結果はCIの`unknownRouteTriage`が正本。**固定CIで検証した数字・候補を得るまでは実データの上位条件型や優先順位を推測しない。**
