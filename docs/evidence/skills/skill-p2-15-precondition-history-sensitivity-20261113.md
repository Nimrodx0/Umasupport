# P2.15：元preConditions初回観測以前の履歴仮定に対する感度分析（2026-11-13）

## 調査の理由

[元UmaSimのコーナー条件を含む同一時刻の元条件統合](skill-p2-15-source-corner-full-join-20261113.md)で、固定8人工GlobalSim無スキルレース、元`distance_rate`253スキルの21,252スキル×走者×レースを評価した結果、**成立確認4,935／未判定8,732／観測全不成立7,585**が得られた。未判定の代表候補経路のうち、**3,076件**に元`preConditions`の履歴ラッチ不明が含まれた。

元UmaSimの`WholeTickMonitor`は元InvokeごとにpreConditionsの成立状態を保持し、一度成立した状態は次のモデルtickへ引き継ぐ。元ソースでは`preChecked = preChecked || preCheck(this)`という仕様がある。**しかし本研究は元UmaSimの実スキルチェックを初期フレームから観測したわけではない**ため、固定GlobalSimモデルの最初の「スキル判定直前位置」を観測する以前に元preConditionsが成立したかは不明としている。

今回の工程は、この最初の履歴不明が未判定に与える影響を**仮想的な比較**として切り出す。**初期履歴が偽と実証されたわけではなく、初期偽のシナリオを本来の根拠に採用しない**。

## A／Bの条件と論理的な限界

- **A（既存正本・保守的）**：全InvokeでpreConditionsが存在する場合、最初に計測できるモデル判定時刻より前の成立履歴を`UNKNOWN`とする。実測後の`TRUE`はラッチし、`FALSE`で戻さない。
- **B（仮説・感度分析のみ）**：同じ全Invokeのラッチが、**最初のモデル判定時刻直前に`FALSE`だったと仮定**する。以後はAとまったく同じモデル観測・元演算子・AND/OR/preConditions・複数Invokeとラッチ更新規則を使う。
- いずれも元スキル装備・実ゲーム発動や元UmaSimのpreConditions評価を追加計測する実験ではない。同じ順位・位置・コーナーを同じtickに適用した**三値論理の感度**のみ調べる。
- Aで既に確定した`TRUE`と`FALSE`は、Bへの切替で矛盾する結果に変更してはならない。具体的に、BはAの`TRUE`件数を維持し、未知→不成立という変化だけが許される。Aでは履歴に未観測のTRUEがある可能性を除外しないため、Bで未判定が減っても**実際の技能成立機会が減ると断定しない**。
- 比較単位は前工程と同じ「元スキル×1人工モデル走者×1人工モデルレース」。複数の判定tickを独立試行と数えない。
- 既存のA正本の全条件成立4,935／未判定8,732／全偽7,585は不変。Bは独立の`preconditionHistorySensitivity`として出力する。公開UIやP3採点へは利用しない。

## 実装と検証

- [元三値解析への明示的な歴史仮定オプション](../../../poc/tools/globalsim_p2_15_source_distance_rate_ticks.cjs)：デフォルトは必ず`initialPreconditionHistory='unknown'`。別指定`'assume-false'`のみ、初回ラッチFALSEを仮定。その他の値は拒否。
- [同じ固定元モデル解析との感度差比較](../../../poc/tools/globalsim_p2_15_source_corner_full_join.cjs)：Aの元モデルをそのまま計算したあとBを並列論理シナリオとして再計算。出典・観測数・モデル物理値・同一スキル×脚質母数の完全一致、三値結果の単調性を検証する。
- [単体回帰試験](../../../poc/tests/skill_source_corner_stage_facts.test.cjs)：初期FALSE仮定だけで未知が不成立へ変わる例と、観測したpreConditions TRUEが履歴仮定に依存せずラッチされる例。
- [固定CI](../../../.github/workflows/p2-source-rank-distance-real-ticks.yml)：元UmaSim・GlobalSim固定出典を取得し、3独立エンジンの8モデルレース・253元スキルで従来の全件結果を再現。そのうえでBの値を独立した研究ログへ出力する。

## 固定モデル実測

CIで得た`P2_15_PRECONDITION_INITIAL_HISTORY_SENSITIVITY`が、この仮説比較の正本である。**CI検証前はBの件数を実測として公表しない。** 既存Aの正本値が一致すること、Bの成立件数がAと同一であること、Bの未判定がA以下で、差が全不成立へ移ることを検査する。

このA／Bは実ゲームのスキル発動率、元UmaSimの実レース処理、先行するランキング・コースモデルの観測の再検証を意味しない。仮説Bの値を元の技術仕様・P2脚質適性・P3カード評価・P4製品UIに昇格しない。

## 次工程

感度が大きい場合、初回未観測フレームで元preConditionsが本当に評価されるか、観測開始以前にラッチが成立し得るかを**出典・元ランタイムの実測**で検証する必要がある。感度が小さい場合には、他スキル発動済み・追い抜き等の動的述語や複数ANDの保留が主な次候補となる。
