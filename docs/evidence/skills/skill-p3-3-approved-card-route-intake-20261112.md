# P3.3：固定公開データの直接獲得候補経路の独立監査（2026-11-12）

**対象と責務**：[P3.2の固定元ID・名称・全条件照合](skill-p3-2-original-source-app-identity-20261112.md)を通った元10条件のうち、アプリに同定できた9スキルだけを使い、**固定アプリの通常ヒント／承認済みイベントに記録された直接のスキル獲得候補経路**を監査する。研究専用であり、元スキル全条件の発動、実ゲーム中の獲得確定、正式なカード脚質適性を評価しない。

## 入力・検査境界

- [P3.2照合結果](../../../poc/src/p3_source_app_identity_audit.cjs)の原スキル数値IDとアプリの数値ID・名称・条件構造の完全一致を前提とする。元10件は一致9、固定アプリ未収録1。スキル名の類似・階層・イベント原文から新たなID対応を推測しない。
- [取得経路監査](../../../poc/src/p3_card_acquisition_routes.cjs)と[固定元データCLI](../../../poc/tools/audit_p3_3_card_routes.cjs)を追加。元UmaSimの固定`skill_data.txt`・`support_card.txt`、公開承認済み`reviewed_events.v1.json`、固定旧スキル辞書のSHAをP3.2研究結果と突合し、再構築したアプリモデルを使う。第三者の元スキル・カードJSONやイベント原文を研究成果物に複製しない。
- 各カードの**0凸〜4凸の通常ヒントを別々に**照合する。4凸の所持を低凸の獲得経路と自動的に同一視しない。
- 公開承認済みイベントの**自動イベント／選択肢／分岐結果**の報酬を元の`eventId`・`choiceId`・`outcomeId`に紐付ける。試用・未承認・歴史資料やマイナススキルを候補にしない。報酬が存在してもイベントの発生やその分岐への到達を保証しない。
- 特定の選択肢・結果・凸段階における確認には、[本番集計器](../../../poc/src/core.js)の`directRoutes`を使う。未選択分岐を無条件獲得としない。
- 元の9件に対して固定アプリ内の直接候補がなければ「**当該固定公開データ内では直接候補未確認**」とし、元ゲームにない・適性0点とはしない。直接の通常ヒントやイベント報酬と、金白・上下位スキルによる**間接獲得**は分離しており、後者は未検証。

## 実装・検証の段階

1. **A（機構）**：人工データの[専用テスト](../../../poc/tests/p3_card_acquisition_routes.test.cjs)にて、凸別候補、独立choice/outcome、未選択、マイナス、無承認、同名異ID、改ざん・不一致、スコア非昇格を検証する。
2. **B（固定出典）**：既存[P2の5,760レース研究CI](../../../.github/workflows/p2-source32-split15-w.yml)でP2.18→P3.1→P3.2を再検証した後、同じ固定元カード名簿と承認イベントでP3.3候補JSONを再生成する。件数・ID別の照合結果と実行リンクを確認後に記録する。
3. **C（公開アプリ／実機）**：今回の研究は公開UIの変更なし。実機の受入は既存の保留を維持する。

## 未解決・次の作業

P3.3の直接候補は、**P2の元スキル部分条件Wの成立機会や全発動率とは異なる概念**である。全AND／OR、動的条件、D=O−U、発動後の有用性、選択済み分岐の本番デッキ集約、上位／下位スキル経由の候補、正式な適性評価・重み・公開UIは未採用。P2が主研究工程である方針は変えず、ここはP3の独立データ接続準備として扱う。
