# P3.2：元スキルと現行アプリ収録スキルの独立三点照合（2026-11-12）

**対象**：[P3.1の研究用受入口](skill-p3-1-research-intake-20261112.md)に保持された元スキルの順位・時期**部分条件10種類**。研究対象とアプリ収録の重なりを検証する。**サポカの取得経路・実スキルの発動・脚質適性・カード総合評価とは別**。

## 照合の必要性

P3.1までの研究は元UmaSimの数値スキルIDと**部分条件W**を保持するが、そのスキルがUmasupportに収録されているかは未確認だった。同じスキル名が複数の元IDに属する、アプリ内の `hint:` 識別子には数値IDが見えない、固定版の条件式が異なる等の問題があり、**文字列名だけでは安全に紐付けられない**。

## 元データと照合の方法

[検証コード](../../../poc/src/p3_source_app_identity_audit.cjs)と[固定元データ実行器](../../../poc/tools/audit_p3_2_source_app_identity.cjs)で、以下をそれぞれ独立に確認する。

- **研究の出所**：[P2.18の未適格研究データ](skill-p2-18-research-evidence-contract-20261112.md)と[P3.1の隔離受領データ](skill-p3-1-research-intake-20261112.md)を元manifestで再検査し、10種類・60脚質ペア・5,040比較設定と元のソースSHAを再確認する。混入・欠落・改ざんは拒否する。
- **元スキル辞書**：`mee1080/umasim@f6e4501ee6c6c2d4ac8698e7796e309d31575bde` の `data/skill_data.txt`（SHA-256 `4c036527bbe6b5aad34d7f12110a06094c9071514e37fdfc68ae195403333be5`）。元IDと正規化後名称、および元の各 `Invoke`、`conditions`、`preConditions`、効果型、角括弧条件を取得する。
- **アプリ側のモデル**：同じ固定版の `support_card.txt` からアプリのモデルを構築し、現在の承認済みイベント `poc/data/reviewed_events.v1.json` を付加。承認済み旧イベント報酬のIDを失わないよう、別の固定版 `cf9366f6a487bd8f197b53d8a11981207beb9f6c` のスキル辞書（SHA-256 `b7ba1d6c5dd2af9ed1f4e649f16ec1d319198e2f1ac9db07c54e14d29f0b25ec`）も照合する。
- **一致基準**：同じ元数値IDに対応するアプリスキルが**ちょうど1件**あり、元数値ID・NFKC空白正規化後の名称・各発動経路の元条件構造を**すべて一致**とする。数値IDが一意に検証された `hint:名称` 識別子は受け入れられるが、同名なだけの `hint:` は受け入れない。
- **保留分類**：元数値IDが重複するアプリ候補、IDは同じで名称が異なる、ID・名称は一致しても条件構造が異なる、名称だけ一致する、現行アプリに存在しない、を**別理由**として記録。現行アプリに収録されていないことを、ウマ娘のゲームにスキル自体が存在しない証拠としては扱わない。
- **出力形式**：10元スキルについて、数値ID、元名、照合状況、対応アプリID（照合できた場合のみ）、元の発動条件構造のSHAと研究条件の識別情報を保存。第三者のスキル元テキスト・発動条件式全文やサポートカード定義は成果物に含めない。

## 実測・適性評価への境界

[専用人工テスト](../../../poc/tests/p3_source_app_identity_audit.test.cjs)は、元IDと名称の一致、元の `AND/OR/preConditions`・効果型の不一致、同名異ID、同ID異名、重複、保留、アプリ・カードの破壊的な変更を検査する。[固定元データCI](https://github.com/Nimrodx0/Umasupport/actions/workflows/p2-source32-split15-w.yml)では、元の5,760モデルレース→P2.17b→P2.18→P3.1の順に検証してからP3.2のID照合を実行する。

**元10種類に対する照合結果と固定CI成果物のリンクは、CIの確定後に記録する。**

判定結果にかかわらず、スキルからカードへの取得経路（通常ヒント・イベント・選択分岐）は**P3.3で別途確認する必要がある**。アプリに収録済みであっても、サポカから入手できると主張しない。また、スキル発動の全AND/OR・複数Invoke・動的条件、D=O−U、現ゲームでの発動率、発動後の効果、P3正式な評価閾値についてはP3.2の成果ではない。**正式なサポカ採点、公開アプリのUI、既存スキルラベルは変更しない。**
