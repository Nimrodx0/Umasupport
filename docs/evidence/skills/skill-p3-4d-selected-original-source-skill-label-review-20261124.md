# P3.4d：固定元ソースの実スキル4件で「汎用／～向け」の認定根拠を狭く検査（2026-11-24）

[P3計画](../../plans/skill-conditions/p3.md) ／ [P3.4bの表示契約](../../plans/skill-conditions/p3-4b-label-presentation-policy.md) ／ [P3.4cの人工反例](skill-p3-4c-relative-bias-three-state-decision-probe-20261120.md) ／ [P3.4aの不確実性分類](skill-p3-4a-uncertainty-semantics-20261119.md)

## 今回検査する問い

「汎用＝絶対的に発動しやすい」ではなく、**適用可能なレース文脈の中で脚質間に実用上重要な偏りがない**という、利用者確定の定義を保つ。そのうえで、実在スキルの**元の全Invoke・AND・OR・preConditions**と、元ゲームモデルの条件チェッカーの仕組みから、何を認定候補にできるかを見る。

**今回の成功条件は、4件の元スキルに直接ラベルを付けることではない。** 以下の4パターンを、元ID・正式名・元条件と元実装を固定したうえで違う証拠状態に分けることである。出典の一部の真偽を勝手に全スキルの発動しやすさ・効果の有用性・サポカ評価へ変換しない。

**出典（固定・検査対象）**：
- [UmaSim の `skill_data.txt`：固定コミット `f6e4501`](https://github.com/mee1080/umasim/blob/f6e4501ee6c6c2d4ac8698e7796e309d31575bde/data/skill_data.txt)、元ソースSHA-256：`4c036527bbe6b5aad34d7f12110a06094c9071514e37fdfc68ae195403333be5`
- [元条件チェッカー `SkillChecker.kt`](https://github.com/mee1080/umasim/blob/f6e4501ee6c6c2d4ac8698e7796e309d31575bde/race/src/commonMain/kotlin/io/github/mee1080/umasim/race/calc2/SkillChecker.kt)
- [近接ウマ娘のランダム近似の定義 `SkillData.kt`](https://github.com/mee1080/umasim/blob/f6e4501ee6c6c2d4ac8698e7796e309d31575bde/race/src/commonMain/kotlin/io/github/mee1080/umasim/race/data2/SkillData.kt)
- [既存P3.4aの元データ4研究成果から独立検証した研究受領書](skill-p3-4a-uncertainty-semantics-20261119.md)。対象となるスキルが**881件のアプリ収録側にも元数値ID・名称で照合済み**であることを本工程のCIで検査する。

### 固定原本から直接確認した4ケース

| 元スキルID・名称 | 固定元Invokeの条件（AND。別OR／preConditionsなし） | Kotlinの対応処理・確かめられること | P3.4dの**研究上の扱い** |
| --- | --- | --- | --- |
| **200432「集中力」** | `always == 1` | 元チェッカーの `always` は真を返す。元条件式自体が脚質を選別する構造ではない。絶対的な発動率は不要でも、**条件式に脚質差を作る項がない**ことを積極的に確認できる | **「汎用」認定に繋がり得る**元条件構造の中立性候補。ただし正式な汎用ラベルではない。発動抽選・発動時点、効果の実戦価値は別 |
| **201312「先行直線○」** | `running_style == 2` AND `straight_random == 1` | `running_style` はレース前の指定脚質と照合され、`straight_random` は別のランダム発動区間機構 | **先行限定という適用範囲**は確認できる。しかし「先行向け」という**非明示的な比較優位が実証された**わけではない。他脚質をモデルW=0として比較しない |
| **201591「ウマ好み」** | `near_count >= 3` AND `accumulatetime >= 5` | `near_count` は元モデルの特殊状態による**近傍人数の近似**、`accumulatetime` は経過時間。実レースの脚質間比較に直結しない | 近傍機構の脚質差が未確認。**汎用とも特定脚質向けとも認定しない**。元モデル上の乱数近似を実ゲーム出現率と呼ばない |
| **203431「才気煥発」** | `distance_type == 3` AND `is_lastspurt == 1` AND `phase_firsthalf_random == 3` | 中距離制限がある。スパート状態とフェーズ前半のランダム区間は**別の条件で、元の同一時点ANDを要する**。P2.43はスパート＋窓の一部だけ再利用し全条件Wを保留した | **中距離という適用範囲を維持**。脚質への偏りは元AND全体で未確定。P2.38の部分研究を全スキルへ上書きしない |

*本表はコードと原本に基づく技術的な**研究分類**である。「元条件に脚質差がない」は「全ゲーム内の効果が脚質無関係」「製品で正式に汎用」と同義ではない。ユーザー用のラベル判定を行う実ゲーム実測・スキルの効果の有用性は検証範囲外。*

### 特に確認した区別

**1. 論理的な偏りの不在と、研究で偏りが検出されなかったことは違う。** `集中力`の元条件は、少なくとも固定元チェッカーの現在の条件式で脚質を区別しない。この**構造的な非依存**は、任意に選んだモデルで有意差が出なかっただけより強い**条件に関する**証拠となり得る。ただし適用可能性、元発動抽選、ゲーム外の効果の有用性は全く異なる問いなので、**この工程で正式汎用には昇格しない**。

**2. 適用範囲が特定脚質なら、4脚質での非明示的な相対比較はそのまま成立しない。** `先行直線○`では`先行限定`を適用範囲欄で表示する。別の`先行向け`ラベルは、制限があるという事実を二重に示すだけではない。将来、ユーザーに実用的な「先行向け」タグも見せるかは**表示設計・明示条件と非明示条件の分離規則の追加判断**とする。

**3. 発動条件の共通の要素を持っていても、未検証のANDが脚質差に影響し得る。** `ウマ好み`や`才気煥発`を、元のランダム・特殊状態・スパート機構が違うのに全体として「汎用」「～向け」へ自動的に変換してはいけない。

**4. 汎用の成立条件に絶対的な発動機会は設けない。** 条件式が一定である例から分かるとおり、相対的な偏りを論理的に除外できるなら、全体の発動機会の大小は必須条件でない。P3.4cの人工的な0／3／5／13ポイント等は製品閾値として採用していない。

- 固定元スキルファイルの**正確なSHA-256**と、4技能について元ID・名称・**Invoke数・preConditions・OR数・ANDの型／演算子／値**が期待通りである。
- 元のKotlinチェッカーで、`always`、`running_style`、`straight_random`、`near_count`、`accumulatetime`、`distance_type`、`is_lastspurt`、`phase_firsthalf_random`の実装が確認でき、近傍状態の近似も`SkillData.kt`から確認できる。

- **実発動率`null`、ユーザー向け適性ラベル`null`、サポカ得点`null`**のまま。出典欠測や書き換えは処理失敗にする。

## 次の採否判断

この4例だけで881件のラベル付けは決めない。**元ソース条件式で脚質間差が論理的に無いと判断できるスキル群**をまず限定的な肯定的汎用候補とし、**元の脚質制限だけのスキル**は適用範囲扱いとしたまま、相対ラベルへの二重表示を避ける。動的順位・近傍・スパートを伴うスキルには、同一文脈の比較機会の調査が必要かをユーザー価値に応じて選ぶ。

**まだ未決定**：元条件が軸非依存だと論理的に確かめられたケースを正式「汎用」として採用するゲートの条件、元実装とアプリデータの照合範囲、比較差の閾値、条件付きラベル表示とカード集約。実装へ進む前にユーザー判断の機会を残す。
