## 設計に直結する注意点

1. **「中盤前方」を脚質制限へ書き換えない**：局面・順位割合という独立した条件の組合せから「逃げ・先行寄り」を推測できる場合もあるが、ゲーム内の作戦固定とは区別する。
2. **「＜条件＞なし」を汎用と断定しない**：有効な元構造には `order_rate`、`phase_random`、他スキルの発動、その他の制限が存在し得る。認識語彙外の発動条件・シミュレーションが近似／無視する条件を含むときも「発動しやすい」の根拠にはならない。
3. **一つのスキルに複数の発動定義**：532件あるので発動定義単位のAND/OR・効果差を保持し、条件を雑に合算しない。
4. **追加効果と基本発動の区別**：複数 `invokes` が一律に異なる選択肢／追加効果だと断定せず、解釈ルールの正確性を次工程で検証する。
5. **出典の許可と検証**：構造抽出が成功しても、ゲーム内の現行仕様・発動率・追加効果の判定が合格したわけではない。UmaSimの近似・無視条件に注意する。
