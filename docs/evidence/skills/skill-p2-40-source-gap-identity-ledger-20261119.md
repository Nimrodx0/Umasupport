# P2.40：固定アプリ881スキルの出典ID照合不能理由を全件分類（2026-11-19）

## 目的とG1への寄与

[P2完了ゲートG1](../../plans/skill-conditions/p2.md#p2研究の完了ゲート2026-11-16確定) は固定対象を全件分類し、元スキル照合・未収録・未解釈の分母と理由を保存する。従来の固定881アプリスキル／818元効果・条件照合済み／63元出典未照合という合計だけでは、「元ID自体が見つからない」と「同じ数値IDの名称が矛盾した」と「通常ヒント名を一意に対応付けられない」を区別できない。

今回は現行[P1元条件照合器](../../../poc/src/skill_condition_profiles.js)が実際に使う **IDと正規化名称の一致規則**を再利用し、同一の固定現行UmaSim辞書と公開承認イベント用の固定辞書（[P0原典監査](../../../poc/tools/audit_skill_conditions.cjs)で取得する2出典）を入力とする、読取専用の[G1理由台帳](../../../poc/src/skill_p2_g1_source_gap_ledger.cjs)を追加した。別のスクレイパーや技能データの複製は行わない。

## 分類方式

- **照合済み**：ID/名称/出典がP1の元構造プロフィールと一致。元の現在辞書か固定辞書かも保持。ただし「元効果・条件構造がある」は **スキルのカード取得、全AND/ORの実発動、脚質適性**を証明しない。
- **数値IDが両辞書で見つからない**：元のゲームに存在しないとは扱わず、ID照合待ちにする。
- **数値IDはあるが名称が一致しない**：同名・異IDとともに危険な自動統合を避け、照合保留にする。元の名称原文を新たなレポジトリ成果物へは転載しない。
- **通常ヒント名が現行辞書で0件／複数件**：未照合と曖昧を区別。固定辞書の名前だけを使った類推はしない。
- **上記以外の非数値・非ヒントID**：出典IDが補えない理由を独立区分に残す。
- **一致するが元Activationの構造記録がない場合**：ID照合済みと元条件の利用不可を別に集計する。

各スキルのアプリ側ID、元数値ID（取得できる場合）、照合区分、出典のみを出力し、数値IDを基にしない推測補完は行わない。元スキル名・辞書本文はCI成果物へコピーしない。

## 機構・データの検証

- [合成テスト](../../../poc/tests/skill_p2_g1_source_gap_ledger.test.cjs)：ID未収録、同ID別名、同名複数件、現行名欠落、固定辞書からのみ照合、非対応ID、P1照合矛盾、重複行、非破壊を検査。
- [固定UmaSim全件CI](../../../.github/workflows/skill-condition-inventory.yml)：既存の `audit_skill_conditions.cjs` の構築したアプリと2辞書をそのまま使う。881行が重複・欠落なく分類され、従来の818照合／63未照合と整合することを検証し、`p2-g1-source-gap-ledger.json`を14日間のCI成果物として保管する。
- **固定出典の照合時に新たな数値差が出た場合は停止**し、元辞書とP1の挙動を再監査する。未照合理由の実測内訳はCI成功結果から更新する。

## 適用判断と終了条件

この工程の成果は、**G1の照合不能理由をスキルIDごとに追跡できるようにすること**に限定する。G1全件Passの認定、63件の元効果の補完、P2 G2～G4/G6の達成、P3・P4公開は行わない。元IDが見つからない／同名衝突の対象は、P3へ引き渡す際も「不明・要照合」とし、汎用・0点・取得不能のいずれにも自動変換しない。次に何を実際に照合すべきかは、固定CIの内訳と対象カードへの影響を見て選定する。
