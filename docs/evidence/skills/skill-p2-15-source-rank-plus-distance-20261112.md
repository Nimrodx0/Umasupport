# P2.15：スキル判定直前の「順位」と「走行進行率」を同一tickで結合する固定モデル研究（2026-11-12）

## 研究の目的とユーザー向けの意味

従来の元条件式の判定器では、GlobalSimの実レースから**走行進行率 `distance_rate`**だけを取り出して、元スキルのAND/OR・事前条件を評価していた。そのため、たとえば元条件が

```text
distance_rate >= 50 & order_rate <= 50
```

であっても、進行率は分かる一方、`order_rate` は未判定として残っていた。今回は、**同じ走者が、同じスキル判定の直前に何位だったか**を直接モデル内部から取得し、出典で説明されている9頭・12頭の順位割合換算を適用する。

例：9頭・`order_rate<=50`なら、9×0.50=4.5を四捨五入して**5位以内**と照合する。その場で進行率50%以上・順位5位以内の両方を満たして初めて、そのAND行を真とする。「レースの別時点では成立していたから」という理由で二つの条件を掛け合わせない。

**重大な区別**：固定版UmaSim自身のSkillCheckerは `order_rate` を**「順位条件は無視」**と扱い、元スキルの実発動条件をすべて再現しているわけではない。今回の順位の境界は[9頭・12頭の換算根拠](skill-order-rate-integer-mapping-20261106.md)に基づく**GameTora解説・GlobalSimと整合する資料上の解釈**である。元UmaSimの順位判定を「直接実測した」ことや、現行の日本版ゲーム内部条件を実証したことにはならない。

## 一次資料・観測機構

- UmaSimの元技能辞書：`mee1080/umasim@f6e4501ee6c6c2d4ac8698e7796e309d31575bde`、元辞書SHA-256 `4c036527bbe6b5aad34d7f12110a06094c9071514e37fdfc68ae195403333be5`。条件式のInvoke/OR/AND/事前条件は元の構造を保持。
- GlobalSim v77：`daftuyda/GlobalSim@80b54cacf174b54ff6f7ca27ee7f88b5856c0bd1`。元`src/race_field_retail.rs`の `for priority in [1, 0]` から `process_skill_priority` を呼ぶ直前の `field.order_of(i)` を読む。順位キャッシュは `src/race_field.rs` の `update()` で1始まり順位として計算される。
- 計測方法：**同じ元ソースから3バイナリを独立ビルドする**。無改造の元エンジン、先行研究の「スキル判定直前の走行位置」観測版、別の先行研究の「スキル判定直前の内部順位」観測版。順位・位置の計測用Rust変更は互いに混在させず、技能発動処理も物理計算も触らない。
- 固定した8レース（9頭または12頭）を、同じシード・同じ走者・同じ装備なし状態で3回走らせる。元版と2つの観測版の位置・速度・体力・レーンが**全件同一**でなければ停止する。順位もpriority=1と0で一致し、前tickの更新後キャッシュとつながることを確認する。
- モデル順位と元条件式の接続には[順位の出典付き境界換算](../../../poc/src/skill_order_rate_bounds.cjs)を使用する。**GameToraに基づく9頭・12頭の範囲だけ**を使い、他の頭数・0位境界等は保留する。
- 同じ走者・同じ時刻の `distance_rate` と `order_rate` の成立・不成立を、[三値AND/OR判定器](../../../poc/src/skill_source_whole_tick_monitor.cjs)に一緒に渡す。`phase_random`、追い抜きなど観測できない条件は引き続き**未判定**。
- [前工程の1スキル×1走者×1レース集約](skill-p2-15-race-runner-opportunity-20261112.md)を再利用し、今回の追加観測によって「一度でも条件式が成立したモデル走行」「条件が不明で評価保留のモデル走行」がどれだけ変わるか、**同じ固定8レースの順位結合前後**で比較する。

## 検証・成果物

[独立した3エンジン＋元条件式の同tick研究用CI](https://github.com/Nimrodx0/Umasupport/actions/workflows/p2-source-rank-distance-real-ticks.yml)、[順位の照合器](../../../poc/src/skill_source_rank_tick_bridge.cjs)、[独立比較プログラム](../../../poc/tools/globalsim_p2_15_source_rank_distance_ticks.cjs)を作成。

CIでは **(1)** 9/12頭の順位境界と元演算子 **(2)** priority=1/0時刻一致 **(3)** 前tick順位キャッシュと現在の観測のつながり **(4)** 3エンジン物理値同一 **(5)** 同じ元スキル条件式に情報を追加しても、従来「成立」と確定していたものを「不成立」に反転させないこと **(6)** スキル・脚質・コースごとの同じ母数の維持 **(7)** 未判定のまま残る追加条件の保持、を検証する。

**これは元のスキル全2,162件を今回すべて再測定する工程ではない。** まず前回と同じ `distance_rate` 対象の253スキルを母集団にして、順位条件を追加する前後の差を厳密に測る。元ゲームの発動率や独立した実レースでの発動しやすさはこの段階では測定できない。

固定CIの数値結果を確認後に、対象スキル数・追加で解決した未判定・脚質内訳を記録する。出典技能辞書そのものをGitHubへ同梱しない。

## 未検証事項

- 元UmaSimが `order_rate` を無視する点、実ゲームの仕様と異なる可能性、GlobalSimの独立モデルである点。
- 先行研究で未観測のランダム窓・追い抜き履歴・複雑な事前条件・技能を装備した場合の挙動・クールダウン。
- 固定8レースの偏った脚質構成と試行数。集計対象は独立した実ゲームレースではない。
- **脚質別の「発動条件の満たしやすさ」の正式評価、サポカ採点、P4公開UIへの採用は引き続き保留。**
