# P2.15：UmaSim由来の全条件式を時系列で判定する三値論理の基礎（2026-11-12）

**位置づけ**：これは**元スキルの全条件の論理構造を失わず判定する基礎処理**であり、GlobalSim等の動的レース実測を結合した「実際のスキルの発動条件の満たしやすさ」の完成ではない。正式P3サポカ適性、スキル発動確率・効果有用性、P4 UIは未変更。

## 一次資料

固定UmaSim：`mee1080/umasim@f6e4501ee6c6c2d4ac8698e7796e309d31575bde`。

- `data/skill_data.txt`：SHA-256 `4c036527bbe6b5aad34d7f12110a06094c9071514e37fdfc68ae195403333be5`。**原文・全条件レコードはリポジトリへ同梱しない**。
- `race/src/commonMain/kotlin/io/github/mee1080/umasim/race/calc2/SkillChecker.kt`：ORの各行がAND、OR行が空なら真。事前条件 `preChecked` は真になった後、次のtick以降も保持される。これは元コードから確認した挙動であり、全スキルが同じ条件を持つという意味ではない。
- 参照実装は**対応しない述語の検査関数を `mapNotNull` で除外できる**が、ウマサルタントの研究用判定器では実測できない述語を勝手に真とせず、**未判定**として保持する。この安全側の扱いは元コードの完全再現とは区別する。

## 実装

[三値・時系列判定器](../../../poc/src/skill_source_whole_tick_monitor.cjs)と[回帰テスト](../../../poc/tests/skill_source_whole_tick_monitor.test.cjs)を追加した。

- 真／偽／不明でAND・ORを評価し、**同じtick**で複数条件が成立したときだけそのAND行を真にする。欠測は偽にも真にも変換しない。
- `conditions` のOR行と `preConditions` のOR行を別々に保持する。事前条件が以前のtickで真になった場合は、以後のtickで再び偽でも記憶を保持する。過去の欠測がある場合も後日の偽だけで消さない。
- 複数Invokeの判定は別記録に分け、少なくとも1つのInvokeの条件が真となった場合に**条件式の論理上は真**とする。ただし技能発動・クールダウン・他の効果を含む**技能自体の発動成立とは主張しない**。
- 明示的静的値として照合するのは `running_style`, `distance_type`, `ground_type`, `ground_condition`, `track_id`。後者は**個別のコースIDではなく競馬場ID**である。
- `order_rate`, `phase_random`, `is_overtake` などの動的条件は、**Invoke番号・conditions/preConditions・OR行・AND要素番号・条件コード・演算子・値が一致する**個別観測がある場合に限って使用する。ない場合は未判定。
- 入力の矛盾、重複、条件違い、順序違いは拒否し、未知の状況を汎用スキルや低適性へ変換しない。
- 判定結果の `true` は**指定した実験入力に対する条件式の成立**であり、ゲーム内のスキル発動・確率・適性ラベルではない。
