# P2.15：GlobalSimで観測したスキル判定直前の位置からUmaSim由来の `distance_rate` 条件を照合（2026-11-12）

**位置づけ**：元の条件式を保った[三値時系列判定器](../../../poc/src/skill_source_whole_tick_monitor.cjs)へ、**GlobalSimの実レース（固定人工モデル）で取得した動的情報を初めて直接入力する研究用の限定工程**。元スキルのゲーム発動確率や脚質・距離・馬場適性の確定ではない。

## 元資料・意味上の注意

- 元技能辞書：`mee1080/umasim@f6e4501ee6c6c2d4ac8698e7796e309d31575bde` の `data/skill_data.txt`。SHA-256 `4c036527bbe6b5aad34d7f12110a06094c9071514e37fdfc68ae195403333be5`。
- 元 `SkillChecker.kt` の `distance_rate` 条件は、レース内の `(simulation.position * 100.0 / baseSetting.courseLength).toInt()` と元述語の演算子・値を比較する。JavaScriptでは `Math.trunc` で同じ整数切り捨て方針を表現する。
- 重要：固定版UmaSimの `race/data2/SkillData.kt` は、`order_rate` を **「順位条件は無視」** と定義している。条件式自体に順位が記録されていても、UmaSimの元 `SkillChecker` だけではゲーム上の順位条件成立を証明できない。元条件式の研究では **無視された条件を「真」へ置換せず未判定**とする。
- GlobalSimのスキル判定直前の位置はGlobalSimにおける観測値であり、UmaSim自身の `simulation.position` や実ゲームのレース状態と**同一であると証明されていない**。今回の結果は元コードの算式をモデル位置へ適用した**研究上の変換結果**である。

## 方法

[実測結合器](../../../poc/tools/globalsim_p2_15_source_distance_rate_ticks.cjs)は、次の順序で判定する。

1. CIでピン留め版元技能辞書と元Kotlinコードを取得し、辞書のSHA-256と技能検査式の元コードの文字列を照合する。外部データはレポジトリへ同梱しない。全元スキルの中から `distance_rate` を条件として持つものを、Invoke・条件行・事前条件の位置まで保持して選ぶ。
2. 元版GlobalSimと、既存の[位置読取専用プローブ](../../../poc/tools/globalsim_p2_15_preskill_phase_position.cjs)を適用した計測版を別々にビルド。固定8レースでは**すべてスキルを未装備**とする。全フレームの位置・速度・体力・レーン、スキルイベント、シードが一致しなければ停止する。
3. スキルの `priority=1` と `priority=0` の実呼出し直前位置が一致し、前フレームの移動後位置とも完全一致することを検査。その実測位置を元の `distance_rate` 算式へ入力し、演算子と閾値まで元記録から照合する。
4. GlobalSimの初期化フレーム（t=0）では技能判定直前の状態を計測できないため、その時点以前に成立したかもしれない事前条件の履歴は**不明から開始**する。以後、事前条件の成立が確認できれば真へ更新するが、欠測前の成立を「なかった」と決めつけない。
5. 進行率の整数境界から `1e-6` 以下、走行前またはゴール到達後の位置は、異なるエンジンの浮動小数点表現による曖昧さを避けるため未判定とする。条件の `conditions`・`preConditions`、複数Invokeを三値時系列判定器へそのまま渡す。
6. 静的項目のうち固定モデルの脚質、距離区分、芝・ダートだけを供給する。競馬場IDや馬場状態、順位、乱数窓、追い抜きなどは、今回のモデル観測と元の対応を確認していないため**未判定**。同じ個体・同じ判定時点で未確認の追加ANDがあれば、スキル全体を高適性へ昇格させない。

## 次に残るゲート

- 追加条件型（順位・局面・ランダム窓）に元条件と検証可能な同判定時刻観測を用意し、AND全体を判定する。
- `preConditions` と複数Invokeのゲーム動作、発動制限・クールダウンについて元実装との一致を検証する。
- 距離・馬場は明示範囲と非明示的な成立傾向を区別し、正式3軸適性とP3カードへの集約には独立の採否判断が必要。
