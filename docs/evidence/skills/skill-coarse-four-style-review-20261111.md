# P2：既存の根拠だけで全スキルの「大まかな脚質適性」を一覧化（2026-11-11）

**状態：P2研究用の全881スキル四脚質プレビューを実装・固定元データで検証。スキル全体の実発動率、高／中／低の正式区分、P3のカード評価やP4の画面は未変更。**

## 目的と簡素化した考え方

本来の目的は、細かなレースエンジンの再現ではなく、**スキルごとに逃げ／先行／差し／追込のどれが比較的発動しやすそうか**を大まかに知ること。すでにある[P1の明示条件解析](../../../poc/src/skill_condition_profiles.js)、[P2の4脚質均衡編成モデル比較](../../../poc/src/skill_balanced_four_style_fit.cjs)、[既存6状態評価](../../../poc/src/skill_activation_fit_v1.cjs)を組み合わせるだけにとどめた。

新規の順位物理モデル、新しい発動確率式、未合意の高／低閾値、点数の加重、学習モデルなどは**追加しない**。追加したのは[単一の簡易評価結果集約器](../../../poc/src/skill_coarse_style_review.cjs)だけ。

各スキルについて、4脚質の各セルを以下の**根拠の種類**で区別する。

| 分類 | 意味 | 注意 |
| --- | --- | --- |
| 明示条件で発動不可 | 元スキルの構造化された `running_style` が、その脚質を全経路で排除 | タグやモデル0%からの推測は使わない |
| 4脚質別の順位傾向 | 均衡編成の固定モデルで、元順位帯・局面に一致する条件について4脚質を比較可能 | **モデルの順位条件の傾向**であり、スキル全体の発動率とは違う |
| 順位条件だけの部分傾向 | 元の順位比較が分かるが、同じANDに追加契機、あるいは別OR経路が残る | **部分情報**のまま。スキル全体の高／低を出さない |
| 旧2群の参考傾向 | 4脚質モデルの完全一致はないが、先行研究の逃げ・先行／差し・追込の比較はある | 4脚質を個別に順位付けしたかのように扱わない |
| 確認済み条件に脚質差なし | 確認済みAND条件がレース全体の共通条件だけ | 実ゲームで全脚質が同じ発動率だという測定ではない |
| 判断保留 | 比較できないAND、局面・順位帯、複数経路など | 保留は汎用や低適合と同義ではない |
| 元条件未照合 | 固定元辞書とアプリのID・名前が一致しない | 既存の63件を埋めたことにはしない |

## 固定の全881スキルで得られたカバー範囲

[固定UmaSim元スキル監査CI](https://github.com/Nimrodx0/Umasupport/actions/runs/42931343547)で、アプリ収録881件中818件が元辞書とID・名称で照合済み。**63件は元条件が未照合**。全スキル×4脚質＝3,524セルを実際のデータから生成した。

| 根拠区分 | 4脚質セル数 | 少なくとも1脚質に該当したスキル数 |
| --- | ---: | ---: |
| 明示条件で発動不可 | **859** | **291** |
| 4脚質別の順位比較根拠 | **197** | **77** |
| 追加AND/ORを残した4脚質順位の部分情報 | **12** | **6** |
| 旧2群だけの参考傾向 | **120** | **30** |
| 確認済みレース共通条件だけ | **484** | **121** |
| 判断保留 | **1,600** | **584** |
| 元条件未照合 | **252** | **63** |
| **合計** | **3,524** | スキル側は重複するため加算禁止 |

**注意**：右列は「当該状態が1脚質以上にあるスキル」の重複集計。たとえば明示脚質制限で一部の脚質が発動不可でも、許容された脚質の他の条件は保留かもしれない。77件の「4脚質別の順位比較根拠」も、全77件が4脚質すべて一意に順位付けできたという意味ではない。順位帯の比較保留をそのまま残している。

## なぜこれで十分に前進と言えるか

- **個々のスキルを入口にして**4脚質の根拠がある部分を取り出せた。先行の53件限定レビューから、881件すべてのどの部分を説明でき、どこで止まるかを機械的に一覧化できる。
- 4脚質比較の方向が明確な一部条件（例：[中盤40～80%の順位帯](skill-position-balanced-four-style-rule-20261106.md)）は、旧2群に潰さずに区別できる。
- 追加ANDやORの複雑さを完全に再現するまで「何も分からない」とはせず、**どの部分条件の目安なのかを明記して提示**できる。
- 既存のルールで説明できないスキルが多いことも実測できた。これを理由に、残る条件のための複雑なレース計測器を際限なく作るのは避ける。

**実データ全件のプレビュー**は[条件在庫CI](https://github.com/Nimrodx0/Umasupport/actions/runs/42931343547)の成果物 `p2-coarse-four-style-skill-review-not-product`（14日保持）に格納。元辞書本文や改造エンジンを再配布しない。機能の回帰は[人工ケースのテスト](../../../poc/tests/skill_coarse_style_review.test.cjs)で検証。

## 次に実施すべき最小限の工程

**P2で延々と計測を追加するのではなく、実際の利用での判断に近づける。** まず数スキルを選び、研究専用の簡易4脚質結果とゲーム内での常識的な解釈の違和感をレビューする。明示不可・モデル順位傾向・未検証条件・保留の区別が伝わるなら、**P3のスキル→サポカ集約の最小データ契約**を検討する。必要な条件が明確に存在した場合にだけ、対象条件に絞って追加研究を行う。ソースの125種すべてを忠実にシミュレートすることを完了条件にしない。

**禁止する短絡**：順位差やモデル順位帯占有率を、実発動確率・獲得率・スキルの強さ・効果の有用性・カード適性に自動変換しない。脚質の明示不可と単なる不利を同義にしない。
