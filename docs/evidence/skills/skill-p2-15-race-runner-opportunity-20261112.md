# P2.15：元スキルの条件成立機会を「1レース×1走者」単位で保留付き集約（2026-11-12）

**今回の工程**：[前工程の `distance_rate` 実測結合](skill-p2-15-source-distance-rate-real-ticks-20261112.md)に対し、従来の「スキル×走者×判定時刻の三値結果」を、**各スキルについて各走者が一つのモデルレースで一度でも条件式を満たしたか**へ変換する。元スキル全条件の研究用観測であり、**実ゲームの発動回数・確率や正式な脚質適性の判定ではない**。

## なぜこの変更を行うか

例えば同じスキルを仮に持つ1人が1レースの中で100回の技能判定機会を得たとする。

- 100回のうち1回だけ全条件式が「真」だった場合：**その走者のそのレースには、観測区間中に一度以上の成立機会があった**。
- 100回とも真であった場合：上と**同じ1件**の「一度以上成立したレース・走者」として扱う。時刻ごとの真100回を100レースに数えない。
- 100回中1回も真がなくても、不明が残る場合：**未判定の1件**。不成立として数えない。
- 100回すべて偽だった場合：**観測できたモデルの判定時点では一度も成立しなかった1件**。ゲーム全体で不可能だったとの断定ではない。
- 技能判定直前を一度も観測できなければ、母数に残したまま**未観測**とする。

今回のモデルでは、一つのレースに同じ脚質の走者が複数いる。これは「同じ脚質について複数の**走者×レース**」の観測であり、独立なレースが同数あったという意味ではない。

## 方法とデータの意味

[レース・走者単位集約器](../../../poc/src/skill_source_race_opportunity.cjs)を新設し、[元条件の同判定時点結合器](../../../poc/tools/globalsim_p2_15_source_distance_rate_ticks.cjs)へ接続した。固定UmaSim元技能辞書の `distance_rate` 対象253件と、スキル未装備GlobalSim v77の固定8モデルレースに限定する。

1. スキルの発動条件式のAND・OR・複数Invoke・事前条件履歴は[従来の三値判定器](../../../poc/src/skill_source_whole_tick_monitor.cjs)で保持する。
2. 走者ごとに、同じレースの実際の技能判定直前時点をすべて通し、「成立」「不成立」「未判定」を蓄積する。順位・乱数・その他の未観測述語は**不明**のまま残す。初期化時点 `t=0` で観測できていない事前条件履歴は**不明で開始**する。
3. レース終了時に、各**元スキル×実験レース×走者**を以下の相互排他的な区分へ分類する。

| コード | 意味 |
| --- | --- |
| `observed-at-least-once-true` | 計測したモデルの技能判定時点で、スキル全体の元条件式が1回以上真になった |
| `observed-unknown-without-true` | 真は確認できず、少なくとも1つの判定時点で元条件式が不明だった |
| `observed-all-false` | 計測できた技能判定時点では全て偽だった。ただし実ゲームでの不発動確定ではない |
| `no-observed-priority-ticks` | その走者の技能判定直前時点を1回も観測できなかった。欠測を偽にしない |

4. 253技能それぞれについて4脚質で集計し、さらに**コース・距離区分・芝ダート・頭数・相手脚質編成・人工能力設定**を区別した内訳も持つ。走者が不在の脚質は割合0ではなく母数なし（`null`）となる。
5. 観測された技能判定時点だけを対象として、記述的な区間：
   - 下側 `confirmed / runnerRaceTrials`
   - 上側 `(confirmed + unresolved + no-observed) / runnerRaceTrials`
   を出す。**これは元の実ゲーム1レース中の発動条件成立確率の上下限でも統計的信頼区間でもない**。元モデルで実際に観測した技能判定時点に限った、未判定を残す集計上の幅である。脚質別でこれらの数値を比較して正式適性を付けない。

## 検証

[専用CI](https://github.com/Nimrodx0/Umasupport/actions/workflows/p2-source-distance-rate-real-ticks.yml)に人工レース×走者の重複チェック、AND/ORによる判定結果との一致、各走者の判定時刻数の保存、脚質・レース文脈別の母数一致を追加する。成果物は元条件原文を配布せず、固定出典での研究集計だけを保持する。

- 「100tickで真1回」と「真100回」を同じ「1走者×1レースで一度以上成立」と数えること。
- 未判定を偽に置き換えないこと。0tick走者を消さないこと。
- 同一レースに同脚質の走者が複数いても「レース数」を水増ししないこと。
- モデル対照版と計測版で位置・速度・HP・レーンの値が完全一致すること。
- `raceOpportunity.totals`、4脚質別、技能別、コース・編成別の件数が一致し、未照合スキルへの適性ラベルが全て `null` であること。

## 固定モデルでの再集計

[初回の独立した8レース実行CI #43186678805](https://github.com/Nimrodx0/Umasupport/actions/runs/43186678805) **PASS**。対象は固定UmaSim辞書の`distance_rate`条件を持つ**253スキル**、GlobalSim v77の固定8無技能レース（合計84走者×253スキル）。元版と計測版の位置・速度・HP・レーン**437,532／437,532値が完全一致**し、従来の元条件式の時刻別「成立」171,509判定とも整合した。

| 研究用「1スキル×1走者×1モデルレース」の判定 | 件数 |
| --- | ---: |
| 観測区間で1回以上成立した | **734** |
| 成立を確認できず、不明が残る | **16,579** |
| 観測した時刻はすべて不成立だった | **3,939** |
| 観測できた技能判定時刻がゼロ | **0** |
| **計** | **21,252** |

4脚質ごとの研究値（同じスキルを**各走者へ仮に割り当てた**結果、脚質別の独立レース件数ではない）：

| 脚質 | 走者×スキル×レース件数 | 一度以上成立 | 不明あり | 観測時刻は全て不成立 |
| --- | ---: | ---: | ---: | ---: |
| 逃げ（Nige） | 3,542 | 98 | 2,695 | 749 |
| 先行（Senkou） | 4,554 | 207 | 3,627 | 720 |
| 差し（Sasi） | 6,578 | 247 | 5,161 | 1,170 |
| 追込（Oikomi） | 6,578 | 182 | 5,096 | 1,300 |
| **計** | **21,252** | **734** | **16,579** | **3,939** |

**この表から脚質の優劣を付けることはできない。** 脚質ごとの走者数が違い、各スキルの明示適用範囲が違い、人工レースの母集団も狭く、しかも不明が大半を占める。成立734という値は、1回以上元条件式が真になった**モデル上の走者トレース**であり、ゲームで734回発動した意味ではない。観測時刻全偽3,939も、元ゲームの1レース全体で発動不可能だったという意味ではない。

結果と集約器の検査項目はCI成果物の[出典固定研究用JSON（14日間）](https://github.com/Nimrodx0/Umasupport/actions/runs/43186678805/artifacts/13928279722)に保存。最新のmainへ統合する際は、新規CIによる同じ固定シード・ソース・集計の再現を確認する。

## まだできないこと

**今回の4脚質別数値は、モデル観測区間における`distance_rate`を結合した元スキル条件式の研究値であり、ゲーム発動率ではない。** 特に元UmaSimは順位条件 `order_rate` を判定せず無視するため、順位・ランダム区間など元条件の意味に合う追加観測が重要である。

8レースは人工編成であり、現実の対戦相手分布や代表的なレース条件ではない。条件式を判定しても、発動判定・クールダウン・スキル装備時の挙動変化・元UmaSimとGlobalSimの違いは解消しない。

**P2研究限定。P3カード適性、P4公開UIへは転送しない。**
