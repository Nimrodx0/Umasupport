# P2.33：元スキル同一IDを固定した芝ダートの条件付きWモデル接続（2026-11-17）

**進捗：固定UmaSim元スキル辞書とGlobalSim部分条件Wを同一CIで照合し、82候補の全てに条件付きモデル参照が存在することを確認（2026-11-17）。** 本工程は同一元スキルを装備してUmaSimの元JVM判定tickで全条件を満たすことや、実ゲームで発動したことを直接測ったものではない。

## 背景と対象

[先行研究](skill-p2-33-shared-surface-mechanism-20261117.md)では、固定モデルの芝・ダートで順位帯と時期条件が共通の4機構（960比較）を検査した。ただし、その4組の芝側・ダート側の**元スキルIDは異なる**。一方、固定元スキル818件・970経路から同じ機構を含み両馬場に静的矛盾のない88スキルを抽出し、単一Invoke・単一OR・履歴事前条件なしなどの単純な82スキルを確認した。

本実装は[元スキルIDと条件式の選別器](../../../poc/src/skill_p2_33_same_id_projection.cjs)により、上記82候補を**元スキルIDごと**に、元のconditions ANDに含まれる静的制限（`running_style`・`distance_type`・`ground_type`・`ground_condition`）と、順位帯・発動時期条件に分離して調べる。1つでも未扱いの追加動的AND、複数Invoke、複数OR、履歴preConditions、固定競馬場 `track_id` がある場合は無条件で投影対象から除外する。

## 比較の定義

1. **元スキル同一IDの確認**：元UmaSim固定スキル辞書とアプリのskill ID・名称・元条件を照合し、芝・ダートで**同一スキルIDと同じ元AND**を対象にする。過去の部分条件の芝側・ダート側の**異なる証人ID**はWの元機構記録としてのみ参照し、今回のスキルIDの代わりに使用しない。
2. **同一静的文脈の厳密な確認**：脚質、距離種別および馬場状態を両馬場で揃え、元の演算子・数値で現在のconditions ANDの静的部分が**両馬場で満たせる**場合に限り対象とする。候補スキルが実際の馬場状態でどれだけ出走するかは測定していない。
3. **モデルの動的な一部分の再利用**：固定GlobalSim v77の[同一順位・時期機構芝ダートW](skill-p2-33-shared-surface-mechanism-20261117.md)を、同じ機構・脚質・距離・相手編成・頭数・能力モードに紐づける。元30シード／前後15シードの機構W下限・上限／保守的な方向をそのまま残す。異なる元スキルで採られたW機構の比較を**当該同一IDスキル自体の元判定実測**へ昇格させない。
4. **出力は研究専用**：対象82スキルのIDと元分岐位置、静的許容文脈、モデル部分条件Wの引用・分割結果・誤用を防ぐステータスのみ。元スキル辞書全文、サポートカード評価値、適性ラベル、ゲーム発動率、全元ANDの成立率は生成しない。

[同一CIでの実行入口](../../../poc/tools/audit_p2_33_same_id_projection.cjs)は既存の[固定モデル研究ワークフロー](../../../.github/workflows/p2-source32-split15-w.yml)を用いる。CIで元UmaSim技能辞書・カード辞書・過去の技能辞書を固定SHA確認し、アプリ881技能（元一致818／未一致63）を再構築して元のANDを評価する。モデル側は同ワークフローでフル30と前後15シードを再生・固定元結果と照合済みの部分条件Wを受け取る。第三者の生データ本文はこのレポジトリへ同梱しない。

## 解釈上の重要な限界

「同一元スキルIDで芝とダートの条件に静的矛盾がないこと」と、「そのスキルの順位×抽選窓の**モデル上の部分機会W**を対応付けられること」までを区別して報告する。**元UmaSimの判定ループにその同一元スキルを装備した実測、同一tickの順位／抽選窓のAND成立、発動率の検証はまだ行っていない**。つまり、これを「同一スキル発動率の芝ダート直接比較」と呼ばない。

固定モデルの芝とダートは距離区分・脚質・能力モード・相手編成・頭数を揃えるが、実コース形状は同一ではない。東京1200m対照でも競馬場と距離しか固定できず、馬場そのものの因果効果は未識別である。両分割で5ポイント超のモデル差が出ても、それは正式な実用差閾値ではない。82スキルそれぞれにWを紐づけて行数が増えても、**独立したモデルレースや元スキルの独立発動数が増えたことにはならない**。

## 固定元出典での実測確認（2026-11-17）

[固定元GlobalSim＋UmaSim技能辞書CI #44002533986](https://github.com/Nimrodx0/Umasupport/actions/runs/44002533986)で、固定30シードと15＋15シードの復元、元スキル辞書のSHA確認、元818技能とアプリ側照合、同一元スキルID静的ANDの判定、部分条件モデルWとの結合まで**成功**した。新しいレースは生成していない。モデルWの元データは依然として異なる芝／ダート証人スキルIDの共通順位・時期条件であり、その**同じ判定機構だけ**を元の候補82スキルの元条件式へ研究用に再利用する。

| 研究項目 | 検証結果 |
| --- | ---: |
| アプリで元効果・条件を照合済みのスキル | **818件**（固定881件中） |
| 単一Invoke／単一OR／履歴preConditionsなし／追加動的ANDなしで、芝ダート両面の元静的条件を共有する元スキル | **82スキル** |
| うち固定順位・時期機構Wを少なくとも1文脈参照可能な元スキル | **82スキル** |
| 同一元ID・同じ脚質・距離・馬場状態の静的許容に基づく**スキルID別のモデル部分W参照** | **5,624件** |
| 上記5,624参照の実際の**重複除去後の元モデルW文脈** | **960件** |
| 5,624参照のうち元モデル30シードで保守的なW区間が分離 | **2,501件** |
| 前半15・後半15シードの双方でも同方向の部分W参照 | **977件** |
| うち仮5ポイント超の方向を両分割が確認 | **22件** |
| 元スキルそのもののJVM全条件成立実測・発動実測・P3適性採点 | **全て0件** |

**分母の注意**：5,624はスキル82件が同じ元モデル文脈960件をそれぞれ許容する部分へ投影した延べ数である。977件も**同じ元機構の観測を複数スキルIDに再利用した参照数**であって、977の独立したモデルレースや元スキル発動、統計的な有意差ではない。独立性を仮定して一般的な芝ダート適性差に変換しない。仮5ポイントは正式な閾値ではない。

**元スキルIDの保持**：元スキル `200541`、`200542` なども、両馬場で同じIDの元静的ANDが満たし得ると判定した例に入っている。一方、全条件の元JVM同時判定は一切観測しておらず、実ゲーム発動率やP3正式スコアは引き続き未知。静的条件がある程度成立し得ることを「モデルW全体が当該スキルの発動条件成立率」と呼ばない。

## CI結果とP2完了ゲートへの接続

今回の元条件式とモデル部分Wの同一ID投影は成功したが、**元スキルを装備した同一tickの全AND・ランダム窓抽選の実測**はまだ行っていない。未観測の条件は未知として残す。

**P2完了ゲートG5は未Pass**。次工程では今回静的条件とモデルWを対応付けられた元スキルから代表例を選び、実際に**同じスキルIDで元UmaSimランダム窓・順位を同一tickに観測**できるように実行系を追加し、完全なANDまたは未観測理由を明示する。今回の部分WはP3採点やP4公開へ出さない。
