# P2.15：装備済みGlobalSimの条件成立とモデル技能イベントの走者×レース照合（2026-11-12）

## 目的と先行研究

[3技能の実抽選窓・判定直前順位AND研究](skill-p2-15-equipped-phase-rank-conjunction-20261112.md)では、固定GlobalSim v77の8人工レース・84走者について、3技能の有効窓210件、窓内1,512走者・tick、元モデル明示AND成立1,383走者・tick、元モデル技能イベント173件を**別々に**確認した。元モデルの条件が一度以上成立した技能×走者×レース191件と、173件のイベントを単純に引き算して「18件が発動しなかった」と結論することはできない。イベントが同一技能・同一走者に重複した可能性や、判定時刻のずれを調べる必要がある。

本研究は、まず**同じモデル技能×同じ走者×同じレースという単位に限って**元モデルAND成立の有無と元モデル技能イベントの有無を対応付ける。イベント時刻とスキル判定直前tickの因果的な同時照合、クールダウンや発動抽選の再現ではない。

## 実装

- [集計器](../../../poc/src/skill_equipped_phase_model_and.cjs)が既存の3独立GlobalSimビルドによる物理状態・技能イベントの完全一致を前提に、元モデルに実際に装備したID `200451`、`200501`、`200701`のみを、技能×走者×レースごとに結合する。
- **同じ技能のAND成立が観測され、モデル技能イベントも存在**、**AND成立が観測されたがイベントは不在**、**観測したAND成立はないがイベントは存在**、**観測したAND成立もイベントも不在**という4区分を保存する。
- 同じ技能×走者×レースの技能イベントが複数あった場合、4区分の母数は**1件**、`modelSkillEvents`は**元のイベント発生件数**として別々に集計する。`runnerRacesWithRepeatedModelEvents`に重複単位を残す。
- 元の窓が有効・無効予約（9999m）・詳細不在かを消さずに保持し、ANDが観測されなかった事例を「ゲームで条件不成立」とはしない。
- 全体・元技能別・4脚質別で、4区分の和が技能×走者×レース母数と一致すること、AND有無の和が元のAND成立走者×レースと一致すること、イベント件数の分割和が元の技能イベント数と一致することを検査する。
- [専用テスト](../../../poc/tests/skill_equipped_phase_model_and.test.cjs)で人工の重複イベント、観測ANDなしのイベント、別走者への誤割当、独立プローブ間のイベント差異・物理値差異を確認する。[固定3エンジンCI](../../../.github/workflows/p2-equipped-phase-window-and-rank.yml)で同じ8レースの出典固定実モデル値を再計測する。

## 結果の解釈

4区分は **「同じモデル走者がそのレースで、条件成立を観測したか／イベントを記録したか」** を表す。同一tickでの対応や、一方が他方の原因だという証明ではない。観測できない初期tick、技能発動済み・再発動制限、内部スケジュールをまだ分解できないため、特に「ANDなし＋イベントあり」のセルは監査対象として保持し、データ不整合・実ゲームの反例と即断しない。

**観測したAND成立走者×レース、モデル技能イベント件数、モデルイベントを持つ走者×レース、元UmaSimの発動確率はそれぞれ異なる単位である。** 集計表の4区分をそのまま独立なベルヌーイ試行や実ゲーム発動率・脚質適性へ変換しない。脚質別内訳も8人工レースの条件に依存する。

## 成果物と未完

本研究の対象は固定GlobalSimの元3技能だけで、元UmaSimの`phase_random`102スキル／371経路の動的全条件を直接実測したわけではない。元スキル・抽選法との対応、技能イベント時刻の判定直前状態との厳密照合、元UmaSimや日本版ゲームでの発動確率、P3カード採点、P4公開UIは**未完・未採用**。

実数値の確定には専用GitHub Actionsによる再実行を要する。CI実測が未確認の段階で新たな4区分の件数を本文には記載しない。
