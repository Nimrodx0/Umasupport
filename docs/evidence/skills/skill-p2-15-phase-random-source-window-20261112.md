# P2.15：`phase_random` の元ソース抽選窓とAND/OR経路の監査（2026-11-12）

**検証の範囲**：固定UmaSimの`phase_random`による抽選**区間の構造**を、アプリの元スキル条件に対応させて監査する。**モデル走者がその窓に入ったか、複数条件の同一時刻成立、実スキル発動、4脚質の正式適性のいずれも測定していない。**

## 調査の動機と位置づけ

[P2.15の全元AND/OR監査](skill-p2-15-full-path-gate-audit-20261111.md)と[未測定条件型ごとの研究候補](skill-p2-15-blocker-impact-20261111.md)では、固定元818スキルのうち102スキル／315脚質セルで、少なくとも1経路の**未研究条件型が`phase_random`の1種類**のみだった。ただし「未知の**型**が1種類」は「条件式が1個」「元の他AND条件をすべて実際に判定した」という意味ではない。

今回の[独立監査器](../../../poc/src/skill_phase_random_source_window_audit.cjs)は、モデルに推測で高／低を付けず、`Invoke × conditions OR × preConditions OR × 4脚質`の候補経路へ、固定参照コードに対する構造的な解釈を追加した。

## 固定版の元実装から検証した意味

参照：`mee1080/umasim@f6e4501ee6c6c2d4ac8698e7796e309d31575bde` の[SkillChecker.kt](https://github.com/mee1080/umasim/blob/f6e4501ee6c6c2d4ac8698e7796e309d31575bde/race/src/commonMain/kotlin/io/github/mee1080/umasim/race/calc2/SkillChecker.kt)。この固定ファイルをCIで取得し、以下の各コード経路の存在を検査。内容が変われば研究結果を生成せずに停止する。

1. `phase_random`条件は値で指定された局面の`initPhaseRandom(value)`を通り、局面開始から終了までの範囲を使う。局面番号を単純に比較する条件ではない。
2. 抽選位置は`RandomPosition.RANDOM`の一様乱数から選び、開始を`zoneEnd-2m`で上限制御、終端を`min(start+10m,zoneEnd)`に切り詰める。
3. `checkInRandom`は抽選した区間をキー付きでキャッシュし、**その走者の現在位置が区間内か**を判定する。順位条件や別のANDをこの分岐単独で照合するものではない。
4. この固定参照コードの`phase_random`分岐内では、元データの演算子を明示的に比較していない。監査では演算子・数値をそのまま保ち、今回の研究対象は**`==`かつ局面IDが0〜3**のみに限定する。別の演算子・数値が現れた場合、意味を補正せず保留する。

判定窓の元コードと、[以前のW・O実験](skill-position-phase-random-opportunity-20261107.md)で幾何学的に比較した10m範囲の概念は関連するが、**今回の窓構造の監査は既存のW値を新しいスキル全条件の発動確率へ転用しない**。

## 元AND/OR・preConditionsを消さない監査

監査対象は、[P2.15の経路別必要条件監査](../../../poc/src/skill_source_path_blocker_impact.cjs)において、同じ脚質に対して明示有限条件が矛盾せず、**その経路で最後に未研究として残る条件コード型が`phase_random`だけ**のもの。

- `conditions`のOR行と`preConditions`のOR行を別々に保持し、さらに`Invoke`ごとの位置と他のOR分岐数を記録する。同じスキルに別経路があっても、分岐全体の発動確率として加算しない。
- `phase_random`の同一AND内複数個は各数値ID・演算子・位置を保持し、同時成立を推測しない。事前条件に含まれる場合も、過去の条件成立が維持される内部状態を再現したと扱わない。
- `running_style`、`distance_type`、`ground_type`、`ground_condition`は既存P2.15の**矛盾検査**で残ったものであり、対象コースで全て実測したわけではない。
- `order_rate`や追い抜きなど**別の未研究型が同じANDに残る経路は、`phase_random`だけを研究した経路へ混入させない**。

## 固定元データの監査結果

[元データによるActions #43150034254](https://github.com/Nimrodx0/Umasupport/actions/runs/43150034254)で成功（`poc/tools/audit_skill_conditions.cjs`）。元のスキル辞書は上記UmaSim固定コミット、`skill_data.txt`のSHA-256は `4c036527bbe6b5aad34d7f12110a06094c9071514e37fdfc68ae195403333be5`。監査はアプリ881スキル、元条件照合818スキル、未照合63スキルを母集団とし、第三者のソース全文を成果物に含めない。

| 項目 | 固定元データでの実測 |
| --- | ---: |
| 元条件を照合できたスキル | **818** |
| `phase_random`型のみが未測定として残る候補スキル | **102** |
| 候補のスキル×脚質セル | **315** |
| 候補セルにある元OR・事前条件経路 | **371** |
| 元コードと比較して抽選窓の構造を確認できた経路 | **371** |
| 今回の対象外の演算子・局面IDによる保留 | **0** |
| 窓の位置を同一判定tickで測定した元経路 | **0** |
| 元スキル全条件の成立・ゲーム内発動・正式適性の検証 | **0** |

**102件・315セル**は、上流のP2.15候補母集団を独立の経路照合で再確認した結果である。**371経路**は別々のスキルでも別走行イベントでもなく、元スキルのOR／precondition組合せに由来するため独立標本の件数として扱わない。演算子・局面IDにより保留0となったことは、抽選結果が確定したことを示さない。

研究成果物 `p2-15-phase-random-window-shape.json` は[固定CIのartifact](https://github.com/Nimrodx0/Umasupport/actions/runs/43150034254)へ14日間保存。数値ID・条件位置・元条件の数値および保留状態のみを含み、元のSkillCheckerや元スキル本文・公開カード変更を含まない。人工の[回帰試験](../../../poc/tests/skill_phase_random_source_window_audit.test.cjs)は、ORとpreconditionを取り違えないこと、未対応の演算子と範囲を保留すること、他のANDが残る経路を混入させないこと、出典実装の変化で失敗することを確認する。

## 次の検証ゲートと終了条件

今回の成果は**発動機構のソース構造上の照合**であり、P2.15全体の終了ではない。次の工程で以下を独立検証する必要がある。

1. **元スキルと同じ判定時刻の抽選結果**：発動対象スキルを元のモデル／エンジンに実際に載せ、抽選された位置とキャッシュの寿命、局面と走者位置が同一tickで正しく照合できるか確認する。Wの幾何学近似だけでは代替しない。
2. **残る元ANDとpreConditions**：脚質・レース文脈が合った経路だけを、同じレースの走者・時刻・状態で評価する。preConditionsの保持状態、AND/OR優先関係、複数Invokeのクールダウンを独立に検証する。
3. **P2の総合判断**：実ゲームとの一致、脚質特異性D、評価閾値・母集団の代表性、P3/P4への採用を別々の判断ゲートとし、**元の窓構造371件を「発動可能371件」「高適性102スキル」とは呼ばない**。

公開アプリ・イベントカタログ・カード採点は変更しない。
