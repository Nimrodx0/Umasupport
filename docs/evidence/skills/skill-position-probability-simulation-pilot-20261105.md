# P2研究：GlobalSim固定版による脚質別順位条件のパイロット（2026-11-05）

**状態：実験設計・集計器およびCIによる試験導入。モデル上の数字を日本版のスキル発動率や脚質の実測優劣と同一視しない。** 

## 目的

2026-11-05に「速度曲線から走行距離を積分し、脚質別の順位推移を導けるのでは」という提案をユーザーから受けた。速度曲線の積分は数学的に可能だが、ポジションキープ・並走・レーンとブロック等を無視できないため、複数頭の位置を同時に出力できるシミュレーターを候補とする。対象は**ある脚質が自分の走行距離のある地点で上位50%以内か／後方50%かというモデル上の頻度**であり、特定スキルの抽選・発動率ではない。

## シミュレーターの検証証拠と限界

検討した[GlobalSim（daftuyda/GlobalSim）](https://github.com/daftuyda/GlobalSim)は、レース全出走者の各時点の位置、速度、レーン、スキル発動と結果を出力できるRust製エンジン。パイロットでは **`80b54cacf174b54ff6f7ca27ee7f88b5856c0bd1`（v77）に固定**し、[同コミットの検証条件](https://github.com/daftuyda/GlobalSim/blob/80b54cacf174b54ff6f7ca27ee7f88b5856c0bd1/docs/ACCURACY.md)と同じ`examples/v77-race.jsonl`の元設定・スキル辞書を利用する。

開発者公表値は2026-10-28固定インベントリの**696,777 / 696,778レース一致（99.99986%）**。比較対象には記録された時点の中間走行位置、速度、レーン、スキル発動、競り合い、ゴール記録を含む。84件の公式比較フィクスチャ、167 Rustユニット、39 Pythonテストも公表されている。これは**開発者自身によるグローバル版の検証**であり、独立無作為ホールドアウトではなく、公式リプレイの全時刻が公開されるわけでもない。未検証の日本版現行ゲーム全ケースへの一般化は不可。同開発者が[検証範囲](https://github.com/daftuyda/GlobalSim/blob/80b54cacf174b54ff6f7ca27ee7f88b5856c0bd1/docs/ACCURACY.md)で近似や未解決の1件を明示している。検証器自体は[TESTING.md](https://github.com/daftuyda/GlobalSim/blob/80b54cacf174b54ff6f7ca27ee7f88b5856c0bd1/docs/TESTING.md)を参照。

**適性分類に利用する前に必要な検証**：出走者9/12頭の人数ごとの順位丸め（例：`order_rate<=50`は9頭なら1〜5位、12頭なら1〜6位）と、ポジションキープ・終盤の追い上げ・JP差分の検証。シミュレーターの自己検証数字が高くても、今回の順位条件成立頻度をそのまま日本版の値にはしない。

## A：固定版9頭パイロット

- コースID`10504`、2,000m。GlobalSim固定例と同じレース設定・ソースデータを使用。
- 9頭全員、同じスピード1,000、スタミナ1,000、パワー1,000、根性800、賢さ900、調子+2、適性A。**発動スキルはなし**。
- 脚質の人数配分は4通り（逃げ／先行／差し／追込）：
  - 均衡型：2／2／3／2
  - 前方多め：3／3／2／1
  - 後方多め：1／2／3／3
  - 逃げ不在：0／3／3／3
- 各配分について複数の乱数シードを実行する。脚質とゲート位置が固定的に結びつかないように、シードごとに脚質をゲート位置へ循環配置する。
- 自分のレース進行率が **1/6・1/3・1/2・2/3・0.70・0.75・0.80・5/6・0.90** に達した**同一時刻で全馬の進行距離を比較**する。各出走馬の到達時刻を別々に出してから進行距離を比較するような、誤った非同期順位計算をしない。
- `frames[t].horses[i][0]`の走行位置が、各対象距離を横断した前後の**密な記録フレーム**を線形補間する。`retainAllFrames:true`のためフレーム間の時間幅による誤差を最小化できる。補間ができない・同位置の曖昧な順位は`unknown`として集計母数から区別する。
- GlobalSimの`order_rate`順位閾値は、その固定出典の`round(出走頭数×率/100)`を初期再現とする。日本版の厳密な丸め・比較は**未検証**。
- 結果は脚質・各サンプル地点・人数配分ごとに`pTopHalf`、`pBackHalf`、確認済みサンプル数・不明数を記録。1頭分×複数シードの集計は互いに独立とは限らず、信頼区間を安易に断定しない。

**重要な制約**：この最初のパイロットは全頭同能力・スキルなし・単一コースといった**人工的なレース編成**である。シード数が多くても、実際の対人マッチングの脚質配分・ステータス・スキルと同じにはならない。

## 実装と再現コマンド

- 解析器：`poc/tools/globalsim_position_pilot.cjs`
- 固定ソース確認・ビルド・実験実行・成果物保管：[手動／PR時の独立CI](../.github/workflows/globalsim-position-pilot.yml)
- サンプルの要求JSONLおよび返信JSONLはCI作業領域のみで使用。第三者の元スキル辞書と実験用バイナリはGitHubリポジトリへ同梱せず、**集計後のモデル上の割合だけ**CI artifactへ記録。
- `workflow_dispatch`で各配分のシード数を1～200に設定可能。通常のPull Requestでの自動実験は計算負荷を抑えるため各配分**2シード**で接続確認を行う。別途[Actions #41937040969](https://github.com/Nimrodx0/Umasupport/actions/runs/41937040969)で一度、各配分**40シード**（合計160レース）のモデル探索を成功させた。これは限定的な条件でのモデル上の試行であり、日本版の適性判定そのものではない。脚質適性を裁定する統計量には使わない。
- 実行例：固定版GlobalSimの`examples/v77-race.jsonl`が得られ、`target/release/race_engine_rs_v2`をビルド済みとする。
  ```sh
  node poc/tools/globalsim_position_pilot.cjs prepare \
    /path/to/GlobalSim/examples/v77-race.jsonl requests.jsonl manifest.json 60
  /path/to/GlobalSim/target/release/race_engine_rs_v2 < requests.jsonl > replies.jsonl
  node poc/tools/globalsim_position_pilot.cjs finish manifest.json replies.jsonl report.json
  ```

## GlobalSim実行結果：160レースの最初のモデル上の観測

[GitHub Actions #41937040969](https://github.com/Nimrodx0/Umasupport/actions/runs/41937040969)で固定v77ソースを直接ビルドし、9頭・ソース固定コースID10504（2,000m）、4つの脚質編成に各40個のseedを投入して**計160レース完走**。全出走者の密なリプレイから解析器が順位割合を計算し、派生された`summary.json`をActions artifactに保存した。固定のスキル辞書・バイナリ・生リプレイは本レポジトリに同梱していない。

以下は「各ウマ娘が**自分の走行距離の80%地点に到達した時刻**に、9頭中**5位以内**だった割合」。**実ゲームではなく、上記の固定条件下でのGlobalSimの値**。

| 人数配分（逃げ／先行／差し／追込） | 逃げ | 先行 | 差し | 追込 |
| --- | ---: | ---: | ---: | ---: |
| 均衡型（2／2／3／2） | 100.0% (80/80) | 100.0% (80/80) | 30.8% (37/120) | 3.8% (3/80) |
| 前方多め（3／3／2／1） | 94.2% (113/120) | 69.2% (83/120) | 3.8% (3/80) | 2.5% (1/40) |
| 後方多め（1／2／3／3） | 97.5% (39/40) | 98.8% (79/80) | 49.2% (59/120) | 19.2% (23/120) |
| 逃げなし（0／3／3／3） | 対象外 | 98.3% (118/120) | 45.8% (55/120) | 22.5% (27/120) |

丸括弧内は**条件成立した走者×seed観測数／有効走者×seed観測数**。同一レース内の観測が相関するため、分母120を120回の独立レースとみなさない。この40seed×4構成は、モデル上の傾向確認の**探索的試験**であって、実ゲーム上の標準レースの代表標本ではない。

**重要な予備的所見**：

1. 同じ位置条件でも脚質人数によって成立割合が変化する。例えば進行率80%の差しは、前方多めの3.8%から後方多めの49.2%まで大きく異なる。**脚質構成を固定した単一の普遍的な順位条件成立率は得られない。**
2. この条件では進行率80%になっても逃げ・先行の上位半数成立割合が高い。したがって「終盤前半の後半に入った瞬間、全脚質が同等の前方適性になる」という旧75%基準を**本モデルも支持しない**。
3. 進行率90%では順位の変化が増えた。例えば前方多め編成で逃げは82.5%（99/120）、差しは26.3%（21/80）。後方脚質の追い上げが作用する時期がある一方、**どの局面で脚質の優位が同程度になるかは、この狭い実験から確定できない**。
4. 逃げ不在など、ポジションキープの別条件もある。出走者の能力を一律にした実験では、一般的な対人レースの能力分布・スキル構成を再現していない。

これらは**ソース固定版GlobalSimの実際の計算結果**であり、公式JPの発動確率・順位分布の独立検証ではない。今後は9/12頭・距離・脚質人数比・能力分布を拡張し、順位推移の安定性と現ゲームとの差を検証するまで、P2の脚質推定に新しい定量的な閾値を採用しない。

## 判断ゲート

**A（機構）**：人工フレームから同時刻順位が再現できること、9/12頭の人数別閾値、人数配分・ゲート交替・空のスキル、フォーマット不整合をテストする。

**B（モデルデータ）**：固定GlobalSim v77の実行結果で実際にモデル上の順位分布が得られること。4人数配分間で脚質傾向が大きく変わらないか観察し、変わるなら統一ラベルを強制しない。全体の出走者構成の代表性を別途検討する。

**C（ゲーム／実環境）**：実際の日本版現行ゲームの途中順位が、その地点において同じ傾向を示すか独立検証する。実機/公的な観測記録と照合が未完の間は、**現在のP2脚質分類ルール・53件のメタデータとユーザー画面を変更しない**。
