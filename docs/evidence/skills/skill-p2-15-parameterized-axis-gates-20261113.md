# P2.15／P2.32：共通判定機構を元スキル固有パラメータへ展開した明示的な3軸ゲート監査（2026-11-13）

**対象と問い**：既存研究を再利用可能な判定機構カーネルに整理した[P2.32の前工程](skill-p2-32-mechanism-reuse-20261113.md)に続き、**各元スキルの比較演算子と数値閾値を保持したまま**、脚質・距離・芝／ダートの3軸の**明示的な適用制限だけ**を実際に各スキルへ展開できるか検証する。目的はまだモデル上の条件成立機会W・脚質間差D・実発動率の算出ではない。

## 再利用した既存の判定基盤

- [元UmaSim論理構造のコンパイラと元述語IDごとの比較器](../../../poc/src/skill_source_whole_tick_monitor.cjs)を**再利用**する。新しく元スキル発動判定器を一から書き直さない。元の`conditions`、`preConditions`、各Invoke、各OR行、AND位置と比較演算子・値を維持する。
- [P2.15の有限ドメイン必要条件判定器](../../../poc/src/skill_full_condition_path_audit.cjs)と、個々の元スキルに対して計算した結果が矛盾しないことを、全照合経路・4脚質で独立照合する。
- [253厳密構造グループと144判定機構カーネル](../../../poc/src/skill_p2_32_mechanism_reuse.cjs)の各元経路メンバーを処理対象とする。同じ演算子・構造でも**元数値が異なれば各スキルの元値で再計算**し、成立結果をコピーしない。

## モデルへ入力する値

4脚質（逃げ=1、先行=2、差し=3、追込=4）×4距離区分×2馬場種別（芝／ダート）の**32比較文脈**について、元スキルの`running_style`・`distance_type`・`ground_type`の元比較式を評価する。

`ground_condition`（良～不良の数値状態）はモデル側で勝手に固定せず、元データの4状態（値1～4）を**同じ文脈の中で同時に列挙**する。各32文脈では、4馬場状態のうち静的ANDに矛盾しなかった状態のビットマスク（0～15）を記録する。例えば`ground_condition <= 2`を満たす場合は、4状態中の1と2に相当するマスク`3`を記録する。条件が互いに矛盾していれば`0`となる。いずれも**実ゲームの馬場状態の出現頻度ではない**。

元の他の条件（順位率・追い抜き・ランダム区間・競馬場ID・能力・時間・事前条件の履歴など）は、固定文脈の入力にデータがないため**判定していない**。未知を偽・真・省略可に変更しない。未確認条件を含む経路でマスクが非0でも「**明示的静的条件に矛盾しない**」以上の意味はない。

元conditionsに空行のみではなく、**条件OR行そのものが欠落しているInvoke**についても、既存SkillCheckerの空条件の扱いと事前条件履歴の不明を区別するため、スキル全体の「全適用不可」判定を確定せず保留する（静的ゲートの過剰な除外を回避）。

## 研究用の出力とテスト

- [元条件値別・3軸の必要条件監査器](../../../poc/src/skill_p2_15_parameterized_axis_gates.cjs)：元スキルごと32文脈×4馬場状態を既存の比較器で検証。出力は元数値を再配布せず、元数値スキルID・Invoke/OR位置・253群/144機構ID・マスク・元閾値パラメータを個別再評価した証拠だけにする。スキル単位では複数元経路が取り得る適用範囲をORで**上限**として合算するが、別経路のAND述語は混ぜない。
- [合成反例テスト](../../../poc/tests/skill_p2_15_parameterized_axis_gates.test.cjs)：同じ構造の別閾値が異なる結果になる、OR2経路、preConditions中の静的制限、矛盾する2つの馬場状態条件、未観測追い抜き・競馬場ID、元条件OR行欠落Invokeの保留、全員分母保持と既存P2.15有限判定器への一致を確認する。
- [固定元スキルCI](../../../.github/workflows/skill-condition-inventory.yml)：`p2-15-parameterized-axis-gates.json`をActions成果物として14日保持。固定元UmaSimの出典SHAと881/818/63、970元経路、253厳密群・144カーネルの整合、32文脈・元スキル結果の非スコア性を自動検証する。

## 判定してよいこと、判定してはいけないこと

- **判定してよい**：元の明示脚質・距離・芝ダート・馬場状態の制限に、各元スキルの比較演算子・数値を当てたとき、その3軸比較文脈が**元条件経路の必要条件として静的に排除されるか**。同じ厳密構造グループで閾値の違いが静的な比較結果を変えるかどうか。
- **判定してはいけない**：明示制限のないスキルに距離・芝ダートの成立機会差がある、元の全AND/OR/Invokeが実際に発火した、馬場状態の分布、固定GlobalSimの順位率を元UmaSimにそのまま移植できる、実ゲームの発動確率や正式P3/P4適性スコアが判明した、という解釈。

**320・54・291件は排他的な集合ではなく、同じスキルが複数軸に含まれる。** 判定には同じ脚質・距離・馬場種別に加えて4つの馬場状態を**それぞれ固定した比較**を用いた。非明示条件が距離・馬場により発動しやすくなるという結果ではない。

**85群の意味**：同じ「条件型・演算子・AND/OR構造」でも個々の元数値が異なるため、適用可能な3軸文脈に差が出る群が85存在した。この事実が、グループ単位の判定方法は再利用しても**成立・不成立の結果そのものを別スキルへコピーしてはいけない**という設計方針を固定元データで確認した証拠となる。

[CI成果物](https://github.com/Nimrodx0/Umasupport/actions/runs/43395869243)の `p2-15-source-parameterized-axis-eligibility-only` に、元スキルID／元Invoke・OR経路／4状態マスクを記録する。第三者由来の元スキル数値条件文は再配布しない。

## 次工程

元スキルごとの明示ゲートを基礎として、実測・コホートが一致する条件（既存順位・局面の同一tick等）だけを**同じ元スキルの同じInvoke/OR経路に、元述語ID単位で追加観測**する。元ランダム抽選の幾何学研究を、実抽選済み観測と取り違えない。`P2.33`の距離・馬場による**非明示的**な成立機会差の調査は、今回の明示ゲートから分離して進める。
