# Phase 2：結果分岐／スキル候補OR／ヒントLv幅の全件独立分類（2026-10-21）

## 動機と測定単位

`skill_hint_or` という **1種類の報酬効果コードの記載数**と、一般の「成功・失敗等により結果が二つ以上あるイベント」の数は全く違う。SSRエフフォーリア30311の最終段階は、3選択肢それぞれに高／低の2結果があるが、`skill_hint_or` ではない。これらをひとまとめに数えると未対応範囲を誤る。

本件では元データを **イベント → 選択肢 → 結果経路 → 数値効果** に分け、`reportedRandomAlternative`、結果経路数、`skill_hint_or`、数値ヒントLv幅、先行状態ガード、`chain_end` の異なる軸をそれぞれ確認した。複数結果は`random_either`だけとは限らず、`segments`が条件ごとに結果経路へ展開されるものも別区分とする。各数値は重複しうる軸であり、足して「イベント数」にしない。

ソース：[GameTora由来の固定実装](https://github.com/systemless10/UmamusumePS/tree/6e38b54af4fad397ff4491e63007a90705a4fe67/server/data/events/gametora) / [変換器](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/gametora.py) / [結果と効果の実行機構](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/event_engine.py)。当該固定コミットと非公開の2025年旧マスター補完の区別は [既存全件報告](phase2-correlated-hint-level-ranges-20261021.md) を参照。

### SSRエフフォーリア30311の意味

[固定 `support_30311.json`](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/data/events/gametora/support_30311.json) の連続最終段階は、3つの選択肢それぞれに2個の`outcomes`。各結果に複数のスキルヒントが入るが、`skill_hint_or`効果は0。つまり結果が2通りあることと、報酬としてスキル候補から1つが選ばれることは別。

## 保留23件と意味論の境界

旧2025年マスターの名称補完を**メモリ内だけ**で使った試験変換は、従来と同じ**2,465/2,488適合・23保留**。保留23件の一次理由は特殊21、先行連続段階1、重複スキル1。特殊21は `TERMINATION_OUTSIDE_CHAIN` のみ12、直接獲得のみ3、双方2、条件付きsegment3、前段状態依存1に区分される。

特に `chain_end` は、GameTora由来の元実行器では **当該サポカの連続イベント全体を止める効果**として使われ、ランダムイベントで発生した場合でも連続イベントへの影響がありうる。現行アプリの`terminal` は親イベントからの到達関係に作用するため、通常ランダムイベントを単に「そのイベントのterminal」に変換しても、**他の連続イベントの到達制御を再現できない**。終了マーカーを削除して保留を解除することも禁止する。

次工程では「ランダムイベントで終了が起きた」という**発生・選択状態**をどこへ保存し、終了後の連続段階と候補報酬をどう無効にするかを設計し、人工例から実行時スキーマ・UI・全件ケースに段階的に反映する。これはゲームイベントの発生確率を予測する要求とは異なる。直接スキル獲得は通常ヒントLvと同じ取得意味論と見なさず、別設計にする。

## 実装・検証と公開境界

`poc/src/gametora_branch_semantics_inventory.cjs` は、事前正規化済みの**未公開数値候補**を入力とし、選択肢、結果経路、ORヒント、幅Lv、終了・直接獲得の数を個別検査する。入力の全件数と結果数が一致しなければ失敗し、カードIDと掲載序数以外の元文言や表示名は出力しない。`project().report.branchSemanticsInventory` の数値監査に含まれ、アプリの利用者向けデータには採用しない。

人工テストは3選択肢×各2結果、別イベントのOR候補、条件付き複数経路、ランダムの終了などで計数単位を検証。固定全件のアクションでは上表の重要な内訳を回帰ゲートとして固定した。A: Node回帰、B: GameTora固定全件監査、C: 既存Chromium回帰。2026年ゲームの経路・報酬を実測していないので**全ゲームイベントの網羅率や99%以上の正確性の主張はできない**。配信用イベントは未承認のまま。
