# Phase 2：出典・利用条件ごとの一括公開審査ゲート（2026-11-02）

> **資料の位置づけ**：イベントの変換・審査に関する調査（時点付きの証拠）。本文の測定対象・出典版・留保を確認してください。
> **現行の参照先**：[正本の入口](../../index.md) ／ [分野別の証拠索引](../catalog.md)。執筆当時の「現在」「次工程」は現行の指示ではありません。

## 主旨と現状

ユーザー確定仕様は**イベント名を維持し、選択肢・結果の文言は仮称**。固定563カード・非公開2,512イベントの変換とChromium実データ試験は成功している。サービスの完成形はPages起動時の自動読込であり、利用者がJSONを用意する方式ではない。

しかし、**構造化した数値・事実の採用と、本番GitHub Pagesでの第三者由来データの提供は別**。短いイベント名は一律「公開不能」と断定できないが、個々の見出し、元DBの創作的構成、第三者サイト利用条件、ゲーム由来素材の扱いを解決したとは言えない。したがって、**現時点の正式公開イベントは0件で、実出典2,512件の許諾／公開承認は得ていない**。

## 新しいv2公開ゲートと既存v1の関係

これまでの `poc/src/event_release_gate.cjs` は、全イベントに個別のレビュー票（カード・イベント・選択肢・結果・内部依存・公開条件の6項目、根拠URL、イベント内容SHA）を要求していた。今後もv1形式は有効であり、現在の正式公開の台帳 `poc/config/event-release-approvals.v1.json` を変更しない。

**新しいv2形式の台帳を明示的に渡した場合だけ**、`poc/src/event_release_cohorts.cjs` の集合審査方式を使う。レビュアーが同一出典・同一利用条件で扱えると判断した複数イベントを、1件の署名済みレビュー単位で監査できる。v2にもv1形式の個別例外レビューを混在させられる。

各集合の必須情報は次の通り。

- **完全な審査対象**：対象イベントIDの接頭辞、必要ならカードID範囲、別条件で裁定するイベントの厳密な除外IDを記述。除外したイベントは**別の集合または個別レビューによる承認が必須**であり、単に除外して公開することはできない。
- **内容を固定する検査**：`expectedEvents` と `eventsSha256`。SHAは、カードID・イベントID・各イベントの正規化された内容SHAの組を並べて計算する。新規追加・欠落・名称変更・分岐変更・ヒントLvの変更で既存承認を使えなくする。入力順は結果に影響しない。
- **人手による判断**：レビュアー、確認日、変更できない出典版（Git 40文字SHAまたはソーススナップショットSHA-256）、アクセス方式、および既存6項目に加え**元サービスのアクセス条件・DBの再利用条件・ゲーム素材と短いイベント名・選択肢台詞が仮称であること**の4項目について、確認済み判定と具体的なHTTPS根拠URLが必要。
- **利用範囲の決定**：公開根拠の種類、理由、具体的にどのフィールド・表現・出典を対象とするか。承認の不存在／空文字／形式不正／根拠URLが無いものは失敗。
- **全域を閉じる**：重複する集合・未承認イベント・同じイベントを個別と集合の両方で承認・草稿しかないイベントは**公開ゲートで拒否**する。

同一の元GitHubから取得できることや公開ライセンスの表示だけで、これらの判断を自動的にtrueにはしない。**v2ゲートは人間の判断を正確なデータに結びつける検証器であり、許諾を発生させる装置ではない**。

## 実データ2,512件の作業分類

全件監査のメモリ内で、元の固定2,512イベントをイベントIDの系統で分類する。

- `gt-`：固定GameTora派生のイベントID系列。**2,488件**を期待。
- `usl:`：GameWith等で補った編集イベントID系列。**24件**を期待。

この分割は**技術的なID系列の分類であり、法的な一括利用権の境界ではない**。GT系列にもGameWithによる具体的な分岐裁定（例：SSR30080/6）があり、同じ利用条件だと断言できない。そのようなイベントは厳密な除外IDを指定して、個別または別の出典審査集合で扱う。実データの項目名・本文・イベント名・選択肢はCIログや公開成果物へ出さない。

合成テストでは、563枚／2,512件を一つの架空コホートとして承認した場合、同じSHAの元データだけが受け入れられ、イベント名・報酬変更や新しいイベント追加を拒否することも検証する。**この架空の承認情報を実出典や公開台帳へ転用しない**。

## 運用上、次に必要なこと

1. **GameTora由来の短いイベント名、ゲーム由来の短い名称・数値事実、GitHubの派生DBの再利用条件**を、取得元と範囲を区別して確認する。著作権の一般論と利用規約・元DBの構成保護を混同しない。
2. GT系列2,488件を単に包括承認せず、GameWith編集箇所、特殊なラベル、例外IDの扱いを固めた上で、同じ条件で審査できる単位へ分割する。
3. 人手で利用条件を確定した範囲だけ、v2台帳に対象・事実・短い見出しの再利用範囲・根拠URLを記録する。**現在のv1空台帳から自動でv2承認票を作らない**。公開用JSONの作成前に同じゲートをローカルCIで走らせる。
4. 承認済みの独自JSONを既存のPages同一オリジン公開ローダーで自動読込する。個々の元サイトへの多重アクセスをユーザー端末に強制しない。元資料のセリフ・本文は提供しない。

今回の変更は**公開ゲートとその合成試験、実データの識別子系列別監査**に限る。既存公開イベントJSON・デッキ設定・ページでのデータ読込方法は変更しない。

### 受け入れ結果の区分

- **A 技術**：v1後方互換、v2集合署名・内容SHA・例外の個別レビュー・未承認の拒否を合成CIで検証。固定元2,512の対象分割を非公開で検証。
- **B 出典**：ID系列、固定ソース版を記録。ただし現行ゲームにおける分岐・再利用可能な著作的表現を全件独立確認したものではない。
- **C 実環境**：表示形式の2,512件Chromium試験は前工程で合格済み。v2から実出典の正式公開・Pages自動配信・Windows／Android物理端末確認は**未実施**。
