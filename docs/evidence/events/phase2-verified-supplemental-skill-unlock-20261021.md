# Phase 2：根拠付き補完スキル2種の統合で保留155→141（2026-10-21）

## ねらい

ユーザー指定の**GameToraをイベントDBの基礎にする方式**を維持し、数値ID照合先のUmaSim固定辞書に載っていないスキルを、**既に独立根拠が審査・保存されているものだけ**追加で認識させる。

対象は既存の `poc/data/curation/supplemental_skills.v1.json` に個別の数値IDページ（ウマ娘Wiki）と名前・効果の別資料（GameWith）、確認日・スキル区分が記録された2種類のみ。

- `200801`：先行駆け引き。該当GameTora数値ヒント5記載。
- `201012`：後方釘付。該当GameTora数値ヒント6記載。

GameWithのイベント情報を全件取り込み直す工程では**ない**。GameWithは従前どおり、GameToraイベント自体に疑義があるときの裁定先。ここでは固定UmaSim辞書が省略したスキル名・数値IDを補完するため、既存の限定的な2件の根拠情報を再利用する。

## 実装

- `poc/src/gametora_app_schema_dry_run.cjs`で既存`curated_skill_resolution.indexSkills()`を再利用し、補完辞書のスキルID・名称・レア度・出典情報が基準を満たしたとき**のみ**検査用UmaSim辞書へ合成する。
- 元の固定UmaSimに存在しなかったIDを**元のUmaSimスキルとして登録されたと偽装しない**。クロスウォークでは依然`curation-only-not-in-runtime-registry`であり、試験変換時に承認された補完ID集合に含まれる場合だけ使用可能とする。使用件数は独立したカウンタに保持する。
- 照合後は既存`skill_bridge.prepare`および`event_schema.validateCatalog`に入力し、IDと名称の一致、レアリティ、全件構造を検証する。
- `poc/tools/probe_gametora_app_schema_dry_run.cjs`で補完の出典が固定されたローカルJSONであることを保証し、ソースカードとスキル辞書のSHAを照合。2,347/141/11/36等の母数を自動検査する。
- `poc/tests/gametora_app_schema_dry_run.test.cjs`で補完ID2種を合成GameToraの分岐報酬としてテストし、**補完無しなら未変換、正しい補完なら変換、偽の証拠URLなら拒否**を確認する。

本番画面に原イベント名・選択肢文をコピーしない。メモリ上の変換候補は破棄し、GitHub Actionsには件数と番号のみ保存。`publicationApproved:false`、未承認の表示名、現行ゲームの到達条件の実測なしという条件は従来どおり。
