# Phase 2：GameToraの排他的ORヒントを非公開スキーマへ変換（2026-10-21）

## 目的と元データの意味

従来の全件変換は、GameTora由来の `skill_hint_or` を一律 `SKILL_HINT_EFFECT_UNRESOLVED` として保留していた。固定元 `systemless10/UmamusumePS` の [`gametora.py`](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/gametora.py) と [`event_engine.py`](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/event_engine.py) の `skill_hint_or` / `resolve_or_effects` は、**選択肢に並んだORスキルのうち、一つだけを取得する**意味を明示している。金と白の両方を獲得済みの報酬に見せないことが今回の主眼。

## 実装と注意点

- `poc/src/gametora_whole_event_normalize.cjs` は、`options` のスキル数値ID・正確な整数Lv・候補順を保持。原文は保持しない。値の範囲表記（例 `+1/+3`）や未解析候補は推定せず隔離する。
- `poc/src/gametora_event_skill_crosswalk.cjs` が各OR候補を別台帳 `alternativeLocations` で分類。元から存在する1,681数値ヒント、13未解析記載、直接獲得7件はそのまま保全。旧2025年の補完は従来と同様に現行ゲーム確認済みと扱わない。
- `poc/src/gametora_app_schema_dry_run.cjs` は、全部の候補が一対一照合できるときに限り、一つの `outcomes` には**ORの各集合から各一つ**しか入れない。共通の確定ヒントがあれば個別候補結果に複写。報酬の技術的な位置件数は元数値事実の各位置を数え、同じヒントを結果ごとに二重の元資料とみなさない。
- 複数のOR集合は最大32通りの積へ展開。ソース位置改変、重複、未登録の数値ID、範囲Lv、レア度未対応、元ヒントとOR候補の同一スキル重複を拒否し、イベント単位で隔離する。
- `outcomes` は成功の確率やゲーム条件を勝手に指定しない。ユーザーがまだ結果を選んでいないときは `core.directRoutes` で **conditional=true**。特定のスキルを無条件の獲得保証にしない。

- `skill_hint_or` の残り2件について、元の選択肢と出典でLvの変動原因を明らかにする。勝手にLv1やLv3の一方へ固定しない。
- 通常イベント外の明示チェーン終了や直接獲得は、連続イベント進行・習得済みかヒントかの意味論を確認してからスキーマ化する。
