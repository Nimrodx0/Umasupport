# Phase 2：GTの同一対象へ繰り返す数値効果を元出典の順序で保持（2026-10-26）

## 対象と出典

前工程の[結果別`chain_end`を認識した固定全件監査](phase2-gt-chain-end-outcome-proof-20261025.md)では、同じ効果種別・同じ受け手に対する数値行が1結果中に複数存在するだけで、`DUPLICATE_EFFECT_COMPONENT_UNADJUDICATED`として非スキル結果の構造化を保留していた（ブロッカー16結果経路）。元データの数値効果が複数の**独立した記載**なのか、一つの数値に潰すべきものなのかを区別する必要があった。

固定元`systemless10/UmamusumePS@6e38b54af4fad397ff4491e63007a90705a4fe67`の[イベント効果処理](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/event_engine.py#L1363-L1405)は`for eff in effects or ():`で元の記載順に各行を処理する。能力の付与は逐次実行され、体力は上限と現在値、やる気は条件・上下限に依存する。したがって同一結果の`energy -20`、`energy +15`を`energy -5`へ**合算した値だけで元処理を代表させることは不正確**。同様に`all_stats`（5能力それぞれに同値）と個別の`speed`加算は、同一種類の列が重なる場合でも別の元記載として区別する必要がある。

## 構造・実装

- `poc/src/event_schema.js`：従来の`effects[]`に`sourceEffectOrdinal`（元GTの同じ結果の効果配列内における**1始まりの位置**）を任意の正の安全整数として追加する。同一の`kind`・`sourceComponent`・受け手を繰り返す場合は、両方に元記載位置があり、それが**配列内で単調に増える**ときに限って受け入れる。番号欠損・同一位置・逆順・非整数は拒否。元の符号付き`delta`を変更しない。
- `poc/src/phase2_gt_whole_nonskill_effect_inventory.cjs`：全GT効果を引き続き1行ずつ走査し、同じ数値効果のキー（効果種別＋数値の受け手）を2回目以降に検出した場合、直前の同対象行と現在行に**実際の元`effectIndex+1`**を記録する。`all_stats`は元1行から5能力を展開するが、その5能力は同じ元位置を参照し、単独の`speed`等と重なっても元順序は保持する。異なる絆相手はそもそも重複ではなく従来通り個別成分のまま。
- `poc/src/core.js`：`UmaCore.directEffectRoutes`の結果へ`sourceEffectOrdinal`を元のまま伝播。これは**各効果行の所在を示すものであり、ゲーム内部の体力キャップややる気変化を完全シミュレートした値ではない**。`effects`の配列順は変えず、確定合計・能力／キャラの新規名を創作しない。
- `poc/src/phase2_2512_private_effect_join.cjs`：元カードID＋元イベント順位＋元選択肢／結果番号＋停止条件が完全に一致した既存スキル用2,512イベントへ、各数値の元位置情報ごと結合。すべての`effects`を除いたSHAは既存のスキル専用候補と全件一致しなければ失敗する。SSR30080#6の既知のGTのautoとGameWithの3択の不一致は残して保留する。
- [合成回帰](../poc/tests/phase2_gt_ordered_duplicate_numeric_effects.test.cjs)で、体力とやる気の正負順、`all_stats`と同能力の重複、同じ／別の絆相手、元位置がない・逆転・同じ番号のスキーマ拒否、結果別停止のスキル不変を検査した。従来[非スキル分類器のテスト](../poc/tests/phase2_gt_whole_nonskill_effect_inventory.test.cjs)も正しい順序保持に合わせて更新した。
