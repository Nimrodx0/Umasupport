# Phase 2：通常8イベントの公開スキーマ候補と未署名承認票（2026-10-23）

## 位置付け

固定GameToraの不足SSR30318～30321について、GameWithから既に編集採用した通常8イベント・16選択肢・4件のスキルヒントを、**本番 `reviewed_events.v1.json` と同じスキーマの候補データ**へ投影する。既存の[ローカル表示と正式イベント名](phase2-eight-standalone-local-interactive-review-20261023.md)を使用。GameTora本体の2,488件、4SSRの連続12段階、重点28件の他の20位置には触れない。

**正式公開0件のまま。** 公開用イベントDB `poc/data/reviewed_events.v1.json` と承認台帳 `poc/config/event-release-approvals.v1.json` は変更しない。

## 完了した作業

- `poc/src/phase2_eight_release_candidate.cjs`：既存のGameWith裁定と元ID/Lv、イベントタイトルのSHA、16個の選択位置を再検証してから、4枚・通常8件を本番スキーマで生成。IDはゲーム内部story_idと別の安定した `usl:30318:random:4` 型でカードと元位置を固定。
- 表示は正式イベント名（個別攻略記事掲載値）、選択肢は原文台詞でなく独立に記述した「上の選択肢」「下の選択肢」。元位置と報酬の対応を維持。オプションの位置ラベルのみで利用者が区別できるかは**公開審査で要確認**。
- `rewards[]` はスキル数値ID、照合済み日本語名、ヒントLvを保持。本番ロード処理 `public_event_catalog.preflight` の通過を、100件以上の合成スキル辞書と実ID4件を使って実証。名称改変・スキル分類誤りを拒否。正式配信前にはUmaSimの実辞書による照合も必要。
- 8イベントのSHA-256、出典参照URL、位置と6確認項目を含む**未署名**レビュー票を生成。レビュー者／確認日／公開利用根拠はnull、6確認事項はfalse、publication根拠URLは空。既存 `event_release_gate` がこの票を拒否することをテスト。
- `node poc/tools/report_phase2_eight_release_candidate.cjs`：8件の件数と個別SHAだけを読み取り出力。`--json` は未署名の候補JSONと審査票を標準出力へ出す。**ファイル書き込み・Github Pages配信を行わない**。
- CI：Node検証、数値/スキル分類すり替え拒否、公開ゲート拒否、既存公開DB・承認台帳0件維持、従来のChromium回帰を分離。

## 今回残した公開判断

| 要素 | 候補の状態 | 公開前の確認 |
| --- | --- | --- |
| カードとイベント | 元記事4枚・通常8件のタイトル/位置と照合済み | イベントの見出しと独自IDが利用者の識別に十分か |
| 選択肢 | 記事にある上・下の位置とヒントを保持 | 「上／下」だけで実ゲームの選択肢を誤認しないか |
| 結果と連続条件 | 掲載のない結果分岐は追加せず、独立した通常8件のみ | 掲載上の選択肢ごとに別結果があるなら個別補正 |
| 公開利用 | 原文選択肢・画像・記事本文は含めない | 短い正式イベント名と独自数値編纂の利用範囲・出典表示を判断 |
| 人手署名 | **0／8** | 6カテゴリの根拠URL・担当者・日付を内容SHAに結合 |

ゲーム内部IDの別資料照合や、育成ゲームでの実際の出現再現は必須にしない。出典に記載のない分岐は補わない。運用上必要なユーザー判断の段階になった際に、候補をまとめて審査できる。

## 次に進める作業

1. この8イベントの手動公開判断を得たら、**同じSHAに署名済みの6項目証跡**を加え、公開JSONを更新する。公開ゲート、実UmaSim辞書照合、本番PagesのChromium試験の成功後に正式件数へ計上。
2. 通常のGameTora由来559枚・2,488イベントは専用非公開正規化器で既に全件試験済み。次は例外差分とスキル辞書不一致を機械的に隔離し、公開候補を大量生成する専用工程。GameWith全カード収集を新たに義務化しない。
3. GameToraの未収録イベント・連続後続分岐・GameWith未掲載のSSR30240等は個別例外として保持する。
