# F-08：レビュー済み公開イベントJSONの検証済みキャッシュ復旧（2026-10-22）

## 全体計画上の位置付け

[ロードマップ](roadmap.md)の**Phase 0（基盤・取得検証と障害復旧）およびPhase 4（異常系統合検証）**、[要件F-08](requirements.md)の「検証済みデータを使い、取得先障害時にも既知の経路を利用可能にする」を実施した。Phase 2のイベント公開承認やゲーム内全件性を省略する目的ではない。

今回の変更前、通常ヒントとスキル辞書はIndexedDBから復旧できた一方、`poc/data/reviewed_events.v1.json`の取得失敗時は、前回レビュー済みイベントを再利用できなかった。この欠落を埋めるため、**イベント単独の取得先が遮断されても、検証済みの最後の正常版のみ復旧**する。

## 実装した復旧契約

- `poc/src/public_event_catalog.js`に`loadVerified`を設け、HTTP取得したJSONを**現在のカードID・スキル辞書・イベントスキーマに対して完全に検証した後**のみキャッシュ保存する。`preflight`は公開イベント`attach`と同じコード経路の検証を使用し、不正イベントが後から混入しないようにする。
- 保存先は既存のIndexedDB `uma-support-lab-runtime-data` / `sources`。キーは`umasupport/public/reviewed_events.v1.json/v1`で、`text`・`sourceUrl`・`fetchedAt`を記録。元データの更新ボタンや未承認イベントの自動収録は追加しない。
- ネットワーク障害、HTTPエラー、不正JSON、意味的に不正なオンライン更新時は、同じURLで保存されている候補を**再度、現在のモデルに対して検証**する。検証に通った場合だけ`mode:'cached'`とし、表示の取得日時と再チェック日時を区別する。
- 破損JSON、未知のカードID、スキーマ不一致、別URL由来のキャッシュ、キャッシュ自体が未存在・アクセス不可の場合は**未検証イベントを採用しない**。カード通常ヒントと独立のスキル辞書構造を優先してアプリを起動し、イベントデータの失敗を明示する。
- IndexedDBが利用不可でも**有効なオンラインJSONの読込は継続**する。公開イベントJSONは既に外部でレビューされる前提であり、クライアント側の形式検証が第三者データの再利用許可や正確性を新たに付与するわけではない。

## A/B/C の検証と範囲

| 軸 | 実施内容 | 結果と限界 |
| --- | --- | --- |
| **A 機構** | Nodeの合成イベントで正常取得→キャッシュ復旧、不正なオンライン更新の拒否、元の正常キャッシュの保存、破損・別URL・未保存キャッシュの拒否、ストレージ拒否下のオンライン運用 | 自動試験に合格。実ゲーム情報は合成テストに含まない |
| **B データ／公開ゲート** | 既存の`verify_event_release.cjs`とイベントスキーマ検証を変更せずに維持。正式公開JSONの収録レコードは0件 | 本作業では実ゲームのイベントを1件も追加・承認していない。実データがある場合の全イベント網羅性・正しさは別途検証が必要 |
| **C ブラウザ** | `poc/tests/browser_skill_smoke.cjs`に、Chromiumで検証済み公開イベントJSONのIndexedDB保存、イベント取得先だけの遮断、復旧時のモード／0件の明確な表示、不正オンライン更新による汚染拒否、破損キャッシュ隔離を追加 | Linux上のChromium、**合成カード563枚＋実公開JSONの空カタログ**で成功。Windows・Android・他ブラウザの物理端末操作は未実施 |

**「検証済みイベントが0件」と「公開JSONを取得できず、検証済みキャッシュもない」は区別する。** 復旧したイベント0件は「前回確認した空の公開JSONを採用」であり、「ゲームにイベントがない」とは解釈しない。

HTML、JS、CSS自体をオフラインで起動できる機能は追加していない。これは**アプリ本体が読み込める状態でイベントJSONの取得先が故障した場合の復旧**である。
