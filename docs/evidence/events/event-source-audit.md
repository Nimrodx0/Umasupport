# 外部イベントデータ照合の検証記録（2026-10-16）

## 基本方針

実ゲーム由来イベントを **カードIDが一致しただけで集計しない**。イベントの到達条件・打ち切り・スキルIDと、第三者データの利用条件を別々に確認する。これは開発用の読み取り・診断であり、公開版の `live_loader.js` にはイベントを追加しない。

## 実際に照合したデータ

- UmaSim: [support_card.txt](https://github.com/mee1080/umasim/blob/main/data/support_card.txt) から生成したモデル（確認時点で563カード）。
- umamusume-data: [supports.json](https://github.com/Tsuyuchan-jp/umamusume-data/blob/main/data/supports.json) と [events.json](https://github.com/Tsuyuchan-jp/umamusume-data/blob/main/data/events.json)（確認時点で45カード／126イベント）。同リポジトリにはGitHubのライセンス欄で明示ライセンスが確認できていないため、再配布・転載はしない。

| 確認内容 | 結果 |
|---|---:|
| supports.jsonのカード件数 | 45 |
| UmaSimのカードID照合一致 | 45 / 45 |
| 同IDに対するカード名の完全一致（NFKC／空白正規化） | 45 / 45 |
| events.jsonのイベント件数 | 126 |
| イベントIDから5桁カードIDを明示的に得られるイベント | 124 |
| IDからカードを直接確定できず、隔離したイベント | 2 |
| イベント種別（選択式 / auto） | 24 / 102 |
| 全126イベント内の識別スキル | 191種類 |
| 124件の直接照合イベント内の識別スキル | 189種類 |
| この189種類でUmaSim通常ヒントの名称と厳密に一致した候補 | 79種類 |
| 残りのスキル（通常ヒント名からは結び付けられない） | 110種類 |

**注意：** 上記の79種類は名称候補の一致であり、正式スキルIDの検証・承認ではない。残り110種類にはイベント固有／上位スキルなどが含まれる可能性があるが、推測で補完しない。

例外の2件は `evt_tazuna_oodate5` と `evt_tazuna_newyear`。カード名称らしいフィールドは存在するものの、**ゲーム内カードIDの明示がないため自動名寄せしない**。

## 元JSONに存在する情報と不足する情報

- `events.json` の各行には `id`、`label`、`selection`（`auto` または `single`）、報酬スキルの `skillId`・`skillName`・`hintLevel` がある。
- 選択式は `choices` と `defaultChoiceId` を持つ。ただし、**defaultChoiceIdは利用者がルートを決めたことを意味しない**。内部の選択状態には自動反映しない。
- **連続イベントの依存関係、各選択肢の打ち切り状態、成功／失敗による結果分岐、発生順序はこのJSONだけでは確定しない**。したがって `auto` を根拠なしに独立イベントとして集計しない。
- supports.jsonの `eventIds` が空でも、これを「イベントが存在しない」とは解釈しない。
- 元スキルIDが数値で、UmaSimの現在の内部IDは `hint:正規化した名前`。厳密な識別子変換表が必要。名称が偶然同じでも自動採用しない。

## 実装した診断・変換ツール

- `poc/src/event_source_audit.js` の `audit({supports,eventsDocument,model})`：カードIDと名称のダブルチェック、イベントのカードID抽出、選択形式の最低限の妥当性、スキル名一致候補、カード別イベント記録数、隔離理由を返す。**モデルを書き換えず、ゲームイベントを有効化しない。**
- `poc/src/event_review_compiler.js` の `buildReviewedCatalog(...)`：開発者が `chainVerified:true` と `rewardSemanticsVerified:true` を別々に明示し、依存関係・打ち切り・獲得条件（無条件または結果依存）・元スキルIDと内部スキルIDの対応を全件確認したイベント**だけ**をイベントv1へ変換し、`event_schema.js` で整合性を検査する。レビューされていない実イベントは出力されない。
- `poc/tools/audit_events.cjs`：提供元3ファイルを**取得元に直接GETして読み取りだけ**行い、統計とID単位の隔離理由を標準出力へ表示。ゲーム由来JSONの再配布・GitHubへの保存を行わない。開発者用ツールでありアプリ画面の手動更新ボタンではない。

リポジトリのルートから、開発者向けに次のコマンドで再監査できる。

```sh
node poc/tools/audit_events.cjs
```

オンライン取得を避ける場合、あらかじめ開発者自身が取得したローカルファイルを渡す。

```sh
node poc/tools/audit_events.cjs --local path/to/support_card.txt path/to/supports.json path/to/events.json
```

ツール実行により取得件数や結果が変わる可能性がある。**この節の数値は2026-10-16に観測したスナップショットであり、自動で最新の網羅率を保証するものではない。**

## 次の判断ゲート

1. ソース提供者・参照元の利用条件を確認。閲覧可能であることと、イベント本文の再利用が許諾されたことは別。
2. 2件のIDなしイベントをゲーム内カードIDと独立に照合する。
3. 元スキルIDを信頼できる識別子から検証し、金白関係も含め内部のスキル辞書へ正規化する。110の未照合候補を自動的に新スキルとして生成しない。
4. 連続イベントの各分岐・打ち切り・結果依存を複数の具体的なカードで検証。レビューしたイベントだけを段階的にコンパイルする。
5. 一部カードで集計・GUI操作を確認後、全カードへ展開して収録率を評価する。投入したカード数やイベント数と真のゲーム内網羅率を混同しない。

現在のイベントの実装と検証方法は [イベントv1スキーマ](event-schema.md) を参照。
