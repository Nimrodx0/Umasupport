# Phase 2：全GameToraイベントの数値スキルIDをUmaSim辞書へ照合（2026-10-21）

## 目的

[全イベント中間DB化](phase2-gametora-whole-event-normalization-20261021.md)で固定GameTora版から保存した**数値スキルID**と、ウマサルタントで既に採用している通常ヒント `hint:スキル名`・イベント専用 `skill:数値ID` を、推測なしで対応させる。GameToraがDBの基礎であり、GameWithによる全件再構築は行わない。違い・欠損が判明した箇所だけ後続のGameWith裁定対象にできるようにする。

### 未照合の内訳

固定UmaSimスキル辞書で不在だった上位ID：`200831`（9回）、`200861`（8）、`200781`（7）、`200851`（7）、`200941`（5）、`200881`（5）。これらは「GameToraが誤っている」という意味ではなく、**参照したスキル辞書の範囲／版が足りない可能性**を含む。実ゲームの現在情報との突き合わせやGameWithでの個別裁定候補にする。

補完辞書にのみ記録されている `200801`（5回）、`201012`（6回）は、既存の`poc/data/curation/supplemental_skills.v1.json`に証拠とともに保存済み。ただし、現在のアプリが直接読み込む固定UmaSimスキル辞書には存在しないため、**11件を「実行時に利用可能」として数えない**。

直接獲得の7記載はID `200283`・`200353`・`200521` の3種類。これらは辞書内にIDが存在したが、**`normal`／`rare`以外の区分**である。従って「辞書未収録」ではなく「特殊区分として実行時の通常ヒントへ変換不可」とした。ヒントLvとも区別する。意味が確定するまで自動集計しない。

## 実装と安全性

- `poc/src/gametora_event_skill_crosswalk.cjs`：すべての数値ヒント・直接獲得について固定スキルID、レアリティ、通常ヒント名称の一意性と実際の`model.skillById`を照合。成功位置と未解決位置を出典番号で保持。
- `poc/tools/audit_gametora_event_skill_crosswalk.cjs`：固定UmaSimスキル辞書・カード一覧のSHA-256検証、全件数保存検査、未公開JSONへの書き出し。第三者イベント名・選択肢文は出力せず、スキル辞書全文の再配布もしない。
- `poc/tests/gametora_event_skill_crosswalk.test.cjs`：合成全経路・既存通常ヒント・イベント専用レアスキル・名称重複・未収録・補完IDのみ・特殊区分の直接獲得・改竄への拒否を検証。**既存の`public_event_catalog.attach`と`skill_bridge.prepare`へ合成イベントを実際に渡して、最終スキルIDが一致することも回帰テスト**。
- `.github/workflows/whole-event-inventory.yml`：GameTora全件変換の直後に独立固定UmaSim辞書を一度取得し、ハッシュを検証。すべての数値スキル位置を監査アーティファクトに記録。
- `.github/workflows/ci.yml`：第三者ファイル取得なしで合成テストを継続。

文字列IDへの対応判定：

1. 数値IDで固定UmaSimの`normal`／`rare`レコードと完全一致することを必須とする。
2. スキル名称が辞書全体で一意で、アプリの現在の通常ヒント`hint:名前`が同一名称で登録されている場合だけそこに結合。
3. そうでなければ数値ID固有の`skill:ID`として区別。名称同一性だけで異なる数値IDを結合しない。
4. 辞書未掲載、補完辞書のみ、通常／レアではない区分、未解析のヒントや直接獲得は独立のレビュー項目。**未解決項目を黙って落とし、カードが完成したことにしない**。

正確にスキル辞書へ対応できても、イベントの選択肢・成功失敗・前段条件、公開文章、権利、実ゲームでの現在性が確認済みとは限らない。今回のJSONは`releaseApproved:false`、`gameVerified:false`を維持し、本番DBには自動反映しない。

## 次の工程

**入力全件を再取得する必要はない。** 今回の照合結果を使い、ID対応済みのイベントを対象に既存のイベント・結果・後続スキーマへ安全に投影する。まず条件マーカー・終了条件・未対応スキルを含まないカードを選び、内部イベントを実際の集計エンジンに流す。複雑な経路は後で条件付き結果としてモデル化し、疑義のある箇所だけGameWithと照合する。

79件（28種類）の固定UmaSim辞書不足、11件（2種類）の補完辞書のみ、13件の未解釈ヒント、7件の特殊直接獲得は別々に処理する。この段階で **本番の承認済みイベントは0件**、ゲーム内実測で検証したイベント経路は0件のまま。
