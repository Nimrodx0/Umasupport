# Phase 2：既存2,512イベントの非公開ローカル一括試用（2026-10-30）

## 目的・公開の境界

既存の全件パイプラインにより技術検証した**563カード・2,512非公開イベント**を、**もう一度変換し直さず**ブラウザで利用するための最初の実装。イベント1件ごとの編集・承認・追記は行わない。公開用 `poc/data/reviewed_events.v1.json` と承認台帳は**0件・未変更**。

今回の方式は**利用者がローカルに持つJSONを、明示的に選択してブラウザ内で読み込む**。元JSON／非公開イベント本体をGitHubの公開リポジトリ・Pages・Actions artifactへ配布しない。これで「加工済みデータの再配布」という経路は避けるが、**元ソースの取得条件・合法的な使用・著作物と表現の利用範囲は別問題**。この実装自体は公開データ一括配信の承認でも、最新ゲーム全イベントの完全性を示すものでもない。

## 既存フルパイプラインでローカルファイルを生成

現行 `poc/tools/probe_gametora_app_schema_dry_run.cjs` の既存2,512の検証済み経路へ、**ローカルでの明示的な書き出しのみ**を追加した。既存の順序は変わらない。

- 元GameTora全件変換 → GameWith補完 → 特別SSR30180の追加 → 全2,512件への非スキル効果結合・既存の範囲値overlay。
- `public_event_catalog.preflight` / `attach` で同一データの2,512イベントを使い捨てモデルへ受け入れ、スキルID・分岐・打ち切りと動的候補を検査。
- 上記がすべて成功した後で、環境変数 `UMASUPPORT_PRIVATE_LOCAL_EXPORT_DIR` が**明示されている場合に限り**、Git管理外の既存ディレクトリへ `private-events.local.json` を作成する。出力ディレクトリとファイルは権限を制限。通常起動時は書き出し0件。

入力は既存の固定出典セットとローカルで取得済みのUmaSimテキスト・独立ソース資料。必要な実行環境とコマンド引数は [全件監査ワークフロー](../.github/workflows/whole-event-inventory.yml) の最後の `probe_gametora_app_schema_dry_run.cjs` 呼出しと同じ。**この実装は出典ファイルの新たなダウンロード方法や直接取得器を追加しない**。そのためローカルの全件出典・監査入力を用意していなければまだエクスポートできない。

例：既存の一括監査入力を準備した後、ローカルの任意の既存ディレクトリを指定する（Windowsではフルパスへ適宜変更）。

```sh
export UMASUPPORT_PRIVATE_LOCAL_EXPORT_DIR="$HOME/private-umasupport"
# この環境変数を付けて、既存の全件監査用 probe を通常どおりローカルで実行
# 完了後：$HOME/private-umasupport/umasupport-2512-private-*/private-events.local.json
```

**GitHub Actionsからは、環境変数を設定しても非公開バンドルを出力しない**。公的なActions artifactに他者の原文を転送しない。元全件監査のログに、通常時はイベントの本文や公開カタログは出ない。

## ブラウザで使う

1. [ローカルイベントの一括試用](https://nimrodx0.github.io/Umasupport/poc/live.html?eventPreview=local) を開く。通常のカード・スキル辞書と**公開イベントJSONが正常・空**であることを検証する。公開イベントJSONの取得失敗は空0件として代用しない。
2. 手元の `private-events.local.json` をファイル選択する。JavaScriptの `File.text()` のみで読み込み、**イベントファイルはネットワーク送信しない**。
3. ファイル全体のSHA-256、固定出典コミット、非公開フラグ、563カード／2,512イベント、現在のカード名簿とのID整合、スキル辞書の数値ID／照合日本語名、選択肢・排他的結果・連続依存を、実公開ローダーの `preflight` で原子的に検証。全件合格した場合だけ `attach` し、デッキ／カード詳細／スキル表を再利用する。
4. 試用フラグ・「正式承認済み0件」の表示を残す。ローカルファイルはキャッシュ保存せず、ブラウザの再起動・再読込時には再選択が必要。デッキ設定は**取り込んだファイルのSHAを含む専用キー**にのみ保存し、通常版と他のローカルファイルを汚染しない。

参照する出典は固定 `systemless10/UmamusumePS@6e38b54af4fad397ff4491e63007a90705a4fe67`。**2,512件は既存の技術的候補の母数**であり、SSR30240の連続3段階、Checker未同定11位置、非スキル一般構造16保留などは自動補完せず、欠落や不確実な結果を「実ゲームには存在しない」とも扱わない。

## 2026-10-30：固定実データ2,512件を新ローダーとChromiumで受け入れ

旧全件監査の**最終データ**（固定563枚、2,512イベント、非スキル効果と特別補修を含む）を、`phase2_private_local_real_acceptance.cjs` で既存 `private_local_event_preview.verifyBundle/activate` に渡して検証した。これは別の変換器ではなく**前項のローカル書き出しと同じJSON形式の内容**をメモリ上でシリアライズした検証。通常公開JSONが正常かつ0件の状態を模して取り込み、同じモデルを公開用 `public_event_catalog.attach` へ渡した場合と、563枚すべてのイベントと未選択／選択済みイベントスキル経路が一致することを確認。改ざんした同じ実データのSHAも拒否した。

実データの測定結果は、**563カード／2,512イベント（自動901、選択式1,611）、代表選択パターンのイベント経路953件**。そのほか未選択時のイベント経路262件は、選択を必要としない出典ベースの自動イベントによる候補であり、イベントの実際の発生確率や獲得保証ではない。すべての選択肢／結果の全組合せを実端末で試したという意味ではない。入力データの内容SHAは `93a182d4acb960acadf46437179a00dedd7946537eb4ea6b4bcb99c5c02bbe4f`、出典固定コミットは `6e38b54af4fad397ff4491e63007a90705a4fe67`。

さらに、固定実データを**Playwrightのメモリ内ファイル選択**から `live.html?eventPreview=local` へ投入する `browser_private_2512_real_in_memory.cjs` を同一の全件監査内で実行した。ブラウザで全件読込→実カードをデッキへ登録→実イベントの選択→イベント由来スキル経路が増えることを確認。通常版へ戻すとイベント0件となり、通常版設定への混入・非公開データの意図しない外部ネットワーク送信を検出しなかった。**ブラウザ実データの試験でも、非公開JSONをGitHub成果物・Pages・公開JSONに書き出していない**。

- **実データ全件・Chromium結果**：[固定全件監査Actions](https://github.com/Nimrodx0/Umasupport/actions/runs/41024259876)。
- **通常のCore／人工データ回帰**：[Core・ブラウザActions](https://github.com/Nimrodx0/Umasupport/actions/runs/41024259949)。
- **未完了**：利用者のWindows／Android物理端末・ローカルPCでの実ファイル書き出しと再読み込み、配信方式と権利・利用条件の確定、現行ゲーム全イベントの完全性、正式公開のゲート変更。**実出典の読込成功は公開許諾ではない。**

## 今回の合格条件と限界

- **A（機構）**：Node合成フル563カード／2,512イベントで正常一括読込、未選択スキル0→選択ヒント付与、誤SHA／出典ピン／出典外カード／スキル名称不一致／不正フラグの一括拒否。
- **C（ブラウザ自動試験）**：人工データで破損ファイル再選択・通常版との隔離を試験。**固定実2,512件をChromiumのファイル選択で読み込み、実カードを編成して実イベント選択とスキル経路反映まで成功**。Windows／Androidの物理端末・実ゲーム再現ではない。
- **B（実ソース）**：既存の固定版全件監査・`preflight/attach` の資産を再利用。固定実2,512イベントを同じローカル読込器で再検証して全563枚のイベント内容と代表2状態の集計を照合。**最新ゲームの独立全件網羅を立証したものではなく**、非公開JSONは配信しない。
- **未完了**：ローカルでの実出典を使用した書き出し・実機試用、取り込んだ実データの現在のゲームとの網羅保証、通常版への自動接続、CORSと規約確認を経た外部直接読込方式、公開可能な独自数値DBの配信。

**次工程**：既存の一括入力の再現性を保ったままローカル実データで入出力を確認し、公開配信が可能な情報単位を確定する。外部サイトへの無許可な自動大量取得、原文・画像の再配布、旧ゲートの無断無効化をしない。
