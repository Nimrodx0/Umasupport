# Phase 2：固定GameTora 2,488件・例外65件を統合した収録トリアージ（2026-10-23）

## 目的

全2,488イベントの「短見出し・数値スキーマ変換完了」から、**実際に調べるべき原因別・出典差異別の対象位置**へ落とし込む。既存レビューキューの注意マーカー34件と旧UmaSim辞書時の投影除外110件を、それぞれ「ソース内に注意すべき構造」と「旧スキル辞書で直接保留または下流が巻き込まれた位置」に分ける。加えて、従来の[GameTora/Checker固定出典差異65件](phase2-cross-source-completeness-exceptions-20261022.md)を統合する。35件の後続段階を、別々の35件の独立スキルID問題だと誤解しないようにする。

## 実装

`poc/src/phase2_release_triage.cjs` が **4つの未承認・固定元一致入力**を照合する。

1. GT固定全件2,488件の元イベント位置・連続順序だけを含む数値正規化台帳
2. [未署名の公開審査キュー](phase2-gametora-unsigned-release-review-20261023.md)：2,488件すべての数値ID、イベントSHA、旧辞書除外と元ソース注意マーカー
3. 固定UmaSimのみの投影除外レポート：73件の `SKILL_ID_OR_HINT_EFFECT_PENDING`、2件の `RANGED_HINT_EFFECT_PENDING`、35件の `CHAIN_PREDECESSOR_NOT_PROJECTED`
4. 固定GameToraとCheckerの独立イベント照合結果：Checker-only40、GT-only非R24、GT-only R395、選択肢数差9（構造不足1＋掲載表示差等8）。RカードはChecker対象外なのでGT-only395をゲーム収録不足と扱わない

各後続段階は、同じカードの `arrows` セクションの直前連続段階を辿り、**元原因イベントのカードID・元ordinal・原因コード・何段後か**を記録する。親が元レポートの除外位置にない場合、順序が重複／飛躍する場合や循環がある場合は失敗する。

出典間差異ではGT側に実位置のある**非RのGT-only24件**と、**SSR30080の3選択肢を元GT1行に圧縮した1件**を元イベントIDへ結び付ける。一方、既に「結果／シナリオ表の掲載行差」5件や「Checkerの1行だけ記載」3件と確認した8件には、勝手に新しい操作選択肢を作らない。Checker-only40件は元GT側に同じイベントが必ず存在すると推定せず、20件のGTカード欠損と20件のイベント未ペアを別の独立した一覧で保持。固定GTとCheckerの両方にない連続3件も別数で保持する。

## 出力とゲート

`whole-event-output/phase2_cross_source_release_triage.v1.json` は固定全件 GitHub Actions の期間限定成果物としてのみ生成する。各イベントのカードID、元ordinal、イベント内容SHA、原因コード、異常ラベル、元原因位置・深さだけを保持する。**出典の見出し・選択肢原文・効果文章・GameWithの記事本文・投影カタログ本体は含めない**。Git管理ディレクトリへの誤出力は拒否し、通常公開DB `poc/data/reviewed_events.v1.json` と承認台帳に変更しない。

- A（機構）：連続第1段階の1つの原因が第2/第3へ波及する人工データ、同名・ID混同、外部ソースの位置の不整合、未対応の除外理由、既に裁定済みの8掲載差分の扱いをNodeで検証。
- B（固定元）：固定全件CIで2,488件、旧辞書の直接原因75／後続35、GT/Checker重点差異65（40＋24＋1）、掲載行の解釈済み8と対象外R395を厳密に照合。結果に基づく実測値を追記する。
- C（表示）：通常アプリや[独立の通常8イベント試用ページ](phase2-eight-pages-browser-preview-20261023.md)は変更しない。新データのPagesユーザー表示やWindows・Android物理端末は対象外。

## 次の実装判断

1. **GT基準の3択構造補正**：SSR30080/6について、裁定済みのプレイヤー操作3択を元GTの操作なし1行へ上書きせず、出典位置＋SHAを保持した非公開補正版として本番イベント型と統合してテストする。未記載の結果・効果範囲は捏造しない。
2. **旧辞書の根本原因75件を別扱い**：2026年の別資料で解消された名称・レアリティ依存の証拠を区分し、35後続段階は先行の修正結果を継承する。古い技術制限を新しい出典差異と同一視しない。
3. **元GT・Checker差異**：非R GT-only24とChecker-only20（GTカード存在）の未ペアについて、カード固有GameTora→疑義のある位置だけGameWithで照合する。GT欠損4SSRの20件は既存のGameWith編集採用台帳へ参照接続する。
4. **公開判断**：本番DBへの収録時に出典・独自UI・公開利用範囲・イベントSHA付き6区分の人手承認を別途行う。

**変換できたこと、分岐の記載が正しいこと、権利上公開できること、Webアプリで実際に使えることはそれぞれ独立。**
