# Phase 2：4SSRの連続12段階を手動到達指定でブラウザ試用（2026-10-23）

**2026-10-23追補：** 同じ画面は[SSR30221の連続3段階](phase2-30221-chain-pages-preview-20261023.md)も追加し、現行の試用対象は**5SSR・15段階・22結果行・9ヒント・未確証17遷移**。以下の4SSR・12段階と15遷移は初版の内訳であり、SSR30221は別出典を監査した3段階として加わる。

## 入口と目的

[GitHub Pages・連続イベント段階別試用](https://nimrodx0.github.io/Umasupport/poc/phase2-chain-preview.html) を独立ページとして追加する。既存の[通常イベント8件](https://nimrodx0.github.io/Umasupport/poc/phase2-eight-preview.html)の試用ページと相互に移動できる。

固定GTにないSSR30318〜30321の4枚について、GameWithで数値採用済みの**連続イベント12段階・19結果行・8件の数値スキルヒント**をブラウザで試せる。ただし、[手動段階到達の編集検査](../poc/src/phase2_chain_manual_replay.cjs)で列挙済みの前段15遷移候補は、すべて続行・打ち切りが**未確証**である。この画面は段階を自動的につなげない。

## 段階の操作と到達条件

各カードの連続第1・第2・第3段階を独立した領域に表示する。

1. 初期状態では**全段階未到達**とし、どの選択肢も報酬は集計しない。プレイヤー選択が存在する段階では、到達するまで選択ボタンを無効化する。
2. ユーザーが明示的に**「この段階に到達した」**をクリックすると、その段階だけを検討対象にする。2択段階ではさらに「上・下」を指定した場合だけ対応するヒント経路を計上。0択段階では到達を指定したときだけその行のヒント経路を計上する。
3. 第1段階を指定しても、第2・第3段階には自動的に到達しない。第2段階を解除しても第3段階の明示的到達指定は勝手に変更しない。**イベント内部の遷移可能性は入力者が確認したことにされず、画面からも推定できない。**
4. 数値効果は記事の採用済みの短い数値表現で表示する。**スキルは照合済みの日本語スキル名とヒントLvで表示する。** 内部の数値IDは報酬ルート照合にのみ使用し、名前が不明ならIDで代替表示せず検証エラーで停止する。各段階にはGameWith記事に掲載された**正式な短いイベント見出し**を表示する。ゲーム台詞・攻略記事の選択肢文章や画像は収録しない。

ページは開発用の**公衆閲覧可能な試用デモ**である。通常版アプリの`poc/data/reviewed_events.v1.json`と`poc/config/event-release-approvals.v1.json`は変更しない（正式公開0件）。ブラウザ内で見える「到達」は手動の仮定であり、実ゲームでの発生や全ての後続条件が保証されるわけではない。

## 固定データとテストの境界

- `poc/src/phase2_chain_pages_preview_artifact.cjs` は既存の `phase2_chain_manual_replay.audit()`、正式名称採用済み4SSRの8件表示台帳を**読んだうえで**、4×3段階・19結果行・8ヒント・15不明遷移を保存する。出典の連続到達フラグはfalseでないとデータ生成を拒否する。
- `poc/preview/phase2-chain-stages.v1.json` は上記生成器の**完全一致**をNode CIで確認。公開利用根拠や人手署名の捏造は行わず、未公開事実の新規スクレイピングも実施しない。
- ブラウザ `poc/src/phase2_chain_pages_preview.js` は `UmaCore.directRoutes` を使用。対象段階をユーザーが確認するまではランタイムイベントに登録すらしない。ゲーム内IDや連続到達の仮の`requires`を創作しない。
- CIのLinux ChromiumでPages風の `/Umasupport/poc/phase2-chain-preview.html` を開き、4カード、各3段階、全段階初期非到達、上／下・0択、8ヒント、デスクトップ／390px、横スクロール、未承認フラグ改ざんの拒否、外部GETなしを試験。

A：編集事実12段階・8ヒントのNode機構とランタイム、ブラウザでの明示到達分離。B：既にGTサイト確認済み・GameWith個別裁定済みの数値事実を再検証し、新しい外部裁定はしない。C：GitHub Pagesの実デプロイとCI/Linux Chromiumでの操作を確認するが、Windows/Android物理端末試験は別。

## 残る本番収録の条件

正式な連続イベントグラフとするには、**後続・打ち切りを決定する各前段の選択／結果条件**についてGameWith掲載事実を追加で確認し、確証がない経路を利用者向け通常集計に自動追加しないこと。独自表示・利用条件・出典・イベントSHAに紐付く6観点人手承認は別。**段階別の単独試用を全体分岐の実装完了と呼ばない**。

## 2026-10-23：日本語スキル名8種類・段階見出し12件の表示改善

[固定UmaSimスキル辞書](https://github.com/mee1080/umasim/blob/cf9366f6a487bd8f197b53d8a11981207beb9f6c/data/skill_data.txt)の該当8数値IDについて、GitHub Actions上で実ファイルを取得して一件ずつ名前・レアリティを照合し、`poc/data/curation/phase2_chain_skill_display_names.v1.json`へ最小の名称対応だけを固定した。例：勇迅円刃、憂いなし、アンストッパブル、ぶっちぎり！、スリップストリーム、解き放つ情念、一往直前、月影円刃。

段階を特定しやすいよう、既存の個別GameWith記事に掲載される12件の正式な短いイベント名を `poc/data/curation/phase2_chain_event_headings.v1.json`へ整理した。出典はライスシャワー[30318](https://gamewith.jp/uma-musume/article/show/578814)、ナリタブライアン[30319](https://gamewith.jp/uma-musume/article/show/578819)、アドマイヤグルーヴ[30320](https://gamewith.jp/uma-musume/article/show/578818)、ドゥラメンテ[30321](https://gamewith.jp/uma-musume/article/show/578817)。公開JSONは変更後も既存の12段階／19結果行／8ヒント／不明15遷移を保持し、**数値事実以外の選択肢文章・攻略記事本文は含まない**。

データ生成時は固定8種類のID→名称の一意対応、数値ID/Lv、既存の`verifiedSkillName`との一致を厳格に検査。ブラウザ側もID代替ラベルを拒否し、選択したヒントの名称が見つからなければ誤った名称の表示をしない。
