# 既存2,512件：イベント名を残し、選択肢・結果だけ仮称化（2026-10-30）

## ユーザーの決定

**イベント名は保持。選択肢のセリフは使用せず、選択肢1（仮）／選択肢2（仮）などの順序付き仮称を使用する。** 成功・失敗等の結果ラベルも結果1（仮）等に揃える。イベント名を「イベント001」に統一する数値専用案は採用しない。

これは**UIとデータ形式の決定**であり、イベント名や第三者由来DBの再利用許諾が得られたという決定ではない。元出典の利用条件と個々の短い見出しの扱い、出典の創作的データベース構成の利用可否は引き続き独立の公開条件となる。

従来の「男性トレーナー向けの選択肢文言優先」「GameWithの選択肢台詞で補完」は、**将来、原文の収録を改めて決定し、出典と権利を確認した場合**の仕様として保留する。現行版では台詞の再収録を求めない。

## 実装と整合条件

- `poc/src/phase2_title_choice_projection.cjs` を追加。固定最終非公開カタログの各イベントの **name、ID、type、順序、スキルID・ヒントLv、数値・非スキル報酬、内部requires、終端フラグ**をそのまま保持する。
- 選択肢・結果の `label` だけを**すべて**「選択肢N（仮）」「結果N（仮）」で置換。元々3件存在した非標準選択肢ラベル、11件存在した非標準結果ラベルも**出典の表示文言を引き継がない**。事実上すでに仮称だった他のラベルも単一規則に統一する。
- カタログの全階層で**許可済みのフィールド一覧**を照合し、新しい `story`、`dialogue`、未分類の自由文、未分類報酬条件が現れたら実行を停止する。編集済みデータを外へ出す処理はない。
- `public_event_catalog.preflight/attach` を実データ2,512件に通す。選択肢ID、結果ID、内部条件、報酬、全数値効果の構造は、表示ラベルだけを除いて**全件で完全一致**させる。563枚について未選択／代表選択の2状態、1,126状態のスキル経路も同等であることを確認する（これは全組合せの実プレイを示すものではない）。
- `poc/tools/probe_gametora_app_schema_dry_run.cjs` の既存フル監査でこの整形器を使い、同一の **563枚／2,512件**をChromiumのメモリ内ファイル選択でも試す。書き込み可能なローカル環境の**明示的な** `UMASUPPORT_PRIVATE_LOCAL_EXPORT_DIR` が指定された場合は、今後この整形後カタログを非公開JSONに出力。GitHub Actionsでは出力を拒否する。
- **公開ゲートは未解除。** 既存 `event_release_gate.verifyRelease` に0件の承認台帳を渡すと、2,512件の公開は拒否されることを固定CIで確認する。`poc/data/reviewed_events.v1.json` と公開承認台帳は0件のまま。法的・契約的な公開根拠を自動生成／捏造しない。

## 次の課題

**実ユーザーにファイル選択を要求しない**ため、イベント名を含む独自の構造化事実DBが公開可能かを、出典／創作的な表現／アクセス条件ごとに評価する。一度に全2,512件を公開してよいと確定する証拠は現段階では存在しない。可能な条件が成立したとき、**同じ整形器の出力形式を既存の本番公開ローダーに接続**するが、現在の個別署名ゲートを無断で迂回することも、未承認イベントを公開することもしない。
