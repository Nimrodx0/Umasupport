## 最終目標とスコープ

全対象サポートカードについて、本育成・継承育成のデッキを手動作成・比較し、**通常ヒント、イベントの選択肢／結果／後続分岐、スキル階層、重複、目標カバー**を確認できるWebアプリ。自動最適化・サポカ以外の経路・イベントの外部的な発生確率は対象外。詳細は [requirements.md](requirements.md)。

## 工程（A／B／Cを独立判定）

| Phase | 目標 | 次の完了条件 |
| --- | --- | --- |
| 0 基盤 | GitHub Pages、取得検証、キャッシュ・CI | 再現可能な手順、ソース障害時の復旧と本番同等の環境確認 |

| 2 イベント | 全カードのイベント・選択・結果・内部連続条件・報酬 | 対象カードで実イベントの収録範囲を分類、数値と分岐を監査、独自公開データと公開ゲート・操作試験 |
| 3 利用者機能 | デッキ、保存、逆引き、所持、目標・検索 | F-01〜F-09のA/B/C受け入れを全対象に実施 |

## 依存と当面の優先順

**2026-10-29最新方針：サービス完成を優先し、イベント取得は第三者GitHubのGameTora派生JSONへ復帰する。** 新規サポカをUmaSim全カード名簿の差分で検出し、`systemless10/UmamusumePS` の対象 `support_<ID>.json` を固定コミットで取得・検証して独自DBへ**増分追加**する。既存カード・イベント・ユーザー設定・承認記録の全件再生成／上書きは禁止。元JSONの更新が遅れている新カードは、イベントが存在しないのではなく**未入手／保留**と明示し、別のカードの機能完成を妨げない。

**GameTora本体HTMLの汎用直接取得器は未完成のまま開発保留**とする。試験コード・根拠資料は残すが、これの完成・構造別100%解析・Chrome再実測は、以下の製品作業やGitHub派生JSONの採用の先行条件ではない。2026-10-27の直接取得への全面移行方針、および2026-10-29午前の「直接取得器を必ず完成させてから下工程へ」という依存を**撤回**する。旧実証の数字を派生DB品質の保証に転用しない。

### 現在の製品完成への作業順（必須）

1. **派生GitHubの新カード取得・更新判断を安定化**：Gitツリー／blobとUmaSim差分から、取り込み済み・JSON存在・未掲載・更新・検証不合格を独立分類。JSONが存在しても即採用せず、バージョン・カードID・完全なイベント構造の検査を通す。前回未取込IDを翌日以降も保留。既存GitHubの監視・全件監査・固定ピン資産を再利用する。
2. **イベント収録を実用レベルにする**：既存のGameTora派生JSONの全件変換器と独自イベントスキーマをつなぎ、選択／排他的結果ごとのスキル・ヒントLv・直接付与と、連続内部の打ち切り・後続依存を保持する。データ不足をスキルなし・無条件獲得に変えず、根拠のあるカード／イベント単位で収録可能と保留を分ける。個別疑義はGameWithで裁定し、GameTora元サイトHTMLの自動スクレイピングを義務付けない。
3. **利用者機能と配信を完成**：本育成／継承デッキの保存・切替、イベント設定、統合／比較、重複、所持・逆引き、目標セット、0〜4凸のヒント性能、検索、設定JSON入出力をF-01〜F-09ごとに実操作で確認し、未実装／不具合を修正する。通常ヒント・スキル辞書のUmaSim直接取得／キャッシュは維持。
4. **全件監査・公開ゲート・実環境**：サポカ母集団、派生JSONが存在するカード、各イベントの対応済・欠損・裁定保留の件数と版を正確に別々に測る。公開できる独自イベント事実に限って権利・ID／到達・レビューゲートを通す。Pages上のChromeとWindows／Androidで実画面・キャッシュ・設定復元・新カード増分追記を確認し、未完了を明示する。

必要な機構の実装PRは段階的にマージできる。ただし**主データを実際の公開イベントDBへ追加し、収録・出典・ブラウザ検証を達成すること**がPhase 2の完成条件であり、単体テストのみや非公開イベント候補の件数だけでは完成ではない。[新しい作業境界](derived-github-primary-restart-20261029.md)、[検証計画](verification-plan.md)を参照。

### 汎用変換器から継続更新工程へ進むための先行ゲート

**旧GameTora HTML直接取得方式専用のゲート（2026-10-29保留）**。[4Aの履歴的な受け入れマトリクス](verification-plan.md#4a-gametora汎用取得変換器の次工程引き渡しゲート)は、将来直接取得を再開したときの参照資料として保持する。**派生GitHub JSONを入力とする製品開発には適用しない**。新しい派生JSON・イベント収録・アプリ配信の検証は[4B](verification-plan.md#4b-構造化github派生dbによる製品完成ゲート2026-10-29)を用いる。

**イベント開発の実行単位（2026-10-26更新）：** 未対応イベントをカードごとの個別プログラムではなく、固定GT全母数の原因別コホートで分類し、効果コード／分岐規則ごとの**共通変換器を一括適用**する。既存の検証A/B/Cは維持するが、1イベントごとに専用overlay・専用PRを増やさない。出典が曖昧な規則は同種全部を保留し、出典に明記されたまとまりから変換する。[全件コホートと最初のU.A.F.対応](phase2-gt-batch-cohort-uaf-20261026.md)。

**出典更新の運用ゲート**：新カードは派生GitHubデータだけの更新待機ではなく、一定の待機期間後に元GameTora公式サイトをカード単位で確認し、その詳細にも欠損が残る場合のみGameWithで補う（[現行手順](upstream-refresh-operations.md)）。公式サイトの事実・結果を自動採用したり原文を転載する更新ジョブはまだ未実装。既存の[継続更新手順](upstream-refresh-operations.md)の毎日日次元blob差分監視→単一レビューIssue→**メタデータだけの未採用Draft PR**を保守する。新規の実元候補に対する**全件の構造・カード・スキル辞書preflight**は実装済みだが、出典内容の内部報酬／GT↔UmaSim数値スキルIDの**意味と経路の独立裁定**は未自動化。残る工程は実候補の陽性ケースでのB全件実地確認と、人間が確認した固定ピン採用PRの作成。監視・候補Draftの成功を正式イベント公開やシナリオ対応の完了と扱わない。

1. **Phase 2・現行の独立IDと全件収録範囲を検証**。固定GameTora由来データの技術用スキル投影と、ゲーム実機の独立再現を必須条件にせず、採用元のGameTora固定版と例外裁定元GameWithの掲載事実を正とする。旧2025年マスター名でのみ対応したスキルIDと、GameTora側が元データを持たないカードについて、最新の独立出典と例外位置を検査する。[現在の母集団・出典と残件](status.md)。
2. **Phase 2・本番イベントの公開ゲートを整備**。イベント内部の結果・選択依存を維持した独自の日本語表示、元データと表現の再利用条件、出典の追跡、ユーザーが承認した公開イベント台帳を用意する。技術変換成功を一括で正式収録・公開承認済みに昇格しない。出典に明記された事実の採用に実ゲーム再実測を追加要求しない。[公開時の要件](checker-public-catalog.md)。
3. **Phase 1・カード／スキル辞書の独立照合**。カードと通常ヒント、ヒント性能、階層、特殊IDの独立検証を実施する。異IDの同名スキルを勝手に同一化せず、2025年限定の古い名称を現行の確定値に置かない。
4. **Phase 3～5・機構／母集団／受け入れの分離試験**。GitHub Pagesでのブラウザ試験に加え、採用元に明記された内部報酬分岐・Windows／AndroidでのWebアプリの表示／操作を別々に確認する。発生確率等の外部条件と、内部連続分岐・打ち切りを混同しない。

**直接取得器は保留**。他機能の実装、派生JSON経由のイベント収録、増分更新、Pages検証を直接取得器の完成でブロックしない。ただし各工程の正確性・権利・公開承認は省略しない。対象範囲を縮めて完了宣言するには利用者の仕様決定が必要です。実データと数値の最新状況は [status.md](status.md) に記録します。

## 現行方針（参照先）

- 旧イベント基準の変更目標（2026-10-27、2026-10-29撤回）： [GameTora本体の直接取得への移行](upstream-refresh-operations.md)を少数カードで実証し、第三者GitHub派生データを検証用へ降格する。**現在の実装基準は依然として[GameTora由来固定データ](gametora-baseline-event-policy-20261021.md)**。未実証のWeb取得を本番に切り替えない。GameWithは**元サイトの疑義・欠損のみ裁定**。GameWith-firstの旧案は廃止。
- イベント内部の分岐／打ち切りは必要、発生確率や絆等の外部条件は対象外：[要件](requirements.md)・[判断履歴](decisions.md)。
- 再配布と大規模取得の制約は別々に判断：[イベントデータ権利・取得](event-data-acquisition-rights-20261019.md)。
- 公開ゲート：[イベント公開審査](checker-public-catalog.md)、[検証計画](verification-plan.md)。
