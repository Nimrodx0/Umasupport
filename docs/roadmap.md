## この文書の役割

本書は「何をどの順序で完成させるか」を定義する。各実装PRの作業履歴、ソース監査の細かな数値、過去の採否は [開発履歴](development-history.md) と個別の監査文書・Issuesに記録する。

- **進捗と完了を分ける。** 部分実装、人工データの単体試験、実ソース全件監査、実ブラウザ検証は別の証拠であり、相互に代用しない。
- 各フェーズは **機構・データ品質・実機動作** の三軸で [ゲート](verification-plan.md) を定義し、スコープ内の必須条件を満たして初めて完了とする。
- フェーズ間で実装や調査を並行してよい。ただし依存元のゲート未達成を、依存先の「完成」や「本番収録」に読み替えない。
- 未解決事項は件数・影響・検証方法・担当Issueを記録する。除外する場合はユーザーが対象範囲を変更し、要件と判断履歴へ反映する。

## 最終目標

本育成と継承育成の二つの6枚編成を、通常ヒント・イベント経路・スキル上下関係・獲得候補の重複・目標カバーで比較する静的Webアプリ「ウマサルタント」を完成させる。サポートカード全体を対象とし、自動編成・獲得確率推定は行わない。詳細は [F-01〜F-09](requirements.md#3-機能要件)。

## Phase 0：開発基盤とアーキテクチャ

**成果物**：リポジトリ、再現可能なCI、GitHub Pages、外部ゲームデータの検証・キャッシュ・障害復旧、データと表示の責務分離。

**残作業**：提供元利用条件・アクセス負荷・形式変更／停止への対策、データ版管理、起動障害を追跡できるログとテスト。実データ同梱の旧v8.1の再ビルドは歴史的な移管課題であり、直接取得版の必須完了条件ではない（必要性を別途判断）。

**完了条件**：独立したセットアップから再現でき、コード・データ・保存領域の障害と復旧が設計どおりにテストされ、必要な利用条件の判断が記録されている。

## Phase 1：カードとスキルの完全化

**成果物**：対象カードのID台帳・通常ヒント、スキル数値ID、金白・○◎上下関係、レアリティ／分類、標準表示順、ヒントLv／発生率・解放段階情報。

**残作業と判定**：[GameTora日本版との563カードID一致](card-population-independent-audit.md)、[4凸通常ヒント4,015件の別公開資料への名称掲載確認](gametora-targeted-hint-audit.md)、さらに[UmaSim内の0〜4凸2,815行で通常ヒント集合が完全不変](stage-hint-consistency-audit.md)を確認。**SSRエフフォーリアを含む6枚の0〜4凸ヒント性能60数値**はGameWithの別資料と一致。322組の金白系列は321組で数値IDを含む別JSONの確認、1組は名称のみ別記事で確認。スキル辞書の数値ID`201012`はUmaSimに欠けているため別ソースと旧マスターで裏付け、推測補完はしない。

一方、**現行ゲーム公式マスターでの全カードと全数値スキルID・0〜4凸性能の独立検証、条件付き固有効果、2026年の標準表示順・同値の並び、物理Android/Windows実機での変更後受け入れ**は未完。公開資料間でID・名称が一致しても公式ゲーム実装の正しさや資料の来歴を証明しない。詳細は[検証計画](verification-plan.md)を参照。

**完了条件**：分母を明示した全件監査で対象レコードを「検証済み／根拠付き非該当／未解決」に分類し、誤統合・推測補完を防止でき、階層と直接／間接カバーを実ブラウザで検証済み。保留カードを全件完了と呼ばない。

ゲーム内の表示順について、[2025年マスターの`disp_order`を1,786共有IDで確認](historical-skill-order-probe.md)したが、同値グループ214と古い版のため、そのまま2026年の標準順として採用できない。数値ID`201012`の旧マスター存在も確認。

詳細：[拡大通常ヒント監査](expanded-card-hint-crosscheck.md)、[カードID独立母集団監査](card-population-independent-audit.md)、[通常ヒント527件の別資料照合](independent-card-hint-audit.md)、[金白スキル全件監査](skill-hierarchy-coverage.md)、[2026年版の独立照合](independent-skill-json-audit.md)、[Pages実ブラウザ受け入れ](pages-browser-acceptance-20261017.md)。

### 2026-10-18：イベント取り込み安全性と公開前ゲートを追加（PR #66〜#70）

SSR30311のWikiイベントリンク5件、GameWith選択肢11位置を突き合わせ、候補が2イベント・8選択肢位置を欠くことを具体的に把握。GameWith/Game8の連続3段目スキルヒント結果16件の一致と、体力/絆の局所的な資料差を記録。**イベント候補の全件検証ではなく、B軸は未完。** [監査](unreviewed-event-numeric-candidate-audit.md)参照。

イベントレビュー変換の成功／大成功別出力と、複数選択肢の無条件化防止、`rewards` と `outcomes` の同時指定拒否を実装。さらに配信JSONのイベント内容SHA-256と人手承認・根拠URLを照合する **CI公開ゲート**を追加。 [公開手順](checker-public-catalog.md)・[イベントモデル](event-schema.md)参照。

**攻略サイト間の数値差については2026-10-18にGameWithを暫定優先と決定**し、異なる掲載値を完全に一致させる工程は公開の前提から外した。[意思決定](decisions.md)を参照。GameWith採用を正式ゲーム実測・権利確認と混同しない。 体力・絆ゲージ等の数値は現行のスキル経路集計の対象外なので、その差異は監査に残しても初回収録のブロッカーにはしない。

次に必要なのは **（1）正式イベントIDと選択/結果別報酬・打ち切り/到達条件の版を明示した独立検証、（2）公開表現と利用条件の適法な判断、（3）少数の承認済み実イベントのPages操作テスト、（4）全カードへの段階的な網羅監査**。この順序を守り、実イベントの公開0件、Android/Windows実機の未受け入れを維持する。

### 2026-10-19：全保存イベント候補の経路状態分類（PR #101）

[経路分類と旧マスター仮照合](route-classification-audit-20261019.md)：保存済みのChecker SSR/SR417枚2,109イベントを、カードごとのソース空・イベントID・条件・報酬の未承認根拠に分離。2025年マスターの数値story_idとタイトル指紋を一括突合するが、正式経路としては承認しない。差異は欠損確定ではなく仮説のまま追跡する。公開イベントDBが0件の現段階でイベントの `verified-route` 件数は0を維持し、確証を得て初めて既存リリースゲートへ移す。

### 2026-10-19：数値ゲームマスターによる連続段階監査（PR #102）

[全件段階診断](historical-chain-stage-audit-20261019.md)：旧マスター上954仮一致レコードから910段階候補を抽出。312グループの全段階が構造的に一意にそろい、33グループで欠番、4グループで段階が曖昧。通常アプリへのイベント経路収録は条件・成功分岐・現行版・利用条件が未確認なので実施せず、公開0件を維持する。**段階の完備≠実ゲームでの経路の確証**。

## Phase 2：イベントデータの完全化

**成果物**：サポカ実IDと対応するイベントカタログ、選択肢・連続条件・打ち切り・結果依存報酬、検証済みスキルID、公開可能な独自JSONおよび更新時の差分監査。

**実施順序**：

1. UmaUmaCheckerをSSR・SR候補の主入力とし、欠損／新規を個別資料で補完する現行方針の適用条件・利用条件を検証する（U-toolsは当面使用しない）。
2. **カードの存在率とイベント全件収録率を分けて**調査し、5枚の空データ、既存412枚のイベント欠損、Rカードの扱い、同名・改題を監査する。
3. 実イベントID、到達・継続・打ち切り、成功／失敗、選択肢ごとの報酬スキルIDとLvを独立確認する。不確実な経路は有効化しない。
4. 小規模な実データで変換器・集計・UIを結合検証する。ここは**全件公開の前段検証**であり、工程完了ではない。
5. 対象全カードを展開し、カード別イベント・選択肢・報酬・分岐の全件監査とPages操作テストを完了する。

[歴史的カード別ストーリーIDの照合](historical-event-story-audit.md)で、2025年固定ゲームマスター495枚（UmaSim現行563枚との重複495）、直結ストーリーID1,028件を確認。2026年Checker候補件数が旧ストーリーID件数より少ない3枚（30240/30241/30269）を調査待ちに追加。共通キャラクター経路は代表キャラクターのIDで別計測済み。ただしグループカードの全構成員やイベント見出しとの1対1対応は未確認。さらに[タイトル指紋照合](event-title-fingerprint-audit.md)で2025年旧masterのSS/SR1,017件のうち956名称が暫定一致、61名称が2026年Checker候補に完全一致しないと判明。実イベント正式IDの採用／全件網羅と読み替えない。

[未一致story_idのメタデータ監査](story-residual-metadata-audit.md)で、30241の残1を830241004と特定。2025年DB上のメタデータ値のみで現在のゲームに存在する・欠損しているとは判定しない。

**完了条件**：採用範囲の全カードについて収録状況と欠損が追跡可能で、公開した各イベントの条件・報酬・公開可否が根拠付きで承認済み。単にソースにレコードが存在することを完全収録と呼ばない。SSR／SRを先に完成させても、Rを含む最終要件の完了とは区別する。

詳細：[供給元監査](event-source-selection.md)、[公開イベントDB手順](checker-public-catalog.md)、[イベントモデル](event-schema.md)。

[Phase 3 F-01 デッキ管理の受け入れ記録](named-deck-library-acceptance.md)：本育成・継承育成それぞれが独立した複数の名前付き6枚編成を保持。旧設定v1の検証付き移行、デッキ毎の凸・イベント選択保持、50件上限、削除保護まで導入。人工入力のCI・Chromium通過のみでAndroid/Windows実機は後で一括確認し、Phase 3全体完了とは扱わない。

[F-02 所持サポカ管理の受け入れ記録](owned-card-registry-acceptance.md)：設定v3に疎なownedCardsを追加。所持・未所持・未登録を分離し、各カードの所有凸と編成の想定凸を独立させる。36枚/ページのグリッドと確認付きの絞り込み全件一括操作を実装。カード画像は未搭載、イベント経路検索等は未完。

[F-02 経路別スキル検索の受け入れ記録](card-route-search-acceptance.md)に、イベント候補を正式提供に混ぜない条件、複合フィルター、120枚ページ制限の解消、人工データ検証の境界を記録。

[F-05 スキル表と逆引きのフィルター・ソート](skill-table-search-acceptance.md)：現在編成の直接スキル経路・条件付き・未カバーの目標などを対象に絞り込み。親子階層を崩さず直接提供枚数で並べ替え、全カード逆引きを0～4凸の通常ヒント和集合・公開承認イベントへ拡張。実カード画像・適性条件等は未実装、端末実機未受入れ。

## Phase 4：統合品質保証

## Phase 5：正式公開と保守

**成果物**：公開版、非公式表記、出典・利用条件、更新差分監査・新規カード対応手順・障害時対応。

**完了条件**：Phase 0〜4の公開ゲート通過、利用範囲の明示、継続更新の担当・手順・停止時の表示が確定。公開中のPages PoCと正式版の完成判定を分ける。

## 直近の順序と依存関係

1. **Phase 1ゲートを閉じる**：4凸ヒント4,015件の別資料掲載と採用元0〜4凸通常ヒントの不変性は確認済み。[6枚5段階の60数値の外部照合](stage-hint-consistency-audit.md)を他カードのヒント性能へ拡張し、金白数値IDの残件・ゲーム標準表示順を追跡する。実機Android/Windowsの必要操作は利用者の意向に従いまとめて確認する。
2. **Phase 2の供給元と網羅の証拠を揃える**：417カード／2,099候補と、実イベント全件性・連続条件・スキルID・利用条件は別に監査。
3. **実イベントを少数で結合試験し、その後対象全件へ展開**。部分試験を公開収録完了としない。
4. 並行してPhase 3のUIを進め、Phase 4の受け入れマトリクスを機能ごとに埋める。
