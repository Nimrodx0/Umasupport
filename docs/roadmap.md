# 開発ロードマップ

この文書は**未完の作業順と完了条件だけ**を記す正本です。達成数と最新の検証結果は [開発状況](status.md)、旧工程・当時の未公開前提は [2026-11-05以前のロードマップ全文](archive/roadmap-through-20261105.md) に保存しています。旧文書に残る「次工程」を現行指示と解釈しません。

## 目的と判定

本育成と継承育成のサポートカードを、通常ヒント、公開承認済みイベント別の獲得候補、上位／下位、重複、目標カバーで比較できる実用的なアプリを完成させる。取得可能な候補の集計とゲーム内での確定入手を混同しない。正しい値・公開許可・実環境の合格は独立に扱う。

| 判定 | 完成に必要な確認 |
| --- | --- |
| A：機構 | デッキ、イベント選択・打ち切り、集計、検索、復元、エラー／キャッシュ復旧の回帰 |
| B：データ | 出典の版・ID・結果・公開承認と保留理由が対応し、未収録をゼロ報酬と誤認しない |
| C：実環境 | Pages、Windows／Android物理端末の表示・操作、通信失敗・復帰・設定復元を独立検証 |

合否基準は [verification-plan.md](verification-plan.md)。CIやChromiumが通っても、現ゲームの全件網羅や物理端末での合格は宣言しない。

## 現在の製品完成への作業順（正本）

1. **公開済みイベントの利用受け入れ**：承認済みの公開イベントを基準に、デッキ・イベント設定・結果の排他・連続打ち切り・目標カバー・保存／復元を実ブラウザと物理端末で横断検証する。公開件数の実測は [status.md](status.md) を参照。旧「公開開始前に利用を止める」という工程は完了・置換済み。
2. **出典別の保留例外と公開条件**：GT由来でGameWith補正が入ったイベントや別出典からの編集追加イベントは、別出典の利用条件・事実・イベント名・結果分岐をそれぞれ確認する。確認できないものは公開保留のまま維持し、承認を捏造しない。[Issue #302](https://github.com/Nimrodx0/Umasupport/issues/302)、[出典例外監査](phase2-source-lineage-exception-map-20261102.md)。
3. **新サポカの継続更新**：UmaSim全カード名簿の差分で増分IDを検出し、第三者GitHubの構造化GameTora派生JSON（systemless10/UmamusumePS）を版固定で検証・変換。JSON未掲載は翌日以降も[Issue #283](https://github.com/Nimrodx0/Umasupport/issues/283)に保留。既存の承認イベント・設定・カードを全件再生成／上書きせず、正式な増分公開ゲートを通す。
4. **未解決のデータ差異を優先度別に再検証**：既存563カード・非公開2,512イベントの技術変換基盤は再作成しない。SSR30240の連続3段階は明示保留済み、CheckerのP2未同定11位置、条件付きヒントや非スキル効果の保留は必要な位置に限定して追跡。出典未掲載は当該位置だけ保留し、他の作業へ進む。[対応監査](phase2-remaining-checker-skill-impact-20261023.md)／[SSR30240](phase2-30240-gamewith-gap-utools-only-replay-20261022.md)。
5. **運用品質を仕上げる**：更新元の仕様変更・欠損・配信停止を安全に検出し、利用者設定を破壊せずキャッシュから復帰できることを検証。出典利用条件・公開リリース・ロールバックを独立してレビュー。

既存DBの一括利用と例外管理が主工程。2,512件を1件ずつ手動承認することを製品完成の前提条件にしない。公開済みの集合と保留例外は別の集合であり、保留を暗黙に配布しない。

## 並行トラック：スキル発動条件とサポカ傾向

出典の明示条件（脚質、距離、馬場等）と順位・時期・位置から推定する傾向を分ける。GlobalSimで計測したモデル上の順位条件成立率を実ゲームの発動確率として表示しない。詳細は [設計](skill-activation-tendencies-design.md) と [現在のP0～P2進捗](status.md)。

1. **P0 全件構造監査**：UmaSim条件型、AND/OR、複数発動条件を固定データで調査（実装済み、変更時再監査）。
2. **P1 発動条件モデル**：明示制限・状況条件・追加効果条件を別々に表現（実装済み、回帰を維持）。
3. **P2 発動条件適合性v1.3とアプリ収録照合（研究専用）**：元順位条件の人数換算 #350、[2,160レースの厳密順位帯比較 #351](skill-position-rank-band-fit-20261106.md)で新たな24スキルの研究用脚質適合性を判定。既存53件の高106／低106は不変。[**収録先の独立ID・名称・元条件監査 #352**](skill-rank-band-app-identity-20261106.md)により、**公開アプリ881スキル中で追加17件が三点一致、7件は未収録**。次の未完ゲートは①17件の**通常ヒント・公開イベント・選択済み分岐の獲得経路**と利用者設定への集約を個別に確認、②明示脚質・追加AND・複数Invoke／preConditionsの保留ルールを厳格に検証、③絶対レース条件・根拠・保留をP3カード集約へ渡す形式を設計すること。**アプリに存在する≠カードから獲得可能**、モデル順位占有率≠実スキル発動率。旧53件の公開ラベル、P3/P4の実装・配布データは変更していない。**追加の軽量調査（未着手）**：展開依存の適合性推定は脚質を主対象とし、距離・馬場が順位・追い抜き等に与える実質的な影響を既存研究と代表条件で簡易確認する。カードの適性判定に影響する差が確認できない場合は距離・馬場別の展開依存推定を追加せず、明示条件のみ維持する。無視できない差が確認された条件だけ追加研究し、調査前に「影響なし」と判定しない。
4. **P3 カード単位の集約**：通常ヒント（凸別）／公開済みイベント候補／実選択済み結果を区別し、重複と未収録を厳密に集計。
5. **P4 検索・表示**：コンパクトなカードUIを維持し、明示／推定別フィルターと根拠詳細を追加。
6. **P5 統合受け入れ**：人工データ、固定全件データ、Chromium、Pages、Windows・Android物理端末で独立検証。

## 実装の境界と変更規律

- **主入力**：GameTora派生GitHub JSON。GameWithは元資料に具体的な欠損・疑義がある場合だけ採用事実を裁定する。旧GameWith-firstと、GameTora元サイトHTMLを必須で直接取得する計画は撤回・保留。直接取得の過去実験は保存し、製品完成の先行ゲートにしない。
- **技術変換と公開を分離**：旧マスターを使う検証はその時点の固定技術変換の根拠で、現在のゲームの完全再現・ライセンス許可・公開承認の代わりにならない。イベント本文・画像・未承認の第三者DBをそのまま公開しない。
- **優先順位の更新**：変更時はこの一つの番号付き作業順を**上書き**し、達成と実測は [status.md](status.md) を更新する。旧内容はPR・監査・必要時の履歴に保存。新しい公開判断や要件変更は [decisions.md](decisions.md)／[requirements.md](requirements.md) と一致させる。
