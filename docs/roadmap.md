# 開発ロードマップ

この文書は**未完の作業順と完了条件だけ**を記す正本です。達成数と最新の検証結果は [開発状況](status.md)、旧工程・当時の未公開前提は [2026-11-05以前のロードマップ全文](archive/roadmap-through-20261105.md) に保存しています。旧文書に残る「次工程」を現行指示と解釈しません。

## 目的と判定

本育成と継承育成のサポートカードを、通常ヒント、公開承認済みイベント別の獲得候補、上位／下位、重複、目標カバーで比較できる実用的なアプリを完成させる。取得可能な候補の集計とゲーム内での確定入手を混同しない。正しい値・公開許可・実環境の合格は独立に扱う。

| 判定 | 完成に必要な確認 |
| --- | --- |
| A：機構 | デッキ、イベント選択・打ち切り、集計、検索、復元、エラー／キャッシュ復旧の回帰 |
| B：データ | 出典の版・ID・結果・公開承認と保留理由が対応し、未収録をゼロ報酬と誤認しない |
| C：実環境 | Pages、Windows／Android物理端末の表示・操作、通信失敗・復帰・設定復元を独立検証 |

合否基準は [verification-plan.md](verification-plan.md)。CIやChromiumが通っても、現ゲームの全件網羅や物理端末での合格は宣言しない。

## 現在の製品完成への作業順（正本）

1. **公開済みイベントの利用受け入れ**：承認済みの公開イベントを基準に、デッキ・イベント設定・結果の排他・連続打ち切り・目標カバー・保存／復元を実ブラウザと物理端末で横断検証する。公開件数の実測は [status.md](status.md) を参照。旧「公開開始前に利用を止める」という工程は完了・置換済み。
2. **出典別の保留例外と公開条件**：GT由来でGameWith補正が入ったイベントや別出典からの編集追加イベントは、別出典の利用条件・事実・イベント名・結果分岐をそれぞれ確認する。確認できないものは公開保留のまま維持し、承認を捏造しない。[Issue #302](https://github.com/Nimrodx0/Umasupport/issues/302)、[出典例外監査](phase2-source-lineage-exception-map-20261102.md)。
3. **新サポカの継続更新**：UmaSim全カード名簿の差分で増分IDを検出し、第三者GitHubの構造化GameTora派生JSON（systemless10/UmamusumePS）を版固定で検証・変換。JSON未掲載は翌日以降も[Issue #283](https://github.com/Nimrodx0/Umasupport/issues/283)に保留。既存の承認イベント・設定・カードを全件再生成／上書きせず、正式な増分公開ゲートを通す。
4. **未解決のデータ差異を優先度別に再検証**：既存563カード・非公開2,512イベントの技術変換基盤は再作成しない。SSR30240の連続3段階は明示保留済み、CheckerのP2未同定11位置、条件付きヒントや非スキル効果の保留は必要な位置に限定して追跡。出典未掲載は当該位置だけ保留し、他の作業へ進む。[対応監査](phase2-remaining-checker-skill-impact-20261023.md)／[SSR30240](phase2-30240-gamewith-gap-utools-only-replay-20261022.md)。
5. **運用品質を仕上げる**：更新元の仕様変更・欠損・配信停止を安全に検出し、利用者設定を破壊せずキャッシュから復帰できることを検証。出典利用条件・公開リリース・ロールバックを独立してレビュー。

既存DBの一括利用と例外管理が主工程。2,512件を1件ずつ手動承認することを製品完成の前提条件にしない。公開済みの集合と保留例外は別の集合であり、保留を暗黙に配布しない。

## 並行トラック：スキル発動条件とサポカ傾向

出典の明示条件（脚質、距離、馬場等）と順位・時期・位置から推定する傾向を分ける。GlobalSimで計測したモデル上の順位条件成立率を実ゲームの発動確率として表示しない。詳細は [設計](skill-activation-tendencies-design.md) と [現在のP0～P2進捗](status.md)。

1. **P0 全件構造監査**：UmaSim条件型、AND/OR、複数発動条件を固定データで調査（実装済み、変更時再監査）。
2. **P1 発動条件モデル**：明示制限・状況条件・追加効果条件を別々に表現（実装済み、回帰を維持）。
3. **P2 発動条件適合性v1.3とアプリ収録照合（研究専用）**：元順位条件の人数換算 #350、[2,160レースの厳密順位帯比較 #351](skill-position-rank-band-fit-20261106.md)で新たな24スキルの研究用脚質適合性を判定。既存53件の高106／低106は不変。[**収録先の独立ID・名称・元条件監査 #352**](skill-rank-band-app-identity-20261106.md)により、**公開アプリ881スキル中で追加17件が三点一致、7件は未収録**。**研究方針を更新（2026-11-06）**：以前の前方群／後方群の2分類を基本判定には使わず、[4脚質の独立比較](skill-position-four-style-pairwise-20261106.md)を先に検証する。11順位帯×4局面×6脚質ペアの比較と前後シード整合性を検査し、特に中団40～80%を先行・差し個別の観点から再検証する。4脚質別の研究用スキル評価規則が確定するまで、以前の53＋追加24件の2群定性ラベルをP3/P4へ自動反映しない。次の未完ゲートは①[4脚質の固定2,160レース実測](skill-position-four-style-pairwise-20261106.md)を踏まえて、**均衡編成の4脚質順位帯比較は[固定根拠](skill-position-balanced-four-style-rule-20261106.md)と[研究専用判定器](../poc/src/skill_balanced_four_style_fit.cjs)に実装済み**。24均衡設定×11順位帯×4局面×6ペアの比較を保留つきで保存し、追加AND/ORが未検証の場合はスキル全体へ格上げしない。**新方針：成立機会と脚質特異性を独立した2軸として確定**。[研究設計](skill-position-two-axis-research-20261106.md)に沿って、固定GlobalSim均衡編成での順位帯距離占有率・一様順位基準との差・脚質ペアの優劣を別項目で生成し、AND/OR保留を維持する研究用スキル照合を実装。**課題①の研究進捗（2026-11-07）**：[10m範囲内の条件成立機会の調査](skill-position-phase-random-opportunity-20261107.md)で、固定UmaSimの `phase_random` がランダム地点1点ではなく約10mの判定範囲を設ける実装であることを確認。GlobalSim均衡720レースで従来の順位帯占有率と10m範囲の幾何学的成立機会を比較し、176組中142組は差1ポイント以内、最大差4.17ポイントを確認。**77件の元条件を再評価し、局面の短いランダム抽選窓の不足を解消**：[全局面のみの旧77件監査](skill-phase10-77-audit-20261107.md)から[元の前半・後半窓を含めた再監査](skill-subphase10-77-audit-20261107.md)へ進み、均衡720レースの同一軌跡で旧モデルSHAの完全一致を検証。**ダート17件の独立モデル再実測も完了**：[実在するダート6コースでの研究](skill-dirt17-10m-audit-20261107.md)で固定GlobalSimのsurface=2と全走路形状ファイルを照合し、720レースの均衡編成から17件・6種類の元順位条件の成立機会を追加。**77スキル中73件で単一経路の順位条件部分を、4件でORの個々の経路をモデル集計**（OR合併は保留）。元81経路を条件に合う芝／ダート別の数値として保持し、元条件・表面を重複除去すると**26芝＋6ダート＝32種類**（無作為代表標本ではない）。**文脈感度検証も完了**：[77件・全81経路のコース／頭数／能力設定監査](skill-context-stability-77-audit-20261107.md)で芝720＋ダート720レースの固定モデルを再実行し、32元条件×4脚質＝128重複除外ケースを調査。20/80の**仮**境界では103/128が文脈を通じて同区分、25件は区分変動（全て差し、9/12頭の平均区分も不一致）。9/12頭の平均差5pt超は43件、能力モード差5pt超は0件、コース別平均差5pt超は3件。**高・中・低閾値は未採用**。**9頭／12頭の差の対照実験を追加実施（2026-11-08）**：[元の9頭固定・追加3頭の脚質変化・整数順位境界の反実仮想による分解](skill-nine-twelve-entrant-cutoff-decomposition-20261108.md)で、固定GlobalSimの芝1600m・ダート1600m／5元条件／720レースを検証。元9頭を維持し、12頭の同一軌跡で9頭用境界と12頭用境界の差を切り出す。例：マイルの支配者・差しでは9頭36.09%→12頭均衡0.02%（境界+0.02pt、追加馬・展開残差−36.09pt）、12頭の追加3頭の脚質を変えると0～55.92%。**頭数のみの純粋因果効果は識別しておらず、実発動率・高中低閾値も未確定**。**4つの人工脚質編成による全32元条件の感度検証が完了（2026-11-08）**：[芝6＋ダート6コース・5,760レースの32条件編成感度監査](skill-roster-sensitivity-32-20261108.md)で、9/12頭・4編成・2能力モード・各30seedの元条件順位10m成立機会を調べた。32元条件×4脚質×2頭数＝256ケース中**123ケースは編成差が確実に20pt超**、仮の20/80区分でも123ケースで区分変動。7ケースは参照モデルでの持続的な順位同点により区間評価、逃げ不在の逃げ64ケースは出走者なし（NULL）とし0%に置換しない。**P3の既定の均衡編成基準は現行決定どおり維持**し、これらの人工編成を現実の出走頻度や本番推奨カード適性に混ぜない。高／中／低境界も未採用。**実対戦のレース単位編成の公開資料監査（2026-11-09）**：[出典別9頭同時編成と相手6頭周辺度数の識別可能性調査](skill-real-joint-roster-evidence-20261109.md)で、2026年1月A決勝の全9頭構成1件（逃1／先4／差1／追3）を確認。2025年10月・12月・2026年1月A予選の相手6頭×40戦＝各240頭の公開周辺度数は、**9頭のレース単位同時分布へ復元不能**。2026年1月の相手逃げ21頭なら『相手6頭に逃げが1頭もいない試合』の数学的な範囲は40戦中19～36戦であり、観測値や推定信頼区間ではない。**従来の均衡編成方針・高／中／低閾値未採用・本番P3/P4非変更は維持**。**未完は①実ゲームの抽選・離散フレーム・順位タイブレーク照合、②同一大会・ラウンドの実9頭レース単位編成の追加公開資料または適法な連続観測と大逃げ分類確認、③9/12頭別の連続値／不確実性表示の合意とP3均衡編成でのカード獲得経路・集約の確定**。発動後のスキル効果の有用性は別の将来軸として保留、②17件の**通常ヒント・公開イベント・選択済み分岐の獲得経路**と利用者設定への集約を個別に確認、③明示脚質・追加AND・複数Invoke／preConditionsの保留ルールを厳格に検証、④絶対レース条件・根拠・保留をP3カード集約へ渡す形式を設計すること。**アプリに存在する≠カードから獲得可能**、モデル順位占有率≠実スキル発動率。旧53件の公開ラベル、P3/P4の実装・配布データは変更していない。**追加の軽量調査（未着手）**：展開依存の適合性推定は脚質を主対象とし、距離・馬場が順位・追い抜き等に与える実質的な影響を既存研究と代表条件で簡易確認する。カードの適性判定に影響する差が確認できない場合は距離・馬場別の展開依存推定を追加せず、明示条件のみ維持する。無視できない差が確認された条件だけ追加研究し、調査前に「影響なし」と判定しない。
4. **P3 カード単位の集約（標準編成）**：4脚質別の研究結果から、**均衡編成だけ**を通常のサポカ適性集約の基準として採用する。9頭（逃2・先2・差3・追2）／12頭（各3頭）の固定研究条件を区別し、均衡編成内の局面・コース・能力差や元スキルの複合条件で根拠が揃わない場合は保留する。観測比率・逃げ不在など他の脚質構成に基づく評価の揺れを標準スコアへ混ぜないが、P2研究の検証根拠としては残す。**均衡編成が現実に最頻の編成であるとの主張はしない**。そのうえで通常ヒント（凸別）／公開済みイベント候補／実選択済み結果を区別し、重複と未収録を厳密に集計。
5. **P4 検索・表示**：コンパクトなカードUIを維持し、明示／推定別フィルターと根拠詳細を追加。
6. **P5 統合受け入れ**：人工データ、固定全件データ、Chromium、Pages、Windows・Android物理端末で独立検証。

**後続のオプション構想（採否未決）**：特定イベント向けに、ユーザーが想定対戦相手の脚質人数を指定し、その編成でのスキル・サポカ適性を標準評価とは別モードで比較する案。人数・自馬を含むか・頭数との整合・任意構成を評価する追加シミュレーションと根拠・UI・保存方法を検討してから着手判断する。固定3シナリオの出力を任意指定への評価として流用しない。

## 実装の境界と変更規律

- **主入力**：GameTora派生GitHub JSON。GameWithは元資料に具体的な欠損・疑義がある場合だけ採用事実を裁定する。旧GameWith-firstと、GameTora元サイトHTMLを必須で直接取得する計画は撤回・保留。直接取得の過去実験は保存し、製品完成の先行ゲートにしない。
- **技術変換と公開を分離**：旧マスターを使う検証はその時点の固定技術変換の根拠で、現在のゲームの完全再現・ライセンス許可・公開承認の代わりにならない。イベント本文・画像・未承認の第三者DBをそのまま公開しない。
- **優先順位の更新**：変更時はこの一つの番号付き作業順を**上書き**し、達成と実測は [status.md](status.md) を更新する。旧内容はPR・監査・必要時の履歴に保存。新しい公開判断や要件変更は [decisions.md](decisions.md)／[requirements.md](requirements.md) と一致させる。
