## 最終目標とスコープ

全対象サポートカードについて、本育成・継承育成のデッキを手動作成・比較し、**通常ヒント、イベントの選択肢／結果／後続分岐、スキル階層、重複、目標カバー**を確認できるWebアプリ。自動最適化・サポカ以外の経路・イベントの外部的な発生確率は対象外。詳細は [requirements.md](requirements.md)。

## 工程（A／B／Cを独立判定）

| Phase | 目標 | 次の完了条件 |
| --- | --- | --- |
| 0 基盤 | GitHub Pages、取得検証、キャッシュ・CI | 再現可能な手順、ソース障害時の復旧と本番同等の環境確認 |
| 1 カード・スキル | 全サポカ、通常ヒント・階層・ヒント性能・表示順 | 対象母集団全数の独立裏付けと例外分類、Pagesと物理端末確認 |
| 2 イベント | 全カードのイベント・選択・結果・内部連続条件・報酬 | 対象カードで実イベントの収録範囲を分類、数値と分岐を監査、独自公開データと公開ゲート・操作試験 |
| 3 利用者機能 | デッキ、保存、逆引き、所持、目標・検索 | F-01〜F-09のA/B/C受け入れを全対象に実施 |

## 依存と当面の優先順

**2026-10-29最新方針：サービス完成を優先し、イベント取得は第三者GitHubのGameTora派生JSONへ復帰する。** 新規サポカをUmaSim全カード名簿の差分で検出し、`systemless10/UmamusumePS` の対象 `support_<ID>.json` を固定コミットで取得・検証して独自DBへ**増分追加**する。既存カード・イベント・ユーザー設定・承認記録の全件再生成／上書きは禁止。元JSONの更新が遅れている新カードは、イベントが存在しないのではなく**未入手／保留**と明示し、別のカードの機能完成を妨げない。

**GameTora本体HTMLの汎用直接取得器は未完成のまま開発保留**とする。試験コード・根拠資料は残すが、これの完成・構造別100%解析・Chrome再実測は、以下の製品作業やGitHub派生JSONの採用の先行条件ではない。2026-10-27の直接取得への全面移行方針、および2026-10-29午前の「直接取得器を必ず完成させてから下工程へ」という依存を**撤回**する。旧実証の数字を派生DB品質の保証に転用しない。

### 現在の製品完成への作業順（正本）

**既存カードのPhase 2は、2026-10-23〜26に全件検証した非公開563カード・2,512イベントを技術上の基準として続行する。** これは[スキル候補の本番互換確認](phase2-30180-special-cornering-2512-20261023.md)と[非スキル効果の後続統合](phase2-outing-unlock-terminal-batch-20261026.md)に基づく。**現行ゲームの完全再現・全件の権利確認・正式公開済みという意味ではない。** 既存2,512件の再変換・再作成はしない。

**2026-10-30確定の工程変更：既存DBの一括利用と例外管理を主工程にする。** 8イベントを含む「1件ずつ人手署名して正式収録する」方式は、残すが**補助的な個別公開手段**へ降格。2,512件を1件ずつ手動承認することを製品完成の前提条件にしない。既存のイベント公開ゲートを無断で無効化し、未承認の元データをPagesへ一括公開する方針でもない。

1. **既存2,512候補の一括読み込みを実用経路に接続**：既存の `phase2_2512_private_effect_join.cjs` と `public_event_catalog.preflight/attach` の一時モデル全件検証を再利用する。改めて2,512件を変換しない。最初に出典版・カード563・イベント2,512・スキルID/Lv・選択／結果・内部連続・元SHA・同一カードでの重複を一括検査し、**読み込み可能**と**本番公開可能**を別の状態として出す。非公開の一括受け入れに加え、[利用者選択のローカルJSON一括試用](phase2-private-local-bulk-import-20261030.md)を実装した。ただしローカルPCでの実ファイル出力、Windows／Android端末、正式公開への接続は未完。固定実出典2,512件は[一括ローカル読込器の実データ／Chromium試験](phase2-private-local-bulk-import-20261030.md)でPASSを確認した。
2. **例外を全件処理から分離し、既知の保留から再開**：[SSR30240の連続3段階](phase2-30240-gamewith-gap-utools-only-replay-20261022.md)は10/30の同一カード版GameTora／GameWith照合で詳細未掲載のため**明示保留済み**。Checkerの**P2未同定11位置**（20075/1、30052/5・11・12、30067/12、30137/4・5・6、30188/10、30207/1・3）は[後続分類](phase2-remaining-checker-skill-impact-20261023.md)を再利用し、実際のスキルID/Lv・選択結果・内部後続への影響だけ優先する。SR20075の+15/+15と+5/+5の結果条件、佐岳メイ海外限定非スキル、[非スキル一般構造の16保留](phase2-outing-unlock-terminal-batch-20261026.md)、SSR30080/6のGT auto対GameWith裁定3択の結合差は独立の例外として維持。SSR30180やP1のL'Arc表示置換3位置など**解決済みの差異を再開発しない**。11位置は追加イベント11件の証拠ではない。**出典未掲載は当該位置だけ保留し、他の作業へ進む**。例外を欠落ゼロ・報酬ゼロ・無条件取得へすり替えない。
3. **最優先：自動提供方法・利用条件を「対象データと利用方法」の単位で決める**（[2026-10-30出典別評価](phase2-event-delivery-route-assessment-20261030.md)・[実2,512件の項目別損失監査](phase2-publication-usability-risk-20261030.md)）：既存2,512候補をアプリで使えるようにする入口を、(a)適切な条件下で元サイト／元GitHubから読み込んでローカルで正規化し**加工済みデータをサイトから再配布しない方式**、(b)事実情報のみの独自JSONを**権利・公開範囲確認後に配布する方式**として検討・実証する。ブラウザのCORS、取得回数・利用規約、出典・版、キャッシュ、元本文・画像や創作的構成を複製しない条件を個別評価する。「読むだけ」は自動的に許諾済みを意味しないが、**全イベントに6項目の人手署名が必須という前提も置かない**。同一出典・同一表現規則のまとまりは共通の利用・監査条件で確認し、個別例外のみ別途裁定する。公開JSONへ投入する際は、現在の`event_release_gate.cjs`との整合・更新方法を**別PRで設計・検証**し、承認を捏造したり既存ゲートを黙って迂回しない。
4. **デッキ操作とA/B/Cを実データで検証**：一般の開発用・実公開用を混同せず、公開配布が認められた範囲または正当に利用できるローカルデータの範囲で、カード検索、イベント未選択、排他的結果、連続打ち切り、スキル集計、目標、保存復元を検証。Windows／Android実端末のCゲートと現行ゲーム網羅のBゲートは個別に記録し、未検証を「完了」としない。新カードの増分取得は旧2,512件を上書きせず継続する。

**利用者の2026-10-30追加条件：公開可否を理由にイベント名を一律削除した低実用版を完成品扱いしない。** 固定2,512件の項目別実測では、全2,512イベントに仮番号ではないイベント名があり、選択肢3,269件中3,266件がすでに仮ラベル、スキル報酬1,735箇所は数値ID・名称照合済み。イベント名がないとゲーム内イベントを同定できないので、**イベント名を利用できる根拠と既存の選択肢の使い勝手を先に評価**する。数値だけでも集計が動くという理由で縮小版を既定路線にしない。[損失と権利リスク](phase2-publication-usability-risk-20261030.md)。

**次の実装順は上の3→4の提供範囲・公開ゲート・既存自動読込への一括接続を優先する。** 上の1は固定2,512件の実データを用いたローカル読込とChromium操作まで合格済み。手元でJSONファイルを生成するための一般利用者向けツールは暫定的な開発方法であり、一般利用の完成条件にしない。GameTora派生GitHubのAGPL表示だけで元サイトとゲームのデータ全体を再配布可能と判断しない。承認可能な数値的事実・独自のDB構成・元の文章・サイトアクセス条件を分けて審査する。

**旧・個別公開用の8件審査・追記リハーサル**（[当時の実装と検証](phase2-first-event-release-rehearsal-20261030.md)）は削除しないが、上記1〜4の前提工程に置かない。既存の非公開候補・現行の正式公開0件・ユーザー設定は、今回の方針決定だけでは変更しない。

**10月29日の重複変換は現行既存DBの工程から除外する。** [`derived_github_runtime_draft.cjs`](derived-github-whole-roster-app-draft-audit-20261029.md) による2,125構造化／363保留は、既存の2,512件より機能範囲が狭い履歴上の別監査である。[10月29日の後続訂正](derived-github-canonical-single-card-adapter-20261029.md)で**新カード主経路からも除外済み**。2,512との件数差の解消、363件の再実装、既存DBの作り直しを今後の作業にしない。診断と変更履歴は残す。

**別系統の並行作業**：UmaSimの新規カードID検出・GitHub派生JSON確認・[Issue #283](https://github.com/Nimrodx0/Umasupport/issues/283)への持越は**新カードの増分取得にのみ**利用する。既存2,512件を新カードとして扱ったり、既存カードを上書きしない。新カード3枚のJSON未掲載は監視を続け、掲載時には**既存の全件変換器を再利用した1枚単位のアダプタ**で事前審査し、正式公開承認後だけ追加する。GameTora本体HTMLの汎用直接取得器は開発保留。

**判断の境界**：既存2,512の技術的変換の正しさを再検証なしで否定しない一方、現行ゲーム網羅・公開権利・未記載分岐を確定したとみなさない。既存文書の残件と後続訂正を参照し、必要な出典事実がない場合は当該位置を保留とする。仕様を変更する必要がある場合のみ利用者へ確認する。

### 汎用変換器から継続更新工程へ進むための先行ゲート

**旧GameTora HTML直接取得方式専用のゲート（2026-10-29保留）**。[4Aの履歴的な受け入れマトリクス](verification-plan.md#4a-gametora汎用取得変換器の次工程引き渡しゲート)は、将来直接取得を再開したときの参照資料として保持する。**派生GitHub JSONを入力とする製品開発には適用しない**。新しい派生JSON・イベント収録・アプリ配信の検証は[4B](verification-plan.md#4b-構造化github派生dbによる製品完成ゲート2026-10-29)を用いる。

**イベント開発の実行単位（2026-10-26更新）：** 未対応イベントをカードごとの個別プログラムではなく、固定GT全母数の原因別コホートで分類し、効果コード／分岐規則ごとの**共通変換器を一括適用**する。既存の検証A/B/Cは維持するが、1イベントごとに専用overlay・専用PRを増やさない。出典が曖昧な規則は同種全部を保留し、出典に明記されたまとまりから変換する。[全件コホートと最初のU.A.F.対応](phase2-gt-batch-cohort-uaf-20261026.md)。

**出典更新の運用ゲート**：構造化した第三者GitHub `systemless10/UmamusumePS` の固定コミット・Git blobと、UmaSimのカード／スキル辞書を基準に追加カードを検出・事前検査する。JSON未掲載カードは持越保留とし、期限経過だけでGameTora本体HTMLの自動取得へ切り替えない。固定出典の更新監視→単一レビューIssue→**メタデータのみの未採用Draft PR**を維持し、公開DBへの投入には独立したイベント内容と利用条件の審査が必要。特定イベントに疑義・欠損があれば、GameTora公式ページとGameWithの記載を**個別の編集確認資料**として用いられるが、サイトHTML汎用自動抽出の再開を先行条件としない。

**他Phaseの横断検証（上記とは別の優先順ではない）**：Phase 1はカードID・通常ヒント・スキル階層・性能の独立照合を継続する。Phase 3〜5はF-01〜F-09、Pages／物理端末の操作、設定復元と利用条件・運用の受け入れを並行して進める。旧固定GameTora由来データの現行ゲーム差・例外は[各監査](status.md)で時点を明示し、必要な場合にGameWithを個別裁定へ使用する。

**直接取得器は保留**。他機能の実装、派生JSON経由のイベント収録、増分更新、Pages検証を直接取得器の完成でブロックしない。ただし各工程の正確性・権利・公開承認は省略しない。対象範囲を縮めて完了宣言するには利用者の仕様決定が必要です。実データと数値の最新状況は [status.md](status.md) に記録します。
