# Phase 2 全件イベント収録：工程と第一段階の統合索引（2026-10-20）

## 巨視的な方針（承認済）

目的は「全563枚のカードについて、独立したイベント一覧、選択肢、結果別スキルID・ヒントLv、連続イベント内の継続・打ち切り・結果依存を収録する」こと。実ゲーム内のイベント**外部出現条件**は対象外。**88件の特殊分岐だけを調査して完了にはしない**。実イベントの全数はまだ検証されておらず、Checkerの2,109件もGameToraの連続1,069件も確定母数ではない。

### ゲートを伴う5工程

1. **全件統合索引（今回）**：563枚の対象母集団からChecker（SSR・SR417枚）とGameTora由来（固定559ファイル）の**全通常・連続イベント**を統合。カードID＋日本語イベント名の一意照合を優先し、記号差による一致は仮提案に留める。追加・片側欠損・同名衝突・選択肢数の差異を全件計数。旧2025 story IDは候補紐付けとして保持、現行ゲームの確定IDに昇格しない。両資料の和集合を「全ゲームイベント」と誤称しない。
2. **結果別報酬の一括構造化**：この索引から全イベント・全選択肢の結果／ヒントIDとLvを正規化し、Checker・GameTora・UmaSim数値辞書を位置単位で比較。複数候補・ランダム選択・ヒント範囲・未対応IDを曖昧なまま保持し、全てを獲得可能とみなさない。
3. **連続内部の到達グラフ**：全連続イベントの段階・後続を確認。明示 `chain_end` と結果依存を活用するが、`chain_end` の欠如は「継続」の証拠にならない。通常継続、経路分岐、前段結果による到達と報酬差のすべてを検査する。全連続チェーンを分類してから修正対象を選ぶ。
4. **残差の集中補完**：一括照合で欠損・曖昧と判明した箇所のみ、GameWith・Game8・Wiki等の別資料と、必要な場合は実ゲームで検証する。GameWithの大規模無許可クロールを行わず、ソース利用条件を別に判断。各未解決事項を根拠・残件・依頼の必要性とともに管理する。
5. **独自DB導入・一括回帰・公開ゲート**：独立して確認した事実のみを既存 `requires`／`terminal`・結果依存スキーマへ変換。全カード、全選択肢、全経路、到達不能報酬の遮断、旧設定の消去、ブラウザ・実端末、権利・データ版をそれぞれ確認する。

### 今回の第1工程の成果物と限界

- 実装 `poc/tools/build_whole_event_index.cjs`、人工テスト `poc/tests/whole_event_index.test.cjs`、固定データ実行 `.github/workflows/whole-event-inventory.yml`。
- 外部ソースをversion-pinned checkout/GETで一時取得。**GameToraの公開サイトへアクセスしない。GameWithへの大量GETを行わない。**
- Checkerの `titleFingerprint` とGameTora日本語タイトルのNFKC正規化ハッシュで一意一致を仮照合。文字種・空白・句読点の差による弱一致は明確に別計上。複数同名は未照合に残す。
- 既存Checkerの `sourceKey` と全2,109件の索引を完全突合し、ずれていたら停止。
- 全559カードのGameTora通常・連続イベントを走査。双方のイベント数、名寄せ数、片側未対応数、選択肢位置数の食い違い、Rカード、新規未収録4枚、P0のイベント名対応数を計数。
- 出力artifactは**カードID・候補sourceKey・イベント位置・GameTora内数値ID・イベント種別・未解決位置**などの自前統合事実だけ。イベント名・選択肢原文・効果文・画像・元のJSONは保存しない。本番コード・通常イベントカタログ・ユーザーUIには接続しない。
- 全件一致率は「イベント名の仮照合率」に過ぎない。選択肢、報酬、ゲーム版、イベント到達の正確性、収録の完全性を保証しない。GameToraの `id` は確定ゲームマスターの `story_id` ではない。

### 工程進捗の独立記録

- **A 機構：** 自動全件照合・厳密な未解決扱い・人工回帰・固定ソースのCI。
- **B データ：** 実測から「一致・片側残差・曖昧」を数値報告。あくまで観測候補索引、全現行イベントの正確な母集団が確認されるまでは未達成。
- **C 実機／UI：** 第1工程は本番UI変更なし。既存機能のブラウザ回帰は実施、Android/Windowsなどの物理実機確認は後の公開ゲートで行う。

### 全件プロセスの優先順位

第1工程終了後、まず**イベント名の両資料対応率と、候補和集合の残差**を判断する。この割合が低ければ名寄せ補正・日本語版データ整備を先行し、十分なら第2工程の全結果・数値照合へ進む。88の特殊分岐、差異カード `30271`／`20023`／`30147`／`30229`／`30102` は第3・4工程へ渡す優先キューであり、全件作業に代わるものではない。

**注意：** 出典の構造化事実を分析したことと、データの大規模再配布に関する利用条件が確定したことは別問題。公開前に許諾範囲・アクセス方法・独自DBへの必要事実のみの採用を評価する。
