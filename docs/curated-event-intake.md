# GameWithを主力参照元とする独自イベントDBの収録（2026-10-19）

## データ管理の方針

ウマサルタントの**イベントデータはGitHubでバージョン管理する独自の構造化JSONが正本**。ゲーム中、GameWithなどのWebページを毎回取得する方式は採らない。GameWithのサポートカード個別記事を優先参照元として、必要なゲーム上の事実を独自のスキーマに整えて収録する。UmaSimの通常ヒント・数値スキル辞書のブラウザ直接取得は従来どおり残す。

2026-10-19時点で外部候補の「45枚・124件試用」は**技術検証**であり、そのデータが正確・網羅的である根拠とはならない。同試用は開発用に残しても、独自DBの収録件数には含めない。

第三者記事の原文・選択肢の文章・画像・HTMLのコピーはしない。記録するのは選択肢番号・イベントの進行関係・獲得スキルID/ヒントLv・成功分岐等の必要最小限の構造化事実と、内部出典URLと確認日。これは文章の複製を避ける設計であり、**自動収集や二次利用が許可されたという意味ではない**。利用条件や大量アクセスの可否を確認するまで無断で大規模クローリングしない。

## 1枚を収録する標準工程

1. UmaSimで数値カードID、名前、レアリティを特定し、GameWithの該当するサポカ**個別記事**を一意に紐付ける。別レアリティと混同しない。ページが見つからないなら未収録とする。
2. 連続・通常イベント、選択肢の位置、スキルID、ヒントLv、成功・大成功、選択なし・打ち切り・進行条件を整理する。GameWithに明記されないことを創作しない。ゲームのstory_idが分からない場合は「draft_カードID_位置」の仮IDとする。
3. 元の選択肢文章を転載せず、短い独自ラベルで各選択肢を区別する。成功別報酬はoutcomesに独立格納し、無条件rewardsに合算しない。数値スキルはUmaSim辞書とID・名称を照合する。
4. source_indexにcardId、primaryArticle、articleCheckedAt、draftFileを追加。独立した全イベント照合ができるまではrecordStatusをdraft、coverageStatusをpartialとする。
5. CIで母集団のcardId集合と草稿のスキーマ・数値スキルをチェックし、入力件数と欠損件数を報告する。「2枚7件の草稿」と「全563枚のイベントを確認」は全く異なる。
6. 公開の条件、根拠、ゲーム内ID、選択肢と報酬を別途確認し、公開承認台帳と照合できた個別イベントだけを本番DBに昇格させる。機械テスト合格だけでは昇格できない。

初期投入の2例はSSRエフフォーリア（カード30311、5候補）とRウイニングチケット（カード10016、2候補）。後者はGameWithのR記事に掲載された通常イベント2件と「差しコーナー○」ヒントLv+1の選択を構造化し、イベントstory_idは未確定のため仮IDを使用する。両者とも全イベント・全効果を承認したものではない。

## 全カードの網羅チェック

固定UmaSimのsupport_card.txtとskill_data.txtをローカルに用意して、以下のコマンドで計測する。

    node poc/tools/report_curated_event_inventory.cjs /path/support_card.txt /path/skill_data.txt

出力項目：母集団のカード総数、GameWith個別記事との対応を記録した枚数、独自草稿のカード枚数・イベント件数、未入力カード数、公開承認済みのカード・イベント件数、レアリティ別の収録数。外部候補45枚は足さない。母集団が増えれば未入力も増える。

**この網羅率はカードの草稿着手率であり、各カードのイベント全件性を意味しない。** 欠損と「ゲーム内にない」を区別する。

## 次のバッチ

最初の20枚をR/SR/SSR混合で調査し、個別記事のカード対応、選択肢・報酬の事実抽出、必要なIDの補完、CI検査が成立するか確認する。その後同じ工程で全カードへ順次拡張。再収録時は元記事の更新日を内部で記録し、新カード差分も管理する。ユーザー向けにはデータの調査状態分類を増殖させず、選択肢とスキル経路を簡潔に示す。

## 2026-10-19：全数値スキル辞書で照合し、IDが不明なイベントを保持する（PR #83）

**変更理由：** `support_card.txt` のヒント一覧は「通常ヒントとして収録された名称の集合」であり、「実ゲームに存在する全スキル」ではない。SRシーキングザパールの通常イベント1「直線コース◯」はGameWith掲載の選択肢2でヒントLv+1だが、通常ヒント集合に無かったため前回の草稿から誤って除外された。

- `poc/src/curated_skill_resolution.cjs` を新設。**`skill_data.txt` のnormal/rare全レコード**で `hint:名称` と草稿内 `unresolvedRewards.skillName` を照合し、唯一の数値IDを取得できた場合だけ、監査用メモリ上のモデルに `skill:<ID>` と辞書の元名称を与える。NFKCに加えて「○」「◯」を表記照合用に等価と扱うが、同名候補が複数数値IDに一致すると**曖昧**として自動統合しない。
- ID未照合のときは、イベントを削除する代わりに草稿の選択肢または結果内へ `unresolvedRewards:[{"skillName":"直線コース◯","level":1}]` と保存する。根拠記事は従来の `source_index.v1.json` に保持。イベント構造・選択肢・報酬名/Lvを失わない。
- CIの草稿検証は、解決に成功した場合だけその候補をメモリ内で `rewards` に変換する。辞書にない・候補ID複数の行は**一切推定せず** `stillPendingSkillRows` に計上し、位置・名称・Lv・理由を報告する。草稿は書き換えず、収録件数と未照合行数を分離する。
- **本番公開安全策：** `unresolvedRewards` を含むイベントは `event_schema.js` と `event_release_gate.cjs` が公開を拒否する。CIが正規スキルID候補を発見しても、そのことだけで公開版へ自動昇格しない。
- SR20029は「通常01」を選択肢2の `直線コース◯` ヒントLv+1として復旧し、固定UmaSim全スキル辞書2,139件の数値ID `202992`・名称 `直線コース○` と照合できたため、**草稿本体を `skill:202992`＋`verifiedSkillName` に更新した**。一方、Rカレンチャン10073の「後方釘付」は固定UmaSim全辞書に名称が見つからず、該当イベントの選択肢2を `unresolvedRewards` として保持した。**独自草稿は9枚25イベント候補、うち未解決のスキル報酬1件**。外部DBの試用45枚は加算しない。Wikiに数値ID `202992` の案内あり：<https://umamusu.wiki/Game:Skills/202992>。この公開索引だけを根拠に `skill:202992` を捏造するのでなく、実際の固定UmaSim全辞書と照合したうえで利用する。

独自草稿のカウントは*記録したイベントの数*。イベントのID、スキルID、掲載条件、権利を完全にレビューした本番公開数は依然0件。通常版UIに未照合分類・バッジは追加しない。

### 固定版UmaSimの実データ監査結果（2026-10-19）

検査元：固定UmaSim `support_card.txt` 563カードと `skill_data.txt` 2,139スキル。結果：R6、SR2、SSR1の9カード、独自25草稿イベント、うち未解決1スキル報酬（R10073「後方釘付」）。SR20029「直線コース◯」は見た目の○/◯の差を調整後、`202992` と単一一致し草稿に数値で保存済み。**GameWithとWiki記載はゲーム内で実際にヒントが発生することを証明するものではない。**
