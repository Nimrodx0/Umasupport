# Phase 2：非スキル効果のイベント結果モデルと佐岳メイ海外限定R/SSR試作（2026-10-24）

## 範囲・目的

従来の`poc/src/event_schema.js`・`poc/src/core.js`は、サポカのイベント選択肢・結果・前段条件を保持し、**スキルの獲得可能経路だけ**を`directRoutes`と`aggregate`で評価する。非スキル報酬を無視する設計では、[前回採用済みの佐岳メイ海外限定「労いのエール」](phase2-p1-larc-replacement-and-mei-overseas-20261023.md)の結果情報が失われる。

今回のスコープは**イベント共通スキーマへの非スキル数値報酬追加＋結果別取得関数＋R/SSR2カードの実出典メタデータを使った非公開プレビュー**。旧通常ヒント・スキル付与経路、デッキカバー率、公開用イベントJSON、GameTora2,488件の元情報、技術用2,512件の実行カタログは変更しない。目標の全ゲームイベント報酬監査や正式公開はこのPRの受入条件ではない。

## データ形式

既存`rewards: [{skillId,kind?,level?}]`は**スキル報酬専用**に維持する。追加した`effects: [{kind,delta,sourceComponent?}]`はイベント本体・選択肢・成功／失敗の`outcomes[]`に置ける。

- `kind`: `speed`, `stamina`, `power`, `guts`, `wisdom`, `energy`, `max_energy`, `mood`, `bond`, `skill_points`, `aptitude_points`のみ。
- `delta`: **符号付きの安全な非0整数**。0は変化なしとしてレコード自体を置かない。負数は消費・減少。入力が不明なら0で代用してはいけない。
- `sourceComponent`: 省略可、または`event-result`（元の結果）・`scenario-bonus`（該当シナリオに限る追加効果）。同じ種類でも二つの異なる成分は別個の数値として保持する。同じ種類・同じ成分の重複は拒否。
- `effects`と`outcomes`は**同じ親で併用不可**。共通で生じる報酬は必要ならレビュー済みの各結果へ明示的に配置する。選択されなかった結果を合計しない。
- `outcomes`は排他的結果を2個以上持ち、スキルが無い結果も`effects`を持てる。既存`rewards:[]`を同時に保持しても、**効果データがある**ので空の偽イベントではない。未照合の`unresolvedRewards`は従来通り拒否。
- `availabilityKind:'scenario-overseas'`は**海外遠征中に該当イベントが発生したときだけ**の候補条件。発生タイミング・確率や発生保証を推定しない。後続のお出かけ打ち切りも資料にない場合は追加しない。

### 非公開試作用「労いのエール」

元の[編集採用台帳](../poc/data/curation/adjudicated/phase2_p1_scenario_event_facts.v1.json)から、`poc/src/phase2_mei_overseas_nonskill_preview.cjs`でR10094・SSR30160のカードごとに別のIDを付けて2イベントレコードを生成。出典が報じた「1種類・2カード」について、技術上のレコード数2と実ゲームのイベント種類数1を区別する。結果の大成功・成功をそれぞれ明示し、元の根性・やる気・絆とL'Arc固有のスキルPt・適性Pt・絆を区別する。絆が+5と+2の場合は単純な`+7`記録ではなく**2成分を保持**し、監査できるようにする。

`UmaCore.directEffectRoutes(card,{choices,outcomes})`は各非スキル数値をイベントID・結果ID・結果条件・成分付きで返す。結果未選択なら**大成功と成功の両方を条件付き候補**として表示し、合計した獲得済み値にはしない。選択済みでも`scenario-overseas`の発生条件は残る。一方`UmaCore.directRoutes`と`aggregate`は従来どおりスキル数値IDだけを集計し、非スキル効果や絆から新しいスキル提供カードを生成しない。

## A/B/C検証と未実装の範囲

A：`poc/tests/phase2_nonskill_outcome_runtime.test.cjs`で実台帳を元にR/SSRそれぞれ2結果、元報酬とL'Arc成分の分離、スキル数0・公開数0を検査。合成例による選択依存・打ち切り・結果未確定の分離、負数・非整数・未知の能力値・同一成分の二重計上・原台帳改変拒否を検査。

B：既存`whole-event-inventory.yml`の**実固定GameToraとChecker全件**でP1の正しい見出し4件、R/SSR5カードの編集採用を確認後、`audit_phase2_mei_effect_runtime.cjs`で元台帳から2カード×2結果の合計4条件経路／22数値成分を試作し、それが実際に計算可能か判定する。実ゲーム全件の非スキル報酬が22件という意味ではない。

C：公開Webアプリ・ユーザー状態・公開カタログは変更しないため、UIへの追加・実機検証は次工程。将来の公開UIに表示するには再利用条件と公開審査を独立に実施する必要がある。

本工程の完了条件はあくまで**技術的な結果分岐の保存と非公開投影**。元のイベント2,512件へR/SSRの2イベントを自動追加しない。今後、固定GT全イベントから非スキル効果を抽出する大規模工程に進む前に、GTの複数効果の同時重複・シナリオごとの発生条件・残る未照合イベントの個別ソース裁定を行う。
