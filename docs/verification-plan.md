## 1. 目的と基本原則

機能が少数のサンプルで動くことは**機構の試験結果**であり、データ全件性や実機品質の証拠ではない。各工程では開始時に検証対象の母集団、例外の扱い、合否基準、実施手段を決める。実装後に都合のよい成功事例だけで完了判定しない。

工程ごとに以下の3軸を別々に評価する。

| 軸 | 何を保証するか | 代表的な証拠 |
|---|---|---|
| A. 機構（ロジック） | 仕様、不変条件、異常系、データ更新への挙動が正しい | 単体・回帰・結合テスト、型／スキーマ検査 |
| B. データ（網羅・正確性） | 対象全件が分類され、ID・経路・例外と独立根拠が追跡できる | 全件監査、未照合一覧、出典・版・ハッシュ、独立照合 |
| C. 実機（利用者の体験） | 配信された同じコードが実ブラウザで正しく読込・表示・操作・保存できる | Pages上の操作手順と期待値・実測値、環境・日付・コミット記録 |

- **ゲート通過**：スコープ内の必須項目がA/B/Cをすべて満たし、影響のある未解決がゼロ、または変更されたスコープと許容理由が要件・意思決定ログへ明記されている場合に限る。
- **部分実装**：1軸でも必須項目が未実施なら「部分実装／検証待ち」。別の軸の合格で代替しない。
- **未解決の扱い**：不明を「なし」に変えない。未収録・取得失敗・未照合・実際に存在しない根拠付きを別の状態として記録する。
- **ソースの真実性**：「入力ファイルに何件あったか」と「ゲームの現行全体に何件あるか」は別。独立分母を得られない場合は真の網羅率を数値化しない。
- **検証と権利**：技術的に取得できても利用可能とは限らない。公開権利・転載範囲・アクセス負荷の判断は公開ゲートに含む。

## 3. Phase 1：現在の具体的な検証ケース

- 入力元：UmaSim `support_card.txt` と `skill_data.txt` の取得日時・版ハッシュ、カード集合・金／白集合。
- **取得元内の全件分類**：サポカ563件、通常ヒント4,015件、スキル辞書2,139件中金325（構造対応322／対応白なし3）。この件数は2026-10-16実測であり、新版では再計測する。
- **独立性**：322の上下関係を独立したマスター由来フィールド等で突合する。全件チェックの未実施を「構造未確定0」と混同しない。
- **異常系**：カードID衝突、同名異ID、レアリティ・group異常、○◎曖昧、多段階例外、ソース不正、古いキャッシュ、初回取得失敗を確認。
- **正しさ**：金→白・金→◎→○、構造上白なし、直接提供0の間接カバー、提供枚数の非加算、目標スキル登録を試験。
- **実機**：最新コミットのGitHub Pagesで辞書の起動時ロード、IndexedDB保存、キャッシュ復旧、一覧の階層インデントと実際の編成・目標反映をPCとスマホで記録。

現状：Node.jsによる実ソース統合検証は合格済み（[実行記録](https://github.com/Nimrodx0/Umasupport/actions/runs/38927481224)）。**独立全件照合と最新ブラウザ検証は未合格**。[詳細監査](skill-hierarchy-coverage.md)。

## 4. Phase 2：イベント網羅を測るための分母

1. カード分母：まずUmaSim内SSR・SR417枚、R146枚。これはソース内の対象集合でありゲーム全実装カードを保証しない。
2. カード対応：ソース名の一致417/417とゲーム内カード／イベント正式IDの照合を区別。明示別名24件は対応登録済みだがイベントIDの確証ではない。
3. カードにイベントレコードが1件以上ある率：UmaUmaCheckerは412/417。**イベントの全件収録率ではない**。
4. イベント分母：ゲーム／独立照合資料に基づくカード別の期待イベント一覧を用意。母数を確立できなければ「収録数／入力候補数」として記録し、「全イベント網羅」を宣言しない。
5. 公開対象：カードID、イベントID、連続関係、選択肢、選択肢別報酬、成功・失敗の条件、Lvと出典・承認状態を列別に追跡する。
6. 公開可否：第三者の文章を無断転記せず、利用条件・表現・公開独自JSONを個別レビュー。未承認なら自動集計へ入れない。
7. 小規模試験の後に全件再監査する。新しいカード・イベント追加時にも同じ条件を適用する。

## 9. 全322構造候補の独立マスター照合（2026-10-17追加）

コード：§poc/tools/verify_skill_master.py§、人工データ回帰：§poc/tests/test_verify_skill_master.py§。通常CIは独立の元データを取得・保存しない。次を**許可された形で別途取得した実ファイル**について実行する：

~~~sh
python3 poc/tools/verify_skill_master.py \
  --umasim local-data/skill_data.txt \
  --master local-data/master.mdb \
  --source-revision "<UmaSimのコミットID>" \
  --master-revision "<マスターの版・日付・ゲーム環境>" \
  --strict
~~~

出力は比較対象の全金スキルについて、構造候補・白なしの分類、独立マスターでの順序一致、マスター欠損・レアリティ・group衝突、余分な同グループ候補などの**件数とIDのみ**を記録する。§--strict§ は独立照合を全件通過できなければ失敗。マスター版がUmaSimと異なる場合の「欠損」は最新版の誤りではなく版差である可能性がある。出典・版を揃えてから結果を審査する。

A：架空SQLite 9ケースの単体検証。B：実マスター全件検証未実施。C：この監査器はCLIであり、ブラウザ実機の検証には代用できない。
