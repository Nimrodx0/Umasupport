# Phase 2：2,496イベントを本番スキル辞書照合・イベント読込器で非公開受け入れ（2026-10-23）

## 目的と既存制約

[2,496件の非公開統合候補](phase2-integrated-2496-private-runtime-20261023.md)は、固定GT2,488件＋GameWith裁定済み通常8件、SSR30080/6の選択肢補正を、実行形式スキーマと集計コアまで検証した。次の差分は、**本番イベント読込器 `public_event_catalog.preflight` と `attach`**で、数値スキルID→レアリティ・照合済み名称・既存モデルのヒント名まで全件変換できるかを試すこと。

GT2,488件のみに対する本番読込検査は以前に通過済みだったが、**追加4SSRの通常8件を含む2,496件**全体ではまだ同じ読込器によるテストがなかった。

## 今回の技術的検査

- `poc/src/phase2_integrated_private_loader.cjs` は、非公開候補の全体SHA、未承認フラグ、モデルのカード数、スキル辞書入力を検証し、公開用と同じ `preflight(model,catalog,{skillText})` を呼び出す。スキル数値IDと名前が一致しなければ、**公開候補の読込を拒否する**。
- その後、**作業用に複製したカードモデル**へ `public_event_catalog.attach` を実行。実際のアプリで使う `cardById` と `cards[]` の同一参照を復元してから、公開用ローダーの出力イベントと `preflight` 出力のSHAを比較する。元スキル辞書・元カードモデル・元2,496イベントJSONは変化しない。
- `attach` は成功すると複製モデルのメタ情報を一時的に `reviewed-partial` とするが、**そのラベルを本番アプリへ配布したり、正式公開の承認として保存したりすることは禁止**。複製は処理終了時に破棄し、個別の出典文章・イベントカタログ・イベント名はCIログへ出さない。
- 数値ID解決後の**4SSR通常8イベント／16選択肢／4ヒント**を本番 `UmaCore.directRoutes` に通し、未選択時0、各選択肢の登録済みID/Lvと集計経路の一致を再検証する。SSR30080/6については前工程の未選択0／3択各1の検証を保持する。

当初の全件CIは `skill:201591` の名称照合で失敗した。**原因はGameWith3択補正に元GTイベント側で既に照合済みの `verifiedSkillName` を渡していなかったこと**。元数値IDやレベルの間違いではない。修正では、元GTのイベント内容SHAと番号・スキルID/Lvをチェックした後に、**同一スキルの既に出典照合済みの名称のみを3選択位置に継承**した。独自の名称や報酬を創作せず、実ローダーの名称再照合に成功。

現行統合元カタログSHA-256：`4f6bdd235838569f54c0ef26d30e43e12ba23934809518302ed1bb2ebb624d5e`。
本番ローダーによる名称/ID変換後の捨てモデル内容SHA-256：`f34b6e3e9571c5da73584704b3a5de9af8a3e537c49614457226c373714c784e`。
ここにある2つのSHAは**変換前後の異なる形式**で、内容の不一致を表していない。変換後モデルと`preflight`をSHA照合して一致した。

本番イベントDBと承認台帳は0件のまま。**実際の正式配信での利用許諾、出典の利用条件、全イベントの独立日本語表示・6項目承認が揃ったことを意味しない**。
