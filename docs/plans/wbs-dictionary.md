# WBS Dictionary：工程ごとの成果物・依存・受入基準

[上位工程](../project/roadmap.md) ／ [詳細計画](index.md) ／ [検証ゲート](../quality/verification-plan.md)

WBSは成果物に基づく分解です。詳細ページの小工程は成果物を得るための**作業**も含みますが、下表では各親工程が何を完成させるかを定義します。

| 親工程 | 主要成果物 | 依存 | 受入基準 |
| --- | --- | --- | --- |
| W1 | 公開済みイベントを使ったアプリ受入記録 | 本番JSON、デッキ・イベントUI | 実データでA/B/C独立確認 |
| W2 | 出典別の審査・保留台帳 | 出典の版、許可条件、候補データ | 採否と保留理由が追跡可能 |
| W3 | 既存データを保護する新カード増分追加経路 | UmaSim名簿、派生GitHub、公開ゲート | 対象ID・分岐・報酬を検証して追加 |
| W4 | 個別欠損の照合結果と修正 | 固定出典・例外台帳 | 保留を0件や対象なしへ変換しない |
| W5 | 障害・更新・公開運用の受入記録 | W1～W4、運用計画 | キャッシュ復旧・設定保護・ロールバック |
| P0 | スキル条件の固定構造監査 | 固定UmaSim辞書 | 構文・未知条件・母集団を記録 |
| P1 | 条件を損なわない内部表現 | P0 | 明示条件と状況条件、AND/ORを区別 |
| P2 | 二軸・4脚質の研究結果と保留形式 | P1、固定GlobalSim | 不確実性・元条件・実ゲームとの差を明示 |
| P3 | サポカ単位の安全な集約 | P2の仕様確定 | 取得経路・不明・均衡編成基準の維持 |
| P4 | 根拠を区別する検索・表示UI | P3 | 明示制限／推定／未判定を区別 |
| P5 | スキル条件機能の統合受入結果 | P0～P4 | A/B/Cを別々に検証 |

## 下位作業パッケージに必要な情報

例：P2.13では「独立シード検証報告」が成果物です。入力（固定モデル・出典）、実行する調査、未確定項目（不確かさ）、合格条件（独立シードの結果と適用限界）、結果と根拠を一組で管理します。実行していない試験はPassにしません。

この表は成果物と受入の**意味を明確にする補助辞書**であり、100%の作業網羅性、担当者、工数、スケジュールを保証するものではありません。
