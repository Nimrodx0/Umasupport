# P2→P3：固定32元条件の研究証拠を、安全に参照するための契約（2026-11-09）

**状態：研究データの検証・参照用。正式なサポカ脚質適性の分類、公開UI、カード得点は実装しない。UIの具体的形式は利用者と未合意のため保留。**

## 目的

P2では、GlobalSim固定版・UmaSim固定版から、77スキルに含まれる81の元条件経路を調べ、重複を除去した芝26・ダート6＝**32種類の順位・時期・距離・馬場条件**について、9頭／12頭の数値を調査した。

今回の [読み取り専用アダプタ](../poc/src/p2_p3_evidence_contract.cjs) は、[二軸研究](skill-specificity32-two-axis-20261109.md)の派生JSONがP3側の内部データへ渡るとき、数値・対象条件・保留が壊れていないか検査する。**新しい実測を得たという報告ではない**。対応しないスキルを「適性が低い」と解釈しない。

## 入力・範囲

- 研究元の32条件・代表元IDは [manifest](../poc/data/p2_position_condition32_research.v1.json) を参照。単純な元スキルIDだけで関連付けず、**代表ID／芝ダート／距離スコープ／時期の元窓／順位帯**の全5成分が一致する研究条件だけを抽出する。同じ代表IDでも距離スコープが異なる実例がある。
- 派生JSONは [P2の固定研究生成器](../poc/tools/skill_specificity32_research.cjs)が作成する \`P2-source32-two-axis-point-specificity-and-10m-pairwise-research-only\` 形式。**32条件×2頭数＝64行**と各行6脚質ペア、9/12頭跨ぎ192ペアの整合性を確認。
- 元データのモデルリビジョン・UmaSim辞書SHA・研究manifestの固定来歴・5入力レポートの固定SHAを検査する。ただしJSONに含まれるSHA表記は**任意の入力ファイルそのものの真正性を証明しない**。実際に使用する派生ファイルは、別途配布元Actionsの固定版・成果物のSHAを確かめる必要がある。
- 成果は当時の固定モデル上の条件部分の比較であり、実ゲームのスキル発動確率でも、スキル効果の有用性でも、獲得確率でもない。

## 出力上の不変条件

| 項目 | 厳密な意味 |
| --- | --- |
| **W** | 元順位条件が約10mの抽選範囲内のいずれかで満たされる、モデル条件部分の成立機会（%）。実発動確率とは異なる |
| **O** | 同一のモデル条件・時間窓における単一地点の順位帯占有割合（%） |
| **U** | 9頭／12頭の整数順位に射影した範囲が、すべて等確率と仮定した理論上の1地点占有割合（%） |
| **O−U** | 1地点同士の比較による順位帯の広さ補正。**W−Uではない** |
| **相対比較** | 同じ頭数・元コース・能力設定・時期条件で4脚質6ペアを比較し、同方向のものだけ確定。逆転・同値・順位解決不能は保留 |
| **9頭／12頭の違い** | 別々の数値を保持。厳密な同方向／逆転／片方保留の監査結果も保持し、機械的に合算しない |
| **均衡編成** | 標準比較用の固定基準。前方偏重・後方偏重・逃げ不在は研究用の感度確認であり、実戦での出現頻度に基づく重みではない |

未観測（例えば逃げ不在の逃げ）、元条件以外にあるAND/OR・preConditions・元スキルの別経路、実ゲームとシミュレーションの相違を「0%」や「弱い」と呼ばない。元スキルのID・名称・全発動条件の独立照合を経ずに、研究条件部分だけをサポカ評価へ結合しない。短窓・ダート32条件について、30シードを15＋15の独立群に分けた方向再検証も引き続き未完。

## APIと検証

Node.js 22以上で利用する読み取り専用モジュールで、インターフェースは \`validate(report,manifest?)\` と \`openEvidence(report,manifest?).lookup(fiveFieldSignature)\`。後者は研究条件と一致しないものを \`not-in-research-cohort\` として返す。結果をランク・点数・脚質適性ラベルへ変換するAPIは**用意しない**。

- 回帰：\`node --test poc/tests/p2_p3_evidence_contract.test.cjs\`
- 対象：モデル固定出典の照合、32条件・9/12頭の完全性、W/O/Uの数値整合、脚質ペア・頭数差・保留、元IDだけからの誤結合の拒否。
- テストは固定32条件manifestを使う**合成数値データ**に対する契約検査。実研究成果物の読み込み・参照・同じ入力での再生は別のBゲートで行う必要があり、CIの合格だけで成果物の正当性を認証したことにはならない。

## P3へ渡す前に残るゲート

1. 固定版のP2二軸研究派生JSONをCIで再生成・チェックサムで固定し、**実データ**としてこの契約に通す。
2. 元スキルの条件行から、芝ダート・距離・順位AND・時期・追加条件を厳密に解釈し、5成分の一致が確実な条件部分だけを結び付ける。AND/ORの条件部分からスキル全体の評価へ格上げしない。
3. 9頭／12頭、均衡編成内のコース・能力・局面、シード独立性について、正式ラベルへ昇格できる区分と保留理由を決める。**閾値やカード合成方法、実UI形式はまだ決めない**。
4. 通常ヒント・レビュー済みイベント・条件付き獲得経路からカード単位の集約を、研究指標とは別に受け入れ検証する。
