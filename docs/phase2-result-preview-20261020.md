# Phase 2：明示結果候補の独立試用モード（2026-10-20）

## 位置づけ

既存の固定Checker由来の独自数値候補2,109イベント・3,458選択位置から、元資料に **複数の結果見出しが明示されたもの**を専用の試用画面へ接続する。正式配信データ `poc/data/reviewed_events.v1.json` は引き続き **0イベント**で、この試用モードは自動公開・承認を意味しない。

**[結果別ヒント候補を試す](https://nimrodx0.github.io/Umasupport/poc/live.html?eventPreview=results)**

既存の全候補・結果未区分 `?eventPreview=facts` とは別のURLとlocalStorageキーを用いる。今回の新画面では、抽出済みの「成功／大成功／失敗／通常」別ヒントとLvを選択肢の中に分けて表示し、選んだ結果以外の報酬候補は集計しない。未選択結果の候補表示は条件付きとし、**選択済みであっても実ゲームの確定報酬扱いはしない**。

### 採用対象と安全上の制約

- 入力 `checker_explicit_result_facts.v1.json` の417枚・2,109候補・3,458位置・203明示結果選択肢・411結果記録・179対象イベントを、起動時に全件計数・版固定確認する。
- 選択肢に明示結果が1つ以上あるイベントのみ候補とし、複数結果を同一スキル報酬へ平坦化しない。
- 未解決スキルID、ヒントLv範囲、曖昧なラベル解析、前段結果を要する説明、元資料の連続終了・次回不発生記載が **1つでもあるイベントを丸ごと除外する**。報酬の一部分だけを採用して完備と誤認させない。
- 数値ヒントの記載がない結果は、試用画面では「資料にヒント記載なし（実ゲームの獲得可否は不明）」と示す。**「スキル獲得なし」と断定しない**。
- 結果見出しがない同イベント内の選択肢は `unspecified` かつ `獲得結果未区分` として扱う。明示されていない「成功」「失敗」を補わない。
- 実イベントID、各段階の依存関係、打ち切り、出現率をこの資料から捏造しない。`requires` と `terminal` は生成せず、連続イベントの到達可能な候補が全部同一育成で取れるとは案内しない。
- 元記事のセリフ・選択肢原文・効果文章・画像は新たに配信しない。表示する名前は「結果別イベント候補N」「候補位置N」、結果はラベル名称だけ。
- 通常版のデッキ設定と `?eventPreview=facts`、`?eventPreview=30311`、`?eventPreview=expanded` の設定に一切混入させない。

### 実装・検証

- アダプタ：`poc/src/checker_result_preview.js`
- 起動・配信：`poc/src/event_preview_loader.js`、`poc/live.html`
- 画面上の結果選択とスキルLvは既存の `event_schema.js` / `core.js` / `live_app.js` を再利用。
- 実候補全件と人工改変データの回帰：`node --test poc/tests/checker_result_preview.test.cjs`
- 実Chromiumの候補表示・結果選択・条件付き集計・通常保存からの分離：`node poc/tests/browser_checker_facts_smoke.cjs`（CIでPlaywright導入後実行）。
- 合格は**固定候補の構造・表示機能に限定**。2026年実ゲームの報酬・イベント経路の全件性や実端末受け入れを証明しない。

次工程は、除外対象の具体的な選択肢／数値差をP0レビューキューで再確認し、前段成功に依存するSSR30103型の「結果依存」や連続終了の分岐モデルを、資料で経路が裏付けられた範囲で段階的に広げること。正式なイベントDBへの採否は別に審査する。
