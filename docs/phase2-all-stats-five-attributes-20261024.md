# Phase 2・GameTora `all_stats` 68記載の5能力別投影（2026-10-24）

## 対象・出典の意味と範囲

前回の[固定GameTora全2,488イベントの非スキル監査](phase2-gt-whole-nonskill-effect-audit-20261024.md)では、`all_stats` 68記載を未対応扱いにしていた。このコードの意味は、元の**同じ固定リビジョン**の[イベント実行コード`server/app/event_engine.py`（約1376～1379行）](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/event_engine.py#L1376-L1379)で明示されている。イベントの符号付き数値を`speed`, `stamina`, `power`, `guts`, `wiz`の5能力それぞれに適用するもの。ゲーム内効果表示でも、プラスは全能力の増加、マイナスは5属性の減少として扱う[同ファイルの表示処理](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/event_engine.py#L716-L734)。この実装根拠はGT派生固定実装の意味解析であり、2026年ゲームの実プレイ直接検証ではない。

`wiz`はゲーム内の賢さ能力としてアプリ側の`wisdom`に対応させる。単一の`all_stats:+7`なら5属性のそれぞれ+7、`all_stats:-15`なら5属性のそれぞれ-15を保持する。ランダム能力の`random_stats`（18記載）は**対象属性が未確定の別効果コード**であり、この規則で展開しない。

## 実装した厳密なゲート

- `poc/src/phase2_gt_whole_nonskill_effect_inventory.cjs`に型`all_stats`のみに適用する5属性変換を追加。GT元の1記載を5属性の異なる行に展開し、各行に`sourceBundle:'all_stats'`を付けて元の由来を保持。元の結果ID・選択肢ID・元カード位置も維持する。
- `poc/src/event_schema.js`は`sourceBundle`を`all_stats`に限定し、許可する属性を5能力だけに制限。`core.directEffectRoutes`でも成分の由来を保持する。
- 符号付き安全整数のみ採用。符号無しの文字、数値範囲、余計な出典フィールド、同じ結果に別の単独能力値が二重登録される場合は保留。既存の結果`random_either`、`segments`条件、`chain_end`制御の保留判定は維持。元スキル`skill_hint`や公開イベントへ自動変換しない。
- 編集上の判断は固定GTの意味論を適用する通常ケースであり、GameWith全件への再照合や第三資料・物理ゲーム再現は要求しない。元の不明効果は別途例外として調査する。
