# Phase 2：GameToraの連動型「低／高」数値範囲を結果別に照合し、SSR30028へ非公開導入（2026-10-26）

## 固定出典と対象

固定GameTora派生`systemless10/UmamusumePS@6e38b54af4fad397ff4491e63007a90705a4fe67`の[元実行器`_split_range_effects`](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/event_engine.py#L414-L445)では、1つの選択肢内で`+5/+10`や`+1/+3`が複数効果にまたがっても、**同じ一度の分岐で全効果が低側または高側へ一緒に切り替わる**。個々の効果に別々の抽選を作って2×2×…の組合せへ広げてはいけない。固定値の効果は両結果に共通する。

## 固定全件の範囲調査

新規`poc/src/phase2_gt_correlated_numeric_range.cjs`で固定全559サポカ、2,488元イベント、4,129選択肢、4,376結果経路、13,263元効果記載を確認。元の`choice`、`segments`、`outcomes`の位置を維持したまま、出典の範囲値に対する低／高の**同じindex**で各数値を投影する。対応する元文言・選択肢テキストは保存しない。

[固定全件CI #40258268984](https://github.com/Nimrodx0/Umasupport/actions/runs/40258268984) **PASS**。

| 指標 | 元出典での実測 |
| --- | ---: |
| 範囲形式の値を持つサポカ | 12カード |
| 範囲形式の値を持つイベント／選択肢 | 14イベント／14選択肢 |
| 範囲の記載件数（スキルヒントも含む） | **15記載** |
| 数値として範囲を持つ効果の展開可能成分 | **6成分** |
| 選択肢内の数値部分を2段階に投影できるもの | **9選択肢** |
| 既存の結果分岐／未知効果等により保留するもの | **5選択肢** |

**9選択肢すべてに非スキルの範囲値があるわけではない。** 例えば固定GT10022#3・#5、20021#3・#5、20024#4は、ヒントLvだけが範囲で、非スキルの数値はもともと固定されている。上記「6成分」はこれらヒント範囲を除いた数値範囲の出典成分である。9は**ソース値を読み分けられた選択肢数**であり、既存スキルイベントの結果トポロジーまで9件分立証された数ではない。なお本監査は選択肢に`random_either`の出典形式がある場合は勝手に低高を新設しない。

固定元で範囲記載のあった数値ID・イベント順位・選択順位は、`GT_CORRELATED_NUMERIC_RANGE_POSITIONS`として全件CIログに残す。非公開JSONファイルはGitHub Actionsの一時フォルダー`whole-event-output`にのみ出力し、公開カタログへ自動適用しない。

## SSR30028の限定的な結果別統合

固定GTの**SSR30028、イベント#4の選択肢#2**には、スピード`+5/+10`と、**同じ結果分岐**にある数値ID`200362`のスキルヒント`Lv1/Lv3`、さらに両方の結果で絆`+5`が記載される。この2結果は元コードの同一低／高抽選に該当する。

`poc/src/phase2_gt_30028_correlated_range_overlay.cjs`で、非公開の**2,512件スキルイベントの同じ元カードID・イベント#4**のスキル結果が`route-01-or-1`（該当ヒントLv1）、`route-01-or-2`（該当ヒントLv3）であることを、元スキル数値ID、報酬内容、元GTのスピード／絆値、選択肢数、チェーン文脈の不変性とともに照合してから**その二つの結果にだけ**非スキル成分を追加。イベント#4の選択肢#1にある固定の体力+10、やる気+1、絆+5も、元の選択肢#1に限って対応する。

- 結果#1：スピード+5、絆+5、ヒントLv1。
- 結果#2：スピード+10、絆+5、ヒントLv3。
- 別選択肢#1の固定効果はこの二つの結果へ混ぜない。
- 既存のスキル結果番号、到達・打ち切り・選択肢、スキル名と報酬は**まったく変えない**。元資料の一部でも違う場合は結合を拒否し、無条件の代替結果を作らない。

[同じ固定全件CI](https://github.com/Nimrodx0/Umasupport/actions/runs/40258268984)で`GT_30028_CORRELATED_RANGE_PRIVATE_OVERLAY`が**追加1イベント、付与した数値成分7件（選択肢#1で3件、#2の2結果に各2件）、同期2結果**を出力してPASS。`public_event_catalog.preflight`と使い捨て実モデル`attach`で全2,512イベントを受け入れ、従来の563カードのスキル計算・元結果のスキル報酬と整合したことを確認。

## A／B／Cと残件

A：`poc/tests/phase2_gt_correlated_numeric_range.test.cjs`は連動数値値・符号・固定値・`all_stats`5成分・二重分岐の拒否を合成検証。`poc/tests/phase2_gt_30028_correlated_range_overlay.test.cjs`はスキル数値ID・ヒントレベル・結果ID・元GT選択肢内容が少しでも違えば受理しないことを検証。

B：全GT母数で14イベント／15記載を検出し、対象SSR30028の**1イベントのみ**を結果別に非公開統合。従来の基準**2,404件の元GT非スキル構造化候補、2,403件のスキル側との厳格結合**はそのまま維持し、**別経路のSSR30028限定overlayで1イベントが追加**。したがって実際に同一スキル用2,512イベントで何らかの非スキル値を保持できる範囲は、重複がないため**2,404イベント**。GT一般分類器の既存の保留84は減らしていない。未知の範囲は解消と誤認しない。

C：Chromiumの既存Web UI回帰は公開アプリの現状保全のみ。SSR30028の今回の追加効果は**未公開ランタイムの使い捨てモデルだけ**で確認したものであり、実際のウマ娘での抽選、GitHub Pagesの正式公開イベント一覧、Windows／Android物理端末に配信した結果ではない。

残る一般分類器の84イベント、特殊コード未対応90記載、結果条件、SSR30080#6の既知のGT auto対GameWith3択は引き続き未解決。今後の優先は「数値だけが範囲」の30030#3、30041#3などで、既存スキル側に結果候補がない場合の**2段階分岐の正しい導入方法**を設計すること。**正式公開イベント0件**、第三者の本文・元カード画像の再配布0件は不変。
