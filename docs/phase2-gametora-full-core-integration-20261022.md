# Phase 2：固定GameTora全イベントを実集計エンジンへ通す統合試験（2026-10-22）

## 意図と前提

固定GameTora由来サポートイベントJSONは、従来のCIの非公開データ正規化・スキルID照合・本番イベント**スキーマ**への投影で、**563枚の母集団のうち固定ファイルを持つ559枚・2,488イベント**まで到達している。固定元がないSSR4枚（30318〜30321）はGameWith個別記事で裁定する例外とし、GameToraに存在すると捏造しない。

しかし「スキーマが受け入れる」は「本番デッキの操作・スキル集計に正しく使える」ではない。そこで同一GitHub Actions実行メモリ内で、これまで捨てていた**未承認の投影カタログを本番と同じ`poc/src/core.js`の`directRoutes`と`aggregate`へ通し**、全カード・全イベントの選択／結果／連続遮断／重複を検査する。イベント本文・選択肢文字列・元候補JSONはファイルに書かず、CIの出力は純粋な件数のみ。

## 新しい機構

`poc/src/gametora_full_runtime_integration.cjs` の `exercise({catalog,report,model},{strict})` は、公開用カタログには触れず、**非公開のメモリ内コピー**で各カードを検査する。

- 固定GT入力側の `report.totals.sourceCards`・投影成功枚数・イベント数・source choices などを保全。2025マスターまたは2026独立スキル名の限定補完を付けた**全件CIでは563枚母集団／559枚投影／2,488イベント／choice1,595・auto893**を厳格要求。固定スキル辞書のみの段階では、未解決IDで除外されたイベントを「投影済み」と誤認しない。
- 各カードの初期状態 `choices={}`・`outcomes={}` で本番`directRoutes`を実行し、**未選択の選択式イベントから報酬が算入されない**ことを検査。明示された通常ヒントは変化させない。
- 各カードの選択式イベントに仮想の選択結果と、選べる場合は非打ち切り結果を設定して再実行する。**結果依存・連続イベント依存は本番エンジンが判断**し、到達できない報酬は採用しない。出典で不明な実ゲーム経路を「確定」したという意味ではない。
- 取得したイベント由来ルートは、元カードのイベントに属する数値スキルID・ヒントLv・選択した経路に限る。選択していない別の選択肢からの報酬を検出したら失敗。
- 同じサポートカードを**仮想デッキの2枠**に配置し、本番`aggregate`の「提供カード数は1・経路はスロット別」の不変条件を全投影カードで検査する。
- 明示`terminal:true`の選択肢がある親と、それを参照する後続イベントがあれば、その選択肢に変えた際の後続`reachability`が必ず`blocked`となることを確認。
- 本番集計エンジンの入力に渡した文章をレポートへ返さない。正式公開レビューの実施・著作物の転載・ユーザー操作の実ゲーム直接試験とは独立する。

## 合否の意味

**A 機構：** 合成フィクスチャでauto／選択式／成功失敗／選択打ち切り／後続依存／通常ヒント／同一カード二枠の集計を検査。不正なカードIDや候補数、公開フラグ、スキルID・Lvを拒否する。元CIのカード・スキル辞書と同じ環境で実行する。

**B 実固定出典：** 元から固定している `systemless10/UmamusumePS@6e38b54af4fad397ff4491e63007a90705a4fe67` の2,488イベントへ、2026独立スキル名照合済みの数値対応を注入する一時的な全件CIで全ルートを通す。これは**GameToraに収録されている範囲でのエンジン実行**であり、実際の現行ゲーム全件の完全性や編集上の正しさを保証しない。

**C 環境：** Nodeから実ランタイム集計エンジンを呼び、既存のLinux Chromium回帰も走らせるが、**未承認2,488イベントを実公開Pagesの表示に入力したわけではない**。ゲーム内の報酬再現、Windows/Android端末、文章の日本語表示や公衆再配布の許可は別。

今回の目的は「全イベントの**実行可能性**に対する統合検証」であって、正式収録の完了ではない。**正式公開イベント0件、GTにないSSR4枚、重点出典差異65件**は変えない。次のボトルネックは元出典確認・公開用のイベント文章の独自表現・ユーザーに見せる時点の権利/編集レビューである。
