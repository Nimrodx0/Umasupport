# Phase 3 F-06 / F-09：目標セット管理と設定JSONの統合読込

更新：2026-10-18。[要件定義](requirements.md)、[ロードマップ](roadmap.md)。

## 読込時の三択と衝突ポリシー

ファイルを読み込んだ段階では保存状態を変更せず、件数・統合の可否・所有記録の衝突数をプレビュー表示。

- キャンセル：保存・選択を一切変更しない。
- **統合**：読込デッキは本育成と継承育成のそれぞれ末尾へ全件追加し、新しい一意のIDを採番する。名前・構成・旧IDが同じでも上書き/重複除去しない。目標セットも別IDで全件追加。**現行の選択デッキ・選択目標・表示モードは保持**。所持情報は現行優先とし、現行が未登録のカードだけ読込側の所持/未所持で補完する。衝突した明示「未所持」を勝手に「所持」に変えない。
- **置き換え**：確認ダイアログを経て現行の全設定を読込内容へ置換。設定に含まれない情報は失われる。

## 安全な統合・目標管理

- settings.js の merge() は元の現在設定と読込設定の双方をクローンし、それぞれ parse() で検証。作業結果も再検証し、失敗した場合にどちらの入力もlocalStorageも部分的に変更しない。
- v1の単一デッキとv2の複数デッキ・v3所持記録を読み込み可能。不明サポカ/スキルIDは勝手に推定しない。
- 上限はデッキ各50件、目標セット100件。統合結果が上限を超える場合、統合操作は拒否し、検証済み読込ファイルによる置き換えだけ可能。新規/複製の目標セットIDは時刻に頼らず一意に採番。目標内容を複製しても元と独立。
- 目標編集画面内に選択中セットの切替を追加。名前は1～60文字で検証し、削除には確認、最後の1件は削除不可。
- 同じJSONファイルを繰り返し選択できるようファイル入力値を読み込み開始後クリアする。

## 独立受け入れゲート

A：正常/破損v1・v2・v3、6枠・凸・選択の保持、全ID衝突、所持記録の一致/衝突、100/50件上限と無変更、作成・複製・改名・削除を人工データで検証。

B：既存の563枚・スキル辞書を参照。実ゲームデータや第三者画像の追加、イベントIDの承認はなし。旧/別時点の参照IDが不明なら取り込みを拒否する。

C：Linux Chromium人工563枚で読込プレビュー・キャンセル・統合・置換・不正JSON拒否と連続目標セット操作を検証。Android/Windows物理端末は後でまとめて受け入れ。
