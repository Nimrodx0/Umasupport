# GameTora本体のR・SRサポカで共通イベント取得器を検証（2026-10-29）

## 目的とスコープ

[汎用イベント変換器の先行ゲート](verification-plan.md#4a-gametora汎用取得変換器の次工程引き渡しゲート)は、SSRサンプルだけでは合格できない。SSR30030／30041／30080およびSSR30322／30323の限定実証に加え、**R10016** と **SR20075** の元GameTora表示にも**同じ**DOM抽出器・スキル辞書ID照合・四系統統合器・非公開アプリ型投影を適用する。実際の新カードを検出する運用テストではなく、**既存カード2枚による診断専用の合成取り込み計画**を使い、読み取り以外の操作はしない。

## 方法

- [.github/workflows/official-gametora-r-sr-source-browser.yml](../.github/workflows/official-gametora-r-sr-source-browser.yml) はGitHub Actionsの実ChromeでGameTora元サイト一覧を1回参照し、そこに掲載された対象2枚の実在URLだけへ進む。事前にrobotsを読み、1回の実行で訪問するカードページは最大2枚。HTTP制限を回避しない。
- 変換器にはR／SR用特別コードを加えない。事前に固定した独立UmaSimスキル辞書を用い、ヒント名からの数値ID解決を厳格に実施。サイトに表示されない報酬・選択肢・連続条件は補わない。
- 原ページの文章・HTML・画像・生のイベントJSONをGit／ログへ保存しない。出力するのはカードIDとイベントパネル数・共通スキーマ形イベント数・結果数・数値効果数・ヒント数だけ。取得できなかったパネルは「報酬なし」にせず保留し、**形式的に処理できたものも承認済みへ格上げしない**。

## 初回の元サイト実Chrome観測

[GitHub Actionsの限定実行 #40818542569](https://github.com/Nimrodx0/Umasupport/actions/runs/40818542569) は、元一覧からR・SR両ページを発見し、合計**2カード訪問**して成功。

| 観測 | R10016 | SR20075 |
| --- | ---: | ---: |
| 元サイトに表示されたイベントパネル | 2 | 5 |
| 共通器で構造化できたイベント候補 | **2** | **4** |
| 未変換・曖昧なイベントパネル | 0 | **1** |
| 非公開の結果経路 | 4 | 7 |
| 構造化された数値効果 | 9 | 16 |
| 一意に照合したイベントヒント | 1 | 2 |
| 公開イベント／元DB変更 | 0／なし | 0／なし |

**R10016の2/2は元サイトの表示2パネルに限定した機械的な構造成功**。元ゲームの全イベントや、ゲームでの効果の正確性を示す数字ではない。SR20075の未変換1件は、今回の概要報告だけでは**どのパネル・どの表示が原因か未切り分け**であり、次の専門的な診断対象とする。サポカIDは元サイトの診断対象識別であって公開承認を表さない。

## A/B/C判定と今後の課題

- A 機構：既存の共通URL発見・カードID境界・統合器と、新しい読み取り専用のR/SR試験ゲートが成功。カード固有の汎用変換ロジックの追加なし。
- B 実データ：このR・SR各1枚の元サイト限定のパネル数と構造候補数を観測。イベントと効果の全件独立照合・別の日の再現は**未実施**。
- C 環境：Ubuntuの実Chromeで取得・非公開投影の限定試験に成功。アプリのWindows／Android実機は別の未完了条件。

**今後**：SR20075の保留パネルを原位置で分類し、R/SRの内部連続依存・未知効果やヒント行の未解決を検査する。友人／グループなど他構造もまだ全種の証拠がない。元サイトの全表示要素の独立照合・反復取得が完了するまでは**汎用変換器の先行工程未完成**、継続更新工程へ進まない。
