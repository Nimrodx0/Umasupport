# Phase 2：通常継続の既定ルールを使った連続イベント・選択ルート試算（2026-10-23）

## 修正理由

従来の [5SSR・15段階の手動到達レビュー](phase2-30221-chain-pages-preview-20261023.md)では、ユーザーが全段階の「到達した」を入力しないと、結果のスキルを計算できなかった。しかし2026-10-21の[固定GameTora基準ルール](gametora-baseline-event-policy-20261021.md)では、**通常の非最終連続イベントは明示的な `chain_end` がなければ継続を既定とする**ことを既に決定済み。段階そのものの発生がランダムなこと、選択による打ち切りがあることを理由に、すべての段階の入力をユーザーに強制したのは設計方針の適用漏れだった。

新しい[連続イベントの選択ルート試算](https://nimrodx0.github.io/Umasupport/poc/phase2-chain-plan.html)では、5枚すべてで初段から順に選択肢を指定するだけで、後続のスキル**候補**を表示する。選択肢のない段階は、前段の選択を指定した時点で自動的に計画上の候補として進む。従来の「各段階に到達した」試用ページは内部の個別段階テスト用に残す。

## 17経路の状態を正確に区別する

5枚のカードに対し、初段→次段の選択／無選択経路が17件ある。参照した各カードのGameWith記事は、次段階のイベントと報酬を記載するが、17件それぞれについて継続を積極的に証明する記述はない。確認した範囲では**明示的な打ち切りの記載もない**。

- **計画上の既定継続：17件**。非最終段階の選択結果に、出典で打ち切りが明示されていない場合の既定モデルを適用。独立の「未承認」プレビューのみで有効とする。
- **個別の分岐条件を資料から確定した経路：0件**。打ち切り記載なしは無条件の継続保証ではない。もし後日特定の打ち切りが判明したら、その選択肢だけ無効化して再計算する。
- **ゲーム内の後続イベントが育成中に必ず発生する件数：0件**。これは経路条件と別の、確率的な発生の問題。[公式FAQ](https://support.umamusume.jp/faq/)も連続イベントの完走が必ず起こる仕組みではないと説明している。

前者の17件を2番目の0件に読み替えたり、計画されたスキル候補を実際に獲得したスキルと誤認したりしない。

## 固定データと処理

- `poc/data/curation/phase2_five_chain_continuation_policy.v1.json`：カードIDと一対一で参照元5記事、各前2段階の0/2選択枝、打ち切り明記の有無、保証していないという区分を保管。
- `poc/src/phase2_chain_plan_build.cjs`：既存GameWith採用済み5SSR／15段階／22結果行／9ヒントを読み取り、17経路を `ORDINARY_DEFAULT_NO_EXPLICIT_CUTOFF` という**通常継続の仮定**で接続。各経路は `individuallyVerified:false` と `nextEventOccurrenceGuaranteed:false`。最終段階には次段を作らない。
- `poc/preview/phase2-chain-plan.v1.json`：外部の選択肢セリフ・記事本文・画像を含めない開発用最小データ。Node CIで上記生成器の全内容との一致を検証。公開用イベントカタログとは別。
- `poc/src/phase2_chain_plan_client.js`：ユーザーが初段を選ぶと、次段の候補を開く。選択肢なしはそのまま進行計画に組み込み、後続を勝手に「発生した」扱いにはせず、予測可能性の**試算**として本番 `UmaCore.directRoutes` を使用。前段を変更したときは後段の以前の選択を解除する。
- 具体的なスキル名はすべて日本語名称で表示し、内部数値IDは出典と計算のキーのみに使用する。

## 検証と未解決

A：通常Nodeで数値元台帳との完全一致、17経路の未検証・未保証フラグ、実 `UmaCore.directRoutes` への候補選択入力、正式公開DB／承認台帳0件を確認。B：5枚個別記事の連続段階／未掲載打ち切り情報に依存した**既定ルール**。**出典が沈黙する箇所を積極的な分岐証明と呼ばない。** C：Chromium実画面で段階1→2→3選択に連動した利用可能化、選択肢のないカードの候補自動表示、390/1280px、改変拒否を試験。

**今後のデータ本番収録では、GameTora元JSONで `chain_end` が明示された箇所の例外除去を先に行い、結果別の報酬条件も精査する。** GameWithのみのカードに関して個別経路の打ち切りや結果分岐の根拠が後から見つかれば、今回の「通常継続既定」モデルを再編集する。5枚・15段階の通常継続シミュレーションが利用者向け正式イベントDBへの掲載許可になったわけではない。

正式公開承認イベントは引き続き **0件**。連続発生を保証したり、実ゲーム再現・ゲーム内部story_idの他資料照合を新たに必須にしたりしない。
