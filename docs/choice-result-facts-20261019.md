# 全417枚の選択肢・結果・スキルファクトDB v1（2026-10-19）

## 重要な追補（2026-10-19・同日後刻のユーザー指示）

本書の先行仕様で「連続イベントの打ち切りや次段階の遷移を収録前提としない」とした判断は、**連続イベント内部の分岐について撤回**された。実ゲームでイベントが自然発生する外部条件（絆・ターン・確率等）は不要だが、**連続イベントの前段の選択が後の選択肢・報酬・打ち切りに影響する場合、ウマサルタントで忠実に再現することは必須**。

`checker_choice_results.v1.json` と `?eventPreview=facts` は、元ソースから抽出した選択肢位置・数値ヒントのみで、`requires`／`terminal` をまだ含まない。**この試用表示を「実際に選べるすべての後続ルート」とみなしてはならない。** 既存の2025年 `chainNum`／`chainMax` は系列構造のヒントであって選択別の分岐を証明しない。次工程ではソースに確認可能な選択肢の進行先や打ち切りを独自データとして付与し、選択変更時の後続無効化までテストする。

## 目的と仕様の変更

ウマサルタントの必要要件を **カード → イベント → 選択肢位置 → 結果（記載があれば結果別） → 数値スキルID・ヒントLv** に限定する。出現率、ゲーム内のイベント発生条件、連続途中の打ち切りや次段階の遷移、ゲームマスターの2026年版との全件同定は収録前提にしない。2026-10-19最新 [要件定義](requirements.md) と [意思決定](decisions.md) を優先する。

ただし、現在のUmaUmaChecker由来の数値候補は **選択肢ごとのヒント記載だけ**を確保したデータで、成功・失敗などの明示的な結果ラベルが構造化されていない。単なるヒント記載を「無条件」や「大成功」と決めない。ゲームでスキルを確実に取得できることは主張しない。

## 永続データベース

**`poc/data/candidates/checker_choice_results.v1.json`** は、既存の `checker_event_hints.v1.json` に含まれるカード／候補イベント／選択肢の全数値事実をウマサルタントの独自スキーマに変換し、元記事のイベント見出し・選択肢文章・効果文章・画像を含まない。本文・元JSONの選択体系を丸写しするのでなく、数値キー、位置とヒントの独自関係データとして管理する。

- `cards[].cardId`：5桁のUmaSimカード数値ID。
- `events[].sourceKey`／`sourceDigest`：候補の位置を追跡するための出典指紋。現行ゲーム正式story IDとはみなさない。
- `events[].sourceEventOrdinal`：資料上のイベント位置。ゲーム内発生順を意味しない。
- `choices[].ordinal`：候補ソース上の選択肢位置。元の選択肢文章は収録しない。
- `choices[].resultCandidates[0].resultKind:"unspecified"`：**結果が資料側で未区分**であることを明示。成功・失敗・無条件取得のどれかに推測しない。
- `skillHints[]`：数値スキルID＋ヒントLv。これまでの全ID照合が成立した記載を保存。
- `unresolvedSkillHints[]`：数値未照合のスキル名称・理由・ヒントLv。既存の不明記載を失わない。
- `candidateStatus`：
  - `numeric-choice-candidate`：ヒント数値IDが揃い、ヒント構文・結果条件の検出フラグなし。
  - `needs-choice-or-result-review`：数値ID未照合または条件／構文フラグあり。
  - `no-observed-skill-hints`：候補ソースの当該イベント選択肢からスキルヒントを抽出できなかった。**現実には報酬なしと確定していない。**

入力元候補ファイルの完全な件数・SHAを検証し、さらにコンパイラを実行すると全カード・イベント・選択肢・ヒント数値が一致することを確認する。結果情報の網羅性を過剰に主張しない。

## 実ブラウザ試用：417枚ソースのうち398枚・879件

対象のリンク：

**https://nimrodx0.github.io/Umasupport/poc/live.html?eventPreview=facts**

全417枚の独自数値DBのうち、ブラウザ表示するのはヒント記載があり、数値スキルIDが単一照合でき、未解析の結果・ヒント構文のフラグがない**879イベント（398カード）**。これは原資料の収録率・現行ゲームの完全網羅を意味しない。残り232件＋998件はDBには保持し、結果の解析が済むまでUIのヒント候補へ加えない。

データベース自身が元の選択肢文章を含まないため、UIには「選択肢 上／下」の意味で **「候補位置1／2／3」** を表示。元記事の台詞や選択肢の意味を推測しない。**いずれの獲得候補にも `condition:"候補資料でヒント記載・獲得結果未区分"` を付ける。** 結果別でスキルやLvが変わる可能性を消さず、現行のスキル一覧では条件付き候補として集計する。初期状態でどの選択肢も選択されず、結果未区分を無条件・確定獲得扱いしない。

ブラウザの読み込み・カードID・スキル辞書照合は既存の `UmaPublicEventCatalog.attach` を再利用する。イベントを本番DBへ昇格するわけではない。次の設定ストレージは互いに独立：

- 通常 `poc/live.html`
- 既存 `?eventPreview=30311`
- 既存 `?eventPreview=expanded`
- 新 `?eventPreview=facts`

通常モードの `poc/data/reviewed_events.v1.json` とスキル候補集計結果には**一切混ぜない**。候補の表示に実ゲーム出現条件や古いchain IDの照合は要求しない。

## ビルドと次に必要な作業

```bash
node poc/tools/build_choice_result_facts.cjs
node poc/tools/build_choice_result_facts.cjs --verify
node --test poc/tests/choice_result_facts.test.cjs
```

一回のみの生成は専用のGitHub Actionsで所有者のPRブランチに数値データだけをコミットする。既存ファイルは明示的に削除しなければ上書きしない。通常CIは各リビジョンで実数全件を検証する。ソース原文・外部DBを再取得しない。

**次の開発優先順位：** 232件の結果・ヒント構文フラグに対応する元の数値事実を、合法的に用意した原資料から「成功／大成功／失敗」を区別して抽出し、`resultKind` が明示された事実のみを追加する。同時に、未照合98ヒントの数値IDを解決する。通常モードへの取り込みは、選択肢位置とスキル・結果別Lvの対応をユーザーが使えるよう正規化できたものから段階的に進める。
