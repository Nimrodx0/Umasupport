## 2026-11-10の再評価（AIエージェントを優先）

この判断は、当初の「すべての文書をフォルダへ入れて人間が見やすくする」という改善動機だけでは正当化できません。Diátaxisは文書の4つの目的を示すものであり、ディレクトリの完全分類を義務化しません。

改めて、AIエージェントが`AGENTS.md`から対象タスクに必要な正本・現行コード・検証証拠へ短い経路で辿れることを最優先します。[OpenAIのHarness Engineering事例](https://openai.com/index/harness-engineering/)に照らし、ルートに`index.md`以外の文書を禁止する条件は撤回しました。

現在のフォルダ構成は、意味ある分類・既存リンクを活かすため**積極的には変更しません**。不要な再移動よりも、常時読み込む指示の節約、タスク別導線、コードと文書の同期、回帰検査に投資します。将来の配置変更は、実際の検索失敗・正本重複・情報の鮮度問題がある場合に限定します。

## 背景

監査文書がdocs直下に大量に並び、roadmapの一部に研究結果が集積し、現行の仕様・歴史・次工程が読み分けにくくなっていました。

## 検討した選択肢

| 選択肢 | 長所 | 短所 |
| --- | --- | --- |
| 平坦構成を維持 | ファイルパスが変わらない | 目的資料の発見が困難 |
| 全文書をDiátaxisの4種へ移動 | 目的は明確になる | 研究の時点付き証拠、意思決定、工程は4種だけでは不十分 |
| 原本は主題別、読者向けは目的別の入口を作る | 証拠保存と読みやすさを両立 | 横断索引・リンク整合性を保つ必要 |

## 判断基準

1. 開発エージェントが起動時に必要な指示の量が少ない。
2. 変更対象から現行要件・設計・コード・テスト・証拠への経路が短い。
3. 過去の判断、未検証の推定、正式な公開承認を混同しない。
4. 文書移動による既存リンク、コード内の参照、CIの破壊を避ける。
5. 新規フォルダは独立した責務と継続利用が必要な場合のみ作る。

## 決定案

第三案を採用する提案です。現在値・要件・技術契約を正本とし、原本はevidenceの主題別に保持します。チュートリアル／手順／参照／解説を実際の利用場面に合わせて区別し、WBSによって工程と成果物、ADRで決定の背景を管理します。

## 影響と未解決

相対リンクの検査、資料の有効性の明示、移動前後の情報保存監査が必要です。全ての過去の判断を自動的にADRへ変換したり、すべての研究結果を「現在の仕様」とみなしたりしません。正式採否はPRのレビューで確認し、採用するときに状態・採用日・判断の根拠を更新します。
