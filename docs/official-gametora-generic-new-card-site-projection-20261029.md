# 新カード共通のGameTora DOM抽出と、ウマサルタント型への非公開結果投影（2026-10-29）

## 目標と対応範囲

**既存ウマサルタントDBの全件置き換えはしない**。新カードIDをUmaSimから検知したら、そのカードの元GameToraページのイベントだけを取得し、既存DBに増分追加するための共通変換器を作る。今回の対象は、既存のSSR30322／30323の限定Chrome実測で再利用可能だった「元サイトDOM→表示グループごとの結果情報」と、「統合した結果別数値・スキル報酬・明示進行マーカー→アプリのイベント形式に似た非公開候補」の2層である。

**GameWith、旧GameTora派生JSON、成功・失敗等の結果名は変換入力にしない。** 取得した原文・HTML・画像を、ログ・PR・アプリ配信先へ保存しない。独立UmaSimスキル辞書によるIDの照合は維持する。

## 新規コードと既存コードの接続

1. `poc/src/official_gametora_route_dom_extractor.cjs` は、元GameToraカード詳細ページの開いたイベントパネルを **Playwright `locator.evaluate(extractRoutePieces)`** に渡して実行するカード非依存のDOMパーサ。外側の表示グループの順序と、明示ORの結果の順序を保持する。表示した結果の範囲内にある数値効果・ヒントの文字列と局所祖先・直接スキル習得候補・連続打ち切り／お出かけ解放の表示断片を収集する。
2. `poc/src/official_gametora_live_event_assembler.cjs` は、従来の四系統（数値、局所ヒントID/Lv、直接習得、進行マーカー）を**元の表示位置を厳密に保持して**結合する。カード固有の条件は持たない。
3. `poc/src/official_gametora_private_schema_projection.cjs` は、四系統の結果別統合を、独自DBと同じく `event→choices（元サイト表示グループ）→outcomes（表示OR結果）→rewards/effects/terminal` に機械投影する。**表示グループをゲーム内の選択肢と確定するものではない**。内部の仮ラベルは「イベント4」「選択肢1」「結果2」等の中立番号だけ。元サイトが直接示したヒント数値ID／Lv、直接獲得の数値ID、数値効果、結果位置、明示的な打ち切りだけを載せる。`terminal:false` や、見えない `requires` の自動補完はしない。
4. `projectNewCardSite` は、サイト上の全イベントパネルの数と、処理したイベントの番号・枚数が**完全一致**しない場合に停止する。すべてのパネルについて非公開のスキーマ形候補を集計し、**カードごとの取得状況を前工程の増分取込器へ渡せる非公開候補**を生成する。元サイトの選択肢意味・スキル報酬の網羅・進行・公開権利が未証明のため `convertedEventCount:0`, `unresolvedEventCount:siteEventPanelCount` として、`stageNewCardEvents` では当該新カードを保留する。ここで一部の報酬をゼロ扱いして公開させない。
5. `poc/tools/probe_official_gametora_new_cards.cjs` は、既存のSSR30322/30323限定ページで上記2共通モジュールを使用するよう切り替えた。**任意の未知カードURLの発見・自動巡回**は今回実装しない。ページのイベントパネルが20件を超えたら、部分取得による完了誤認を避けて停止する。

共通DOM抽出は当初内部で最大30グループを切り捨てていた。今回、最大20表示グループ・1結果80数値行・60ヒント行などの上限を超えた場合に例外で停止する。元のHTMLを部分抽出して「完了」と認定しない。

## 検証区分

- **A 機構**：合成DOMでORの2結果を別々の位置として抽出、別グループへ混ぜないこと、表示パネルの欠損・件数超過を検知。独自DB形の非公開投影について、結果1/2の別々のヒントLv、直接付与、数値効果、明示停止、結果順序不正、別カード混入、ページイベント件数の差をテスト。加えて既存イベントDB増分追記の保留ゲートを通す。
- **B 実サイト**：GameTora本体SSR30322／30323の**限定2カード**のイベントパネル18、元サイトで直接観測できた16イベント27結果の既存母集団を、カード固有処理を使わず共通DOM抽出・私的DB形へ投影し、元四系統集計の結果数と比較する。
- **C 実ブラウザ**：GitHub ActionsのPlaywright Chromeで**2ページだけ**の結果抽出・投影、既存アプリのブラウザ回帰も維持。ユーザーのWindows／Android物理端末は今回未実施。

## 残る完成条件

今回の出力は**実際のアプリ用DBイベントではなく、位置と報酬が写像できた非公開候補**である。ゲーム内の選択肢と表示グループの同定、GameToraに表示されたスキル報酬の全行の抽出、連続イベント内部の後続依存の確定、各新カードの全イベントの位置照合を完了し、公開承認ゲートに通す必要がある。**これらをGameWithの名称分類で代替しない。**

運用として、任意の新カードIDから元サイトのページを適切な制限で取得する機構、保留リストの継続保存、承認済み新カードのみを既存イベントJSONへ追記する原子的コミットは次の接続工程。正式公開イベントは0件のまま。
