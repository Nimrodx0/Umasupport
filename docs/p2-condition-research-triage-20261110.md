# P2 条件コード別の研究優先度・初期全件監査（2026-11-10）

**位置づけ：研究計画と元辞書に対する分類監査。スキルの脚質適性・サポカの優劣は未判定。製品UIの構成も保留。発動後の効果の有用性は将来の拡張候補とし当面の対象外。**

## 目的と資料

元コードを125種類一律に深掘りしない。**脚質別の発動条件成立機会に、繰り返し検証できる傾向があるか／モデル上で測定可能か／アプリ収録スキルの研究価値がどの程度か**を優先判断する。スキル効果やヒントの取得確率は評価しない。

[P0元条件監査](skill-condition-inventory-audit-20261104.md)と同じ固定UmaSim \`f6e4501ee6c6c2d4ac8698e7796e309d31575bde\` の \`skill_data.txt\` と、公開済みイベントを読み込んだアプリモデルを再利用する。[監査器](../poc/tools/audit_skill_conditions.cjs)から[分類関数](../poc/src/skill_condition_research_triage.cjs)を呼び出し、原典辞書本文をPublicへ転記せず分類・集計JSONをActionsの研究成果物に保存する。

- 元辞書 **2,162スキル**・**125条件コード**。アプリは881レコード中 **818件の元条件をID＋名前で照合**（63件は未収録のまま保持）。
- 90種類のアプリ対象コードについて、**初期分類漏れなし**。カテゴリーは出典に存在する条件の**研究方針**であり、条件が実際に脚質の優劣を生むとの実験結果ではない。

**コードを保留すること ≠ 当該スキルが全脚質で汎用であること**。たとえば先頭・前方馬との距離差（\`distance_diff_top\`, \`bashin_diff_infront\`）は文脈に依存するため、脚質推定の根拠から除外する。AND内に明示脚質や別の検証済み順位条件があるときは、それらを独立に扱う。**未知を0%、制限なし、脚質差なし、全脚質で高適合とはしない**。

アプリ照合済みスキルの構造監査：複数Invoke **35**、前提条件あり **23**、OR条件あり **102**、順位系条件を含む **273**、予備研究系条件を含む **142**、推定見送り／保留条件を含む **89**、順位系と推定見送り／保留が混在する **17**。いずれも重複あり。**一つの条件が研究対象でもスキル全体を研究済みへ昇格しない**。

## 何を優先して調べるか

### 優先度A：既存モデルの観測量と接続できる研究

1. **絶対順位 \`order\`（34件）**：既存の順位軌跡から、明示された整数順位の成立機会を研究する。順位割合 \`order_rate\`（238件）と同義に扱わず、9/12頭、同順位・時期窓・ANDの同時条件を維持する。後続の全アプリ対象経路別監査で研究済み32条件との重なりと未対応数を確認する。
2. **発動区間・走路形状（\`phase_random\` 200件、\`all_corner_random\` 35件、\`straight_random\` 31件など）**：時期・区間は原則脚質自体の「好適合」根拠ではなく、順位や動作条件と**同じAND・同じ抽選窓で交差させる**。固定モデルのコース形状と実ゲーム側の区間定義が一致しているか確認。

### 優先度B：成立機会の実験可能性を確かめてから拡張

1. **スパート状態** \`is_lastspurt\` **55件**：モデルのスパート判定がレースの状態・体力・区間と整合するか確認。終盤なら必ず成立するという近道は使わない。
2. **順位変動** \`change_order_onetime\` **30件**、**追い抜き状態** \`is_overtake\` **21件**：意味が異なるため別々に検証。モデルが順位の入れ替わりは出せても、追い抜きモードの正確な原条件を持たないならモデル上の代理値から正式評価へ移行しない。
3. **横ブロック** \`blocked_side_continuetime\` **20件**：追走状態・相手編成・レーン・接近時間の情報が必要。UmaSimの近似状態を実ゲームの出来事として扱わず、実測可能性・モデル依存度・代表ANDの交差を確認して、困難なら研究保留。

### 原則見送り・低優先

- 馬身差・先頭との差・近傍の他馬など（\`distance_diff_top\` 13件、\`infront_near_lane_time\` 10件など）：一般的な4脚質への判定が不安定／環境依存の可能性が高い。必要な条件は保持するが、近似値から汎用・不利・有利ラベルを作らない。
- 他スキルの発動、抽選、育成ステータス、枠番など：明示的な条件はそのまま保持し、単独の脚質傾向研究には使わない。需要・検証可能性が確認できるまで保留。
- 発動後のスキル効果（速度／加速／回復の有用性）：**将来拡張候補**。今回の条件研究にもサポカ評価規則にも混ぜない。

## 採用ゲート

1. **母集団と対象経路の一致**：固定辞書とのID＋名称照合、通常ヒント／承認イベント報酬の取得経路の対応、同じAND・OR・preConditions・Invokeの分離。条件コード出現数はサポカ枚数でも確定報酬数でもない。
2. **測定機構の確認**：GlobalSim/UmaSim/実ゲームのどの仕組みで何が測れているかを根拠とともに明示。観測不能なものは保留し、作った代理値をゲーム発動率と呼ばない。
3. **条件単体 → 組み合わせ**：同じAND経路内の同時成立を確認する。周辺確率を独立と仮定して乗算しない。ORは正しい和集合が得られるまで経路別に扱う。
4. **条件付きの一般化**：4脚質別、9頭／12頭、編成・コース・能力差、同順位、シード分割、反例で妥当性を確認。既存の32元条件についての研究を、すべての順位条件に無条件適用しない。
5. **製品への適用**：判定基準・サポカへの集約規則・具体的UIは未確定。研究結果が不確かな条件は「汎用」ではなく「脚質傾向の推定対象外／不明」とする。

今回の監査は条件を単純な表に分けた**最初のスクリーニング**であり、研究可能／不要との最終結論ではない。次は条件型の出現数だけでなく、**同一ANDの元条件ごとに、実データ上で追跡可能なスキル・サポカの数**を確認し、優先度A/Bの代表例と反例を固定する。
