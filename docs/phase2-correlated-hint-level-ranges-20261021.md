# Phase 2：GameToraヒントLvの低／高同期結果を試験スキーマ化（2026-10-21）

## 仕様の根拠

固定GameTora由来データの `+1/+3` のような効果値は、`systemless10/UmamusumePS` の固定版 [`event_engine.py`](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/app/event_engine.py) で、**1つの選択の低結果・高結果を表す数値対**として処理される。同じ効果経路に複数の幅値があれば、同じ低／高インデックスを適用する。ORヒント（`skill_hint_or`）は別軸として、複数のうち必ず1候補だけを選ぶ。

従来の「幅値は未解釈なので拒否」は安全だったが、全候補に共通の低／高結果を生成できる場所でもスキル表示を止めていた。今回、ゲーム元データに掲載された正確な数値だけを `outcomes` に投影する。**ゲーム実機の現行2026年結果と出現確率を検証したものではない。** 原イベント名・選択肢・本文を配信しない。

## 実装

- `poc/src/gametora_whole_event_normalize.cjs`：`value`の符号付き整数ペアを検査し、元の数値事実として `numericRange` と `levelRange` だけを保存する。文字列原文は保存しない。レベルが1〜20の範囲外なら無効。
- `poc/src/gametora_event_skill_crosswalk.cjs`：幅値を持つ通常ヒントは `rangeLocations`、OR候補の数値幅は `alternativeLocations` に元位置番号・数値ID・値のペアだけ保持して別々に照合。通常の固定整数の1,681件とは別の未解析記載から昇格させる。
- `poc/src/gametora_app_schema_dry_run.cjs`：同じ元経路内の複数の幅ヒントを**同一の低／高結果**に同期し、固定Lv報酬は両方へ共通収録。OR候補との積は最大32結果で打ち切る。ID／Lvに不一致、重複スキル、条件不明ならイベント全体を保留する。
- `poc/tests/gametora_app_schema_dry_run.test.cjs`：`+1/+3`と能力値`+5/+10`の相関、共通ヒント、OR候補との排他、クロスウォーク改ざん、結果未選択時の `conditional` を合成データで検査。
- `.github/workflows/whole-event-inventory.yml`：2025年補完を含まない全件変換と含む全件変換の**両方**を、出典SHAの固定と数値母集団・正確な適合/保留件数で失敗判定する。安全ゲートはスキップしない。

## 次工程と公開ゲート

残る特殊ケース21、依存1、重複1を数値位置別に解析する。特に直接獲得はヒントとは異なる仕組みであり、取得保証として一般のヒントに混ぜない。連続以外の `chain_end` を無視すると連続進行の保証を誤るため、別の連続到達条件を検証するまでは保留する。

現行ゲームの2026年版スキルと報酬、選択肢の独自表現、権利、GitHub Pagesへの公開は**独立ゲート**。`poc/data/reviewed_events.v1.json` の本番イベントは0件のまま。Windows/Android実機でも新UIを検証したとは言わない。
