- **現行の主経路**：`systemless10/UmamusumePS` のGameTora由来構造化JSON、`server/data/events/gametora/support_<ID>.json`。版を記録し、カード単位で既存の独自イベントDBへ追加する。
- **撤回**：2026-10-27以降のGameTora本体HTML直接抽出を主たる収録元へする計画、2026-10-29の「直接取得器の完全な引き渡しゲートを通過するまで継続更新・サービス完成へ進まない」という依存。
- **保留**：GameTora本体のDOMを閲覧するPlaywright・抽出・統合の試作と、SSR／SR／Rの検証資料。未完成であると明記した上で削除せず保存し、今後のイベント収録や公開ゲートの必須条件にしない。
- **維持**：GameWithの個別欠損・疑義に限る編集裁定、文章／画像等の無許可転載禁止、既存カード・承認履歴・設定を変えない増分追記、公開審査の独立性。
- **利用者向けの目的**：本育成・継承デッキ、カード選択・所持管理、イベント選択／結果、条件付きスキル・ヒントLv、金白階層、比較、重複・未カバー・目標・逆引き・保存の全機能を、実用可能なデータと共に公開する。収録元の技術実証を完成品と呼ばない。

## 開発順序（旧直接取得工程から移行）

1. **取得入口**：UmaSimの新旧全サポカIDと旧DBの収録IDに対し、固定コミットのGitHub tree上で対象カード `support_<ID>.json` があるかを判定。存在しても本文の変換は別ゲートにする。旧名簿差分がなくなる翌日も保留IDを持ち越す。追加・変更・削除の差を既存の監視から再利用。
2. **本文変換と例外整理**：取得したJSONのkind・cardID・イベント件数・選択肢・結果・各ヒントID/Lv・直接付与・明示打ち切り・内部先行条件を、カードやゲーム内の選択肢に勝手な補完なく正規化。旧固定コホートの全件監査に戻り、構造の原因別に一括対処する。未知効果・名寄せ・到達関係は該当結果単位で保留する。対象外の非スキル効果はスキル獲得集計を無用にブロックするか再評価するが、結果位置を取り違えない。
3. **独自DBへの安全な投入**：収録対象カードの全イベントと依存関係が確認できたものを審査し、必要な公開条件を通ったカードだけ既存DBへ**原子的に追加**する。既存イベント・承認台帳・ユーザー設定は一切変更しない。新カードのJSONが未到着なら保留、新カード以外を更新する処理は拒否。公開0件の状態から実収録イベントを増やせる機構と審査を整える。
4. **利用者機能の受け入れ**：F-01〜F-09のUIでデッキ・イベント選択・保存、同一／別デッキ重複、目標カバー、金白・ヒントLv、所持・逆引き、スマホ表示の異常系まで通す。GitHub Pagesの配信物とソースを一致検査し、Windows／Androidの実端末未実施は明記する。

## 完成判定と保留の境界

- **A 機構**：構造化GitHub JSONの同一カード／イベント／選択肢／結果の重複・欠落・異IDを拒否。スキルヒントLvと直接付与を混同しない。非連続・連続・結果依存・打ち切りを分け、上流更新／破損／キャッシュ障害でも既存データを無変更に保つ。全件自動公開は不可。
- **B データ**：対象の最新UmaSim母集団、GitHub出典の版とカード別ファイルの有無、独立イベント収録・未照合・例外の分母と件数を記録。サポカを選択できることとイベントの全件性を混同しない。固定旧出典の件数を現行ゲーム網羅率として使わない。
- **C 実体験**：GitHub Pagesで公開されたアプリに、審査済みの実カードのイベントを読み込み、選択変更・到達解除・重複・未カバー・目標・保存復旧・モバイル表示を確認する。Chrome合格はWindows／Androidの物理端末検証の代替ではない。
- **公開・権利**：第三者JSONをそのままコピー・公開せず、独自形式の報酬に関する数値事実と参照メタデータに限定する。必要な権利・再配布・出典条件、レビュー台帳の個別承認は最終公開の独立条件。数値の取り込み技術だけで公開を保証しない。
- **停止条件**：GameTora本体の直接DOM解析のための個別カードごとの特例追加・Chrome試験は主開発から除外。新しいサイトHTMLが変わってもこの主経路はブロックされない。必要な将来の再開は利用者が優先順位を再決定した場合のみ。

## 直近の成果と残件

本方針変更の最初の実装は `derived_github_new_card_source_plan.cjs`。このモジュールは**GitHub treeのSHAとパスだけ**から、候補／不在／収録済みを安全に分け、完全でないtreeや対象外カード、同一カード重複、現行名簿から消えたIDを拒否する。新カードが1回目に不在でも、保留IDを渡した次回には新規名簿差分が0件でも取得候補へ復帰できる。テストは人工Git treeで、実イベントの取り込み・公開を意味しない。

残件は、実上流Git treeを供給するワークフローへの接続、GitHubの該当JSONを独自スキーマへ変換する結合、承認済みデータの初回追加、アプリ全機能の本番Pages受け入れである。**直接取得器の実装継続はここに含まない**。
