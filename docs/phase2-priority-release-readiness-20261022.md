# Phase 2：重点28イベントの公開受け入れブロッカー一覧（2026-10-22）

## この工程の役割

[roadmap](roadmap.md) のPhase 2における、前半「出典の収録範囲・数値差異監査」と後半「公開できる独自イベントデータへの移行」の間の受け入れ整理。固定GT2,488件全体や対象563カードの収録完全性をここで認証しない。全件監査とは独立した、直近で個別に編集照合した**8カード／28イベント位置**のみ。

このPRより前に**公開イベントのSHA・6分類の根拠URL・レビュー者・公開判断**は `event_release_gate.cjs` に実装済みだった。新たな機構は承認の代用ではなく、**各未公開イベント位置が何を欠くのか**を機械的に洗い出す入口である。出典の数値編集採用だけで正式公開できる扱いにしない。

| --- | ---: | ---: | --- |
| SSR30318〜30321の4枚 | 20（連続12／通常8） | 20 | 連続12段階の後続・打ち切り |
| SSR30221サトノダイヤモンド | 3（連続） | 3 | 前後関係・到達条件 |
| SR20075タップダンスシチー | 1（連続） | 1 | 結果の+15/+15と+5/+5の分岐条件 |
| SSR30240ジャングルポケット | 3（連続） | **0** | GameWithイベント本文が「検証中」、数値3段階の採用・選択／結果の同定 |
| SSR30080安心沢刺々美 | 1（特殊） | 1 | GT元で省略された操作3択はGameWithで裁定したが、報酬の可変部分・結果条件の確認 |
| **合計** | **28**（連続19／通常・特殊9） | **25** | 全件未公開 |

SR20075初段階とSSR30221の3位置は、既存Checker-only40／重点65に含まれる位置であり**新しい母数として足さない**。SSR30240の3位置は固定GT・Checker双方の外にある別枠。SSR30080は既存の固定GT選択構造不足1件。**28はこの受け入れワークリストの数であり全ソース不一致の件数ではない。**

各位置に共通する未解消事項は**2026年実ゲーム情報との照合、公開する独自表示の審査、公開利用根拠の判断、既存6項目の人手署名**。各位置には、さらに該当する連続内部経路、未分類結果、GameWith未掲載のブロッカーだけを追加する。

## 実装

- `poc/src/phase2_publication_readiness.cjs` は既存の`phase2_chain_manual_replay`、`phase2_30221_missing_chain_intake`、`phase2_20075_first_stage_intake`、`phase2_30240_pending_chain_replay`、`phase2_30080_three_choice_repair`を**呼び直して**固定数値・前段未確証・出典採用境界を監査する。旧個別裁定の改変があれば生成失敗。
- `node poc/tools/report_phase2_publication_readiness.cjs`：非公開／オフラインで、カードID、イベント位置、種別、採用状況、具体的なブロッカーとHTTPS参照先だけを一覧。 `--json` はプログラム連携用。ファイルは一切書き込まず、元記事の本文や第三者画像も含まない。
- `poc/src/event_release_gate.cjs` は、イベントに`noAutomaticRuntimeAdoption`や`possibleOnly`、`manualStageAssertionOnly`などの隔離マーカーが紛れた場合、**承認SHAが一致し6観点がすべてtrueでも拒否**するよう強化。これは手動レビューの代わりではなく、未承認下書きの誤配信を防ぐ追加ガード。
- テストは重点28件・8カードの件数と、編集採用25／数値保留3、連続19／通常特殊9、改変拒否、隔離マーカーの無効化、既存の公開イベントと承認台帳の空を確認する。

## 受け入れの順序

1. カードID・イベント位置を確定。元GTイベントがあるか、Checker-onlyや両固定元の外側かを区別する。
2. GameToraの固定版を第一資料に、**個別欠損／疑義に限り**GameWithを裁定。GameWithが「検証中」のSSR30240は**数値採用しない**。
3. 選択肢と結果の排他性、スキルID／ヒントLv、連続中の後続・打ち切りを照合。発生率など外部トリガーは実装不要。
4. 独自表現、利用条件、現行ゲームとの差、出典追跡を個別確認。疑義に対して公開担当者が根拠を残す。
5. 公開イベントを個別に`poc/data/reviewed_events.v1.json`へ入れ、**同一イベントのSHAで一致する人手の承認項目**を`poc/config/event-release-approvals.v1.json`へ別途記録し、`node poc/tools/verify_event_release.cjs`を通す。非公開の`poc/data/curation`を公開JSONへ一括コピーしない。
6. GitHub Pagesの実ブラウザ＋物理端末の操作、異常系を実施し、全件受け入れを別途判定。

A＝Node／CIの正負テスト。B＝固定元の重点28位置照合（**全563枚の正しさを主張しない**）。C＝Chromiumの既存UI回帰のみ。Windows/Androidとゲーム本体の実操作、承認済み公開イベントの本番表示検証は未実施。

**直近の作業優先順位**：既に数値採用済みで連続依存がない4SSRの**通常8イベント**から、独自表示・イベント識別子・結果形状の公開用レビューを進める。次にSSR30080の3択と、連続19段階のルート検証を並行する。認証済みゼロは引き続きゼロと表示。
