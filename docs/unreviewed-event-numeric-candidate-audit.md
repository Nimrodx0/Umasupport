### 過去資料での2 ID・名称の照合（2026-10-18追記）

採用辞書とは別の過去の公開データ一覧 [Bilibiliウマ娘Wikiの日本語・中国語対照表](https://wiki.biligame.com/umamusume/中日文对比表) と [同Wikiのスキル因子対応一覧](https://wiki.biligame.com/umamusume/缺失技能因子检测页)、および [2023年頃のスキル効果表](https://pages.snep.pw/uma/anni2-skill-changes/) には、**200831 = 逃げけん制**、**200851 = 逃げためらい** が掲載されている。固定候補の該当2レコードにも同じ名前・数値IDが入っている。過去に使用されたIDと名称の組の傍証が得られたため、監査器は `historicalNameMatchedAbsentSkillIds` と `historicalNameDisagreedAbsentSkillIds` を機械的に区別する。人工テストでは一致2件・名称変更1件・採用辞書への追加を検査する。

**重要：** この外部照合は歴史的な名称対応のみ。上記の公開資料は同一抽出源に依存する可能性があり、2026年現行ゲームにそのスキルIDが実装されているか、2サポカの報酬として出現するか、第三者データを転載してよいかを証明しない。`unmatchedSkillIds` には引き続き2件を残し、`historicalEvidenceApprovesEventReward=false`、`gameRewardClaimsApproved=0` を維持する。公開イベントJSONにも一切追加しない。

イベント候補 `evt_30311_830311003` の**最初の選択肢の大成功時**に対応するスキル名・ヒントLv3項目は、GameWithの記事の記述（大成功時3スキル）と一致している。ただし**GameWithの記事には同じ選択肢について成功時の別の低いLvの報酬も記されている**。候補JSONは、この成功/大成功の分岐を個別の結果として表現していない。さらに選択肢の最後まで含めた全成功・失敗条件、前後の連続イベントの到達・報酬の正確性、正式story_idと名称のゲーム内確証は未取得。

特に `selection=auto` は出典の**計画用・自動計上の独自区分**であり、「実ゲーム中に必ず発生する」「すべての報酬を無条件で獲得できる」ことを意味しない。これをアプリの `type:auto` や確定報酬へ機械的に変換してはならない。

## 分離した検証ゲート

**A：監査器の機構。** `poc/tools/audit_unreviewed_numeric_event_candidates.py` と `poc/tests/test_unreviewed_numeric_event_candidates.py`。manifest版と配信ファイルのSHA、採用UmaSimサポカの固定SHA・全563×5段階、カードID/イベントIDの型・重複・収録範囲、選択モード、スキルID/名称/Lv、30311の限定大成功サンプル、Wiki数値IDの差分を検査。壊れた入力で失敗する人工回帰を通常CIに含む。

**B：実データの限定監査。** [専用Actions](../.github/workflows/event-candidate-numeric-audit.yml)だけが固定版JSON3ファイルとUmaSim2ファイル、およびWiki公開記事を**1回だけ**読み、構造化した個数と数値IDのみを出力する。元データの著作物、サポカ画像・イベント本文・選択肢テキストをPublicに同梱しない。GameWithの3報酬の一致は別資料の**1枝の人手による限定確認**であって、126件の自動独立報酬照合ではない。

**C：実ブラウザ。** このPRでアプリUI・イベントデータJSON自体は一切変更しない。Linux Chromiumの既存回帰を通すが、Android/Windowsの実機受入れには含めない。
