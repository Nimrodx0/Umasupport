# Phase 2：GT欠損4SSRの通常8イベント・公開前の独自表示案と16選択肢監査（2026-10-22）

## 目的

[重点28件の公開受け入れ一覧](phase2-priority-release-readiness-20261022.md)から、連続段階12件を切り離した**通常2イベント×SSR4カード＝8位置**を、独自日本語表示案・選択肢ごとの数値事実・技能ID／ヒントLv・公開阻害事項の一体の**非公開レビュー記録**に変換する。すでに実装されている`phase2_remaining_ssr_intake`と`phase2_editorial_intake`の通常8件の非公開スキル草稿を再利用し、実ゲーム未証明の連続自動報酬は絶対に混ぜない。

| サポカID | 通常イベント位置 | 選択肢 | 技能ヒントが報告される位置 |
| --- | --- | ---: | --- |
| SSR30318 ライスシャワー | 4・5 | 各2択 | 5番の選択2 → ID200152、Lv1 |
| SSR30319 ナリタブライアン | 4・5 | 各2択 | 5番の選択2 → ID201641、Lv1 |
| SSR30320 アドマイヤグルーヴ | 4・5 | 各2択 | 5番の選択1 → ID202082、Lv1 |
| SSR30321 ドゥラメンテ | 4・5 | 各2択 | 5番の選択2 → ID202602、Lv1 |
| **合計** | **8イベント** | **16択** | **4ヒント** |

数値IDは正本の編集済み台帳を照合するためのキーであり、ゲーム内で条件どおり必ず獲得できることや公開権利の確認ではない。GT固定版にこれら4カードがないこと、指定GameWith個別記事による数値裁定、SSR30319/5の専用記事による**2択**確認は、[4SSR全20件の数値編集採用](phase2-three-ssr-final-editorial-adoption-20261022.md)の既存根拠を継承する。GameWithとCheckerを独立した実ゲーム証拠として二重計数しない。

## 生成するもの

`poc/src/phase2_eight_standalone_review_pack.cjs` の`build`は、4カードの16選択肢の能力・体力・絆等の数値報酬、4件のヒントのカードID／位置／レベル、既存の日本語仮表示、根拠URLと個別公開ブロッカーを一括監査する。実集計コアで**未選択0経路・選択肢別の4件だけ該当ヒントが出る**ことも試験する。

実行：

```sh
node poc/tools/report_phase2_eight_standalone_review.cjs
node poc/tools/report_phase2_eight_standalone_review.cjs --json
node --test poc/tests/phase2_eight_standalone_review_pack.test.cjs
node poc/tools/verify_event_release.cjs
```

`--json`も標準出力だけに書き、承認されていない`previewCatalog`の機械的な一括公開用出力を意図的に含めない。**公開DB・承認台帳の書き換えコマンドではない**。元イベント名・選択肢文章・ゲーム画像は再配布しない。

表示用の`通常イベント候補4`／`選択肢1`等は**位置を表す機械的な仮ラベル**で、実ゲームのイベント名称、正式なイベントID、既にユーザー公開審査を通った独自文面だとは主張しない。レビュー識別子 `editorial_candidate_30318_random_4` なども**ゲームの実イベントIDではない**。

## 公開前に別途必要な確認

1. 対象カードとGameWithの正式掲載名・出典位置を照合して、重複タイトル・名前揺れ・収録位置のずれを除外する。固定Checkerの位置はゲームの正式イベントIDを証明しない。
2. GameWithに明記された**操作選択肢2個**を採用する。報酬数値と技能IDは編集採用済みだが、**成功／失敗など全結果が網羅されているか**は別。
3. GameWithの表示順と数値報酬を基準に、プレイヤーに選択肢を識別できる**公開用の独自日本語表示案**をレビューする。今ある位置だけの仮ラベルで完了と見なさない。
4. 技能辞書の現行数値ID・名称との整合、既存の通常ヒントとの重複計上抑止、ヒントLvを実UIで照合する。
5. [権利・取得利用条件](event-data-acquisition-rights-20261019.md)に従って文章・構成の公開利用根拠を確認し、[既存6観点の承認台帳](checker-public-catalog.md)へ**人手で判断を記録**する。何の根拠もなく承認フラグを自動で立てない。
6. `poc/data/reviewed_events.v1.json`へ個別に取り込むときは、独自表示、イベントSHA、出典リンク、全結果・分岐の検査を実施し、GitHub Pages／Chromium／Windows／Androidを別々に受け入れる。

## ゲート結果

- **A 機構**：16選択肢のスキル集計、カード別選択、公開DBへの変換拒否、改変拒否をNode + CIで検証。
- **B データ**：GameTora固定欠損4SSRの20件から数値編集済み通常8件に限定。スキル4件のカード／イベント位置／選択肢が既存固定レビューと一致する。元数値90項目のうちこの8件の非スキル数値を抽出して表示案へ付随させる。これによって全カード全イベントの実ゲーム完全性を証明するわけではない。
- **C 実機**：既存Linux Chromium回帰を実施できる。物理Windows／AndroidでのWebアプリ操作、公開承認済みの実イベントのPages表示は未実施。

正式公開イベント・承認台帳は**0件**のまま。今回の成果は正式承認に回すための具体的な8件のケースファイルであり、機能実装や数値編集採用の完了と公開審査完了を混同しない。

> **2026-10-23改訂:** 詳細は[正式名称と実ゲーム再検証を不要とする決定](phase2-eight-standalone-local-interactive-review-20261023.md)。この監査当時の「通常イベント候補4」は非公開数値草稿の内部ラベルであり、レビューUIの正式イベント見出しはGameWith掲載名へ変更済み。実ゲーム操作で再現を確かめることは承認前提ではない。
