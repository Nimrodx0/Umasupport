# U-toolsイベントデータの利用可能性検証（2026-10-16）

## 目的

Uma Support Lab（Umasupport）の **SSR・SR 417枚のイベント全件網羅**に向けて、[U-tools](https://xn--gck1f423k.xn--1bvt37a.tools/about) を (1) 個別イベントの検証先、(2) 公開アプリの実行時データソースのいずれかとして利用できるか判断する。

**結論：個別ページでの事実確認・照合には有力。継続的な直接取得元への採用は保留。** URLのID対応と情報の細かさは確認したが、HTTP 403が観測され、利用許可や安定したAPI提供は確認できていない。

## 公開ページで確認したデータ内容

- サポカIDがURLに含まれる。例： `/supports/30302/event` はサトノダイヤモンド、`/supports/30164/event` はヒシアマゾンのイベント。
- **連続／ランダムの分類、イベントタイトル、選択肢、ステータス報酬、スキル名、ヒントLv**がHTMLに表示される。
- [SSRヒシアマゾン](https://xn--gck1f423k.xn--1bvt37a.tools/supports/30164/event) の一部選択肢には「イベント終了」と表示され、分岐の打ち切りの裏付けに有用。
- [SSRサトノダイヤモンド](https://xn--gck1f423k.xn--1bvt37a.tools/supports/30302/event) は連続3件・ランダム2件を表示。
- ただし **イベント発生確率、条件分岐の完全な機械可読表現、ゲーム内イベントID、全417枚の掲載内容の完全性**は今回検証していない。

## 少数HTTP実験（GitHub Actions 2026-10-16）

調査ログ：[CI #38887993161](https://github.com/Nimrodx0/Umasupport/actions/runs/38887993161)。`poc/tools/probe_utools.cjs` を1回実行し、robots.txtとSSR2枚のイベントページの計3 GETを送信。**元のイベント文面はログに出力・保存していない**。

| 確認内容 | /supports/30302/event | /supports/30164/event |
|---|---|---|
| HTTPステータス | **403** | **200** |
| 応答サーバー | Cloudflare | Cloudflare |
| HTML本文（実際のイベント情報） | 取得できない。403ページ | **取得できた**。309,451文字 |
| Cross-Origin Resource Sharing（CORS） | Allow-Originヘッダーなし | **Access-Control-Allow-Origin: `*`** |
| HTMLの内容 | イベント本文なし | 連続／ランダム・ヒントLv・打ち切りを含む |
| 内容構造 | ブロックページ | HTML内にテキスト、37件の外部JS参照、2件のJSON型script要素 |

robots.txtについてはHTTP 200が返り、検査した2つのイベントURLに対する明示的なDisallowは診断プログラムでは検出されなかった。ただし、robots.txtは法的な再利用許諾ではない。検証プログラムはroot `Disallow: /` にも対応し、明示的な禁止があればページのGETをスキップする。

**注意：HTTP 403は一回の観測結果であり、Cloudflareのボット対策・一時的な判定・その他の原因を特定していない。** 片方が通ってもう片方が拒否されるため、ブラウザから全417ページを定期的に直接取得して安定動作することは現時点で保証できない。

`Access-Control-Allow-Origin: *` はその**成功したレスポンス**についての技術的なアクセス許可に過ぎず、サイトからの恒久的なAPI提供・全ページのCORS保証・データ再利用許諾を意味しない。APIの公式仕様・バルク配布元は公開資料から確認できていない。

## 権利・運用条件

U-toolsの[Aboutページ](https://xn--gck1f423k.xn--1bvt37a.tools/about)には問い合わせ窓口として [@u__tools](https://twitter.com/u__tools) が記載され、フッターに `All Rights Reserved` がある。データを公開アプリへ**自動取得・反復キャッシュ・転載してよい**とするライセンスや利用範囲の説明は確認できていない。利用規約・権利条件の網羅調査や権利者とのやり取りは未実施。

今後、以下について運営者に許可または公式提供方法を確認する必要がある。

1. サポカIDに紐づくイベント名・選択肢・報酬・ヒントLv・連続順・打ち切り情報を、非公式・無料のGitHub Pagesアプリから利用できるか。
2. もし公開可能なら、**HTMLのスクレイピングではなくJSON／API／ダンプ等の正式な受け渡し方法**を提供できるか。
3. アプリ利用時の直接取得とIndexedDBへのキャッシュ、更新頻度、HTTPリクエスト量、出典表記、転載可能な項目や量についての範囲。

## 採用判定

| 用途 | 判定 | 根拠 |
|---|---|---|
| 少数カードの掲載内容を人が確認する参照先 | **利用可能** | ページが検索・閲覧でき、分類と結果の情報がある |
| 417枚のイベント掲載を確実に網羅できると断定 | **未検証** | 2ページしか直接GETしておらず、イベント件数照合が未完了 |
| HTMLを直接クロスオリジンGETしてその場で抽出 | **試験成功1件・失敗1件** | 200+ワイルドカードCORSと403が混在 |
| 公開アプリの常時データ供給元（本採用） | **保留** | 403・公式API不明・著作物の再利用条件未確認 |
| 連続・ランダム／分岐情報の独立照合元 | **推奨** | SSRサポカ個別ページの記述を比較可能 |

### 開発作業の次の順番

1. **U-tools運営者にデータ利用・提供方法を問い合わせる**。明示的な権利条件と技術的APIの可否をまず確定する。
2. 許可の有無に関係なく、**ゲームマスター由来のカードIDとイベント連続構造**で照合できる方法を調べる。U-tools側のHTMLスクレイピングをコア依存にしない。
3. 利用許可／提供APIが得られれば、レコード検証・率制限・IndexedDBキャッシュ・失敗時の既存データ維持を設ける。APIがなければ正式なデータ提供が可能か相談する。
4. それまではU-toolsを**人手での個別イベント確認先**と位置付け、SSR・SR 417枚の情報を大量に抽出／保存／再配信する機能を導入しない。

検証コマンド（明示的に開発者が実行する場合のみ）：`node poc/tools/probe_utools.cjs`。このツールは1回で3 GET以下に制限しており、CIから自動定期実行しない。ページの実データ内容をログに出力しない。
