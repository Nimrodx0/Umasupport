# GameTora本体の直接取得実現性：少数カード技術検証（2026-10-27）

## 目的と非対象

[直接取得移行の現行方針](upstream-refresh-operations.md)に従い、第三者GitHubの派生JSONを本番更新資料に必須としない構成にできるか、**最初はわずかなカードだけ**確認する。GameTora本体を「ゲーム開発元の一次資料」とは呼ばず、GameTora派生JSONより直接のサイト出典として扱う。

- 静的HTTP応答検査：固定対象3枚のみ、既存SSR `30001`、新規SSR `30322`／`30323`。
- ブラウザ表示検査：既存SSR `30001` のみ。URLから追加カードを検索・巡回しない。
- [限定ソース検証ワークフロー](https://github.com/Nimrodx0/Umasupport/actions/runs/40464401966) でGitHub Actions上のNode 22とChromiumを実行した。
- 本体HTML・JSON・イベント名・選択肢・報酬原文・画像・スクリーンショットはGit履歴、Actionsアーティファクト／ログへ保存しない。確認したのはカテゴリ見出し、JSのデータ形式、数値による構造シグナルだけ。

## 実際の取得結果

| 項目 | 30001 | 30322 | 30323 |
| --- | --- | --- | --- |
| 公式カードHTTP 200／サポカページの判定 | Yes | Yes | Yes |
| 初期HTMLに「育成イベント」見出し | Yes | Yes | Yes |
| 初期HTMLだけで「連続イベント」「ランダムイベント」の分類 | **No** | **No** | **No** |
| 初期HTMLにNext.js `__NEXT_DATA__` | Yes | Yes | Yes |
| `__NEXT_DATA__` のJSON解析 | Yes | Yes | Yes |
| JSON内に `choices`／`outcomes` の配列 | **0／0** | **0／0** | **0／0** |
| 初期JSON内にイベント相当の `choices` 持ちオブジェクト | **0** | **0** | **0** |

初期JSONのオブジェクト走査数は順に39／37／33、`effects`という配列名は各2か所。効果の元データがそれだけで取得できたという意味ではない。これらの結果は**初期HTML・初期JSONのみでは分岐や報酬を取り込めない**ことを示し、GameTora本体にも内容が存在しないことを示さない。

[Chromiumの実地結果](https://github.com/Nimrodx0/Umasupport/actions/runs/40464401966)（カード30001だけ）：

- ページのJS描画後は「育成イベント」「連続イベント」「ランダムイベント」の見出しが実際に見える。
- ページ表示中の同一サイトXHR／fetchは38件、そのうちJSON応答27件（同じ27件の応答をメモリだけで形状検査）。初期HTTP本文では足りない情報がクライアント側で動的に表示されることは確か。
- JSON応答27件のうち、イベント関連の名前を持つ項目が見つかった応答は8件。ただし **`choices` 配列・`outcomes` 配列・イベントらしい `choices` と `section` の組合せは0件**。4件には `effects`／`rewards` らしい配列名があったが、これだけでイベントの結果構造やスキルの意味を証明しない。
- 既知のイベントボタンが描画されたことを確認した。1回のクリックで本文テキスト長の変化は観測されなかったが、表示方法／モーダル／遅延更新までは調べていない。**「イベントの詳細は存在しない」という結論にはしない**。
- 403/429は未観測。ネットワーク越しの動作が少数件で成功したことは、大規模な定期自動アクセスの許諾やサイトAPIの長期安定性の証拠ではない。

比較用の歴史的固定 [GT派生JSON `support_30001.json`](https://github.com/systemless10/UmamusumePS/blob/6e38b54af4fad397ff4491e63007a90705a4fe67/server/data/events/gametora/support_30001.json) にはイベント5件（連続3件・ランダム2件）。[GameTora本体の該当カードページ](https://gametora.com/ja/umamusume/supports/30001-special-week)にも連続3件・ランダム2件の一覧が表示される。しかし**選択肢／ヒントLv／報酬数値／結果分岐／打ち切りの全件同一性は未確認**。2026年10月26日新カードの派生JSONが欠損していても、本体ページの掲載状況を別途確認できる。

## 収穫と次の工程

**確認できたこと**：元サイトの閲覧は一部のカードについて現行GitHub Actionsから可能。ページ情報はJS描画にも依存し、初期JSONやJSONレスポンスの浅いキー走査だけではイベント経路の完全情報を得られない。

**解決していないこと**：

1. UIに表示されるイベント一覧と、クリック後の選択肢／結果の構造が、DOMまたはページを構成する通信データのどこから提供されているか特定する。少数カードの通常の閲覧経路を使い、検証済みカードIDと選択肢・結果を取り違えないこと。
2. 正式に提供される安定API／低負荷のアクセス方法と、取得・継続運用の利用条件を確認する。アクセス制限を回避しない。サイトから大規模にデータを抽出して配信する前提を置かない。
3. 実取得内容が利用可能と判断できた場合、変換器のイベントID・カードID・選択位置・結果位置・報酬数値ID・連続分岐を旧固定GTと独立照合する。過去のGT派生元は比較用資料として維持する。
4. 上記のA機構／Bソース実証／Cブラウザ回帰を区別して本番の出典変更PRを行い、イベント原文・画像の配布や公開承認は別に検査する。

**未実装**：GameTora公式HTMLの実イベント正規化アダプタ、正式な継続更新ジョブ、データ承認／公開への自動反映。既存の固定派生GT元とレビュー済みイベント0件の状態は不変。

## 追加実地検証：イベント見出し・カテゴリ・展開パネルの照合（2026-10-27）

[検証CI](https://github.com/Nimrodx0/Umasupport/actions/runs/40468572562)は、SSR30001の**既存の1カードページだけ**をChromiumで通常表示した。旧GameTora派生JSONは固定版の`support_30001.json`（Git blob SHA `6aca60590854f402a67da82c2ffa7295e564b40f`）をCI一時領域で取得し、データ本文を保持・公開しない。ブラウザ上のイベントボタン文字列と歴史的イベント見出しを**メモリ内で照合**した後、件数・数値だけ報告した。

| 照合対象 | 実測 | 意味 |
| --- | ---: | --- |
| 元データのイベント | 5件 | 対象の旧固定版内の事実 |
| 公式サイトのイベント開閉ボタン | 5件 | DOMに5件のイベント詳細パネル |
| 見出しが一意一致したイベント | **5/5件** | 表記正規化後の名称単位の同定は全件成功 |
| 連続3件・通常2件の分類一致 | **5/5件** | 開閉ボタンの同グループ件数3／2と旧データの種別が一致 |
| 画面上で詳細を実際に展開したイベント | **5/5件** | DOMの詳細パネルに数値を含む表示が存在 |
| 通常イベントの暫定詳細行数と旧結果経路数 | **2/2件が一致** | 両方とも旧経路2・暫定DOM行2。**意味の一致を証明しない** |
| 連続イベントの暫定詳細行数 | **3件とも未判定** | DOM階層が異なるため同じヒューリスティックで計数不能 |
| 結果ごとの数値効果・スキルID・ヒントLv照合 | **未実施** | 正式なイベントデータ収録の根拠にはならない |
| 打ち切りと前段依存関係 | **未実施** | 連続イベントの内部制御を未検証 |

比較コードは [一時的なタイトル照合器](../poc/src/official_gametora_title_crosscheck.cjs)、固定カードしか巡回しない [通常ブラウザのDOM調査](../poc/tools/probe_official_gametora_browser.cjs)、[独立した人工試験](../poc/tests/official_gametora_title_crosscheck.test.cjs) で管理する。判定器は`sourceRoutesAndRenderedRowsSemanticallyEquivalent:false`、`rewardAndOutcomeFactsVerified:false`、`chainTerminationVerified:false`、`resultForPublication:false`を常時出力する。現時点の採用／公開承認済みイベント0件は変更しない。

この実測から、**GameTora本体のHTMLからイベントの見出し・通常／連続のグループ・展開パネルを構造的に取得できる**ことが分かった。第三者派生JSONが恒久的な実行時の入手元である必要はない可能性が高い。一方、表示された内部報酬値を数値IDへ厳密に結びつけるには、**Choice／Result／EffectのDOM層を区別するアダプタ**が必要。特に連続イベントは、暫定的なDOMの行数を結果分岐数として即採用してはいけない。

次の工程は、同じ既存カードの範囲で選択式と成功／失敗式の詳細構造を識別し、選択位置・結果位置・数値ヒント候補を抽出して既存の固定参照と比較する。独自DB全カードの自動取得・GameToraの大規模巡回はサイトの利用条件と取得の安定性が確認できるまで進めない。
