# アーキテクチャと開発境界

## 現行PoC v8.1

```text
外部データ（開発時のみ）
  → データ取得・正規化（Python）
  → カードID突合／レビュー済みエイリアス／重複検出
  → 通常ヒントと一部イベントのデータを同梱する静的HTML
  → JS集計エンジン + ブラウザGUI + ローカル設定保存
```

**React/TypeScript/Viteは未導入**。将来の実装案であり、現行コードがこれらを使用していると誤認しない。

## 2026-10-16：新たな直接取得方式

[実行時データ取得の設計](runtime-data-loading.md) を正とする。ビルド時同梱は以前のPoCの実装履歴であり、新規の配布方式ではない。現在は `poc/live.html` に通常ヒントの直接取得・IndexedDBキャッシュを実装中（イベント未移植）。

## 望ましいモジュール分割

1. データ収集：外部サイトと内部モデルの隔離。
2. データ正規化・検証：ID、出典、欠損状態、イベント到達条件の検証。
3. 集計エンジン：デッキ・イベント選択・目標セットから副作用なく結果を算出。
4. UI：統合表／左右比較／密度の切替とカード・イベント・目標編集。
5. 保存：所持カード、デッキ、イベント選択、目標スキルをゲームデータから分離。
6. 配布：GitHub Pages等でアプリのコードのみ配信。公開元のゲームデータをブラウザが起動時に直接取得・検証・キャッシュ。

## 守るべき不変条件

- 同一サポカが同一スキルを複数経路で提供しても提供枚数は1。
- イベントの未選択ルートと打ち切り後の報酬を集計しない。
- 間接カバーは直接ヒントの枚数に加算しない。
- 金スキルの直下に下位スキルを表示するが、それぞれ独立集計。
- 未収録を「なし」と表示しない。
- 新旧IDの移行後も保存設定が壊れず、同じカードが二重表示されない。
- 利用者向けのデータ更新ボタンを作らない。

## ソース公開の境界

ビルドスクリプト、ユーザー独自UI・集計ロジック、人工のテストデータは公開できる候補。第三者由来データ、画像、イベント本文のコピーは、再配布権限を確認するまで保留する。元の配布HTMLはゲームデータを埋め込んでいるため、Publicへそのまま登録しない。

## 開発環境の引き継ぎ

新規チャット／Codexは `AGENTS.md` → `docs/requirements.md` → `docs/roadmap.md` → `docs/development-history.md` を読み、GitHubの内容を優先する。既存PoCのソースがレポジトリに未収録なら、資料だけで完成済みと見なさず、移管ステップを明示する。

## 実行時取得版の構成

- `poc/src/live_loader.js`：取得、形式検証、IndexedDBキャッシュ。
- `poc/src/settings.js`：保存設定のスキーマ検査・レビュー済みID対応表の変換・未知ID保全。
- `poc/src/live_app.js`：設定をlocalStorageに保存し、未収録項目を明示。未知IDのスキルを集計しない。
- `poc/src/core.js`：純粋な集計エンジン。ゲームデータが未収録なら推測しない。

データ取得のキャッシュ復旧とアプリ本体の完全オフライン起動は別工程。
