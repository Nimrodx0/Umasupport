# Phase 2：旧マスターのストーリー名とChecker候補の文字列照合

検証日：2026-10-17。関連：[ストーリーID監査](historical-event-story-audit.md)、[工程ゲート](verification-plan.md)。
**目的は、30241「旧マスター直結18 ID / Checker候補17イベント」という数量差を、イベント名の一致・不一致まで分解すること。** 一対一の正式ゲームイベントID同定や完全収録の主張はしない。

## 入力と事前条件

- 2026-10-13 UmaSim固定版の全563サポカID・レアリティ。
- 2025-10-10の公開ゲームマスターSQLiteのsingle_mode_story_data（カード直結・gallery_flag=2）とtext_data（カテゴリー181のタイトル文字列）。実ソースのキー構造を独立に確かめ、text_data.indexと**single_mode_story_data.story_id**が一致することを検証した。内部行IDのidとshort_story_idを代用しない。SQLiteのテーブル・列が不一致なら監査を失敗させる。
- 2026-10-17 UmaUmaChecker固定版のSSR/SR417枚（2,099候補）。既存の厳密393・明示的別名24の対応を利用し、候補配列内のイベント見出しのNFKC正規化＋空白正規化にSHA-256を適用する。ハッシュは**一時ファイルにのみ記録**し、イベント名・選択肢・効果本文をPublicレポジトリに保存しない。

正規化イベント名のSHA-256が一致しても、**ゲーム内の正式ストーリーIDとは対応付けない**。名称重複には多重集合（multiset）で対応し、複数の同名ストーリーを1つに併合しない。

## 機構／データ／実機の合格条件

**A 機構：** 各行についてカードID・レアリティ・タイトル指紋の形式・候補合計を検証。旧マスターのカテゴリー181のキー重複や表欠落を拒否。文字列のNFKC統一、同名重複数、タイトルなしIDの「不明」分類が人工SQLiteテストで合格する。

**B データ：** 実ソースを固定コミットで限定取得し、旧マスターのカード直結ストーリー行数とタイトル取得件数、Checker候補件数、同名一致件数・非一致件数を集計する。SSR30241の18対17は数値として維持し、同名の一致／非一致を分ける。タイトルの由来やキーの意味を推測で書き換えない。2025年以降の新カード68枚、カード共通のイベント、イベント名の改題差等は未解決として保持する。

**C 実機：** アプリ自体を変えないので対象外。公開DBの実イベントは引き続き0件。

## 取り扱いと制限

- 前段のChecker候補は、人手によるソース表記対応を経た候補で、ゲーム内正式イベントIDではない。
- カテゴリー181の旧マスター表記が2026年の公開攻略資料と一致する保証はない。名前が一致しないケースを直ちに「イベント欠損」としない。
- 0件の意味を「未確認／元データ未掲載／ゲーム内になし」にすり替えない。グループカードは構成員の複数キャラ経路を別途調べる。
- 通常CIでは人工SQLiteのみ。実ソースは[限定ワークフロー](../.github/workflows/historical-event-master-audit.yml)で固定版を一時取得し、**タイトル／本文もハッシュも標準出力しない**。

検査コード：[候補のタイトル指紋生成](../poc/src/checker_candidate_pipeline.cjs)、[独立照合](../poc/tools/audit_story_title_links.py)、[人工データ回帰](../poc/tests/test_story_title_links.py)。

| 2025年masterのカード直結 | Checker候補 | 同名一致 | 旧側のみ | Checker側のみ |

**判定：30241の「18対17」は単純に1件が消えただけとは結論できない。** 双方に名称差が存在するため、3と2の相互改題・表記差、無選択イベントの掲載範囲、履歴的な入替などを個別確認する必要がある。名称一致の15件も、名前だけを根拠に実ゲームストーリーIDへChecker候補を確定紐付けしていない。

次：30241の片側のみの3／2件について、同時点に近い独立ソースのイベント名・選択肢有無、グループカードのイベント区分、ゲーム正式イベントIDに照らして解決する。2025年マスターの残る61名称も同じ方法で全件分類する。Phase 2のB（正式ID・分岐・報酬・収録率）は未通過、C（実機）は未実施、公開DBの実イベント0件を維持。

## 追加監査：句読点・記号だけの表記差（PR #46）

30241の厳密一致15/18・15/17をさらに分類する目的で、**二段階に分けた比較**を追加する。

- 主判定：これまでのNFKC＋空白正規化による厳密一致を**維持**。既存15件や全体956件を自動で書き換えない。
- 副診断：NFKC＋小文字化の後、句読点・空白・記号を除いた文字数字列から別のSHA-256を作成。ゲーム名中の文字そのものは置換・音訳・編集距離補正しない。新しい指紋は候補専用ローカルJSONだけで、公開イベントDBには追加しない。
- 文字の異なるタイトルが記号除去により偶然一致する可能性があるため、**副診断の件数は同一イベント候補を探す手掛かりにすぎない**。同じ指紋が同一カード内に重複したときも一対一のIDを自動結合しない。
- 比較不能・指紋の形式不正・ソース版不一致は人工回帰と限定ソース監査で区別。CIは厳密一致数を超えない結果や逆行があれば失敗させる。元タイトル・候補本文を標準出力・Publicへ転載しない。

実ソース監査：[Actions #39036963530](https://github.com/Nimrodx0/Umasupport/actions/runs/39036963530) **成功**。厳密な名称照合と、記号・空白・英字大小の違いを除いた補助照合を明示的に分離し、次の数値を確認。

| 名称指紋の比較 | SSR/SR旧1,017件のうち | 30241旧18件のうち |
|---|---:|---:|
| 主判定：NFKC＋空白統一 | **956** | **15** |
| 補助診断：さらに記号・空白除去＋小文字化 | **985** | **17** |
| 補助診断後も旧master側にのみ残る | 旧1,017からの残32（タイトル別・多重集合） | **1** |
| 補助診断後Checker側にのみ残る | カード未収録・共通イベントを含む候補群が存在 | **0** |

30241について、厳密比較で旧側のみ3／Checker側のみ2だったものが、表記差を緩く扱うと旧側のみ1／Checker側のみ0へ減少した。**旧側の残1が実イベントの欠損・無選択イベント・バージョン差のどれであるかは引き続き不明。** 同名の衝突可能性もあり、この17件を正式なイベントIDへ自動確定はしない。

これらは他のカードやソース更新時にも同じ手法で再実行可能。**確定したイベントID・分岐・報酬・公開承認は0件**とする。
