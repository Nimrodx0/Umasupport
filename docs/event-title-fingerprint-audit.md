# Phase 2：旧マスターのストーリー名とChecker候補の文字列照合

検証日：2026-10-17。関連：[ストーリーID監査](historical-event-story-audit.md)、[工程ゲート](verification-plan.md)。
**目的は、30241「旧マスター直結18 ID / Checker候補17イベント」という数量差を、イベント名の一致・不一致まで分解すること。** 一対一の正式ゲームイベントID同定や完全収録の主張はしない。

## 入力と事前条件

- 2026-10-13 UmaSim固定版の全563サポカID・レアリティ。
- 2025-10-10の公開ゲームマスターSQLiteのsingle_mode_story_data（カード直結・gallery_flag=2）とtext_data（カテゴリー181のタイトル文字列）。IDキーはまずidとして試験し、代替short_story_idは自動採用しない。SQLiteのテーブル・列が不一致なら監査を失敗させる。
- 2026-10-17 UmaUmaChecker固定版のSSR/SR417枚（2,099候補）。既存の厳密393・明示的別名24の対応を利用し、候補配列内のイベント見出しのNFKC正規化＋空白正規化にSHA-256を適用する。ハッシュは**一時ファイルにのみ記録**し、イベント名・選択肢・効果本文をPublicレポジトリに保存しない。

正規化イベント名のSHA-256が一致しても、**ゲーム内の正式ストーリーIDとは対応付けない**。名称重複には多重集合（multiset）で対応し、複数の同名ストーリーを1つに併合しない。

## 機構／データ／実機の合格条件

**A 機構：** 各行についてカードID・レアリティ・タイトル指紋の形式・候補合計を検証。旧マスターのカテゴリー181のキー重複や表欠落を拒否。文字列のNFKC統一、同名重複数、タイトルなしIDの「不明」分類が人工SQLiteテストで合格する。

**B データ：** 実ソースを固定コミットで限定取得し、旧マスターのカード直結ストーリー行数とタイトル取得件数、Checker候補件数、同名一致件数・非一致件数を集計する。SSR30241の18対17は数値として維持し、同名の一致／非一致を分ける。タイトルの由来やキーの意味を推測で書き換えない。2025年以降の新カード68枚、カード共通のイベント、イベント名の改題差等は未解決として保持する。

**C 実機：** アプリ自体を変えないので対象外。公開DBの実イベントは引き続き0件。

## 取り扱いと制限

- 前段のChecker候補は、人手によるソース表記対応を経た候補で、ゲーム内正式イベントIDではない。
- カテゴリー181の旧マスター表記が2026年の公開攻略資料と一致する保証はない。名前が一致しないケースを直ちに「イベント欠損」としない。
- 0件の意味を「未確認／元データ未掲載／ゲーム内になし」にすり替えない。グループカードは構成員の複数キャラ経路を別途調べる。
- 通常CIでは人工SQLiteのみ。実ソースは[限定ワークフロー](../.github/workflows/historical-event-master-audit.yml)で固定版を一時取得し、**タイトル／本文もハッシュも標準出力しない**。
