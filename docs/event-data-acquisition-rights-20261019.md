# イベントデータを一括収録するための取得・利用条件の解決（2026-10-19）

## 結論と境界

イベント収録を止めている要因は一種類ではない。**アクセス・データの編集／再利用・ゲーム原権利・収録内容の正確さ**の4つに分割して進める。

1. **事実と表現は異なる。** スキルID・ヒントLv・発生条件などの単なる事実やデータは、一般に文章のような著作物ではない。文化庁は単なる事実・データ・ありふれた表現は著作物に当たらないと説明している。ただし実際のデータベースの選択・体系的構成、ゲーム画面・演出・名称、出所となるページの利用条件は別途評価する。**事実を使うのに全件一律で転載許諾が必要、という過剰な前提は採らない。** かといって第三者資料から一括取得して任意に公開できるという意味でもない。
2. **GameWith日本語版のアクセス条件が独立の問題。** [日本語利用規約](https://gamewith.jp/terms) 第9条1項14号（通常利用を超える負荷）、17号（提供機能の複製・修正・転載・改変・解析等）、19号（商業目的利用）や第10条の権利帰属は、個別の事実が著作物かどうかと別問題。現時点で563ページ以上の無許可一括GETを承認したと扱わない。
3. **gamewith.net の創作ガイドラインは gamewith.jp に適用されない。** [英語版ガイドライン](https://gamewith.net/guidelines) の冒頭に明記。
4. **UmaUmaCheckerのMITはコードの条件であってGameWith由来イベントデータの再配布許諾ではない。** [README](https://github.com/Cilda/UmaUmaChecker) が出典を明記。UmaUmaCruise系もコード／元データ／表現・画像の権利を分離する。
5. **Umamusume Wiki のCC BY-SAにも権利者留保がある。** [サイトの説明](https://umamusu.wiki/Umamusume_Wiki:Getting_Started) はCygamesの権利物を例外とする。ゲーム由来の数値メタデータ／カードID／story_idを確認用に使うことと、文章・画像・ゲーム資産を再配布することを分ける。ウィキ側の利用条件とAPIの負荷も確認する。
6. **Cygamesの権利は独立。** 公開する表現がゲームの原文・画像・音声・物語を含む場合は第三者記事の許諾だけでは完結しない。現行アプリは固有名の数値的照合と短い独自のルートラベルに限定する。

これは法律相談の最終結論ではない。大量・継続的収集の運用可否、選択・構成を広く複製したデータベースの利用可否は、具体的な許諾内容や専門家判断に従う。

## 結果を出す二経路

### A. GameWithへ用途と条件を明示した照会（最短で許諾の有無を確定）

**送付先候補**：GameWith公式 [ゲームメディア・記事問い合わせ窓口](https://gamewith.co.jp/contact-sales)。[ヘルプ](https://gamewith.jp/help/show/feedback_home)が記事関連の問い合わせ先として案内している。窓口による転送や別窓口の案内があれば従う。

**質問を分ける**：
- 個別記事からイベントの事実情報だけを機械的に抽出する一括アクセスの可否（無料個人開発、公開GitHub Pages）。
- サーバ負荷を抑えた低頻度アクセス（提案条件：1リクエスト/10秒以内、同時実行なし、一日600ページ上限、HTTP 429/403は即停止、差分だけ再取得）の可否。**あくまで交渉案であって許可済みではない**。
- 加工後の独自構造化データの公開可否。対象フィールド：カード数値ID、イベントの連続／通常区別、選択肢の順序、条件別の獲得スキル数値ID／名称／ヒントLv、発生条件・打ち切り区別。GameWith独自の文章・表の組み方・画像は複製しない。
- 出典表示方法、クレジット、更新頻度、権利表示、利用停止の申出方法。
- より望ましい提供方法（構造化ファイル・API・適切な一次データ）の有無。無償提供が難しい場合の提供条件や費用。

**返信が明確に認めた範囲だけ**自動収録を解禁する。返信なし、あいまいな内容、単にrobots.txtに禁止がない、他社ツールが収集している、という理由で承認しない。第三者の機密的な返信文面を公開GitHubへそのまま貼らない。条件と確認日だけを台帳化。

## B. 許諾待ちと切り離して今すぐ一括実行できる工程

- 既存の `poc/tools/build_checker_catalog.cjs` により、権利状態を公開利用許可と混同しない形で、UmaUmaCheckerの候補を**読み取り・分析用**の個別カード／イベント索引に正規化できる。既存の全563カード比較基盤・名称エイリアス監査を再利用する。
- 既存の `poc/tools/batch_gamewith_import.py` は、適切に入手したローカルファイルのみを解析する。ネットワークGETを追加しない。将来GameWithの許可が得られたら**許可された方法で別工程が原本を集める**。元データはGit除外の `poc/inputs` / `local-data` にだけ置く。
- UmaSimの563カードおよび全スキル数値辞書は既存の実ソースCIで確認。Wikiの数値story ID・連続段階は別の補助監査。**GameWithとWikiを互いに独立するかのように一律カウントしない**。
- 収録の価値は候補件数ではなく、「カードID→イベントID→選択肢位置→結果依存→報酬スキルID→ヒントLv」の各段が追跡できた件数で計る。
- **公開ゲートは従来の `event_release_gate.cjs` / `verify_event_release.cjs` を維持**。GameWith優先の編纂方針は、アクセス許可、第三者の文章転載権、ゲーム内事実の正確性について保証しない。

## 実行判断

| 項目 | 今できること | 大規模本番化の残ゲート |
| --- | --- | --- |
| UmaSim | GitHubの固定公開ファイルからカードID／スキルIDを実データ照合 | 最新実ゲームとの版差 |
| UmaUmaChecker / UmaUmaCruise | 既存の候補構造をオフラインで数値・件数監査 | 加工データの実際の再利用・公開根拠、正確性 |
| Umamusume Wiki | CC BY-SAの一般編集情報とゲーム権利物を区別してID／段階を検証 | API負荷条件・実ゲーム版・帰属表示と権利評価 |
| GameWith.jp | 人手の限定的な資料照合、許可されたローカル資料の解析 | 一括GETの条件と独自構造化データの公開範囲を正式照会 |
| ウマサルタントの本番公開 | 既存の独立レビュー・SHA・6項目検査済みイベントだけ | 上の条件が満たされるまで未承認データを混入しない |

**次の具体的な解除条件**：GameWith担当者から回答があれば、アクセス頻度・対象URL・保存範囲・公開表現・撤回条件を収録工程へ反映する。回答がなくても、独立に記録した数値的事実と別資料の正規の利用範囲を用いて収録を進める。禁止されたアクセスや権利不明の文章の丸写しを一括処理の近道にしない。

## 2026-10-19：Checkerの数値ヒント候補をローカル一括抽出（PR #98）

`poc/src/checker_hint_fact_extract.cjs` と `poc/tools/extract_checker_hint_candidates.cjs` を追加した。入力は合法的に用意したローカルのUmaSim `support_card.txt`、全 `skill_data.txt`、UmaUmaChecker `Events.json`。アプリのSSR/SRカードIDへ正規化名と監査済み24別名で結合し、イベント・選択肢の順序ごとに「ヒントLv」から**観測された短いスキル名／数値ID／ヒントLv**だけを抽出する。成功・失敗や構文未解析ヒントは手動レビュー対象にする。イベント名・選択肢原文・効果原文を出力せず、`sourceKey`・SHA・順序と数値だけを返す。候補の原文をコピーせずに作業量を測定するための処理であり、データ公開の許可ではない。

`--local`のデータ入力に加え、専用の手動／関連PR用 `checker-hint-batch-audit.yml` では、既に公開されているGitHub上のChecker候補ファイルを1回のみ取得して一時領域で処理し、件数のみ出力する。GameWith.jpへのGETは行わない。API・源ファイルの公開状態／アクセス条件と、候補由来データの本番再利用可否は別と扱う。

実行例：

```bash
node poc/tools/extract_checker_hint_candidates.cjs \\
  local-data/umasim-support-card.txt \\
  local-data/checker-Events.json \\
  local-data/umasim-skill-data.txt \\
  local-data/checker-hint-candidates.json
```

**出力は編集・比較専用。** 出力先がGit追跡済みの `poc/data` やコードの場所なら拒否。既存の出力ファイルを上書きしない。候補数は正式なゲームイベント数でも、正しい分岐数でも、許諾済み公開数でもない。独立したカードID／イベントID／選択位置／成功条件／再利用根拠を全件確認してから採用する。

## 2026-10-19：417枚候補の「例外だけレビュー」優先順位キュー（PR #99）

`poc/src/checker_review_queue.cjs`、`poc/tools/build_checker_review_queue.cjs` を追加。既存Checker一括候補から **(1) 未解析ヒント・数値ID不足／曖昧、(2) 成功・失敗等の条件付き表記、(3) 別資料だけに現れたイベント見出し／Checkerの空カード** のレビュー待ちを自動分類する。

- P0：ヒント表記を読み切れない、またはUmaSim数値スキル辞書に対するID未照合／複数候補。候補を自動解決せず、選択肢位置ごとに残す。
- P1：条件付き結果を含む可能性。成功／失敗の文面があっても到達条件・ヒントの無条件獲得とは決めない。
- P2：同じGameWith由来を含むUmaUmaCruise系とCheckerのイベント見出し差分、およびChecker側のイベント空配列。元データの独立性がなく、タイトル表記差もあり、あくまで**カード単位の追加調査対象**。異なるイベント・真の欠損の確定ではない。
- 無条件の候補も**承認済み**ではない。各項目に `requiresIndependentReview:true`、レポート全体に `UNREVIEWED_NOT_FOR_PUBLICATION` を付与する。

実行例（4入力をローカルで用意する。GameWith.jpから直接取得しない）：

```bash
node poc/tools/build_checker_review_queue.cjs \
  local-data/umasim-support-card.txt \
  local-data/checker-Events.json \
  local-data/umasim-skill-data.txt \
  local-data/cruise-library.json \
  local-data/checker-review-queue.json
```

`checker-hint-batch-audit.yml` の手動／関連PR限定実行時にGitHub上の両候補JSONを1回ずつ取得し、一時領域で既存のカードID・スキルID照合と資料間差分を生成。**ログはカードID・順位・件数のみ**。検討資料の著作文章・効果文・選択肢原文・ゲーム画像を配布せず、レポートをPages・公開イベントJSONへ書かない。

レビュー優先順位は作業効率を上げるための順序であり、ゲーム的な重要度・成功確率・取り込み権利・独立実証を示さない。現在の正式公開0件を維持し、上流データの版差は都度検査する。
