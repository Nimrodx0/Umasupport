# Phase 2：未変換39イベントの原因別・前段依存診断（2026-10-21）

## 現状と目的

GameTora固定559枚・2,488イベントから、2025年旧マスター限定の未公開スキル名を一時利用したスキーマ検証では、**2,449件が技術的に変換でき、39件が保留**となった（[固定全件実測](phase2-2025-historical-only-skill-schema-preview-20261021.md)）。39件の主理由は特殊ケース34、前段の欠損4、同一結果の重複報酬等1。**現行ゲームでの分岐・報酬確認、公開承認は0件**で変わらない。

従来の `SOURCE_SPECIAL_CASE_REQUIRES_REVIEW` は、一つのイベント中に異なる不確実性が混在していても最初の理由だけを出力していた。これを修正せずに公開スキーマへ取り込むと、前段の結果依存を省いたり、直接獲得を「ヒントLv」と誤表示したりする危険がある。

## 追加した診断

`poc/src/gametora_schema_blocker_diagnostics.cjs` は、正規化済み数値中間DBと既存の技術的変換結果を**両方同時に検査**し、除外位置が元イベントID・序数と一致しなければ拒否する。出力は `report.blockerDiagnosis` として従来の `gametora_app_schema_dry_run_summary.v1.json` 内へ追加される。

- `primaryReasonCounts`：既存の `excludedReasons` と一致しなければ失敗する、合計39件の排他的な一次分類。
- `sourceEvidenceEventCounts`：各イベントが持つ特殊状態の**複数ラベル**。前段結果やフラグ依存、条件付きsegment、`skill_hint_or`、`obtain_skill`、連続外終了を別々に記録。重複計上があるため合計39件になるとは限らない。
- `specialCaseEvidenceCombinations`：特殊ケース34件を、複数の根拠コードの組み合わせごとに分類した件数。同時に複数の問題を持つイベントを落とさない。
- `numericOnlyPositions`：サポカ数値ID・元イベント掲載序数、元セクション分類、選択分岐ガード数、ヒント数値未解決数、直接獲得件数、同一経路スキル重複数を含む。連続前段が未変換で遮断されたときは、先行イベントの掲載序数と主理由も追跡する。

**保存禁止：** イベント名、選択肢文面、元スキル名称、報酬本文、外部サイト記事の全文。元 `route.effects` の配列は診断結果へコピーせず、フラグ・集計と既知の診断コードだけを残す。未知のマーカーは文字列をそのまま転載せず `UNCLASSIFIED_SOURCE_REVIEW_MARKER` とする。

## 検証・運用

`poc/tests/gametora_app_schema_dry_run.test.cjs` には、一次理由の総数・元カードID・前段へのリンク、直接獲得・未解析ヒント・条件付き前段・同一結果重複、原文を含まない出力、元IDの改ざん拒否の合成テストを追加する。GitHub Actionsの `whole-event-inventory.yml` が固定版を再取得すると、前工程の**2,449/39の件数ゲートを変えず**実データで診断の内訳を生成する。

本処理は**原因の可視化のみ**。GameToraを基礎とし、GameWithで疑義箇所だけを確認する方針、2025限定スキルの未承認扱い、GitHub Pagesの本番イベントDB0件を維持する。成功・失敗を勝手に補完せず、個別の効果コードから意味を確定できる箇所だけ今後スキーマ化する。

## 後続工程

全件実行の `specialCaseEvidenceCombinations` と `numericOnlyPositions` を用い、34件のうち条件付き結果・直接取得・スキルヒントの未解決が単独か複合かを先に整理する。4件の後続遮断は元イベントの原因が解消されたときだけ再試験する。独立した現行版ソースの数値ID照合、公開表示文面、公開権限、物理Windows/Android端末の確認は別ゲートであり、診断成功だけでは完了にならない。
