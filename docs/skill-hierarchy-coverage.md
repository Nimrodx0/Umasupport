# 金白スキル全件監査と実装範囲（2026-10-16）

## 目的と定義

**従来の3組PoCを完成扱いしない。** UmaSim `data/skill_data.txt` の `rare`（金）と `normal`（白）を**全件**調査し、未確定を可視化してからイベント実装へ進む。自動的なIDグループ推定と、攻略記事・ゲームマスター由来の独立検証は別の証拠段階として扱う。

- 出典：[UmaSimのスキル辞書](https://github.com/mee1080/umasim/blob/main/data/skill_data.txt)
- データのSHA-256: `b7ba1d6c5dd2af9ed1f4e649f16ec1d319198e2f1ac9db07c54e14d29f0b25ec`
- 2026-10-16の[限定的なGitHub Actions実測](https://github.com/Nimrodx0/Umasupport/actions/runs/38926068054)による全件監査。スクリプトは `node poc/tools/audit_skill_groups.cjs --online`。通常CIでは公開元を取得しない。
- **元ゲームデータはPublicレポジトリに同梱しない**。読取専用監査。新データはランタイムで直接取得してIndexedDBにキャッシュ。

## 特殊グループへの対応

### 標準的な二段階（金→白）

通常は同じ `group` に `rare` 1つと `normal` 1つがある。内部数値IDの末尾規則だけに依存せず、両方の `group` が一致すること、名前の一意性、レアリティを検証する。「究極のヒルクライマー→登山家」等、金の数値ID末尾が `2`、白が `1` の7組もここに含む。独立例：[GameWith](https://gamewith.jp/uma-musume/article/show/456407)、[Game8](https://game8.jp/umamusume/623915)。

### 3段階（金→白◎→白○）

31グループでは `rare` が1つ、`normal` が○・◎の2つ。名前末尾がそれぞれ一意である場合だけ以下のように接続する。

`右回りの鬼 → 右回り◎ → 右回り○`

独立した記載例：[GameWithの金](https://gamewith.jp/uma-musume/article/show/322646)、[GameWithの◎](https://gamewith.jp/uma-musume/article/show/302931)、[Cygames公式調整対象一覧](https://umamusume.jp/news/detail?id=3413)。別の攻略サイトが金から○へ直接言及していることもあるため、スキル段階を単に二者の名前が一致するだけで決めない。

### 対応する白がない金

`大逃げ`、`日本一のウマ娘` 等、同じ `group` に `normal` レコードが存在しない3組には、下位白スキルを**推定して追加しない**。対象データ上の `noLowerInSource` として記録する。プレイヤーが育成中に獲得できる経路の有無とは別問題。

## 実装と安全装置

- `poc/src/skill_hierarchy.js` の `derive` が全件を読んで、構造上一意な候補・例外・白なしを分類。誤ったグループ・レアリティ・同名衝突・○◎以外の3候補等は自動採用しない。既存の3組の個別レビュー結果は回帰検査用アンカーとして維持。
- `stage({fullRegistry:true})` は `rare` 325件＋`normal` 478件を対象に、現在の通常ヒント（`hint:名称`）との一意名照合と未収録スキル（`skill:数値ID`）の登録を行う。**元の通常ヒントの提供元・獲得経路を変えない**。
- `poc/live.html` は公開イベント0件でもスキル辞書を起動時に取得。成功した辞書だけをIndexedDBへ保存し、通信障害なら前回の検証済み版に復帰。失敗時は通常ヒントだけで起動し、金白未照合を画面へ明示。
- `poc/src/core.js` の間接カバー判定と一覧の階層表示は金→◎→○の多段階を扱う。間接カバーの提供枚数は0。**通常ヒントと金イベントの発生・取得条件を同一視しない**。
- `poc/src/public_event_catalog.js` はスキルデータ全件の整合性とイベント検証を**完了してから**モデルを更新する。別スキル同名、辞書不正、不明イベント報酬の際には未検証情報を採用しない。

## 完了判定と残課題

**スキルデータ方式についての完了条件：** 全 `rare` のうち、(a) 厳格な一意対応、(b) 複数段階の明示的な連鎖、(c) 白なし、(d) 未解決のいずれかを100%分類し、例外を勝手に補完しない。今回の監査では325/325を分類できた。通常ヒント／スキル辞書の設定、間接カバー、3段階表示は人工データの回帰テスト対象。

**まだ未確認：** 全322組を第三者資料で一対一の対応として独立照合したわけではない。実マスターデータの `group_rate` 等による全件検証、○・◎・金の習得仕様の実機確認、公開Pages上での新辞書を使用した画面操作（スマホ含む）、データ提供元の利用条件は次の品質ゲート。新規データ到来時はこの監査を再実行する。

**イベント公開DBは引き続き実イベント0件**。金白辞書の整備は、選択肢・打ち切り条件やイベント報酬の承認に代わるものではない。

## 実UmaSim2ソース結合の追加検証（2026-10-16）

[GitHub Actions一回限りの統合検証](https://github.com/Nimrodx0/Umasupport/actions/runs/38927481224) で、UmaSimの実 `support_card.txt` と `skill_data.txt` を各1回だけGETし、ブラウザと同じ `buildModel` → `public_event_catalog.attach(..., {fullRegistry:true})` の純粋ロジックをNode.jsで検証した。

- サポカ563枚、通常ヒント4,015件、統合スキル辞書836エントリ。
- 金325、全件一意構造連鎖322、ソース上白なし3、構造未確定0、公開イベント0。
- 「右回りの鬼→右回り◎→右回り○」および「究極のヒルクライマー→登山家」が既存ヒントIDとの実名寄せを含めて通過。836は重複を除いた**内部モデルの項目数**であって、ゲーム実収録スキル種類の公式数値ではない。
- 統合検証はGitHub ActionsのNode環境であり、ブラウザのDOM・IndexedDB、表示やモバイルUIの実機操作検証ではない。
- `poc/tools/verify_live_skill_hierarchy.cjs --online` は**開発者の明示実行専用**とし、検証用一時workflowは除去済み。通常CIは外部データをGETしない。

## 2026-10-17：イベントDB障害からの隔離とブラウザ回帰

スキル階層のランタイム結合処理が、イベント独自JSONの取得失敗・形式不正に巻き込まれないよう、イベント読込失敗時も安全な空カタログで全スキル辞書を組み込む。UIの説明は実際の§meta.skillHierarchy§に連動し、322組等の自動推定を独立検証済みと表示しない。

追加したPlaywright Chromiumテストでは、架空563カード・架空126スキルで画面表示／カード追加／IndexedDB保存／通信障害／イベントJSON障害を確認する。**このテストは実ブラウザの機構・表示検査であり、322組の独立マスター照合でも実Pages／スマホ試験でもない。** [検証計画](verification-plan.md)参照。

## 2026-10-17：独立マスターデータ全件照合器を追加

§poc/tools/verify_skill_master.py§ は、UmaSim §skill_data.txt§ と**別途取得した**ゲームマスターSQLite §master.mdb§ を読み取り専用で比較する。コード上の群分類だけで「完全照合済み」としないため、金レア／白通常のID・group_id・group_rate昇格順序を群単位で全件突合し、存在しないID、余分な候補、ランク逆転、同名衝突、マスター側にある想定外の下位スキルを記録する。マスターの §rarity=2§ を金、§rarity=1§ を白とする。検証の元になった [Umamusume Wikiのマスター参照処理](https://umamusu.wiki/Module:Game/Skills/Data/Groups) では §group_id§ と §group_rate§ をスキルのアップグレード系列に使用している。

マスターデータを本リポジトリへ保存せず、**開発者が許可された方法で取得した実データをローカル入力**する。CIは架空のSQLiteデータで監査器を検査するのみ。現時点では**322組を独立マスターで照合した実行結果はない**。マスター版が古い場合は欠損と版差を区別し、最新ゲーム全体を保証しない。完了条件とコマンドは [検証計画](verification-plan.md) を参照。

## 2026-10-17：独立旧版マスターの重なり測定

旧版SQLiteの固定版との実照合を [専用文書](historical-master-audit.md) で記録する。マスターの更新停止は2025年10月であり、現行322組の全件独立裏付けにはならない。

**旧版マスターによる実測：** [限定的照合の記録](historical-master-audit.md)では、2026年UmaSim金325中251系列の一致、53系列の旧版欠損、18系列の構成差、3系列の白なしを確認。独立ゲームマスターの同時期版による全件照合ではなく、金白スキル機能の工程完了を意味しない。

**補正：** 2025年マスターの余剰18 IDは全件 `group_rate=-1` と判明。昇格系列に含めず、旧版マスター一致は初期251から**269組**へ訂正し、[修正後Actions](https://github.com/Nimrodx0/Umasupport/actions/runs/38937864644) で再実測。残る53組は旧版未収録。現行322全件の裏付けは未完。
