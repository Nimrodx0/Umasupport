# U-toolsをサポカイベントのデータ元として使えるか（2026-10-16）

## 結論

**人間が少数カードのイベントを照合する参考サイトとしては有力。現時点では Uma Support Lab が直接取得する機械可読データ供給元としての採用は見送り。**

利用の可否を (A) データ内容、(B) 技術的取得、(C) 権利・運用に分ける。

## A. サイトに載っている情報（ページ閲覧）

- [サトノダイヤモンド（30302）](https://xn--gck1f423k.xn--1bvt37a.tools/supports/30302/event) の公開ページには「連続イベント」「ランダムイベント」、選択肢・能力値・ヒントLvが掲載されている。
- [カレンブーケドール（30295）](https://xn--gck1f423k.xn--1bvt37a.tools/supports/30295/event)、[ジャングルポケット（30240）](https://xn--gck1f423k.xn--1bvt37a.tools/supports/30240/event)、[ダンツフレーム（30269）](https://xn--gck1f423k.xn--1bvt37a.tools/supports/30269/event) についても、イベントの内容がWeb上で参照できる。
- `/supports/{cardId}/event` の5桁IDはUmaSimと一致する例がある。**417枚全部の存在・正しいID・全イベントの完全性は未測定。**
- これらは「記事を開けばイベントの記載がある」ことの確認で、JSON APIの公開や再利用権限を意味しない。

## B. GitHub ActionsによるHTTP実測（本レポジトリ PR #15）

実施日：2026-10-16 UTC 10:32、実行環境：GitHub Actions Ubuntu/Node。開発者向け `poc/tools/probe_utools.cjs` を1回だけ実行。通常CIへの自動組み込みは削除。ゲーム本文・効果文はGitHubに保存せず、通信メタデータのみ記録。

- `GET /robots.txt`：**200**、`text/plain; charset=utf-8`。試験した簡易判定では `/supports/` を明示禁止するルールは見つからなかった。ただし、robotsの結果はデータ再利用許諾ではない。
- `GET /supports/30302/event`（Origin `https://nimrodx0.github.io`）：**403**、応答ヘッダー `cf-mitigated: challenge`。Cloudflareによる保護画面が返る。
- 403の応答に `Access-Control-Allow-Origin` ヘッダーはなかった。これは**チャレンジ応答のヘッダー**であって、正常に返るWebページのCORS可否を証明しない。
- 403を受けたので `30295` への追加試行は中止した。保護回避、セッション模倣、サイト全件巡回を試していない。

**ここから確定できる技術的事実：** GitHub Actionsなどの自動取得環境から普通のGETを行う方式は、今回の検証では取得に失敗した。静的なGitHub PagesのJavaScript `fetch` が成功するかも未確定。公開API・一括JSON・提供者に承認されたデータ配布方法は発見できなかった。

## C. 利用条件と運用

- 公式の[U-toolsについて](https://xn--gck1f423k.xn--1bvt37a.tools/about) には運営連絡先（X [@u__tools](https://twitter.com/u__tools)）が掲載される。フッターに「All Rights Reserved」と表記。ページ上に公認データAPIの仕様や第三者アプリでの再利用許諾は確認できなかった。
- ページ閲覧可能、robotsで明示禁止がない、事実データが掲載されることは、それぞれ機械的取得・コピー・再配信の許可とは別である。
- リクエスト数の多い巡回を開始する前に、運営に **非営利の外部Webアプリでの利用可否、データ取得手段、再配信／保存／公開の可否、クレジット表記、アクセス頻度** を確認する必要がある。
- 著作権だけでなくサイトのサービス条件、運営コスト、Cloudflare保護への配慮も必要。

## 今後の設計判断

- U-toolsは **不足SSR5枚とイベント名差分11枚について、人間が内容を確認する独立参照先** として保留する。
- **運営の明示的な許可と公式の配信手段が確認できない限り、本番コードからの自動取得、Cloudflareの保護回避、一括スクレイピング、イベント文章の同梱は行わない。**
- 第一候補UmaUmaChecker（GitHub上にあるJSON）についても元データのGameWith由来情報の利用許諾を別途確認する。
- U-toolsの運営からAPI／データ利用の許可が得られるなら、**一部カードでの利用条件・HTTP/CORS確認 → データ契約とキャッシュ方針 → 417枚の網羅性評価**の順に進む。
- U-toolsを機械的供給元に採用できない場合は、データ利用を認める供給元を探すか、自作の事実データ（イベントID・対応するスキルID・数値報酬等）を権利関係に注意して整備する。

### 保留事項

(1) 通常応答時のCORS、(2) 公認API・一括データ、(3) 大量アクセスと転載の許可、(4) 417枚における全イベントの完全性、(5) 報酬の成功／失敗・打ち切りの全経路。**未検証事項を「使える／使えない」と断定しない。**
