# Phase 3 F-03：6枚分のイベント設定と分岐状態の俯瞰

更新：2026-10-18。対象：[要件F-03](requirements.md)、[検証計画](verification-plan.md)。

## 実装・操作

本育成・継承育成それぞれ「イベント一括設定」を開くと、**現在選択している保存デッキの6枠**について、公開承認済みイベントを一覧に表示する。個々のカードの選択はカード詳細画面と同じ `slots[index].choices` に保存される。

- 公開イベントがあるカードは「未設定（到達できる選択式イベント）」「設定済み」「到達不可（先行分岐が未設定・打ち切り等）」「自動候補（到達可能な選択肢なしのイベント）」に分けて集計。選択式の後続イベントは先行選択が成立するまで到達不可となる。
- 公開承認済みのイベント記録がないカードは**「イベント未収録」**として数え、未設定イベント数には含めない。「未収録」はゲームにイベントがない証明ではない。空のスロットは未収録カードにも数えない。
- 成功/失敗など分岐結果に依存する報酬の**経路数**を「条件付きの報酬経路」として表示する。カード・イベントの実発生率や実獲得率ではない。
- 状態別フィルター（全体/未設定/設定済み/到達不可/自動候補/未収録）を設ける。非表示の先行イベントも到達判定には用い、フィルターだけで到達可能性や集計結果を変更しない。
- 既存の「デッキ全体のイベント設定」画面から個別選択を更新できる。カード単位と**選択中の保存デッキ全体**に対して、イベント選択を解除できる。どちらも選択数を示し確認ダイアログを経て適用し、カードID・0～4凸・他の保存デッキ・もう片方の育成デッキ・目標は変えない。
- すべての選択が解除されている場合は一括解除ボタンを無効化。6枠にゲームイベントがまったく収録されていなくても管理画面を閲覧でき、完了済みと誤表示しない。

## 検証の3ゲート

| ゲート | ケース・境界 |
|---|---|
| A：機構 | `poc/src/deck_events.js`で、選択式イベント・先行分岐未選択による後続到達不可・自動後続・成功失敗報酬・無イベントカード・空スロットの各状態を検査。カード/デッキ単位の選択解除と他の保存設定・段階を変更しないこと、操作前の不正なスロット形式を拒否することを人工テスト |
| B：実データ | 起動時の独自公開イベントJSONにはレビュー承認済み実イベントが0件。したがって実イベントの分岐や報酬の収録完了・正確性を承認したのではない。新しいゲーム原文や未承認Checker候補を公開UIへ入れない |
| C：ブラウザ | Linux Chromiumで人工563枚を読み、隔離した別コンテキストのみに**人工イベント**を追加。全体/フィルター/先行イベント選択/到達状態/条件付き経路/確認キャンセルとカード・デッキの解除/本育成と継承育成の独立/390px画面幅を検証。Android・Windows物理端末での受け入れは後日に集約 |

## 残件

実ゲームの連続イベントの全件収録・カードIDとイベントID・選択肢・報酬IDの根拠、取得確率、配布権利の確認とスマホ実機検証は依然として未完。Phase 2で公開イベントDBを全件照合する前に、F-03やPhase 3全体が完了したとは扱わない。

関連CI：対応するPRのPoC Core Testsを参照。`poc/tests/browser_skill_smoke.cjs` の人工イベントは試験環境限りで、公開DB `poc/data/reviewed_events.v1.json` の実イベント件数を増やさない。
