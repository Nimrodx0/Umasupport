# 文書運用規約（Documentation policy）

この文書は**文書の責務、正本、変更先の判断**を定める恒久的な規約です。AI・人間の両方に適用します。変更履歴やその日の進捗は、ここにも`AGENTS.md`にも追記しません。

## 文書の責務と正本

| 文書 | 書くこと | 書かないこと |
| --- | --- | --- |
| [`../AGENTS.md`](../AGENTS.md) | 開発支援AIが守る恒久的な規則、参照順、検証・権利・公開の境界 | 日付入りPR報告、達成件数、個別カードの監査、時系列ログ |
| [`../README.md`](../README.md) | プロジェクト概要、利用・起動入口、主な正本文書への案内 | 日々の進捗、過去の暫定方針を現行のように書くこと |
| [`requirements.md`](requirements.md) | 機能の要求、対象・対象外、受け入れ条件 | 実装したという報告、テスト件数、次PRの作業ログ |
| [`decisions.md`](decisions.md) | **ユーザーが確定した**採否・変更理由・旧決定の撤回関係 | 実装しただけで成立したことにする新しい仕様決定 |
| [`architecture.md`](architecture.md) / [`event-schema.md`](event-schema.md) | 現行構成、データフロー、スキーマの設計契約 | PR別の数字やその日の進捗 |
| [`roadmap.md`](roadmap.md) | 目標・優先度・依存関係・工程ゲート・次の未完タスク | 日付ごとの成果を連結した時系列レポート |
| [`verification-plan.md`](verification-plan.md) | A 機構、B 母集団・出典、C 実環境の合否条件 | CIが通ったという結果だけで全軸合格にする表現 |
| [`status.md`](status.md) | **時点と出典を明示した**最新の到達点・未完一覧・検証結果 | 恒久的指示や仕様変更の決定 |
| [`development-history.md`](development-history.md) | 時系列の作業記録とPR・Actionsへの参照 | 旧方針を最新方針として上書きすること |
| 監査・調査個別文書（`*-audit*.md`、`phase2-*.md` 等） | 対象の固定ソース・手法・結果・限界・再現方法 | すべての文書に同じ進捗段落を再掲すること |
| [`index.md`](index.md) | 文書への案内と現行・履歴の識別 | 仕様そのもの |
| [`archive/`](archive/) | 移行前の記録や旧版の保存 | 現行のAI指示としての利用 |

## 優先順位と衝突時の対応

1. **利用者が確認した最新の決定**を `decisions.md` に記録し、現在の仕様を `requirements.md` に反映する。過去の決定は履歴として残し、明示的に「撤回」「置換」を記す。
2. 実装の正しい現状はソースコード／公開用データ／CIの実行結果で検査する。文書の「実装済み」がコード・テストと違えば文書を調査・訂正し、根拠なくコードを文書へ合わせない。
3. 技術設計は `architecture.md`／対応するスキーマ文書、運用・公開条件は `verification-plan.md` と公開ゲート、詳細出典は対象の監査文書を参照する。
4. `status.md` の件数には**測定日・母集団・出典固定版・検証条件・何を保証しないか**を添える。古いスナップショットは現在値に読み替えない。
5. `docs/archive/` や古いPR・ドキュメントは追跡の証拠であって、最新の指示ではない。矛盾があれば正本を確認し、**自動で都合よく統合しない**。

## 変更の書き込み先（1つの事実に対し原則1つの正本）

- **要件変更**：`requirements.md`（現在の契約）＋ `decisions.md`（決定と変更理由）。必要なら関連する検証契約とスキーマも同期する。
- **実装設計変更**：対応する設計・スキーマへ。再現手順や試験結果は専用監査文書とPRに記録。
- **優先順位／工程変更**：`roadmap.md` へ。日々の実績は `status.md` へ最新値を**更新**し、個別監査文書とPRを根拠としてリンクする。 `roadmap.md` の末尾に毎日追記しない。
- **試験・調査結果**：対象監査レポート、PR・Actionsへ。最新の意思決定に影響するなら、それらを根拠に正本を必要最小限修正。
- **AI運用ルールの変更**：`AGENTS.md` の恒久ルールを改定する。ここへの追記は規則の変更があった場合だけで、個別の成果報告はしない。
- **古い記載の整理**：初めに履歴保存（必要なら `archive/`）し、旧版に「現行ではない」と注記。リンク先を点検し、現在の事実の出典を失わない。

## レビュー時のチェック

- 同じ数字・結論・優先度を複数の入口へコピーしていないか。
- 過去の方針（例：「GameWith全面正本」）が現在の方針と誤認されないか。イベント基礎は [GameTora](gametora-baseline-event-policy-20261021.md)、GameWithは特定の疑義の裁定者。
- 「元データに記録された分岐」と「`skill_hint_or` 効果コード」を混同していないか。「技術変換率」と「ゲーム報酬の正確性・公開承認率」を混同していないか。
- URL、相対リンク、コマンドが現在の配置に合うか。
- PRには変更文書の役割と、A/B/Cの実施・未実施を記録したか。

文書責務の機械的回帰は `poc/tests/documentation_policy.test.cjs` をCIで実行する。**機械検査は文書内容の真偽や意思決定の承認を代替しない**。
